# 文章分类与标签治理规则

## 目标与边界

分类和标签都是线上文章元数据的一部分，影响公开搜索、目录导航、首页统计、文章详情和后台筛选。日常维护遵循以下边界：

- 分类用于稳定的层级目录和文章归属；标签用于跨分类的主题检索。
- `默认分类` 是系统兜底分类，保留 `isSystem: true` 与固定排序，不参与普通分类清理。
- 父分类即使没有直接文章也可能承担目录结构，不能因为 `articleCount` 为 `0` 自动删除。
- 单篇文章使用的技术概念属于有效长尾标签，不能按引用次数批量删除。
- 分类、标签、排序、发布状态是线上运营元数据；本地正文同步不得覆盖这些字段。具体回写方式见[文章本地仓库同步流程](文章本地仓库同步流程.md)。

## 日常操作

### 新建与使用

1. 新建分类前先检查现有分类树，优先放入已有稳定父类；确有长期维护价值时才新增目录节点。
2. 新建标签前先搜索同义词、大小写、空格和连字符变体。英文产品、框架和协议名称以官方常用写法为准，例如 `Axios`、`CSV`、`uni-app`。
3. 文章导入后，在后台补齐分类、标签、排序和发布状态；随后按线上运营回写流程更新本地 `output/线上文章` 和 `manifest.json`。
4. 文章下架或进入回收站不代表关联标签可删除。恢复文章仍需保留完整标签引用。

### 修改与删除

1. 分类改名、迁移文章或调整排序前，先确认其子分类、文章和目录展示影响；分类路径调整完成后，执行文章权威快照对比并将运营元数据回写本地。
2. 无文章引用的标签可以在后台直接删除。任何文章（包括回收站文章）仍引用的标签，后台会拒绝删除并返回 `TAG_IN_USE`。
3. 对含义相同的标签，优先选择一个保留标签并将文章引用合并过去；不通过“删除后重建”的方式处理。

## 重复标签合并流程

重复标签合并属于数据库迁移，不是普通后台编辑：

1. 审计候选项，确认只是大小写、空格或连字符等规范化差异，并列出保留 ID、移除 ID、规范名称和受影响文章数。
2. 生产执行前使用 `mongodump` 创建独立备份；普通发布不允许整库覆盖。
3. 使用 `npm run tag-merge:dry-run` 审阅迁移范围。脚本默认只读，缺少预期标签会中止。
4. 确认后执行 `npm run tag-merge:apply`。脚本先迁移全部文章（包含回收站）的标签 ID 并去重，再删除重复标签，最后只对未删除文章重算 `articleCount`。
5. 迁移后独立核验标签总数、已删除 ID、文章是否仍引用旧 ID、`articleCount` 是否与有效文章引用一致，以及文章和分类数量是否保持不变。
6. 将规范名称回写 `output/线上文章` 的 Front Matter 和 `manifest.json`，再记录当天项目台账。
