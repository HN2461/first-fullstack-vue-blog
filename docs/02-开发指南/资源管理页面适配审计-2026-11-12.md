## 本次修复

| 问题 | 影响 | 修复方式 |
| --- | --- | --- |
| 初始化调用超级管理员专用系统设置接口 | 普通媒体管理员遇到 403，初始化流程中断或使用错误上传约束 | 新增仅返回上传约束的媒体接口；上传设置及回收站入口按实际权限显示。 |
| 列表分类默认只加载本人范围 | 超级管理员的文件列表与分类数量、可选范围不一致 | 分类列表与文件夹均按授权加载全部归属，同名分类展示归属信息。 |
| 翻页、筛选和切换视图保留旧选择 | 后续批量命令可能操作当前页面外的文件 | 列表和文件夹请求开始清除选择；回收站使用同样规则。 |
| 回收站响应无请求版本保护 | 快速翻页时旧结果可能覆盖新页，关闭后仍保留结果 | 迟到请求只采用最新结果；关闭后清空，页面关闭时卸载弹窗。 |
| 文件夹末页删除后仍停在空页 | 看不到前页仍然存在的资源 | 根据最新总数回到最后一个有效分页。 |
| 密码箱锁定未覆盖回收站及静态确认框 | 已解锁的文件名或确认操作可继续留在界面 | 本地立即隐藏；关闭回收站、预览和操作弹窗；专属确认框随锁定或卸载销毁；迟到风险检查不能再弹窗。 |
| 仅脱敏密码箱显示字段 | 可用搜索或类型筛选推断锁定文件内容，哈希和时间仍暴露 | 锁定搜索不匹配密码箱，类型统计统一按隐藏类型处理，清空哈希、时间及关联信息。 |
| 密码箱原件直接按原 MIME 内嵌响应 | HTML 等主动内容缺少统一资源接口的响应限制 | 共用原件响应策略，主动内容按附件返回，设置 CSP、nosniff 和私有禁止缓存；读取复用真实路径校验。 |
| 清理候选在等待资源锁期间进入回收站 | 原清理任务取得锁后仍可能物理删除文件 | 取得锁后重新检查 deletedAt；恢复同样持有资源锁，待清理文件恢复后改为主动保留。 |
| 批量操作逐个发现失效或越权 ID | 前面文件已改变、后面才报错 | 删除、恢复和彻底删除均先校验完整可操作范围。 |
| 媒体安全描述和旧上传回执返回 storagePath | 客户端获得无业务用途的服务器绝对路径 | 移除返回字段，兼容过滤旧分片上传完成回执；磁盘记录本身保留。 |
| 来源字典与帮助说明过时 | 文章附件无法按来源筛选，部分说明与当前行为相反 | 补齐文章附件来源、分享限制、搜索选择和密码箱说明，纠正存储、系统分类、临时资源及恢复规则。 |

## 运行边界

- 本次没有数据库结构、枚举、索引或权限种子变更，不需要迁移或历史文件搬移。Media 调整仅影响安全返回字段。
- 若发布本次代码，前后端需要一起更新，页面使用了新的上传规则接口；不需要 `-RunDatabaseTasks`。
- 资源锁和分片会话仍按现有单进程部署设计，多实例扩容前须引入共享协调。
- 引用状态筛选为兼容旧业务扫描，会扫描候选资源后再分页；大库存下需要专项性能评估，不能据本次测试承诺任意规模吞吐。
- 批量预检查避免可提前发现的范围错误，并不等价于 MongoDB 与磁盘之间的跨系统事务；执行期间发生存储故障仍应按实际返回结果核对。
- 复杂 Office 文档仍由浏览器本地解析，本次未进行超大文件压力测试；真实窄屏布局、滚动、媒体播放和文档渲染需人工验收。
