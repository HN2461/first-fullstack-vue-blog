# 工具箱体验研究与改造建议

研究日期：2026-11-20。代码基线：`13b74b39`。

本文记录研究结论及后续根据实际截图调整的实施范围。没有运行数据库任务或部署，本轮未启动浏览器；布局判断来自用户截图、源码及项目 UI 规范，修改后的实际视觉效果和交互感受仍需后续验收。

用户后续通过截图明确了三项优先问题：全部工具时外框被撑长、少量工具时外框缩小；进入具体工具后，来回切换不便；常驻内部导航与分散按钮让对比区域显得拥挤。最终落地固定尺寸的工具箱、临时工具切换面板和顶部集中操作栏，输入与结果使用完整宽度并平分剩余空间。算法整改仍作为独立后续事项。

## 1. 建议结论

将工具箱收敛为“容易找到工具、稳定处理输入、可靠取得结果”的日常工作区。先解决错误结果和操作断点，再统一页面结构。

最终方案采用：**固定尺寸的工具箱 + 临时工具切换面板 + 顶部集中操作栏 + 全宽输入/结果对比区**。

现有控制台已提供系统侧栏，工具内部再次常驻导航会挤占结果对比空间。移除工具内部侧栏，点击工具名称或使用 Ctrl/Cmd+K 打开临时切换面板；面板顶部主搜索占满一行，下面再组织分类、收藏和最近工具，选择后立即回到工作区。模式、示例、清空、执行和复制集中在顶部一行，输入与结果编辑区占用剩余空间。复用控制台现有专注模式进一步扩大工作区。外框显式使用控制台可用高度，工具列表、编辑内容分别滚动。系统一级导航、侧栏、数据库菜单及 RBAC 仍按现有契约运行。

首期沿用已有 29 个工具，以搜索、收藏、最近使用和交互规范提升现有工具的完成度。自动识别、跨工具处理和复杂编辑器按实际需求逐步增加。

## 3. 当前体验问题

### 3.1 寻找与切换路径不完整

| 问题 | 代码依据 | 对使用的影响 |
| --- | --- | --- |
| 目录只有分类筛选，没有工具搜索或任务关键词 | `index.vue:82`；`toolCatalog.js` | 想“JSON 压缩”“去重”“解析 Token”时，需要先理解分类再逐个找名称 |
| 收藏有存储和星标，没有独立收藏入口 | `index.vue:27`、`:57`、`:77`、`:108` | 收藏后仍需在全部工具中寻找，未形成快捷入口 |
| 最近使用只读写，没有渲染入口 | `index.vue:78`、`:127` | 已有的数据没有帮助用户回到上一个任务；从直接链接进入也不会经过 `openTool` 记录 |
| 工具内的侧栏仍只列分类，未列具体工具 | `index.vue:4`、`:121` | 同类工具切换仍需回到目录；点击当前分类时还会停留在当前工具，分类选择同时承担筛选与导航两种含义 |
| 卡片依赖视口宽度决定列数 | `tools.css:82`、`:101` | 实际可用宽度还受系统侧栏和工具分类栏影响，卡片可能过窄；描述仅 11px 并截断，窄屏直接隐藏 |
| 收藏和最近工具采用全站固定 localStorage 键 | `index.vue:77`、`:78` | 同一浏览器切换用户时会混用偏好；后续应按当前用户隔离 |

历史台账 `2026-09-15.json` 记录过“去除搜索框”的决定。当时以紧凑入口为目标；现在已有 29 个工具，且用户明确反馈使用不便，建议重新引入轻量搜索，以新需求重新评估这项取舍。

### 3.2 输入、处理与取结果缺少一致规则

- 29 个组件中只有 UUID 工具提供显式复制功能；JSON、Base64、哈希、JWT、密码等结果需手动选中复制。
- JSON 使用左右输入输出，Base64 使用上下输入输出，各工具的“处理、示例、清空”位置不一致。不同任务可以使用不同布局，但相同任务应采用相同操作习惯。
- 手动处理后再修改输入或参数，旧结果往往继续显示，成功状态也不会失效，无法清楚判断结果属于哪次输入。
- 工具内部动态组件没有草稿保存机制。跨工具切换通常会卸载旧工具并丢失输入；外层控制台标签缓存受用户设置和菜单策略影响，不能作为工具草稿契约。
- 时间戳工具同时开放日期和时间戳输入，却在两者都有值时悄悄优先使用时间戳。用户修改日期后可能以为新日期已经参与计算。
- 正则工具说明包含捕获组，脚本也保存捕获组，但页面只展示匹配文字和位置；颜色工具描述 HSL 互转，实际不接受 HSL；百分比工具描述增长率和占比，实际仅提供折扣。
- 日期间隔、BMI 的计算结果实际上实时变化，“计算”按钮对应空函数，增加了无效动作。
- 正则和时间戳错误区使用固定浅红配色，深色主题下应改用项目语义 token。部分选择器未开启项目要求的搜索能力。

### 3.3 已复现的结果正确性问题

这些问题应进入第一批修复，不能只通过视觉调整解决。

| 工具 | 输入或操作 | 当前结果 | 建议行为 |
| --- | --- | --- | --- |
| 颜色转换 | 默认 `#1677ff` 点击转换 | 报“颜色值超出范围” | 正确解析六位 HEX 并转换 RGB/HSL |
| 颜色转换 | `#000000` | 出现 `#00`、`undefined`、`NaN` | 返回完整有效颜色值；非法输入不能留下貌似有效结果 |
| CSV 转 JSON | `name,code,id`，下一行为 `"Doe, Jane",00123,9007199254740993` | 简单分隔导致列错位、数据丢弃 | 正确处理引号、分隔符和换行；默认保留字符串，类型推断显式开启 |
| 进制转换 | 二进制 `102` | 返回十进制 `2` | 对整串输入校验并指出不允许的字符 |
| 进制转换 | 十进制 `9007199254740993` | 变成 `9007199254740992` | 使用精确整数转换，或明确拒绝超出支持范围的输入 |
| JSON 格式化 | `{"id":9007199254740993}` | 数值被改为 `9007199254740992` | 格式化应保真；采用保留数字字面量的方案，暂不支持时明确拒绝相关输入 |
| Query String | 生成 `tag=vue`、`tag=node` 两行 | 仅保留 `tag=node` | 支持重复键并保持预期顺序 |
| 硬币统计 | 先执行 100 次，再将输入次数改为 10，未重新执行 | 正反面概率合计变成 1000% | 结果使用实际执行时的参数快照，或明确失效等待重算 |

对应代码：`ColorTool.vue:27`、`CsvJsonTool.vue:17`、`NumberBaseTool.vue:19`、`JsonTool.vue:40`、`QueryStringTool.vue:22`、`CoinTool.vue:12`。

另有需要专项处理的边界：Markdown 表格未转义单元格中的竖线、日期与 BMI 空值可出现无效数值、日期默认值取 UTC 日期可能偏离本地日期、UUID 复制 API 不存在时仍显示成功。

## 4. 成熟工具集可借鉴的机制

| 参考 | 实际查阅到的机制 | 本项目的取舍 |
| --- | --- | --- |
| IT-Tools | 工具定义含稳定路径、说明、关键词与异步组件；收藏持久化且在首页优先展示；模糊搜索有独立实现；格式转换组件统一输入、校验和可复制输出 | 扩展现有注册表与公共输入输出面板；先做好别名和任务词匹配。几十个工具不必先引入插件系统，也不必立即增加模糊搜索依赖 |
| DevToys | 强调完成具体小任务；官网展示搜索、统一编辑体验、离线工具、多实例和可设置的智能识别 | 学习任务导向和一致的编辑体验。若做识别，由用户主动粘贴后展示候选工具，保留用户选择；浏览器环境单独处理剪贴板权限 |
| CyberChef | 分类/搜索操作，明确的 Input、Output、Recipe 区域，可关闭自动执行，结果可保存文件，支持本地处理和深链接 | 学习输入与结果分工、手动/自动处理取舍，以及“将结果作为输入”。复杂拖拽编排、断点和 recipe 编辑器暂时后置 |

IT-Tools 的独立站工具布局有大标题和较大上下间距，与本系统的工作台规范不同。这里采用其交互机制，页面视觉仍服从项目主题、字号、间距和工作区结构。

“最近使用”是本项目已有未完成能力，本轮资料不足以证明以上三个产品都提供该能力，因此不将其描述为全部竞品的既有功能。

## 5. 推荐页面方案

### 5.1 工具目录（研究初稿，实施以第 1 节的调整方案为准）

```text
┌────────────────────────────────────────────────────────────┐
│ 搜索工具：名称 / 缩写 / 用途    分类 ▼   全部 / 收藏 / 最近   ? │
├────────────────────────────────────────────────────────────┤
│ JSON 格式化      Base64 编解码      时间戳转换                │
│ 格式化与压缩     文本编码与解码     日期和时间戳互转           │
│ …按可用宽度排列的紧凑工具条目…                              │
└────────────────────────────────────────────────────────────┘
```

- 初次进入显示全部工具；之后可恢复用户的视图和分类偏好，搜索词按当前会话处理。
- 搜索默认覆盖全部工具，匹配中文名、英文缩写、别名和任务词。例如“正则 / regex”“时间戳 / timestamp”“JSON 压缩”“去重”“解析 Token”。
- 中文不强制依赖拼音库；先做好常见名称与任务词，后续根据实际使用补别名。
- 搜索结果优先名称/别名精确匹配，其次前缀与任务关键词，描述匹配置后；不做输入不完整就自动跳转。
- 若提供分类范围内搜索，必须明确范围，并在无结果时允许一键扩大到全部工具。搜索词和分类均可独立清除。
- 收藏支持目录内直接操作，提供独立视图。最近使用最多展示现有设计的 8 个工具，只保存工具 ID 与必要时间信息。
- 目录卡片可改为轻边框条目，名称保持可读，说明使用 12–13px。按内容容器宽度排列；窄屏切成单列或保证标题完整的双列。
- 尚无收藏、尚无最近工具、搜索无结果分别提供合适空态和下一步入口。
- “随机密码”归入随机生成或编码安全相关语义，避免只放在娱乐概念下；其余分类先小范围校准，搜索和收藏承担快速直达。

### 5.2 工具工作区（输入输出规则保留，工具切换改由临时面板承担）

```text
┌────────────────────────────────────────────────────────────┐
│ JSON 格式化 ▼（可搜索切换）  格式化 / 压缩   执行    ☆  ?  目录 │
├────────────────────────────┬───────────────────────────────┤
│ 输入 JSON       示例 / 清空 │ 处理结果             复制 / 更多 │
│                            │                               │
│ 输入编辑区                 │ 输出编辑区                    │
│                            │                               │
├────────────────────────────┴───────────────────────────────┤
│ 就近显示校验结果、错误位置或“输入已修改，待重新处理”          │
└────────────────────────────────────────────────────────────┘
```

上图为交互结构示意，按钮数量和文案按工具调整，最终布局仍需按真实宽度验收。

- 标题、工具切换、主要参数与主操作形成紧凑工具栏；帮助图标承担用途、支持范围和边界说明。
- 工具切换选择器同时搜索全部工具，分类作为分组信息。无需先返回目录再切换。
- 输入操作放在输入侧，结果操作放在结果侧。高频结果均支持复制，较长文本提供下载；“用结果作为输入”等次级能力放在更多操作中。
- 普通转换工具宽屏左右分栏，窄屏上下排列；输入输出可以在受约束的编辑区域内部滚动，操作区保持可达。
- 小型计算器按字段与结果组织，不机械放大成全屏双编辑器。专用工具保留合理布局。
- 统一执行状态：未处理、处理中、成功、失败、输入已修改。修改输入、模式或参数后，旧结果需标记失效或自动更新，不能继续显示为当前输入校验通过。
- 错误保留原始输入，并说明问题与修复方向。错误对应输入时标识输入字段，避免只给输出框加红边。
- 复制按钮仅在实际复制成功后提示成功；失败时保留结果并提供手动复制方法。可选的“粘贴”按钮只在用户主动点击后读取，失败不妨碍常规键盘粘贴。
- 清空已有内容时遵循项目确认规则；示例替换已有输入前也应避免静默覆盖草稿。

### 5.3 三类交互模板

| 模板 | 适用工具 | 统一能力 | 保留差异 |
| --- | --- | --- | --- |
| 文本转换 | JSON、Base64、URL、CSV、Markdown、行处理等 | 参数、输入/输出、复制、示例、清空、运行状态和错误 | 输出格式、校验规则、是否允许实时执行 |
| 参数生成/计算 | UUID、密码、哈希、时间戳、比例等 | 字段校验、运行参数快照、结果复制 | 多结果展示、方向、单位、时区等领域参数 |
| 专用交互 | 正则、秒表等 | 工具切换、帮助、主题和状态规范 | 匹配高亮与捕获组，或计时与分段记录 |

轻量、确定性的计算可以实时更新；涉及大文本或高计算开销的工具使用显式执行及处理中状态。正则必须有可终止的独立执行机制和输入、匹配数量边界，单独增加防抖无法中止已经阻塞主线程的表达式。

## 6. 状态、路由与权限边界

- 保留 `/console/tools` 与 `/console/tools/:toolKey` 的稳定工具地址；刷新、收藏页面或从其他位置进入都能正确定位工具。
- 不把待处理正文、JWT、密码放进 URL。工具链接只定位工具及适合公开的非敏感配置。
- 收藏、最近使用和非敏感偏好按登录用户隔离；清理不存在的工具 ID，并允许本地存储不可用时正常使用工具。
- 普通文本草稿优先在当前工具箱会话的内存中恢复，限制保存数量或总大小；刷新不承诺恢复。JWT、密码等敏感内容默认不进入自动草稿，其他文本工具的输入也可能包含敏感数据，不应统一写入长期存储。
- 退出登录、切换账号时释放当前用户的临时内容。处理输出时也要遵循同样边界。
- 外层多标签栏对工具详情当前只显示“工具箱”，建议在工具页面范围内接入已有标题更新能力，显示“工具箱 · JSON 格式化”等实际名称；无需改造公共标签组件。
- 系统菜单是否展示、工具箱挂在哪个一级分类下、哪些用户可进入，继续以后端菜单与 RBAC 为准。目录中的工具元数据用于页面内部组织，不能替代权限判断。
- 当前工具脚本未发现主动请求后端的处理逻辑；本地处理优势可以保留。未来若接入远程服务，应单独明确处理方式，不能沿用笼统的“全部本地处理”声明。

## 7. 开发拆分与实施顺序

### 第一批：结果可靠与基本操作闭环

1. 修复颜色、CSV、进制、JSON 大整数、重复查询参数和结果参数不同步问题，明确各工具支持范围。
2. 为高频结果补统一复制及真实失败反馈；统一“输入变化后结果失效”的契约。
3. 补输入边界、空值与错误状态；修复正则主线程无界执行风险。
4. 针对已复现的错误补有意义的逻辑测试，避免只测试按钮存在或复刻实现细节。

### 第二批：目录与工作区体验

1. 将固定分类栏收敛为临时工具切换面板；补全搜索、分类、收藏与最近使用能力。
2. 建立文本转换和参数生成/计算的公共交互模板，优先迁入 JSON、Base64、URL、时间戳、哈希、JWT、CSV 等高频工具。
3. 增加工具直接切换和普通文本会话草稿恢复，检查账号切换与外层标签缓存的配合。
4. 统一字号、间距、主题 token、帮助入口和响应式规则。

### 第三批：根据实际使用增加能力

- 正则匹配高亮、捕获组和命名组展示。
- JSON 更清晰的错误定位、可折叠查看或编辑辅助；先复用现有依赖，是否引入专用编辑器单独评估。
- 时间戳明确转换方向、秒/毫秒和时区；百分比区分折扣、占比、增长率，或收窄名称和说明。
- 明确的“用结果继续处理”入口，以及用户主动粘贴后的候选工具推荐。
- 娱乐工具作为保留能力，不在实际使用证据不足时抢占默认推荐区域。骰子/硬币与硬币统计存在重叠，是否合并另行评估并保留旧链接兼容。

建议代码边界：工具元数据注册表、工具目录、工具工作区、输入/输出面板、复制工具函数、会话状态，以及可独立验证的纯转换逻辑。独立计算逻辑有测试价值时再抽取，避免为了每个小工具制造一套插件接口。

本方案主要为前端范围。内部工具目录不必新增后端数据库表；个性化跨设备同步有明确需求时再考虑接口。若进入实施，按项目规则维护当天项目记录，并依据实际改动选择发布目标。

## 8. 验收要点

| 场景 | 预期结果 |
| --- | --- |
| 输入“正则”“regex”“去重”“JSON 压缩” | 能找到合理工具，支持键盘打开；无结果时有清除或扩大范围入口 |
| 收藏工具，再进入收藏视图 | 可直接找到；取消收藏后反馈清楚；不同账号偏好隔离 |
| 直接打开工具链接 | 正确定位工具并更新最近使用；无效 key 提供明确返回路径 |
| JSON 格式化后修改输入或模式 | 结果自动更新或明确待重算，旧成功状态不冒充当前状态 |
| 在普通文本工具间切换再回来 | 当前会话内能恢复预期草稿；敏感工具不自动长期保存内容 |
| 复制成功、权限拒绝、API 不可用 | 分别反馈真实状态，结果始终可以手动取得 |
| 六位 HEX、带引号 CSV、非法进制、大整数、重复查询参数 | 返回正确结果或明确拒绝，不能静默截断、改值或丢列 |
| 复杂正则或大量匹配 | 处理可取消或超时结束，页面其他操作仍可响应 |
| 时间戳两种输入、日期与 BMI 空值 | 转换方向和单位明确，不出现 NaN、Infinity 或输入被悄悄忽略 |
| 浅色/深色与窄屏 | 结果、错误、焦点、选择器和操作区可读可达；按内容宽度排布，避免双侧栏挤压 |
| 键盘使用 | Tab 顺序合理、焦点可见、按钮可激活；快捷键不截获输入法组合和编辑器输入 |

实施阶段运行对应前端测试与构建，完成项目编码检查。若调整后端公共能力，则补后端相关测试。真实浏览器检查须另有用户授权，仅覆盖本问题所需页面和交互。
