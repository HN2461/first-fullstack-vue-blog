# 菜单权限接口约定

本文说明当前控制台菜单的真实来源、角色分配方式和 RBAC 接口。业务菜单保存在后端 MongoDB 中，由用户角色决定；前端负责按返回的菜单树渲染导航，并把菜单路径映射到页面组件。

## 菜单从哪里来

登录后，后端根据用户的启用角色读取角色 `menuIds`，只返回已启用的菜单，并补齐所需的父菜单。超级管理员获得全部已启用菜单。前端 `authStore.rootMenus` 从用户权限数据读取菜单树，再过滤禁用或隐藏项。

因此：

- 数据库里的角色菜单分配决定用户实际看到的业务菜单。
- 菜单隐藏用于保留路由映射或内部入口；隐藏菜单仍可能通过其他页面操作访问，不代表接口授权。
- API 是否能访问仍由后端认证、角色和菜单权限中间件单独校验。
- 前端静态路由只负责页面组件和路径映射，不是权限数据来源。
- 控制台支持多级菜单；顶层菜单显示在顶部，当前顶层下的子菜单显示在可折叠侧栏。
- 文章目录是特殊的系统内置导航模块，但其是否显示和挂载位置仍由数据库菜单配置控制。

## 内置角色

当前内置角色代码为：

| 角色代码 | 默认范围 |
| --- | --- |
| `visitor` | 知识库和被分配的普通协作功能，不含后台管理入口 |
| `admin-base` | 知识库、管理工作台，以及被明确分配的后台业务菜单 |
| `super-admin` | 全部已启用菜单与超级管理员操作权限 |

默认角色菜单只在角色首次创建时初始化。数据库中已存在的角色不会在每次启动时被重置。因此线上实际角色菜单必须查看当前数据库，不应仅根据 `rbac.service.js` 的默认种子或历史快照推断。

## 查看当前用户的实际菜单

### 当前登录用户

`GET /api/rbac/me/permissions` 需要登录，返回当前用户根据现有角色计算的权限，其中包括：

- `permissions.rootMenus`：用于顶部导航的分组树。
- `permissions.flatMenus`：扁平菜单列表。
- `permissions.menuPaths`：可访问菜单路径。
- `roles`：用户当前启用的角色。

普通用户可通过该接口确认自己账号最终拿到的菜单。

### 管理员查看角色分配

以下读取接口需要登录，并受对应后台菜单权限保护：

- `GET /api/rbac/roles?page=1&pageSize=100`：角色列表、菜单 ID 和用户数量；
- `GET /api/rbac/roles/permission-menus`：角色可分配的菜单树；
- `GET /api/rbac/menus`：完整菜单清单和分组树；
- `GET /api/rbac/menus/roots`：当前启用且未隐藏的根菜单，返回 `{ items }`。

`/menus/roots` 不返回 `maxRootMenus` 字段。读取接口只用于检查；角色菜单修改接口是写操作，只应在明确调整授权时调用。

## 关键接口

### 查询菜单

`GET /api/rbac/menus` 返回：

- `items`：菜单扁平列表；
- `tree`、`groups`、`roots`：包含递归子节点的菜单树。

### 新建或编辑菜单

- `POST /api/rbac/menus`
- `PATCH /api/rbac/menus/:id`
- `POST /api/rbac/menus/reorder`
- `DELETE /api/rbac/menus/:id`

以上菜单管理写接口需要登录、菜单访问权限和超级管理员权限。菜单可以多级嵌套，`parentId` 指向父菜单；`level` 由后端根据父级计算。

### 查询及修改角色菜单

- `GET /api/rbac/roles`：查询角色；
- `PATCH /api/rbac/roles/:id/menus`：更新一个角色的菜单；
- `POST /api/rbac/roles/batch/menus`：批量更新角色菜单。

角色菜单写操作需要超级管理员权限。修改前先确认目标角色和受影响用户，保存后用目标用户账号重新读取 `/api/rbac/me/permissions` 验证最终结果。

## 菜单快照

菜单快照用于比较和同步菜单配置，不是线上当前状态的实时镜像。例如 `backend/src/data/menuConfig/local-menu-snapshot-2026-10-03.json` 是 2026-10-03 的线上快照；其后菜单仍可能增删、改名或重新分组。

使用 `backend/src/scripts/syncMenuSnapshotByCode.js` 时：

- 必须显式提供 `--snapshot=<路径>`；
- 默认只预览差异，不写数据库；
- 只有检查计划、确认备份后才增加 `--apply`；
- 脚本按稳定 `code` 匹配，不替换本地菜单 ID，也不负责角色授权同步。

线上菜单检查应优先使用当前登录用户权限接口或后台角色管理页面。不要把旧快照当作当前普通用户或管理员的最终菜单。
