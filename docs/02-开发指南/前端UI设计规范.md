# 前端 UI 设计规范

## 1. 文档定位

本文是控制台、管理后台和企业级业务页面的详细 UI 规范，用于约束新页面、组件扩展和视觉整改。

规则优先级如下：

1. `AGENTS.md` 中的项目结构、权限、组件和开发约束优先级最高。
2. 本文负责补充可执行的视觉、布局和交互细则。
3. 已确认的页面骨架和公共组件契约不得被局部页面随意覆盖。
4. 公开门户、登录注册、文章阅读器等专属场景可以保留自己的视觉语义，但不能污染控制台工作台。

## 2. 目标风格

目标是成熟、克制、清爽、偏年轻的企业级知识库管理系统，整体体验接近 Element Plus 的清晰产品感，同时继续使用 Ant Design Vue 作为基础组件语言。

界面应当具备以下感受：

- 第一眼能识别页面层级、当前状态和主要操作。
- 适合长期、高频使用，信息密度适中，不像营销落地页。
- 有颜色和状态反馈，但不靠大面积颜色、渐变或装饰制造存在感。
- 布局稳定、左右平衡、边界整齐，不出现“某一侧突然多一块”的失衡感。
- 复杂功能通过组件结构和悬浮说明变得易懂，不用大段常驻文字挤占页面。

## 3. 核心原则

### 3.1 工作区优先

- 页面第一屏直接展示可操作的表格、表单、列表、树或编辑器。
- 除非业务确实需要，不增加独立页面头卡、欢迎语、宣传说明、状态横幅和装饰性统计区。
- 页面顶部优先是一条连续工具栏，承载标题、搜索、筛选、统计和主操作。
- 列表页优先把工具栏放入 `BlogTable` 的 `toolbar` 插槽，不在表格上方再叠一张筛选卡片。

### 3.2 克制用色

- 蓝色只表达当前状态、链接、焦点和主要操作。
- 成功、警告、危险必须使用各自语义色，不能全部改成蓝色。
- 禁止大面积浅紫、紫蓝渐变、粉紫光晕、霓虹高光和常见 AI 产品式渐变。
- 禁止为了“高级感”随意给普通容器加渐变；业务工作区默认使用纯色表面。

### 3.3 减少卡片化

- 页面分区不等于卡片。优先使用留白、网格、分隔线和标题层级组织内容。
- 卡片仅用于独立、可重复或确实需要边界的对象，例如统计项、资源项、弹窗和专属工具面板。
- 禁止卡片套卡片，禁止每个表单字段一张卡，禁止顶部标题卡加筛选卡加表格卡的连续堆叠。
- 卡片圆角不得超过 `8px`，阴影应轻微或不使用。

### 3.4 对齐与平衡

- 同级内容优先等高、等宽、同基线、同间距。
- 成对字段使用对称双列；成组操作左右边界应与内容区一致。
- 同一行的标题、筛选和按钮必须垂直居中，不允许按钮单独上浮或下沉。
- 左右布局可以不是机械的 `50% / 50%`，但视觉重量必须平衡，主次关系必须有业务理由。
- `280px + 1fr` 的导航/内容结构、`1fr + 320px` 的主内容/辅助信息结构属于受控不对称；任意宽度、任意错位和无理由留白不允许。

## 4. 视觉语言

### 4.1 浅色主题基准色

| 用途 | 色值 | 使用范围 |
| --- | --- | --- |
| 主色 | `#409EFF` | 主按钮、当前叶子菜单、焦点和关键状态 |
| 主色按下 | `#337ECC` | active、强调文字和深一级交互 |
| 主色浅底 | `#ECF5FF` | 轻量悬浮、弱选中和辅助提示 |
| 成功 | `#67C23A` | 成功状态、正常运行 |
| 警告 | `#E6A23C` | 风险、待处理、注意事项 |
| 危险 | `#F56C6C` | 删除、失败、不可逆操作 |
| 主文字 | `#303133` | 标题、正文和关键数值 |
| 次文字 | `#606266` | 菜单、说明和辅助信息 |
| 弱文字 | `#909399` | 占位符、弱提示和非关键图标 |
| 强边框 | `#DCDFE6` | 输入框、明确容器边界 |
| 弱边框 | `#EBEEF5` | 表格分隔、区域分隔 |
| 页面画布 | `#F5F7FA` | 控制台背景 |
| 工作表面 | `#FFFFFF` | 表格、表单和面板主体 |

实现时优先使用 `--console-*` 主题变量和 Ant Design Vue token，不在业务组件中重复硬编码同一套颜色。

### 4.2 深色主题

- 所有新增工作区必须同时适配深色主题。
- 顶部、侧栏、标签栏、内容区和浮层必须属于同一主题，不能出现局部白块或浅色子菜单包裹层。
- 深色主题沿用同样的层级关系，不通过过亮蓝色、大面积发光或高饱和紫色强调状态。
- 新增颜色必须确认浅色和深色下的文字对比度、边框可见性与禁用状态。

### 4.3 字体、圆角和阴影

- 默认字号 `14px`，紧凑辅助信息可使用 `12–13px`。
- 工作区标题通常使用 `16–20px`，不在控制台使用英雄区级超大标题。
- 强调字重使用 `600`，避免整页粗体。
- 字间距保持 `0`，中文和英文使用项目现有 `Knowledge Sans SC` 字体栈。
- 常规圆角使用 `6px`，容器和弹窗最大 `8px`。
- 阴影仅用于悬浮层或轻微分层，普通工作区优先使用边框，不使用厚重漂浮阴影。

## 5. 控制台骨架

### 5.1 顶部一级导航

- 顶部一级导航保持连续平面结构，不做胶囊、卡片或独立色块。
- 当前项使用主色文字、图标和底部状态线，不使用整块浅蓝背景。
- 右上角工具使用熟悉的图标按钮，尺寸稳定，并配 tooltip。
- 用户信息区使用头像、用户名、角色和下拉菜单，不添加突兀的灰色边框或灰底。

### 5.2 左侧菜单

- 左侧承载当前一级导航下的二级和三级菜单，并保持可折叠。
- 当前叶子菜单使用实色主蓝和白色文字/图标，必须一眼可识别。
- 当前叶子不显示左侧颜色条，悬浮和按下时不得丢失选中背景。
- 选中路径中的父级只使用蓝色文字和图标，背景保持透明，避免多级浅蓝色块堆叠。
- 子菜单展开层与当前主题同色，不出现突兀的异色包裹层。

### 5.3 多标签栏

- 标签栏使用连续平面页签，不把每个标签做成独立小卡片。
- 当前标签使用主色文字和底部状态线；悬浮只改变文字或轻量背景。
- 标签栏与侧栏标题高度保持 `48px`，横向边界线应对齐。
- 标签操作区保持紧凑，关闭、刷新、最大化等图标必须有 tooltip。

### 5.4 内容画布

- 控制台内容使用 `#F5F7FA` 画布和白色工作表面。
- 默认内容间距使用 `14–18px`，内部常用间距按 `8 / 12 / 16 / 24px` 递进。
- 页面主体尽量使用完整可用宽度，不无理由设置较小 `max-width`。
- 文章阅读器可保留暖白纸张等专属阅读语义，但不得反向覆盖其他后台页面。

## 6. 页面结构

### 6.1 列表与管理页面

标准结构：

```text
BlogTable
├─ toolbar：标题 / 搜索 / 筛选 / 统计 / 主操作，尽量单行
├─ table body：固定剩余高度，内部滚动
└─ footer：分页居中，刷新 / 列设置在右侧
```

硬性规则：

- 优先使用 `frontend/src/components/BlogTable.vue`。
- 不重复手写 `a-table + a-pagination` 通用封装。
- 搜索、筛选、批量操作和新增按钮放在 `toolbar` 插槽。
- 页面外层固定工作区高度并 `overflow: hidden`，数据滚动交给表格主体。
- 宽表通过列 `width`、`fixed` 和 `scroll.x` 控制，不手写 `scroll.y`。
- 操作列优先使用带 tooltip 的图标按钮，避免重复文字按钮挤占列宽。
- `striped`、`column-border` 和 `bordered` 只在扫读、对账或强录入场景开启，不默认叠加全部效果。
- 个性化需求优先通过 props、columns、slot 和业务局部样式实现，默认不改 `BlogTable` 公共组件。

### 6.2 表单与设置页面

- 相关字段按业务主题分组，使用连续表单工作区，不给每个小组套一张悬浮卡片。
- 成对字段优先使用对称双列：`repeat(2, minmax(0, 1fr))`。
- 单个长文本、说明编辑器或复杂选择器可独占整行。
- 标签、控件和帮助图标保持同一基线；按钮区与字段边界对齐。
- 保存按钮位置应稳定，同一页面多个设置域可以使用各自明确的保存动作。
- 禁用字段必须保留足够对比度，不能像空白或加载失败。

### 6.3 仪表盘与统计页面

- 只有真正独立、可比较的数据项适合使用卡片。
- 同一行卡片必须等高，标题、数值和辅助信息采用一致基线。
- 颜色用于区分语义，不用每张卡一个随机渐变。
- 图表、待办、快捷操作和最近数据应按共享网格对齐，避免左右底边参差。

### 6.4 详情、编辑器和树形页面

- 详情页优先使用字段分组、描述列表或连续阅读区，不把每个字段做成卡片。
- 编辑器的工具栏、正文和预览应形成明确工作区，固定工具栏尺寸，动态内容不能推动操作区跳动。
- 树形页面允许左右分栏，但分栏顶部、底部和操作区必须对齐；树与表单各自内部滚动。

## 7. 组件规则

### 7.1 按钮与图标

- 主按钮只用于当前区域最重要的提交或创建动作，同一区域通常只有一个主按钮。
- 删除、清空、永久移除使用危险语义，必须有二次确认。
- 熟悉动作优先使用图标：刷新、编辑、删除、下载、预览、更多、展开和收起。
- 图标按钮必须有 tooltip 和 `aria-label`，不能要求用户猜含义。
- 同一操作组尽量使用同一套图标风格；优先复用当前模块已有 Ant Design Icons 或 Lucide 图标。
- 不使用手绘 SVG 代替已有图标。

### 7.2 问号帮助

以下情况必须在标签或标题旁增加 `QuestionCircleOutlined`：

- 字段名称不能完整表达影响范围。
- 操作会覆盖、同步、公开、删除或影响其他用户。
- 数据来源、重复执行行为或权限边界容易误解。
- 指标口径、状态含义或自动化行为不直观。

帮助内容应说明“是什么、用在哪里、会影响什么、不会影响什么”，而不是重复字段名称。说明优先放 tooltip / popover，不在页面顶部堆大段常驻文案。

### 7.3 选择器

- `a-select`、树选择和级联选择默认支持搜索。
- 使用 `show-search`、`option-filter-prop` 或等价过滤能力。
- 只有选项极少、含义一眼明确时才可以省略搜索。
- 长选项必须考虑省略、tooltip 和弹层宽度，不能撑破容器。

### 7.4 标签、状态与提示

- 标签用于状态、分类和简短属性，不作为普通按钮或大段说明容器。
- 状态颜色必须稳定，同一状态不能在不同页面使用不同颜色。
- 操作成功或失败使用 message / notification；需要用户决策时使用 modal / popconfirm。
- 空状态放在稳定尺寸工作区内，不因无数据让页面高度突然塌陷。

## 8. 弹窗、抽屉与浮层

- 所有业务弹窗必须设置最大高度，常规建议为 `60–72vh`。
- 弹窗头部和底部操作区保持稳定，超长内容只在 body 内滚动。
- 长表单可使用 `:body-style="{ maxHeight: '68vh', overflowY: 'auto' }"` 或等价 `styles.body` 配置。
- 图片预览、资源选择、树、长列表和文件区必须有固定或受约束的内容容器。
- 禁止图片、表格、资源卡片或长表单直接把弹窗撑到视口外。
- 弹窗内不能再套无意义的外层卡片；用分组标题和分隔线组织内容。
- 危险确认弹窗必须明确对象、影响和不可逆性。

## 9. 滚动与固定尺寸

- 页面、侧栏、表格、弹窗之间只能存在有明确职责的滚动容器，避免多层滚动互相抢夺。
- 固定高度工作区必须设置 `min-height: 0`，让内部滚动生效。
- 个人导航、简单设置面板等滚动范围明确的区域可以隐藏原生滚动条，但必须保留滚轮、触控板、键盘和触摸滚动。
- 表格、资源列表和无法预判长度的数据区优先保留细滚动条或组件原生滚动反馈，不能为了干净牺牲可发现性。
- 禁止通过 `overflow: hidden` 直接截断用户必须访问的内容。
- 固定格式控件应使用稳定高度、网格轨道或 `aspect-ratio`，避免加载、悬浮和长文字导致布局跳动。

## 10. 响应式规则

- 桌面优先保证左右对齐和工作区高度稳定；移动端再转换为单列。
- 双列字段在窄屏下变为单列，不压缩到文字和按钮互相遮挡。
- 移动端可以隐藏多标签栏，但不能丢失导航和核心操作。
- 固定操作按钮在窄屏下允许换行或占满一行，禁止缩到文字溢出。
- 弹窗移动端宽度应保留视口边距，内容仍只在内部滚动。
- 所有长标题、菜单和按钮文案必须验证换行、截断和 tooltip，不允许遮挡相邻内容。

## 11. 禁止模式

- 紫色、紫蓝或粉紫渐变主导的 AI 风界面。
- 大面积渐变、光晕、装饰圆球、模糊色块和无业务含义插画。
- 页面标题卡、说明卡、筛选卡、表格卡连续套叠。
- 顶部一级导航和多标签栏做成一个个独立小卡片或胶囊。
- 左侧菜单当前项增加左侧颜色条。
- 多级菜单父节点和叶子节点同时铺满浅蓝背景。
- 用户信息按钮增加突兀的灰色边框和灰色底块。
- 在后台页面使用大标题、大留白、营销文案或英雄区。
- 模糊概念没有问号说明，或者把说明写成占据首屏的大段文字。
- 弹窗没有高度阈值，长内容直接撑出屏幕。
- 成对字段、并列卡片或左右面板无理由不等高、不对齐。
- 为单个页面直接修改高复用公共组件的默认表现。

## 12. 页面验收清单

提交前逐项确认：

- 页面第一屏是否直接进入实际工作区。
- 是否移除了无必要的头部卡片、宣传文案和重复说明。
- 标题、筛选、统计和主操作是否能在一条工具栏内组织。
- 列表是否优先使用 `BlogTable` 及其现有能力。
- 左右列、上下边界、按钮和字段是否对齐、等高或有明确主次理由。
- 是否存在紫色渐变、随机色块、厚重阴影或过度卡片化。
- 颜色是否来自主题 token，语义色是否使用正确。
- 模糊字段和影响范围是否有问号 tooltip。
- 图标按钮是否有 tooltip 与 `aria-label`。
- 选择器是否支持搜索。
- 弹窗是否有最大高度且只在内部滚动。
- 长内容是否可访问，滚动条隐藏后是否仍能滚动。
- 浅色和深色主题是否一致。
- 桌面和移动端是否无重叠、截断和异常留白。
- 是否保持原有菜单、RBAC、路由和业务行为不变。
