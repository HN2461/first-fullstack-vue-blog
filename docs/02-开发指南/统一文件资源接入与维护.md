# 统一文件资源接入与维护

本文描述本地已实现的代码行为；截至 2026-11-10，本次改造尚未发布或在生产执行补录。面向日常使用的解释、线上只读盘点及发布前后区别见 [文件资源统一管理白话说明](../01-项目总览/文件资源统一管理白话说明.md)。后续编程还必须遵守根目录 `AGENTS.md` 的“统一文件资源规则”。

## 日常使用

图片和附件仍在对应业务页面上传。头像、简历照片、讨论附件、工作日志凭证、反馈截图、文章图片与媒体素材现在共同使用媒体模块完成文件校验、存储和登记。

媒体资产页面可以按文件来源、保留状态和现有分类筛选。主动上传到素材库的文件会保留；先上传但未保存到业务中的文件处于待绑定状态，超期后由任务再次检查引用，确认不再使用后清理。

私人文件只有所属业务授权用户可以读取。媒体后台菜单本身不会授予全部私人内容的读取权限；不能为了预览把私人附件改成公开链接。

## 新页面接入

新增文件字段时按下面顺序接入，不再自行写目录、文件名和物理删除。

1. 在 `backend/src/modules/media/constants/resourceScenes.js` 登记场景：文件大小、允许图片格式、数量、分类、是否可复用及访问范围。
2. 在 `resourceAccess.service.js` 增加上传和读取的业务授权。上传前检查用户是否有业务菜单权限、是否拥有目标记录；读取时再次执行相应规则。
3. 前端使用 `ResourceUpload`、`ResourcePicker`、`ResourcePreview`、`ResourceImage`，或在已有裁剪、编辑器粘贴回调中调用 `uploadResource`。
4. 后端保存业务时调用 `saveResourceBindings`，在 `validate` 中用 `assertResourceBinding` 检查上传人、场景和目标记录，再执行业务保存。移除、删除或替换时同步差量引用。
5. 在历史对账服务中登记业务的权威字段，便于修复失败或遗漏的反向引用。

前端组件示例：

```vue
<ResourceUpload
  v-model="selectedFiles"
  scene="已在服务端登记的场景"
  :target-id="recordId"
  multiple
  :max-count="5"
/>
```

`selectedFiles` 是安全文件描述数组，包含 `mediaId`、文件名和访问 URL。提交业务时主要传 `mediaId`。前端的数量限制用于交互反馈，后端业务仍必须独立检查总数量，不能相信客户端组件。

已有业务随正文一起提交文件时，可以保留原有接口和用户体验，在服务端调用 `createResource`。`createResource` 只接收经过授权适配器生成的元数据，禁止直接把 `req.body` 展开传入；`accessScope`、分类和磁盘路径不是客户端可自由决定的参数。

从素材库选择目前对文章和管理员素材场景开放。私人讨论、反馈和证件照不会出现在普通素材选择结果里。头像保留现有裁剪界面，裁剪后的文件仍由服务器真实解码校验。

`resourceIdentity.service.js` 统一解析完整网址、查询参数、旧 `/uploads/` 地址和新文件 ID 地址。这只识别文件身份，不授予使用权限。简历手动填入已登记公开图片地址时，会规范到服务端地址并登记照片引用；私人照片要求本人归属与简历场景，未知的旧简历照片只能沿用本人已有简历的实际引用。公开 PNG 等照片用于 Boss 导出时转换为 JPG 副本，原文件不变；专用照片上传仍只接受有效 JPG。

## 文件与引用

`Media` 保存文件元数据、上传人、来源场景、存储提供方和相对存储键。`MediaReference` 保存文件与业务对象的关联，唯一键为文件、业务类型、业务 ID、字段。

业务字段是实际用途的权威来源；反向索引用于定位、删除保护和生命周期管理。现有 URL 扫描保留为历史兼容和对账能力。

`saveResourceBindings` 会在业务保存前建立保守的 pending 引用，业务成功后改为正式引用并释放旧引用。数据库写入结果不确定时保留 pending 引用，避免网络错误导致仍在使用的文件被清理。用显式对账处理悬挂引用，不能因文件当前没有展示在页面上就直接删除。

保留状态：

| 状态 | 含义 |
| --- | --- |
| pending | 上传后等待保存，或原业务解除最后一处引用后等待清理 |
| attached | 已保存到业务，存在结构化引用 |
| retained | 用户主动保留的素材，不因暂时无引用而自动清理 |
| deleting | 清理提交阶段，新的业务绑定必须拒绝 |
| 回收站 | `deletedAt` 有值，禁止新业务引用和统一接口读取 |

待绑定有效期目前为 24 小时。清理每 15 分钟运行一次，每批最多 100 个文件，删除前重新读取状态、结构化引用和历史业务扫描。资源集合不使用 MongoDB TTL 自动删记录，否则会遗漏磁盘原件和派生文件。

扫描到受保护的待绑定文件会延后 24 小时再检查，避免保守引用持续占据最早一批、阻塞后续废弃文件清理；dry-run 不修改到期时间。列表和详情使用同一引用合并口径，已有具体文章用途时不重复增加笼统索引，未确定保存结果的 pending 引用仍显示并保护文件。历史扫描包含尚未补录引用的简历照片、头像和回收站文章。

文章回收站继续保留结构化引用，只有彻底删除文章才释放。简历复制产生第二条照片引用，替换其中一份简历照片不会删除另一份使用的文件。讨论撤销和清理解除引用，文件由统一清理任务按保留期限回收；保留期间已发送的撤销附件不能作为待上传文件预览。

当前部署使用单进程 PM2 fork，绑定和删除通过按文件 ID 的进程内锁串行化。若改为多实例，需要先将锁、上传会话和后台清理升级为共享协调机制，不能直接扩容复用本地会话文件。

## 存储与读取

统一目录清单由 `getResourceStorageAreas()` 提供：

- 上传根目录：兼容历史公开资源；新公开资源位于 `resources/<场景>/年月`。
- 上传根目录旁 `uploads-private`：私人资源和密码箱，位于公开静态根目录之外。
- 历史 `work-journal-private`：兼容旧凭证。
- `.media-tmp`：临时接收、分片和会话，可重建数据。

新文件使用随机文件名。服务端同时保存 provider、storageKey 和兼容的 storagePath；前端业务描述不返回磁盘路径。读取及删除核验路径归属和 realpath，防止目录穿越或符号链接逃逸。

公开文件使用 `/api/resources/:id/content`。私人文件经过同一入口的业务鉴权。前端 `useResourceUrl` 会用已认证 HTTP 实例读取并创建 Object URL，切换文件、取消或卸载后释放。禁止把长期访问令牌放进 URL。

新资源的 `/uploads/resources/` 地址不提供静态直出，避免绕过删除状态和内容类型策略。讨论、简历、反馈、工作日志、密码箱和缩略图目录同样禁止静态读取。发布脚本会维护对应 Nginx 隔离规则，不能仅依赖 Express 拦截。

栅格图片在服务器尝试解码，拒绝只有文件头的伪造图片、截断图片及超过像素阈值的图片。SVG、HTML、脚本等文件可以按场景作为文件保存，但统一原件接口默认附件下载；文本由前端转义后展示，不当作可信页面执行。Office 预览复用本地解析组件，不把私人文件发送给外部在线预览站点。

## 历史文件登记和对账

脚本路径：`backend/src/scripts/reconcileResources.js`。

先执行只读预演：

```powershell
cd backend
node src/scripts/reconcileResources.js
```

输出范围、待登记文件数、元数据更新、引用更新、业务字段更新及异常。预演关闭自动建集合和索引，不写业务数据、不移动文件、不删除未知资源。

正式写入前需要完成 MongoDB `mongodump`，并备份上传根目录、`uploads-private`、历史工作日志目录。在维护窗口暂停 API 写入和资源后台清理（例如停止 API 服务后独立运行 CLI），以免跨进程对账与在线保存或清理交错。明确指定已有备份目录：

```powershell
node src/scripts/reconcileResources.js --apply --backup-dir=绝对备份目录
```

`--backup-dir` 只检查目录存在且非空，不能代替人工确认备份内容与可恢复性。

apply 会显式创建资源引用索引和待绑定清理索引。它会补登记头像、简历照片、讨论附件，补全已有媒体存储描述，并回填文章、工作日志和反馈引用。重复执行依赖服务端原路径和引用唯一键，不靠文件名或哈希合并不同人的私人文件。写入后自动再次 dry-run，仍有差异或异常返回非零状态。

历史文件先保留原物理位置和已有公开 URL，简历与讨论页面通过鉴权兼容入口读取。来源路径越界、文件缺失或私人文件归属冲突会报告异常，禁止按猜测改归属。整个扫描无异常时才移除已知业务的过时引用；发现异常则保守保留旧索引。

已有文件保留原 ID、上传人、分类、公开或密码箱范围；缺失生命周期字段的旧媒体明确补为 retained，不参与临时资源清理，筛选也能查到旧库存。公开文件被其他成员使用不代表修改原上传人。文章引用私人或密码箱资源时报告异常，不自动改为公开。apply 为逐条补录，发生异常时可能已有部分记录完成更新，不能当成整批事务回滚。

此脚本不会自动部署、连接生产执行或覆盖数据库。发布后台代码时也不会默认运行迁移，需要按数据库发布规则单独安排。发布时启用运行数据备份的情况下，备份清单包含 `uploads-private`；前端发布不触碰数据库或文件运行数据。

## 验证

常规验证使用 `frontend/npm run build`、前后端 `npm run test` 和根目录 `pwsh -File scripts/check-encoding.ps1`。本次没有启动浏览器。

新增专项测试覆盖：普通用户头像上传、伪造图片拒绝、私人照片鉴权、简历复制和替换、导出兼容、主动保留素材、待绑定清理、多篇文章复用及回收站保护、绑定与清理并发、失败保守引用、私人文件禁止公开挂载、历史路径保护和迁移幂等。
