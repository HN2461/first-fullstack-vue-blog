# 后端代码说明

后端是独立的 Express + MongoDB 应用，位于 `backend/`。代码按业务模块组织，路由、业务逻辑、数据模型和参数校验放在同一业务边界内。

## 目录结构

```text
backend/
├─ src/
│  ├─ app.js / server.js       # Express 应用与启动入口
│  ├─ config/                  # 环境、数据库、路由和运行配置
│  ├─ constants/               # 跨业务领域常量
│  ├─ middlewares/             # 鉴权、错误处理、请求指标
│  ├─ modules/                 # 按业务划分的后端模块
│  │  ├─ auth/                 # 登录、注册、会话与认证
│  │  ├─ content/              # 文章、分类、标签
│  │  ├─ rbac/                 # 菜单、角色、权限申请
│  │  ├─ settings/             # 系统设置
│  │  └─ .../                  # 互动、媒体、工作日记等其他模块
│  ├─ scripts/                 # 初始化、迁移、修复和维护脚本
│  └─ utils/                   # 跨模块通用工具
├─ tests/                      # 后端测试
├─ uploads/                    # 本地运行上传目录，不进入发布包
├─ ecosystem.config.cjs        # PM2 配置
├─ package.json
└─ .env.example
```

每个业务模块通常使用下面的结构：

```text
backend/src/modules/<业务模块>/
├─ routes/       # HTTP 路由与请求响应组织
├─ services/     # 业务流程与数据读写
├─ models/       # Mongoose 数据模型
└─ validators/   # 请求参数校验
```

不是每个模块都需要四个目录。新增文件应放在实际负责该业务的模块中；只有多个模块真正共用的能力才放进 `config`、`constants`、`middlewares` 或 `utils`。

## 新增文件和发布包

- 新增文章、分类或标签代码：`backend/src/modules/content/`。
- 新增认证代码：`backend/src/modules/auth/`。
- 新增菜单、角色或权限代码：`backend/src/modules/rbac/`。
- 新增设置代码：`backend/src/modules/settings/`。
- 新增一次性修复或迁移脚本：`backend/src/scripts/`。
- 新增测试：`backend/tests/`。

`scripts/package-release.ps1` 会把 `backend/src` 和 `backend/tests` 放入后端白名单发布包。后端根目录下若新增运行必需目录，例如 `templates`、`public`、`views`、`migrations`、`prisma` 或 `openapi`，必须同步把它加入发布白名单。

后端发布包不包含：

```text
backend/.env
backend/node_modules
backend/uploads
backend/logs
backend/legacy-notes
```

生产 `.env` 由服务器独立维护；上传文件是运行数据；依赖在服务器安装；日志和历史迁移资料不属于常规应用发布内容。

## 启动和请求链路

```text
src/server.js
  -> connectDatabase()
  -> createApp()
  -> app.listen(SERVER_PORT)
```

浏览器请求 `/api/...`，请求经过 Express 路由和中间件，再进入对应业务模块的 service 和 model，最终由 Mongoose 访问 MongoDB。

关键文件：

- `backend/src/server.js`：服务启动入口。
- `backend/src/app.js`：全局中间件、静态资源和模块路由挂载。
- `backend/src/config/env.js`：读取环境变量和运行路径。
- `backend/src/config/database.js`：MongoDB 连接。
- `backend/src/config/routes.js`：API 前缀配置，当前为 `/api`。

路由按模块拆分，统一由 `app.js` 挂载，不再集中放在旧的 `backend/src/routes` 目录。

## 权限和菜单

认证中间件位于 `backend/src/middlewares/`。菜单和角色数据由 `backend/src/modules/rbac/` 管理。登录用户的实际权限由数据库角色、角色关联的菜单和启用状态共同决定；前端读取返回的权限树进行展示，路由映射只负责把菜单路径连接到页面组件。

新增后台菜单或角色权限时，应同时检查：

- 菜单是否进入 `rbac` 模块的种子或管理流程。
- 对应 API 是否有正确的认证、角色和菜单访问校验。
- 普通用户、管理员和超级管理员的菜单是否符合预期。
- `backend/tests/` 中是否需要增加权限边界测试。

详细接口约定见[菜单权限接口约定](./菜单权限接口约定.md)。

## 数据模型

Mongoose 模型位于各业务模块内。例如：

```text
backend/src/modules/user/models/User.js
backend/src/modules/content/models/Article.js
backend/src/modules/content/models/Category.js
backend/src/modules/content/models/Tag.js
backend/src/modules/interaction/models/Comment.js
backend/src/modules/media/models/Media.js
backend/src/modules/settings/models/Setting.js
```

修改模型、索引、字段必填规则或关联关系时，先判断是否需要数据迁移。项目数据库发布规则见[数据库发布与迁移流程](../03-部署发布/数据库发布与迁移流程.md)。

## 环境变量

```bash
cd backend
cp .env.example .env
```

核心配置示例：

```env
NODE_ENV=development
SERVER_PORT=3001
CLIENT_ORIGIN=http://127.0.0.1:5173
MONGODB_URI=mongodb://127.0.0.1:27017/personal_fullstack_blog
JWT_SECRET=replace-with-a-long-random-secret
UPLOAD_DIR=uploads
```

`RELEASE_META_FILE` 可选，用于指定只读发布元数据文件路径；未配置时，服务从项目运行目录上级的 `runtime/release-meta.json` 读取。发布脚本在所有部署和公网检查成功后写入该文件，frontend-only 发布不访问 MongoDB。
