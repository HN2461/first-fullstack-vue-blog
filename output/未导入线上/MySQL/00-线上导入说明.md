# MySQL 专题线上导入说明

## 导入范围

在后台“文章导入”页面只选择 `output/MySQL` 下的 `.md` 文件：

- `README.md`：专题总目录。
- `00-线上导入说明.md`：本文。
- `notes`：MongoDB 对照导读和 16 章正文。
- `exercises`：阶段练习和参考答案。

不要把 `sql` 目录中的 `.sql` 文件放进 Markdown 批量导入。它们是本地可执行实验附件，核心语法和示例已经包含在各章正文中。

## 导入步骤

1. 在后台提前创建或确认 MySQL 专题使用的分类和标签。
2. 一次选择上述全部 `.md` 文件进入导入预览。
3. 检查每篇文章的标题、slug、摘要和排序值，确认没有重复 slug。
4. 提交后文章统一以草稿创建，这是系统既定的安全行为。
5. 批量设置分类、标签和文章目录挂载位置。
6. 抽查总目录、第一章、长代码章节、练习答案和移动端表格。
7. 确认内部章节链接对应的文章都已发布后，再发布专题总目录。

## 格式约定

- 每篇 Markdown 都包含 UTF-8 无 BOM 的 Front Matter。
- slug 只使用小写字母、数字和短横线，批量导入时不会依赖中文标题自动生成。
- `sortOrder` 按总目录、导入说明、MongoDB 对照、01 到 16、练习和答案排列。
- 正文只使用系统渲染器支持的标题、列表、表格、引用和 fenced code block。
- 长代码块会在线上自动折叠，可通过“展开”查看完整内容。
- 表格在窄屏中使用横向滚动，不依赖固定页面宽度。
- 章节链接使用知识库 `/console/articles/<slug>` 路径，不使用本地相对文件路径。

## 发布前检查

- 分类不能为空，否则系统会阻止发布。
- 摘要最长 300 个字符，标题最长 120 个字符。
- 总目录中的章节链接只有在目标文章发布后才能正常打开。
- 本地 SQL 文件不会通过 Markdown 导入自动成为附件；确需提供下载时，应在媒体资产中单独上传并绑定文章资源。
- 同一批文件重复导入会按 slug 判定重复并跳过，不会覆盖线上原文章。
