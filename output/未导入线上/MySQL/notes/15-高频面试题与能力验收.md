# 15 高频面试题与能力验收

## 1. 基础必答

### 主键、唯一索引、普通索引有什么区别？

主键唯一且非空，一张表一个主键；InnoDB 主键通常是聚簇索引。唯一索引限制键值唯一，但 NULL 语义需注意；普通索引只提升访问，不保证唯一。

### CHAR 和 VARCHAR 怎么选？

CHAR 固定长度，VARCHAR 可变长度。绝大多数用户名、邮箱、标题用 VARCHAR；真正固定长度且不会变化的编码才考虑 CHAR。

### 为什么金额不用 FLOAT？

二进制浮点无法精确表示许多十进制小数，会出现舍入误差。金额使用 DECIMAL 或统一最小货币单位整数。

### NULL 和空字符串有什么区别？

NULL 表示未知/缺失/不适用；空字符串是已知长度为 0 的字符串。NULL 用 `IS NULL` 判断，聚合和唯一索引中也有特殊语义。

## 2. 查询必答

### WHERE 和 HAVING 的区别？

WHERE 在分组前过滤行，HAVING 在分组后过滤聚合结果。能在 WHERE 过滤的条件尽量提前过滤。

### INNER JOIN 和 LEFT JOIN 的区别？

INNER 只保留匹配行；LEFT 保留左表所有行，右侧未匹配列为 NULL。LEFT JOIN 的右表条件放 WHERE 可能把未匹配行过滤掉。

### EXISTS 和 IN 怎么选？

首先按业务语义选择并查看执行计划。只判断相关行存在时 EXISTS 清晰；小型固定集合适合 IN。反向查询要警惕 `NOT IN` 子查询中的 NULL，常优先 NOT EXISTS。

### UNION 和 UNION ALL？

UNION 去重，UNION ALL 保留重复且通常更快。不需要去重时用 UNION ALL。

### 如何取每组最新一条？

MySQL 8 使用 `ROW_NUMBER() OVER (PARTITION BY 分组列 ORDER BY 时间 DESC, id DESC)`，再筛选序号 1。

## 3. 索引必答

### 为什么使用 B+Tree？

B+Tree 扇出高、树高低，适合磁盘页访问；叶子有序，既支持等值又支持范围扫描。面试不必手写树算法，但要能联系到页、范围和排序。

### 什么是最左前缀？

联合索引按列顺序组织。索引 `(a,b,c)` 通常支持从 a 开始的连续前缀，跳过 a 直接查 b/c 无法依赖它完成常规定位。

### 索引为什么会失效？

常见是对列做函数、隐式转换、前导通配符、跳过联合索引左列、返回范围过大。准确答案应结合 EXPLAIN，不应只背规则。

### 什么是回表和覆盖索引？

二级索引找到主键后再从聚簇索引取其他列是回表；索引包含查询需要的所有列时可直接返回，称覆盖索引。

### 有索引为什么还是慢？

可能扫描范围仍大、回表多、排序聚合重、锁等待、随机 IO、返回数据多或高并发。`key` 非 NULL 不等于性能好。

## 4. 事务与并发必答

### ACID 是什么？

用下单/转账解释原子性、一致性、隔离性、持久性，不要只展开英文。

### 隔离级别有哪些？

READ UNCOMMITTED、READ COMMITTED、REPEATABLE READ、SERIALIZABLE。MySQL InnoDB 常见默认是 REPEATABLE READ，需说明具体实现有 MVCC 和锁语义。

### MVCC 是什么？

通过多版本和可见性规则让一致性读读取适当版本，减少读写互相阻塞。它不消除写锁和所有锁等待。

### 乐观锁和悲观锁？

悲观锁先锁定当前数据再操作，如 FOR UPDATE；乐观锁用 version/旧状态作为 UPDATE 条件，影响 0 行表示冲突。根据冲突概率和流程选择。

### 死锁怎么处理？

固定资源访问顺序、缩短事务、补充索引、减少锁范围；收集死锁日志；应用对幂等事务做有限退避重试。不能承诺系统绝不死锁。

## 5. 场景题

### 如何防超卖？

使用 `UPDATE ... SET stock = stock - ? WHERE id = ? AND stock >= ?` 并检查影响行数；多步下单放事务。极高并发还需限流、排队和专门库存架构。

### 注册邮箱如何防重复？

数据库建立唯一索引，应用插入并捕获重复键错误。先查再插只能改善提示，不能防并发。

### 百万数据如何分页？

普通页码较浅时 OFFSET；深分页或滚动列表用基于稳定排序键的 Keyset/游标分页，并建立对应联合索引。

### 支付回调如何防重复？

验证签名、金额和订单；平台事件 ID 建唯一约束；状态条件更新；处理重复事件为幂等成功；重要流程保存回调记录并对账。

### 生产表新增非空列怎么发布？

先新增可空/有兼容默认值的列，发布兼容代码，分批回填并校验，之后再收紧 NOT NULL，最后清理旧结构。评估大表 DDL 和回滚。

## 6. 不推荐投入过多的入门内容

了解名称和用途即可：

- 自己实现存储引擎或深入页分裂源码。
- 大量复杂存储过程、游标和触发器技巧。
- 冷门数据类型和函数全集。
- 手工搭建复杂多主复制拓扑。
- 没有规模证据就研究分库分表中间件。

入门投入应集中在 SQL、建模、索引、事务、Node.js 数据访问和排障。
