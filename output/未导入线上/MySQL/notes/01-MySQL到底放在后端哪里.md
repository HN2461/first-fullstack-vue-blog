# 01 数据库到底解决什么问题

## 1. 本节目标：先认识工具，不急着写代码

这一课不安装软件，也不要求你记住英文缩写。我们只回答一个问题：**一个网站或应用为什么需要数据库？**

读完后，你应该可以用自己的话解释下面几组词的区别：

- 数据、数据库、数据库管理系统。
- MySQL 和 SQL。
- MySQL Server 和 MySQL Client。
- 前端、后端、数据库各自做什么。

你暂时不需要会建表、会查询，更不需要懂“高并发”“分布式”“索引树”这些词。先把基本画面建立起来。

## 2. 从一条笔记开始：数据应该放在哪里

假设你做了一个很简单的“学习笔记”页面。用户输入：

| 项目 | 用户输入的内容 |
| --- | --- |
| 标题 | 今天认识了 MySQL |
| 正文 | MySQL 可以帮助程序长期保存数据。 |
| 状态 | 草稿 |

这三个内容就是**数据**。数据不一定是数字，文字、日期、图片地址、是否完成的开关，都是数据。

现在问题来了：用户点击“保存”后，这条笔记应该放在哪里？

### 2.1 放在程序变量里，为什么不行

程序运行时当然可以先把内容放在变量里。变量像你手里临时拿着的一张便签：读取很快，但程序一关闭、服务器一重启，便签就没了。

```text
程序正在运行：变量里有“今天认识了 MySQL”
程序停止运行：变量被清空
再次启动程序：找不回刚才的内容
```

变量适合“当前这一步暂时要用的数据”，不适合“下次打开还要看到的数据”。

### 2.2 放进 txt 文件，为什么也不够

把笔记追加到一个文本文件里，确实能长期保存。但当笔记变多，问题会逐渐出现：

| 你想做的事 | txt 文件会遇到的麻烦 |
| --- | --- |
| 找出所有草稿 | 要自己一行行读、判断格式 |
| 把第 15 条笔记标题改掉 | 要自己找到位置、重新写文件 |
| 两个人同时保存 | 两次写入可能互相覆盖 |
| 禁止两个用户使用同一邮箱 | 需要自己写很多检查逻辑 |
| 按创建时间从新到旧分页 | 文件本身没有这种查询能力 |

txt 文件像一本没有目录、没有栏目限制、允许所有人同时乱写的笔记本。数据少时可以；当程序要频繁查、改、多人使用时，它就不合适了。

### 2.3 Excel 又为什么不是网站数据库

Excel 非常适合人手工整理和查看表格，但它的主要使用方式是“人打开文件后编辑”。网站后台更常见的情况是：许多请求在很短时间内来到服务器，服务器需要稳定地读取、写入、筛选、排序和保护数据。

数据库更像一个有规则的档案室：

- 每种档案放在对应的表格里。
- 每个栏目规定好能填什么。
- 可以快速按条件找档案。
- 可以限制重复和空值。
- 多个人同时来办理，也有规则避免把记录写乱。

## 3. 什么是数据库：不是一个普通文件夹

先把三个层次分开：

| 名称 | 用人话说 | 学习笔记例子 |
| --- | --- | --- |
| 数据 | 一条具体信息 | “今天认识了 MySQL” |
| 数据库 | 按规则存放一批数据的地方 | `mysql_learning` |
| 数据库管理系统 | 管理数据库的软件 | MySQL |

可以把它想成图书馆：

```text
图书馆管理系统（MySQL）
└── 一个图书馆分馆（数据库 mysql_learning）
    └── 一本登记册（表 learning_notes）
        ├── 一条登记记录（行）
        └── 书名、作者等固定栏目（列）
```

这里要特别注意：**MySQL 不是某一张表，也不是 SQL 语言。**MySQL 是负责保存、检查和查找数据的软件。

## 4. MySQL 到底做了哪些事

当后端请求 MySQL 保存一条笔记时，MySQL 不只是“写进去”。它会依照表的规则做很多工作：

1. 判断目标数据库和表是否存在。
2. 判断标题是不是必填项。
3. 判断浏览量应该是数字而不是“很多”。
4. 给新笔记分配一个不重复的编号。
5. 把数据可靠地保存起来。
6. 以后收到查询请求时，按条件把需要的数据找出来。

后面课程里会逐个学到这些规则：字段类型、主键、默认值、查询、索引、事务。现在只要知道，它们都属于 MySQL 的职责。

## 5. MySQL 和 SQL：一个是“系统”，一个是“对系统说的话”

这两个词很像，最容易混淆。用餐厅作比喻会比较直观：

| 餐厅场景 | 数据库场景 |
| --- | --- |
| 餐厅厨房和服务流程 | MySQL 数据库管理系统 |
| 你写下“我要一份炒饭”的点单内容 | SQL 命令 |
| 服务员把点单送到厨房 | 客户端把 SQL 发给 MySQL Server |

下面是一句真正的 SQL：

```sql
SELECT id, title
FROM learning_notes;
```

暂时不用害怕它。现在只把它翻译成人话：

```text
请从 learning_notes 这张笔记表中，给我 id 和 title 这两列。
```

逐行认识：

| SQL 片段 | 当前先这样理解 |
| --- | --- |
| `SELECT` | 我要看数据 |
| `id, title` | 我只想看编号和标题这两个栏目 |
| `FROM` | 数据从哪里来 |
| `learning_notes` | 表的名字 |
| `;` | 这条命令说完了，可以执行 |

这一课不要求你能写它。第 03 章会先让 MySQL 跑起来，第 07 章才会把查询完整拆开。

## 6. Server 和 Client：谁保存数据，谁发出请求

初学者常常在安装后看到好几个程序，然后不知道自己到底打开了什么。把它分成两种角色就清楚了：

| 角色 | 它做什么 | 常见例子 |
| --- | --- | --- |
| Server，服务端 | 真正保存数据、执行 SQL、管理权限 | MySQL Server |
| Client，客户端 | 连过去，输入或发送 SQL，展示结果 | `mysql` 命令行、Workbench、DBeaver、后端程序 |

Server 像银行的金库和柜台系统，数据在这里；Client 像你使用的手机银行 App 或柜员窗口。客户端可以有很多个，但它们最终都要连接到同一个 MySQL Server。

所以：

- 只安装 Workbench 或 DBeaver，不等于已经有数据库可以保存数据。
- MySQL Server 没启动，客户端通常会报“无法连接”。
- 你在图形界面里点“运行”时，本质仍然是在把 SQL 发送给 Server。

## 7. 前端、后端、数据库怎样完成一次保存

以“保存学习笔记”为例，真实网站通常不会让浏览器直接连接数据库。流程大致是：

```text
用户输入标题和正文
        ↓
前端页面把内容发给后端接口
        ↓
后端检查：是否登录、标题是否为空、长度是否合理
        ↓
后端通过数据库驱动向 MySQL 发送安全的操作
        ↓
MySQL 保存数据并返回执行结果
        ↓
后端把“保存成功”或错误原因返回给前端
```

为什么不让前端直接连 MySQL？因为网页代码会运行在用户电脑上。把数据库地址、账号和密码放进去，相当于把档案室总钥匙交给每一个访问网站的人。后端是中间的值班人员：它先判断这次请求有没有资格做这件事，再代替用户和数据库沟通。

你学习 SQL 时会直接用客户端连接练习库，这只是为了让你看清数据库本身的行为；真实应用中，这些 SQL 通常由后端代码发出。

## 8. 本课先记住的词

| 词 | 一句话解释 |
| --- | --- |
| 数据 | 程序需要保存或处理的信息 |
| 数据库 | 有结构、有规则的一批数据 |
| MySQL | 管理数据库的软件 |
| SQL | 操作数据库的语言 |
| Server | 真正保存数据并执行命令的一端 |
| Client | 连接 Server、发送命令的工具 |

不需要死背英文。后面每一次使用这些词时，都会再次结合实际操作解释。

## 9. 常见误解

### “数据库就是 Excel 吗？”

它们都能用表格思路组织数据，所以看起来相似；但数据库是程序用来持续、并发、按规则处理数据的系统。Excel 更偏向人手工分析和展示。

### “SQL 是一种编程语言吗？”

SQL 是一种专门用来和关系型数据库沟通的语言。它和 JavaScript、Java 这类通用编程语言的用途不同。现在只需要学会读、写常用 SQL，不需要把它当成另一门大型编程语言。

### “用了 MySQL，就不需要后端了吗？”

不对。MySQL 负责数据；后端负责业务规则、登录校验、权限、接口、错误处理等。它们合作，不互相替代。

## 10. 小练习：不用打开 MySQL

请先用自己的话回答，不确定也没有关系：

1. 程序重启后，为什么变量里的笔记不能作为长期保存方案？
2. 一百条笔记和十万条笔记都放在 txt 文件里，想找出“所有草稿”时会有什么区别？
3. MySQL 是“系统”还是“命令语言”？SQL 又是什么？
4. MySQL Server 和 Workbench/DBeaver 分别更像资料室，还是更像访问资料室的工具？
5. 用户点击“保存”后，为什么一般先到后端，再到数据库？

能答出这些问题，就可以进入下一章认识表格本身。
