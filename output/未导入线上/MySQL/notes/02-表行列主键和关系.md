# 02 一张表到底长什么样

## 1. 本节目标：先看懂表，再去创建表

上一章知道了数据库是一个按规则保存数据的地方。这一章继续把镜头拉近：数据库里最常见的存放方式，是一张张**表**。

学完后，你应该能指出一张表中的行、列和值，并理解为什么每一行都需要一个唯一编号。你会看到一点 SQL，但重点是看懂它在描述什么；第 05 章才会亲手创建表。

## 2. 先看一张你已经见过的表格

假设我们要保存学习笔记，可以先把它写成下面的普通表格：

| id | title | content | status | view_count |
| --- | --- | --- | --- | --- |
| 1 | 认识 MySQL | MySQL 用来保存数据 | active | 5 |
| 2 | 学习 SELECT | SELECT 用来查询数据 | active | 12 |
| 3 | 整理 JOIN 问题 | 还没有完全弄懂 JOIN | draft | 0 |

你可以把这张表理解成一页“学习笔记登记册”。它不是随便的文字，而是规定好了每一条笔记都要按同样的栏目填写。

## 3. 表、行、列和值：把四个最基础的词拆开

先不要被英文吓到。它们只是表格中的不同位置：

| 名称 | 英文 | 生活里的画面 | 上表示例 |
| --- | --- | --- | --- |
| 表 | table | 整本“学习笔记登记册” | `learning_notes` |
| 行 | row / record | 某一条完整登记 | id 为 2 的整行 |
| 列 | column / field | 每条登记都必须有的栏目 | `title` |
| 值 | value | 某个格子里实际写下的内容 | `学习 SELECT` |

用第 2 行来练习：

```text
id = 2
title = 学习 SELECT
content = SELECT 用来查询数据
status = active
view_count = 12
```

这里 `title` 是列名，`学习 SELECT` 是这一列在第 2 行中的值。把“栏目”和“栏目里填写的内容”分开，是后面读 SQL 的基础。

## 4. 表的规则：一张表只回答一类问题

学习笔记表的每一行都在回答同一个问题：**“这是一条什么样的学习笔记？”**

它不应该同时拿来登记用户、评论、订单、分类。否则会变成一个什么都能填、但大部分栏目都空着的杂物表：

| type | username | note_title | comment_content |
| --- | --- | --- | --- |
| user | alice | NULL | NULL |
| note | NULL | 认识 MySQL | NULL |
| comment | NULL | NULL | 写得不错 |

这张表有几个明显问题：

1. 每一行的含义不一致。第一行是用户，第二行是笔记，第三行是评论。
2. 大量 `NULL` 出现，说明栏目和记录不匹配。
3. 很难规定规则。例如 `username` 对用户是必填，对笔记却根本不适用。
4. 以后要查询“所有评论”或“一个用户的所有笔记”，条件会越来越绕。

正确的思路是分类建表：

```text
users           保存用户
learning_notes  保存学习笔记
comments        保存评论
```

表不是杂物箱，而是格式稳定的登记册。一张表中的每一行，应该描述同一种东西。

## 5. 字段名为什么要认真起

列名也叫字段名。它像表头上的标签，告诉以后看到这张表的人，这一列装的是什么。

| 不清楚的字段名 | 更清楚的字段名 | 原因 |
| --- | --- | --- |
| `time` | `created_at` | 知道它是创建时间，不是任何时间 |
| `num` | `view_count` | 知道它是浏览次数，不是任意数字 |
| `text` | `content` | 知道它是正文内容 |
| `flag` | `status` | 知道它表达的是状态 |

课程中使用 `snake_case` 命名，也就是小写单词用下划线连接，例如 `created_at`、`view_count`。这不是唯一写法，但同一项目里保持一种风格，读起来会轻松很多。

## 6. 主键：每一行的身份证号

标题可能重复。比如你今天和下个月都写了一篇“学习 SELECT”；两条笔记的正文甚至也可能一样。数据库需要一种绝对不会混淆的方式来指定“到底是哪一行”。这就是**主键**。

可以把主键想成身份证号或学号：人名可能相同，但学号在学校里必须唯一。

在学习笔记表中，`id` 最适合作为主键：

| id | title | 说明 |
| --- | --- | --- |
| 1 | 学习 SELECT | 第 1 条笔记 |
| 2 | 学习 SELECT | 标题相同，但仍是另一条笔记 |

常见的主键定义是：

```sql
id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT PRIMARY KEY
```

这一行先只建立直觉，后面第 04、05 章会逐词讲透：

| 片段 | 先理解成什么 |
| --- | --- |
| `id` | 这个栏目叫编号 |
| `BIGINT` | 编号存大整数 |
| `UNSIGNED` | 编号不允许是负数 |
| `NOT NULL` | 每一行都必须有编号 |
| `AUTO_INCREMENT` | 新增一行时自动分配下一个编号 |
| `PRIMARY KEY` | 这是整张表识别一行的唯一身份证号 |

`AUTO_INCREMENT` 只是很常见的编号生成方式，不是“主键”本身。即使编号由程序生成，只要它唯一、稳定、不能为空，也可以做主键。

## 7. 唯一约束：除了 id，某些信息也不能撞车

主键负责“每行都不重复”。有时业务本身还规定某个字段不能重复，例如：

| 表 | 不应重复的内容 | 原因 |
| --- | --- | --- |
| 用户 | 邮箱 `email` | 同一个邮箱不应注册两次 |
| 文章 | 访问短地址 `slug` | `/articles/mysql-start` 要能定位一篇文章 |
| 分类 | 分类名称 `name` | 不希望出现两个同名分类 |

MySQL 可以用**唯一约束**保护这条规则：

```sql
UNIQUE KEY uk_users_email (email)
```

当前只需要读懂它的意思：`email` 这一列的值不能重复。`uk_users_email` 是这条规则的名字，常见约定是 `uk_` 开头，表示 unique key。

为什么不能只在后端里“先查一下有没有重复邮箱”？因为两个请求可能恰好同时查到“还没有”，随后又同时插入。后端检查能给用户更友好的提示；数据库唯一约束才是最后一道不会被并发绕过的规则。

## 8. NULL、空字符串和 0：三种不同情况

初学者最容易把“没有值”都当成同一回事，其实数据库中它们含义不同：

| 写法 | 含义 | 归档时间的例子 |
| --- | --- | --- |
| `NULL` | 这个值目前不存在或未知 | 还没有归档 |
| `''` | 有一个字符串值，但字符串长度为 0 | 不适合表达时间 |
| `0` | 数字零 | 不适合表达“还没有归档” |

例如，笔记还没归档时，`archived_at` 可以是 `NULL`。这不是“空白文本”，而是“这件事还没发生，所以没有时间”。

判断 `NULL` 时不能用等号：

```sql
-- 正确：寻找归档时间不存在的笔记
WHERE archived_at IS NULL
```

```sql
-- 错误：SQL 中 NULL 不能用 = 来判断
WHERE archived_at = NULL
```

原因可以先简单理解为：`NULL` 代表“未知/不存在”，而“未知是否等于未知”并不能得到普通的真或假，因此 SQL 专门提供了 `IS NULL` 和 `IS NOT NULL`。

## 9. 表之间的关系：先有画面，不急着写 JOIN

一张表只保存一种东西后，表和表之间自然会产生关系。

### 9.1 一对多

一个分类可以有很多条笔记，而每条笔记先只放进一个分类：

```text
数据库分类 ──> 认识 MySQL
           ├──> 学习 SELECT
           └──> 复习索引
```

这就是一对多：

```text
一个分类（1）  ----  多条笔记（N）
```

之后会在笔记表中放一个 `category_id`，记录它属于哪个分类。第 08 章会实际建两张表并解释它们怎样对上。

### 9.2 多对多

一条笔记可以有多个标签，一个标签也能贴在多条笔记上：

```text
“认识 MySQL” -> 入门、数据库
“学习 SELECT” -> 入门、查询、数据库
```

这就是多对多。多对多不能只靠其中一张表的一列解决，通常需要第三张“中间表”记录每一次关联。现在先认识这个现象即可，毕业项目中会再完整演示。

## 10. 看表时的自测方法

看到任意一张数据库表，可以按下面顺序问自己：

1. 这张表每一行在描述什么东西？
2. 有哪些固定栏目？每个栏目里的值是什么？
3. 哪一列能唯一找到这一行？
4. 哪些值可以暂时没有，哪些必须有？
5. 是否有某个编号指向另一张表？

能回答这五个问题，你已经不是只会把表当 Excel 看了。
