# 第 1 篇：Ant Design X Vue 安装与第一个对话页面

这篇文章只做一件事：在 Vue 项目中安装组件库，并把一条用户消息、一个 AI 回复气泡和发送框显示出来。此时先使用本地模拟回复，不连接真实模型。先确认依赖和基础组件能工作，再做复杂布局会更容易定位问题。

## 1. 检查运行环境和兼容范围

Ant Design X Vue 当前 npm 包声明 Vue `>=3.5.0`、Ant Design Vue `>=4.0.0`。它是 peer dependency，意思是应用需要自己提供这两个宿主依赖，组件库不会替应用选版本。

在项目根目录查看前端版本：

```powershell
cd frontend
npm ls vue ant-design-vue ant-design-x-vue
```

若库尚未安装，最后一项会显示空或未找到，不代表 Vue 本身有问题。也可以查看仓库声明的范围：

```powershell
node -p "require('./package.json').dependencies.vue"
node -p "require('./package.json').dependencies['ant-design-vue']"
npm view ant-design-x-vue version peerDependencies --json
```

版本范围相容只是第一道门槛。真实项目还需要验证 Vite 构建、主题、暗色模式以及具体组件 API。团队最好在功能分支中先试用，不要在多人正在开发的公共分支上临时升级基础依赖。

## 2. 安装包

新项目可执行：

```bash
npm install vue ant-design-vue ant-design-x-vue
```

如果已经有 Vue 和 Ant Design Vue，只添加 AI 组件库：

```bash
npm install ant-design-x-vue
```

在本仓库中要从 `frontend` 目录安装。安装前先确认依赖版本，再检查 `package.json` 和 `package-lock.json` 的差异。不要同时混用 npm、pnpm 和 yarn 安装同一个前端项目，否则锁文件和 node_modules 容易不同步。

## 3. 先用显式导入

初学时建议在使用组件的 Vue 文件里显式导入，这样更容易看出组件来自哪个包：

```vue
<script setup>
import { ref } from 'vue'
import { Bubble, Sender } from 'ant-design-x-vue'

const input = ref('')
const messages = ref([
  {
    key: 'welcome',
    role: 'ai',
    content: '你好，我是演示助手。你可以先问我一个问题。'
  }
])

function handleSend(value) {
  const text = String(value || '').trim()
  if (!text) return

  messages.value = [
    ...messages.value,
    { key: `user-${Date.now()}`, role: 'user', content: text },
    { key: `ai-${Date.now()}`, role: 'ai', content: `收到：${text}` }
  ]
  input.value = ''
}
</script>

<template>
  <main class="chat-demo">
    <Bubble.List
      class="chat-demo__messages"
      :items="messages"
      :roles="{
        user: { placement: 'end' },
        ai: { placement: 'start' }
      }"
      auto-scroll
    />
    <Sender v-model="input" @submit="handleSend" />
  </main>
</template>

<style scoped>
.chat-demo {
  display: flex;
  flex-direction: column;
  gap: 16px;
  width: min(100%, 760px);
  height: min(720px, calc(100vh - 32px));
  margin: 16px auto;
}

.chat-demo__messages {
  flex: 1;
  min-height: 0;
  overflow: auto;
}
</style>
```

当前官方文档把发送回调定义为 `onSubmit`，Vue 模板中监听为 `@submit`。事件名和 Props 可能随版本演进而变化，若运行时没有触发，先对照当前版本的 Sender 文档，不要凭 React 版 API 猜事件名。

这个示例展示了最小的状态方向：输入框绑定 `input`，消息列表读取 `messages`，发送事件调用 `handleSend`，处理函数创建新消息数组。真实应用不能用 `Date.now()` 作为永久消息 ID；服务端消息应由数据库或请求层给出稳定 ID。

## 4. 了解 XProvider

官方文档提供 `XProvider` 用于 Ant Design X Vue 的全局配置和上下文。组件简单试用时，可以按当前版本文档确认是否需要它；开始使用全局配置时，在应用根部按官方示例配置：

```vue
<script setup>
import { XProvider } from 'ant-design-x-vue'
</script>

<template>
  <XProvider>
    <RouterView />
  </XProvider>
</template>
```

不要未经检查就把项目原有的 Ant Design Vue `ConfigProvider`、`App` 或主题 Provider 删掉。项目可能依赖它们提供 locale、主题、消息提示和弹层上下文。先查 XProvider 当前文档如何与 Ant Design Vue 配合，再在根组件中做最小调整，并跑完整构建。

## 5. 自动导入是可选项

官方仓库也提供 `AntDesignXVueResolver` 与 `unplugin-vue-components` 配置，组件数量较多时可以自动导入。初学阶段建议先显式导入，熟悉 API 之后再考虑自动导入。引入 resolver 需要新增插件依赖并改 Vite 配置，所以属于工程设置变更，要让项目组确认后再合入。

## 6. 常见安装错误

| 现象 | 常见原因 | 检查方式 |
| --- | --- | --- |
| 安装时提示 peer dependency 冲突 | Vue 或 Ant Design Vue 低于声明范围 | `npm view ant-design-x-vue peerDependencies --json` |
| `Failed to resolve import` | 包装到了错误目录，或未完成安装 | 确认当前目录是 `frontend`，再执行 `npm ls ant-design-x-vue` |
| 组件标签当普通 HTML 显示 | 模板没有导入组件，或名称/导入路径不正确 | 检查 `<script setup>` 的 import 是否对应安装版本 |
| 页面布局高度为零 | flex 子项缺少 `min-height: 0` 或滚动容器没有高度 | 给消息区域设置可计算高度并使用 `overflow: auto` |
| 构建成功但事件没响应 | 使用了其他版本示例中的事件名称 | 查当前版本 Sender 的 Events，不要仅看组件外观 |
| 暗色页面里部分控件仍是亮色 | 主题 Provider、CSS 变量或自定义覆盖不一致 | 先使用默认主题核对，再按主题规范逐项接入 |

## 7. 本篇验收清单

- 能在终端说明 Vue、Ant Design Vue 和 Ant Design X Vue 的版本。
- 页面能显示用户和 AI 两种气泡。
- 回车或发送按钮能触发发送事件，空文本不会产生消息。
- 连续发送时新消息始终追加在末尾，输入内容发送后被清空。
- 消息列表有明确的高度和自己的滚动区域，不会把整个页面无限撑高。
- `npm run build` 成功，浏览器控制台没有组件解析错误。

## 从空项目到成功发送：按步骤理解示例

如果你刚开始学 Vue，可以按下面顺序读前面的代码，不用一次理解所有组件属性：

1. `ref('')` 创建一个响应式输入草稿。模板绑定后，输入框改变时 Vue 会更新这个值。
2. `messages` 是页面当前显示的消息数组。它是临时演示数据，刷新页面会消失。
3. `handleSend` 先把输入转成字符串并去掉首尾空格，空内容直接返回。
4. 通过新数组追加用户消息和演示回复。Vue 会观察新数组并重新渲染列表。
5. `Bubble.List` 读取 `items`，用角色映射决定左右位置。
6. `Sender` 通过 `v-model` 同步草稿，通过 `submit` 事件通知页面发送。
7. CSS 为对话容器设置稳定高度，让消息列表自己滚动，Sender 留在底部。

这个练习的目的只是建立“输入状态 → 页面事件 → 消息状态 → 组件显示”的闭环。不要把本地假回复误认为模型接入已经完成。

## `main.js` 入口检查

新项目通常在入口创建 Vue app。若组件库当前版本要求 provider，可在这里包住整个应用；如果官方最小示例无需 provider，也不要为了形式强行增加一层：

```js
import { createApp } from 'vue'
import App from './App.vue'
import 'ant-design-vue/dist/reset.css'
import 'ant-design-x-vue/dist/index.css'

createApp(App).mount('#app')
```

Ant Design Vue 与 Ant Design X Vue 的 CSS 文件名可能按发布版本变化，安装后先查包内导出和官方安装文档。入口样式要导入一次，避免每个页面重复导入造成顺序冲突。

如果项目已有主题变量、暗色主题或 ConfigProvider，应先记录已有入口导入和 Provider 层级，再决定如何合并。删除已有 Provider 可能导致 locale、主题或弹层上下文丢失。

## 从官方文档复制 API 的正确步骤

组件库的在线文档会随着最新版变化。一个稳妥的学习步骤是：

1. 在项目 `package.json` 和锁文件确认实际安装版本。
2. 在组件文档找到该版本支持的 Props、Events、Slots、类型定义和完整示例。
3. 先复制一个最小示例，只保留一个组件和一个交互。
4. 确认事件真的触发、参数形状符合预期，再接入业务方法。
5. 对照源码类型声明排查文档不清楚的可选属性。
6. 版本升级后重新编译并回归关键交互，不假定属性名永远不变。

优先区分四种概念：Prop 是“父级给子级的输入”，Event 是“子级向父级发出的通知”，Slot 是“父级传入一段模板”，Method 通常是组件实例可调用方法。React 示例中的 `onSubmit` 属性命名不能机械照搬到 Vue 模板；Vue 组件往往通过 `@submit` 监听事件。

## 完成第一个界面后做这些检查

- 从窄到宽改变窗口，页面不会出现整页水平滚动。
- 长回复和长代码只影响消息区域，不把输入框挤出屏幕。
- 连续提交多次，每条消息都有唯一 key。
- 输入空格、粘贴多行内容和使用中文输入法都能正常工作。
- 用 Tab 键可以进入输入框和发送操作。
- 升级 Ant Design Vue 或 Ant Design X Vue 前先确认 peer dependency，不使用 `--force` 掩盖版本冲突。
- 浏览器控制台没有组件解析错误和未处理 Promise rejection。

这个阶段不需要模型账号、真实密钥、后端接口或数据库。先把组件库的 UI/API 学会，再单独学习请求层。
