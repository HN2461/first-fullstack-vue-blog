# MaxKB 实战开发资料库

> 整理基线：2026-07-19。适用场景是 MaxKB 已由公司部署在其服务器上，开发者通过 Web 管理界面完成智能体、知识库、工具和接入联调，不负责日常服务器运维。
>
> 官方版本基线：MaxKB `v2.10.4-lts`。后续使用本资料前，必须先确认目标环境的实际版本；界面、节点字段、API 路径和安全行为以目标环境与该版本官方文档为准。

## 1. 资料库定位

本资料库分为两层：

| 层级 | 目录 | 用途 |
| --- | --- | --- |
| 实战总指南 | [`01-实战开发指南/`](./01-实战开发指南/) | 从接手环境、设计、开发、联调到发布回滚的完整方法 |
| 细节规范包 | [`02-公共规则/`](./02-公共规则/) | 变量、逐节点配置、导出包、渲染标签和 API 接入细节 |

第一次开发新项目时，不建议直接从某个节点文档开始照抄。推荐顺序：

```text
1. 先读 01-实战开发指南/README.md，确认版本、权限和责任边界。
2. 按 01-从接手环境到发布的标准流程.md 建立环境基线和依赖清单。
3. 根据项目类型阅读智能体编排、知识库、工具/API 专题。
4. 真正配置某个节点时，再进入 02-公共规则/02-节点创建手册。
5. 发布前执行 05-调试测试发布与回滚清单.md。
```

## 2. 最重要的使用原则

### 2.1 四类事实必须分开

| 事实类型 | 例子 | 可否跨项目直接照搬 |
| --- | --- | --- |
| 官方版本事实 | 节点字段、公开 API、导入导出范围 | 先核对版本后复用 |
| 当前环境实测 | 公司服务器上的界面、权限、客户端渲染行为 | 只能在同环境优先采用 |
| 项目协议 | 业务接口、状态码、租户字段、附件协议 | 不能跨项目照搬 |
| 逆向或内部实现 | `.mk` pickle 结构、内部附件下载路径 | 高风险，只作受控研究 |

文档中只要出现“当前截图”“当前环境实测”“部分版本”“内部路径”，就不能当作 MaxKB 永久公开协议。

### 2.2 AI 与确定性逻辑分工

```text
AI 节点：理解自然语言、分类、抽取、总结、生成用户可读文案。
工具/后端：鉴权、权限、字段校验、金额与日期计算、幂等、提交、附件转存、状态变更。
判断器/变量：流程状态机、分支条件、失败兜底、会话状态清理。
知识库：提供可追溯知识，不代替业务数据库和权限系统。
```

任何会产生真实业务副作用的动作，都不能只依赖模型一句“可以提交”或一段自由生成的 JSON。

### 2.3 公司服务器责任边界

开发者通常可以负责：

- 创建或复制智能体、知识库、工具，并完成调试发布。
- 配置接口传参、会话变量、模型和知识库引用。
- 联调公司允许访问的业务 API，提交版本和回归结果。
- 从对话日志、执行详情和命中测试中定位应用问题。

下列动作应先联系平台管理员：

- MaxKB 升级、容器重启、修改 `.env`、安装 Python 依赖。
- 创建或下发模型密钥、系统级 API Key、工作空间和角色权限。
- 配置反向代理、域名、CORS、网络白名单、证书和文件大小限制。
- 读取服务器日志、数据库数据或修改系统保留参数。

## 3. 版本敏感提示

截至 2026-07-19，官方仓库最新发布为 `v2.10.4-lts`，发布时间为 2026-07-16。该版本修复了多项权限、API Key、MCP、文件访问、SSRF 和提示词注入相关问题。

如果公司环境版本低于该版本：

```text
1. 不自行升级服务器。
2. 把当前版本、受影响功能和官方发布说明交给管理员评估。
3. 在升级前避免扩大公开访问、MCP、自定义工具和 HTML 渲染的使用范围。
4. 升级后重新回归接口传参、用户输入、文件上传、工具调用、知识库检索和公开链接。
```
