# 知识库与 RAG 实战规范

## 1. 知识库开发不是“上传文件就结束”

一个可用知识库至少包含：

```text
知识范围与责任人
文档来源与版本
文档结构与清洗规则
分段策略
向量模型
检索模式与阈值
标签与关联问题
命中测试集
更新、禁用和下线流程
对话日志反馈闭环
```

知识库只回答“文档中有什么”，不能代替用户权限、实时业务状态和数据库查询。

## 2. 知识库类型选择

官方 v2 文档提供通用型、Web 站点、飞书和工作流知识库等类型。

| 类型 | 适合场景 | 主要风险 |
| --- | --- | --- |
| 通用型 | 手册、制度、FAQ、离线文档 | 文档更新和版本管理依赖人工流程 |
| Web 站点 | 静态在线文档、帮助中心 | 页面结构变化、抓取范围过大、SSRF 与内网页面风险 |
| 工作流知识库 | 自定义数据源、解析、分段和写入 | 节点依赖更多，需要完整调试与执行记录 |
| 飞书知识库 | 企业飞书文档 | 属于特定版本能力，依赖授权和同步配置 |

公司环境中创建新知识库前，先确认开发者是否有资源授权、模型和知识库创建权限。

## 3. 文档准备规则

优先使用结构规范的 Markdown、DOCX 或 HTML：

```text
1. 标题层级表达真实主题层级。
2. 一个段落围绕一个完整问题或事实。
3. 表格前后留出清晰结构，避免正文与表格粘连。
4. 删除导航、页脚、重复版权、无意义空行和广告。
5. 每份文档记录来源、版本、生效时间和责任人。
6. 过期制度不要和现行制度混在同一检索范围。
```

PDF 扫描件、复杂排版、图片表格和旧 `.doc` 文件需要先验证解析质量；“向量化成功”不代表文本提取正确。

## 4. 分段策略

官方文档说明智能分段会按 Markdown 标题逐级下钻，最多支持 6 级标题，单段最大字符数为 4096；高级分段支持自定义分隔符、长度、清洗和正则表达式。

选择建议：

| 文档情况 | 推荐方式 |
| --- | --- |
| 标题规范、章节清晰 | 先用智能分段 |
| 制度条款、编号章节 | 高级分段 + 经预览验证的正则 |
| FAQ/问答对 | QA 问答对导入或关联问题 |
| 表格密集 | 先验证每行语义，必要时转成 QA 或结构化文本 |
| 超长操作手册 | 按任务和章节重构原文后再导入 |

不要只追求更小分段。分段过小会丢失上下文，过大会稀释相关性并增加模型输入成本。每次导入都应检查分段预览。

## 5. 检索模式

官方命中测试支持：

| 模式 | 特点 | 适合场景 |
| --- | --- | --- |
| 向量检索 | 语义相似，依赖向量模型 | 用户问法多样、同义表达多 |
| 全文检索 | 关键词匹配 | 产品编码、制度条款、专有名词 |
| 混合检索 | 向量与全文结合并重排 | 通用企业知识问答首选候选方案 |

自定义分词只对全文检索和混合检索的全文部分生效，新增术语后需要重新执行分词索引；它不会改变纯向量检索。

## 6. 命中测试方法

建立真实问题测试集，至少包含：

- 标准问法、口语问法、缩写和错别字。
- 精确编号、产品名、制度名和人群限制。
- 文档中有答案、无答案、答案已过期。
- 多文档冲突、相似制度、同名术语。
- 恶意诱导、越权询问和要求忽略知识范围的问题。

每条记录：

```text
问题
期望命中文档/分段
实际 Top N
相似度
是否应直接回答
最终回答是否引用正确
处理动作：改原文/改分段/加关联问题/加标签/调参数
```

调参顺序建议：

```text
先修文档内容和分段
  -> 再补标签、关联问题和专业分词
  -> 再选择检索模式
  -> 最后微调阈值、Top N 和重排
```

不要用不断降低相似度阈值掩盖文档质量问题。

## 7. 标签检索与多知识库

文档标签检索适合在大知识范围中先按业务域、版本、角色或地区缩小文档范围，再交给知识库检索。

多知识库组合时：

```text
1. 先确认所需向量模型兼容，尤其是同一检索节点关联多个库时。
2. 确认当前用户有权使用每个知识库。
3. 多来源结果需要统一重排时使用多路召回。
4. 不把不同版本、不同租户的文档无条件合并检索。
5. 回答中保留知识来源，便于核验和反馈。
```

## 8. 直接回答与模型优化

官方文档支持文档命中后的“模型优化”和“直接回答”处理方式。

直接回答适合：

- 固定链接、图片、标准短答案或不能被模型改写的内容。
- 已由责任人审核、允许原样展示的分段。

模型优化适合：

- 需要综合多个分段、调整表达或结合用户问题生成解释。

直接回答不是免检机制。仍要验证权限、相似度、分段内容和文档是否过期。

## 9. 更新与回滚

```text
1. 新版本文档先在测试知识库导入和命中测试。
2. 确认引用该知识库的智能体和依赖关系。
3. 替换向量模型后，对旧分段执行重新向量化。
4. 文档禁用可用于临时下线；删除不可恢复，删除前先导出。
5. 替换原文档不会自动改变既有分段和向量化内容，不能当成知识更新。
6. 知识库跨环境迁移使用官方导出/导入能力，并复核模型、权限和关联资源。
```

## 10. 对话日志反馈闭环

官方对话日志支持查看用户问题、AI 回答和反馈，并可将修正内容沉淀到知识库。推荐每个版本定期归类：

```text
未命中：补文档、关联问题或分词。
错命中：修分段、标签、阈值或冲突文档。
有证据但回答差：优化提示词和回答格式。
实时业务问题：移出知识库，改用工具/API。
权限问题：修资源授权和业务校验，不通过提示词隐藏。
```
