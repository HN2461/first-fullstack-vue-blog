## 3. 收纳规则

应该放这里：

```text
MaxKB 节点真实配置项
接口传参和会话变量边界
变量引用写法
工具节点和自定义工具规则
跨服务器导入环境参数
发布网址和原生 API 接入边界
跨阶段文档组织和演进规则
MaxKB .mk 导出包解析、半自动改包和巡检规则
```

不应该放这里：

```text
流程目录接口细节
表单元数据接口细节
发起流程完整链路
审核查看完整链路
总智能体完整路由链路
某次联调的长流水账
后端原始接口来文
真实环境地址、租户 ID、学校 ID、测试流程名、真实字段编码
```

这些内容应放回对应功能智能体阶段目录或 `../99-后端来文/`。

## 4. 共用口径

### 4.1 跨项目复用先做字段映射

下面字段是目标项目常用示例字段，不是 MaxKB 内置字段：

```text
businessBaseUrl
agentBaseUrl
schoolID
serviceSecret
userTicket
```

其他项目必须先确认真实字段名。例如 `schoolID` 可能要替换成 `tenantId/orgId/corpId`，`userTicket` 可能要替换成 `accessToken/sessionToken`。

### 4.2 接口传参

位置：

```text
基本信息 -> 接口传参
```

字段只有：

```text
参数
描述
是否必填
默认值
```

接口传参没有“显示名称”“类型”“组件类型”。

### 4.3 会话变量

位置：

```text
基本信息 -> 会话变量
```

字段只有：

```text
参数
显示名称
```

会话变量没有“描述、是否必填、默认值、类型”。

### 4.4 节点创建

当用户问“这个 MaxKB 节点怎么创建 / 怎么配置”时，AI 必须先读：

```text
02-节点创建手册/00-AI创建节点必读.md
```

再读对应节点文件。不要把其他节点的字段套到当前节点，不要补 MaxKB 界面没有的配置项。

## 5. 迁移检查

把本目录迁移到其他项目之前，至少检查下面几类内容：

```text
1. 是否还写着真实项目名称、真实流程名、真实接口路径。
2. 是否还写着真实环境地址、内网 IP、租户 ID、学校 ID、密钥或测试账号。
3. 是否还写着某个项目的页面路径、组件路径、代码文件路径。
4. 是否还写着某次联调、某次导出画布、某个复制节点的流水账。
5. 是否把项目字段写成了 MaxKB 内置字段。
```

如果发现强项目化内容：

```text
1. 可复用方法留在公共规则。
2. 真实字段、真实路径、真实业务链路迁到对应项目进度目录。
3. 公共规则里只保留占位示例和字段映射原则。
4. 不确定是否通用的结论，先标注“待目标项目验证”，不要写成定论。
```
