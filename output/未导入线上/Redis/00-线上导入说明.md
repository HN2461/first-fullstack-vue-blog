# Redis 专题线上导入说明

本文是内容管理说明，不是 Redis 学习正文。当前专题最终收敛为 8 篇详细主文章和 1 篇总目录，在保持小白慢节奏讲解的同时，不再拆成二十多篇碎片文章。

## 目录结构

专题根目录只保留：

- `README.md`：专题总目录和两种阅读路线。
- `00-线上导入说明.md`：本文。
- `notes`：8 篇主文章。

不再保留独立 examples、exercises、参考答案或大段业务代码附件。

## 内容形态

8 篇正文采用统一教学节奏：

1. 先说明本篇阅读定位和必须理解的范围。
2. 用生活场景和比喻建立直觉。
3. 用 Mermaid 展示流程、时序或结构。
4. 穿插最小 Redis、Lua 或 JavaScript 片段。
5. 对代码逐行解释，并明确它不是完整生产实现。
6. 补充常见误区、失败边界和项目判断表。
7. 使用本章小结收束。

当前正文包含 34 幅 Mermaid 图和 19 个短代码块。允许的围栏语言为：

- `mermaid`：流程图、时序图和决策图。
- `redis`：最小 Redis 命令示意。
- `lua`：两段短小原子规则。
- `javascript`：Cache-Aside 和 ioredis 连接示意。

不要把文章重新扩展为命令百科、完整项目代码或练习集。需要可运行项目时，应另建独立实战专题。

## 推荐导入顺序

1. 先导入 `notes` 下 8 篇主文章。
2. 检查标题、slug、sortOrder、正文和 Mermaid。
3. 再导入 `README.md` 作为专题总目录。
4. 本说明可作为内部管理文章保留，不必对普通读者发布。

导入系统当前仍按现有规则创建新草稿，并在 slug 重复时跳过，不会自动覆盖线上旧文章。不要使用旧专题 slug 强行覆盖已存在文章；发布和下架顺序应在后台人工确认。

## 分类和目录建议

建议挂载到“后端开发 / Redis”或“数据库与缓存 / Redis”分类下。

主目录保持 01 到 08 的平面顺序即可，不必再为每个知识点建立深层子目录。总目录已经提供“快速了解”和“完整体系”两种阅读路线。

## Mermaid 发布前检查

发布前至少检查：

1. 每个 `mermaid` 围栏都正常闭合。
2. 中文节点、冒号、括号、引号和箭头可被线上 Mermaid 版本解析。
3. 时序图参与者和消息文字在窄屏下可横向滚动或完整查看。
4. 浅色和深色主题都有足够对比度。
5. 图表内容能从正文推出，不是无关装饰。
6. 页面没有把 Mermaid 源码当普通代码显示。

不同 Mermaid 版本支持的语法可能不同。导入后应在实际文章详情页抽查，而不是只依赖本地编辑器预览。

## 代码块发布前检查

短代码用于教学，不是附件：

- Redis 命令应保持小规模，不增加大批量测试数据。
- Lua 只解释原子判断，不扩展成长业务脚本。
- JavaScript 示例必须保留“简化示意”和生产边界说明。
- 代码块中的 Key、密码、URL 和令牌不得包含真实敏感信息。
- 平台应正确高亮 `redis`、`lua` 和 `javascript` 围栏；即使不支持 Redis 高亮，也不能破坏正文。

## 导入后验收

至少完成以下检查：

- `notes` 恰好有 8 个 Markdown 文件。
- slug 唯一，sortOrder 为 10、20、30、40、50、60、70、80。
- 总目录恰好链接 8 篇主文章，链接与 Front Matter slug 一致。
- 每篇至少有一幅 Mermaid。
- 所有代码围栏成对闭合。
- 中文无乱码，文件为 UTF-8 无 BOM。
- 随机打开基础、数据结构、缓存、高可用和项目案例文章，确认表格、代码和 Mermaid 均正常。

本专题的目标不是让读者背完 Redis，而是让零基础读者在文章数量可控的前提下，仍然得到足够细的解释、正确的知识体系和可用于真实项目的判断边界。
