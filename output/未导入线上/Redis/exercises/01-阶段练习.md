# Redis 阶段练习

所有实验使用 `redis-learning:` 前缀。不要在共享或生产实例执行 `FLUSHDB`、`FLUSHALL`、`KEYS *`、`MONITOR`。

## 第一阶段：Key、TTL 与数据结构

### 1. Key 设计

为生产环境的文章详情、用户 Session、登录 IP 限流、每日文章排行榜分别设计 Key。说明每一段含义、Value 类型和 TTL。

### 2. 临时值

使用一条命令创建邮箱验证码，要求 Key 不存在才写入，并在 5 分钟后过期。说明为什么不能分成 SETNX 和 EXPIRE 两条命令。

### 3. TTL 判断

说明 `TTL key` 返回正数、`-1` 和 `-2` 分别代表什么。如何移除一个 Key 的过期时间？

### 4. JSON 还是 Hash

用户公开资料需要整对象缓存；后台会频繁单独增加登录次数。分别选择 String JSON 或 Hash，并说明依据。

### 5. 最近浏览

使用 List 保存用户最近浏览的 100 篇文章，新文章放最左侧。写出插入、裁剪和读取前 20 条命令。

### 6. 点赞关系

使用 Set 保存文章点赞用户，完成点赞、取消点赞、判断是否点赞和统计点赞数。

### 7. 排行榜

使用 Sorted Set 记录文章浏览榜，增加文章 1001 的 3 次浏览，查询前 10 名，并查询文章 1001 的倒序名次。

### 8. 扩展类型

为“月签到”“日活 UV”“附近门店”分别选择 Bitmap、HyperLogLog 或 Geo。说明其中哪个结果不是精确值。

### 9. 安全遍历

为什么生产不能使用 `KEYS app:*`？写出 SCAN 方案，并说明 SCAN 结果的两个重要边界。

### 10. 无边界增长

指出以下设计的问题并给出修改方案：一个 `online-users` Set 永远 SADD 用户，从不删除；一个 List 保存全站全部访问日志。

## 第二阶段：缓存与一致性

### 11. Cache-Aside

写出文章详情缓存的完整读流程和更新流程，包含未找到文章、Redis 读取失败和缓存删除失败。

### 12. 缓存穿透

攻击者持续请求不存在的文章 ID。提出至少三种防护，并说明空值缓存 TTL 为什么应较短。

### 13. 缓存击穿

一个首页配置 Key 每秒读取 5 万次，物理过期后数据库被打满。给出两种可行重建策略和各自边界。

### 14. 缓存雪崩

部署脚本把 10 万个商品缓存都设置为整 30 分钟。指出风险并给出至少四项改进。

### 15. 更新顺序

解释为什么默认使用“更新 MySQL -> 删除 Redis”，而不是“删除 Redis -> 更新 MySQL”或“更新 MySQL -> 直接 SET Redis”。

### 16. 删除失败

MySQL 更新已提交，但 Redis DEL 超时。接口应返回成功还是失败？如何让缓存最终收敛？

### 17. 旧值回写

描述“读请求查到旧数据库值，写请求更新并删除缓存，读请求随后把旧值写回”的竞态。提出三个增强方案。

### 18. 缓存 DTO

设计一个包含 `schemaVersion`、`cachedAt` 和 `data` 的文章缓存 Value。说明 BIGINT、DECIMAL 和敏感字段如何处理。

## 第三阶段：并发、消息与可靠性

### 19. 固定窗口限流

设计一个 Lua 脚本：每分钟最多 10 次，首次 INCR 时设置 60 秒 TTL，返回是否允许和当前计数。

### 20. 分布式锁

写出获取锁和安全释放锁命令。说明唯一 value、TTL 和 Lua 比较删除分别解决什么问题。

### 21. 锁过期

任务执行 40 秒但锁 TTL 是 30 秒。说明会发生什么，以及为何即使增加 Watchdog 仍需要幂等或 fencing token。

### 22. 幂等

支付平台可能重复回调。设计 MySQL 与 Redis 各自承担的职责，不能只依赖 Redis SETNX。

### 23. Pipeline

需要获取 100 个缓存 Key。说明 Pipeline 的收益、它是否原子，以及批次为什么不能无限大。

### 24. Pub/Sub 与 Stream

“在线系统公告”和“订单创建后发送邮件”分别选择 Pub/Sub、Stream 或专业消息队列，并说明原因。

### 25. Stream 崩溃恢复

消费者读到消息后、XACK 前崩溃。消息在哪里？其他消费者如何恢复？为什么业务处理必须幂等？

### 26. RDB 与 AOF

比较两者的数据丢失窗口、恢复、文件和运行时成本。纯缓存实例是否可以关闭持久化？

### 27. Sentinel 与 Cluster

说明两者解决的问题区别。一个 10 GB 缓存、单机容量充足但要求自动故障切换的系统，应从哪种方案起步？

### 28. 故障切换

主节点写成功但尚未复制就宕机。说明新主可能发生什么，`WAIT` 能降低什么风险、不能保证什么。

## 第四阶段：Node.js 与线上排障

### 29. ioredis 连接

列出普通 HTTP 缓存连接必须配置/考虑的超时、重试、事件监听和关闭方式。为什么 Stream 阻塞读取不应复用相同命令超时？

### 30. Pipeline 结果

`ioredis pipeline.exec()` 返回每条命令的 `[error, result]`。编写处理思路，不能只判断整体 Promise。

### 31. Redis 降级

分别为文章缓存、Session、排行榜、登录限流设计 Redis 不可用时的降级策略，并说明哪些可以 Fail-open。

### 32. 大 Key 排查

线上 P99 突增，SLOWLOG 出现 `HGETALL giant-hash`。列出定位、止损、修复和防复发步骤。

### 33. 热 Key 排查

Cluster 中只有一个分片 CPU 95%，其他分片 20%。提出证据收集和至少四种治理方法。

### 34. 缓存命中率

某缓存命中率 99%，接口仍很慢。列出至少五个可能原因，说明为什么不能只看命中率。

### 35. MySQL + Redis 综合设计

为博客系统设计：文章详情缓存、浏览数缓冲、日榜、Session、搜索限流。给出 Key、类型、TTL、权威来源、一致性策略和 Redis 故障降级。

### 36. 上线评审

编写 Redis 功能上线检查清单，至少覆盖容量、TTL、Key、超时、一致性、持久化、高可用、监控、权限、降级和故障演练。
