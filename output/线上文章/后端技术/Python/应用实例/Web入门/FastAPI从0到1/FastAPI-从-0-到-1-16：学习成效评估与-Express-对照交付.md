# FastAPI 从 0 到 1 16：学习成效评估与 Express 对照交付

这一章不是继续堆技术名词，而是回答两个必须诚实回答的问题：

1. 零基础学习者能不能跟着教程写出第一条 API？
2. 看完 00–15 章，能不能独立负责企业生产服务？

结论先说：第一问基本可以，第二问目前不能直接承诺。教程已经具备一条很好的“从 Python 基础到后端工程方法”的主线，但高级章节仍有一部分是局部机制示例，最终企业项目还需要读者自己完成拼装、部署和故障演练。

## 分项评估

采用 10 分制，评分针对“教程作为学习材料”的完成度，不是对 FastAPI 框架本身打分。

| 维度 | 评分 | 判断 |
| --- | ---: | --- |
| 零基础可读性 | 8.5 | 00–06 章有前置边界、逐行解释、错误路径和明确练习；仍需要学习者具备基本 Python 语法，不能替代完整 Python 入门课。 |
| FastAPI 核心闭环 | 8.5 | 路由、参数、Pydantic、响应、异常、依赖和分层已经形成连续项目。 |
| 数据库与业务工程 | 7.5 | SQLAlchemy、迁移、事务、分页、并发、状态机覆盖较好，但章节间替换文件较多，小白容易在合并时出错。 |
| 安全与质量 | 7.5 | JWT、RBAC、对象权限、测试、日志和部署基线齐全；Refresh Token、CSRF、密钥轮换、真实 CI 和恢复演练仍需独立实践。 |
| 企业级独立交付 | 5.5 | 缺少一份从空目录可启动的最终版本、完整迁移链、可复制的 CI/CD 和线上故障演练，学完更接近“具备项目实战基础”，不是“可独立担任生产负责人”。 |

## 零基础学习者的真实终点

完成第 06 章并通过配套项目测试后，学习者应能：

- 启动服务、调用接口、解释 200/201/204/404/405/422。
- 区分 Path、Query、JSON Body 和响应模型。
- 按 Router、Service、Store 的边界定位一个简单错误。
- 为正常路径和错误路径写最小接口测试。

完成第 09 章后，学习者可以在指导下完成注册、登录、JWT、RBAC 和“只能修改自己的文章”。这里的“在指导下”很重要：能看懂教程中的完整文件，不等于能在陌生业务中独立设计权限模型。

## 还不能直接承诺的能力

以下能力在章节中被介绍或讨论过，但必须通过额外项目验收后才能算“会做”：

| 能力 | 需要补做的证据 |
| --- | --- |
| 数据库发布 | 从空库执行完整迁移，回滚一次，验证备份恢复。 |
| 并发一致性 | 两个客户端同时更新同一文章，稳定得到一次成功、一次 409。 |
| 安全交付 | 密钥轮换、旧 token 失效、登录限流、上传内容签名和审计日志。 |
| 异步任务 | Worker 重启、任务重复投递、失败重试和死信恢复。 |
| 生产运行 | Docker 启动、健康检查、优雅关闭、日志检索、指标告警和回滚。 |
| 团队协作 | README、环境变量说明、代码审查清单、CI 质量门禁和变更记录。 |

## 用 Express 复刻同一条纵向链

每学完一章，在现有 Node + Express 项目中完成同名验收。推荐顺序如下：

1. 用 `express.Router` 复刻 `GET/POST/PATCH/DELETE /articles`，状态码与 FastAPI 版本保持一致。
2. 用 Zod 建立 `Create/Update/Read` 三份 Schema，测试未传字段、`null`、超长文本和未知字段。
3. 把 `Article` 查询和写入放进 Service/Repository，Router 不直接写 Mongoose 查询。
4. 用 `authenticate`、`requirePermission` 和查询数据范围实现对象级权限，禁止信任客户端 `authorId`。
5. 用 `mongoose.startSession()` 实现“文章状态 + 审核记录”事务，用 Vitest + Supertest 验证回滚。
6. 用 Docker 和独立测试数据库完成一次从构建到回滚的演练。

可复用的验收断言是：同一个非法请求在两套服务中都返回相同的 HTTP 状态码和稳定错误码。这样 FastAPI 学习会直接反哺你现有 Express 项目的质量，而不是形成两套互相割裂的记忆。

## 最终能力门槛

不要以“读完 16 章”作为结业条件。满足下面四项，才可以把自己描述为“具备企业 FastAPI 项目实战基础”：

- 能从空目录创建一条带数据库的文章 CRUD，并完成迁移。
- 能实现登录、对象权限、统一异常和核心接口测试。
- 能完成一次 Docker 发布、备份恢复、故障注入和回滚。
- 能在 Express 中复刻同一条业务链，并解释两种框架的职责差异。

如果只能完成前两项，表述为“掌握 FastAPI 核心开发并具备继续参与企业项目的基础”更准确；如果四项全部通过，才接近初级后端工程师可以独立接手一个边界清晰模块的水平。大型系统的架构设计、容量规划、跨团队协作和线上事故处理仍然需要真实项目经验。

## 作者维护建议

为了让教程最终达到“可交付”而不只是“可阅读”，后续应继续维护：

- 一份第 14 章最终版本的完整仓库或压缩包，避免读者手工合并十几个章节文件。
- PostgreSQL、MongoDB 副本集、Redis 和任务 Worker 的一键开发环境。
- GitHub Actions 或同等 CI：格式化、静态检查、测试、迁移检查和依赖漏洞扫描。
- 一次可重复的发布演练，包含备份、健康检查、回滚和日志/指标截图或命令输出。
- 与当前 Express 项目目录的对照索引，标出真实文件路径，而不仅是概念代码。

这几项补齐后，教程才能从“高质量学习路线”升级为“可复用的企业入门训练营”。
