# 接口与会话控制详解第八篇：前后端联调与常见问题排查

## 一、从空文件夹跑起认证系统

### 1.1 创建项目目录

```bash
mkdir auth-system
cd auth-system
npm init -y
```

### 1.2 安装依赖

```bash
npm install express mongoose jsonwebtoken bcrypt express-validator express-rate-limit helmet dotenv cors
```

每个依赖的作用：

| 依赖 | 作用 |
|------|------|
| express | 创建 HTTP 服务和接口路由 |
| mongoose | 连接 MongoDB，定义用户模型 |
| jsonwebtoken | 生成和验证 JWT |
| bcrypt | 哈希密码，避免明文存储 |
| express-validator | 校验请求参数 |
| express-rate-limit | 登录、注册等接口限流 |
| helmet | 设置常见安全响应头 |
| dotenv | 读取 `.env` 环境变量 |
| cors | 允许前端跨域访问后端接口 |

## 二、后端补上 CORS 配置

### 2.1 为什么需要 CORS

开发时常见结构：

```text
前端：http://localhost:5173
后端：http://localhost:3000
```

域名、协议、端口只要有一个不同，浏览器就认为是跨域。前端请求后端时，如果后端没有允许跨域，浏览器会拦截请求。

常见错误：

```text
Access to XMLHttpRequest at 'http://localhost:3000/api/auth/login'
from origin 'http://localhost:5173' has been blocked by CORS policy
```

注意：**JWT 不能绕过 CORS。**  
JWT 只负责认证用户身份，CORS 是浏览器安全策略，两者不是一回事。

### 2.2 在入口文件配置 CORS

```javascript
// index.js
require('dotenv').config()

const express = require('express')
const cors = require('cors')
const helmet = require('helmet')
const rateLimit = require('express-rate-limit')
const connectDB = require('./src/db')

const authRoutes = require('./src/routes/auth')
const userRoutes = require('./src/routes/users')
const adminRoutes = require('./src/routes/admin')

const app = express()

app.use(cors({
  origin: process.env.FRONTEND_ORIGIN || 'http://localhost:5173',
  credentials: true
}))

app.use(helmet())
app.disable('x-powered-by')
app.use(express.json())

app.use(rateLimit({
  windowMs: 15 * 60 * 1000,
  max: 200,
  message: { code: 429, message: '请求过于频繁，请稍后再试' }
}))

app.use('/api/auth', authRoutes)
app.use('/api/users', userRoutes)
app.use('/api/admin', adminRoutes)

app.use((req, res) => {
  res.status(404).json({ code: 404, message: '接口不存在', data: null })
})

app.use((err, req, res, next) => {
  console.error(err.stack)
  res.status(500).json({ code: 500, message: '服务器内部错误', data: null })
})

const PORT = process.env.PORT || 3000

connectDB().then(() => {
  app.listen(PORT, () => {
    console.log(`服务器运行在 http://localhost:${PORT}`)
  })
})
```

### 2.3 如果有多个前端地址

```javascript
const allowOrigins = [
  'http://localhost:5173',
  'http://localhost:3001',
  'https://example.com'
]

app.use(cors({
  origin(origin, callback) {
    if (!origin || allowOrigins.includes(origin)) {
      return callback(null, true)
    }
    callback(new Error('不允许的跨域来源'))
  },
  credentials: true
}))
```

## 三、前端如何保存和携带 Token

### 3.1 学习版：localStorage

小白阶段最容易理解的方案是：

```text
登录成功后：
  accessToken 存 localStorage
  refreshToken 存 localStorage

请求接口时：
  从 localStorage 读取 accessToken
  放进 Authorization 请求头
```

优点：

- 实现简单
- 刷新页面后 token 还在
- 适合学习接口联调

缺点：

- 如果页面存在 XSS 漏洞，攻击者可以用 JavaScript 读取 localStorage
- refresh token 放 localStorage 风险更高，因为它有效期更长

所以学习时可以先这样做，但真实项目要根据安全要求升级。

### 3.2 更安全的常见方案

| 方案 | access token | refresh token | 说明 |
|------|--------------|---------------|------|
| 学习版 | localStorage | localStorage | 简单，适合练习 |
| 改进版 | 内存变量 | httpOnly Cookie | refresh token 不能被 JS 读取 |
| Cookie 版 | httpOnly Cookie | httpOnly Cookie | 更依赖 CORS credentials 和 CSRF 防护 |

如果项目是普通后台管理系统，可以先用学习版跑通，再逐步改进。

## 四、axios 联调示例

### 4.1 创建请求实例

```javascript
// src/utils/request.js
import axios from 'axios'

const request = axios.create({
  baseURL: 'http://localhost:3000/api',
  timeout: 10000
})

request.interceptors.request.use(config => {
  const token = localStorage.getItem('accessToken')
  if (token) {
    config.headers.Authorization = `Bearer ${token}`
  }
  return config
})

request.interceptors.response.use(
  response => response.data,
  async error => {
    const originalRequest = error.config

    if (error.response?.status === 401 && !originalRequest._retry) {
      originalRequest._retry = true

      try {
        const refreshToken = localStorage.getItem('refreshToken')
        if (!refreshToken) throw new Error('缺少 refresh token')

        const { data } = await axios.post('http://localhost:3000/api/auth/refresh', {
          refreshToken
        })

        const newAccessToken = data.data.accessToken
        localStorage.setItem('accessToken', newAccessToken)

        originalRequest.headers.Authorization = `Bearer ${newAccessToken}`
        return request(originalRequest)
      } catch (refreshError) {
        localStorage.removeItem('accessToken')
        localStorage.removeItem('refreshToken')
        window.location.href = '/login'
      }
    }

    return Promise.reject(error)
  }
)

export default request
```

### 4.2 登录接口

```javascript
// src/api/auth.js
import request from '@/utils/request'

export async function login(email, password) {
  const res = await request.post('/auth/login', { email, password })

  localStorage.setItem('accessToken', res.data.accessToken)
  localStorage.setItem('refreshToken', res.data.refreshToken)

  return res.data.user
}
```

### 4.3 获取当前用户

```javascript
// src/api/user.js
import request from '@/utils/request'

export function getMe() {
  return request.get('/users/me')
}
```

### 4.4 退出登录

```javascript
// src/api/auth.js
import request from '@/utils/request'

export async function logout() {
  const refreshToken = localStorage.getItem('refreshToken')

  await request.post('/auth/logout', { refreshToken })

  localStorage.removeItem('accessToken')
  localStorage.removeItem('refreshToken')
}
```

## 五、Refresh Token 入库安全升级

第七篇为了让小白先理解流程，直接把 refresh token 存进数据库。真实项目更推荐存哈希值：数据库泄露时，攻击者拿不到可直接使用的 refresh token。

### 5.1 哈希工具函数

```javascript
// src/utils/hashToken.js
const crypto = require('crypto')

function hashToken(token) {
  return crypto.createHash('sha256').update(token).digest('hex')
}

module.exports = hashToken
```

### 5.2 Model 字段改名

```javascript
// src/models/RefreshToken.js
const { Schema, model } = require('mongoose')

const refreshTokenSchema = new Schema({
  tokenHash: {
    type: String,
    required: true,
    unique: true
  },
  userId: {
    type: Schema.Types.ObjectId,
    ref: 'User',
    required: true
  },
  expiresAt: {
    type: Date,
    required: true
  }
}, {
  timestamps: true,
  versionKey: false
})

refreshTokenSchema.index({ expiresAt: 1 }, { expireAfterSeconds: 0 })
refreshTokenSchema.index({ userId: 1 })

module.exports = model('RefreshToken', refreshTokenSchema)
```

### 5.3 登录时保存哈希

```javascript
const hashToken = require('../utils/hashToken')

await RefreshToken.create({
  tokenHash: hashToken(refreshToken),
  userId: user._id,
  expiresAt: new Date(Date.now() + 7 * 24 * 60 * 60 * 1000)
})
```

### 5.4 刷新时查询哈希

```javascript
const stored = await RefreshToken.findOne({
  tokenHash: hashToken(refreshToken),
  userId: payload.userId
})
```

### 5.5 退出时删除哈希

```javascript
await RefreshToken.deleteOne({
  tokenHash: hashToken(refreshToken),
  userId: req.user.userId
})
```

## 六、常见报错排查表

### 6.1 MongoDB 连接失败

报错类似：

```text
MongooseServerSelectionError: connect ECONNREFUSED 127.0.0.1:27017
```

排查：

| 检查项 | 说明 |
|--------|------|
| MongoDB 是否启动 | 本地服务没启动时一定连不上 |
| 端口是否正确 | 默认端口是 27017 |
| `.env` 是否读取 | 确认 `require('dotenv').config()` 在入口文件顶部 |
| 数据库地址是否正确 | `MONGODB_URI=mongodb://127.0.0.1:27017/auth-system` |

### 6.2 JWT secret 缺失

报错类似：

```text
secretOrPrivateKey must have a value
```

原因：

- `.env` 没有写 `ACCESS_TOKEN_SECRET`
- 入口文件没有执行 `require('dotenv').config()`
- 变量名拼错了

### 6.3 401 未登录

常见原因：

| 原因 | 解决 |
|------|------|
| 没带 token | 检查请求头是否有 `Authorization` |
| token 格式错 | 应为 `Bearer <token>` |
| access token 过期 | 调用 `/api/auth/refresh` |
| 使用了 refresh token 访问业务接口 | 业务接口只能用 access token |

### 6.4 403 权限不足

说明用户已经登录，但角色不满足接口要求。

常见场景：

```text
普通 user 访问 /api/admin/users
```

解决：

- 检查数据库中用户 `role` 是否为 `admin`
- 检查 JWT payload 里的 `role`
- 修改角色后重新登录，因为旧 token 里还是旧角色

### 6.5 429 请求过于频繁

说明触发了 `express-rate-limit`。

学习调试时可以临时把限制调大：

```javascript
const loginLimiter = rateLimit({
  windowMs: 15 * 60 * 1000,
  max: 100
})
```

真实项目不要随意放开登录限流。

### 6.6 E11000 duplicate key

报错类似：

```text
E11000 duplicate key error collection: auth-system.users index: email_1 dup key
```

说明唯一字段重复：

- 邮箱已注册
- 用户名已存在

代码里应返回 `409 Conflict`。

### 6.7 CastError: Cast to ObjectId failed

报错类似：

```text
CastError: Cast to ObjectId failed for value "abc"
```

原因：接口需要 MongoDB ObjectId，但传了普通字符串。

建议给路由参数加校验：

```javascript
const { param } = require('express-validator')

const mongoIdRule = [
  param('id').isMongoId().withMessage('ID 格式不正确')
]

router.put('/users/:id/role', mongoIdRule, validate, async (req, res) => {
  // ...
})
```

### 6.8 bcrypt 安装失败

如果 `npm install bcrypt` 失败，可以先使用纯 JS 版本：

```bash
npm install bcryptjs
```

用法类似：

```javascript
const bcrypt = require('bcryptjs')
```

真实项目优先用 `bcrypt`，安装环境有问题时再临时换 `bcryptjs`。

## 七、接口测试清单

在 Apipost 里按顺序测试：

| 顺序 | 接口 | 期望结果 |
|------|------|----------|
| 1 | `POST /api/auth/register` | 注册成功，返回双 token |
| 2 | 再次注册同邮箱 | 返回 409 |
| 3 | `POST /api/auth/login` | 登录成功，返回双 token |
| 4 | 密码错误登录 | 返回 401 |
| 5 | 不带 token 访问 `/api/users/me` | 返回 401 |
| 6 | 带 access token 访问 `/api/users/me` | 返回当前用户 |
| 7 | 普通用户访问 `/api/admin/users` | 返回 403 |
| 8 | access token 过期后调用 `/api/auth/refresh` | 返回新 access token |
| 9 | 使用新 access token 重试业务接口 | 请求成功 |
| 10 | 调用 `/api/auth/logout` | refresh token 被吊销 |
| 11 | 退出后再次 refresh | 返回 401 |

如果这 11 步全部跑通，说明认证主流程已经闭环。

## 八、毕业练习：接入文章模块

学完认证系统后，不要停在登录注册。继续做一个文章模块，才能真正把认证能力迁移到业务项目里。

### 8.1 需求

```text
文章接口：
  GET    /api/articles              获取文章列表
  GET    /api/articles/:id          获取文章详情
  POST   /api/articles              发布文章，需要登录
  PATCH  /api/articles/:id          修改文章，需要登录且必须是作者
  DELETE /api/articles/:id          删除文章，需要登录且必须是作者或 admin
```

### 8.2 Article Model

```javascript
// src/models/Article.js
const { Schema, model } = require('mongoose')

const articleSchema = new Schema({
  title: {
    type: String,
    required: [true, '标题不能为空'],
    trim: true,
    maxlength: [80, '标题最多80个字符']
  },
  content: {
    type: String,
    required: [true, '正文不能为空']
  },
  author: {
    type: Schema.Types.ObjectId,
    ref: 'User',
    required: true
  }
}, {
  timestamps: true,
  versionKey: false
})

articleSchema.index({ createdAt: -1 })
articleSchema.index({ author: 1, createdAt: -1 })

module.exports = model('Article', articleSchema)
```

### 8.3 发布文章

```javascript
// src/routes/articles.js
const express = require('express')
const { body, param } = require('express-validator')
const Article = require('../models/Article')
const { authMiddleware } = require('../middleware/auth')
const validate = require('../middleware/validate')

const router = express.Router()

const createRules = [
  body('title').trim().notEmpty().withMessage('标题不能为空')
    .isLength({ max: 80 }).withMessage('标题最多80个字符'),
  body('content').trim().notEmpty().withMessage('正文不能为空')
]

router.post('/', authMiddleware, createRules, validate, async (req, res) => {
  try {
    const article = await Article.create({
      title: req.body.title,
      content: req.body.content,
      author: req.user.userId
    })

    res.status(201).json({
      code: 201,
      message: '发布成功',
      data: article
    })
  } catch (err) {
    res.status(500).json({ code: 500, message: '服务器错误', data: null })
  }
})

module.exports = router
```

### 8.4 删除文章：作者或管理员

```javascript
router.delete(
  '/:id',
  authMiddleware,
  [param('id').isMongoId().withMessage('文章 ID 格式不正确')],
  validate,
  async (req, res) => {
    try {
      const article = await Article.findById(req.params.id)
      if (!article) {
        return res.status(404).json({ code: 404, message: '文章不存在', data: null })
      }

      const isAuthor = String(article.author) === String(req.user.userId)
      const isAdmin = req.user.role === 'admin'

      if (!isAuthor && !isAdmin) {
        return res.status(403).json({ code: 403, message: '没有删除权限', data: null })
      }

      await article.deleteOne()
      res.json({ code: 200, message: '删除成功', data: null })
    } catch (err) {
      res.status(500).json({ code: 500, message: '服务器错误', data: null })
    }
  }
)
```

### 8.5 练习验收标准

做到下面这些，说明你已经能继续写项目：

| 能力 | 验收方式 |
|------|----------|
| 会写公开接口 | 不登录也能看文章列表和详情 |
| 会写登录保护接口 | 不登录不能发布文章 |
| 会使用当前用户身份 | 发布文章时 `author` 自动取 `req.user.userId` |
| 会做资源权限判断 | 只能作者或 admin 删除文章 |
| 会做参数校验 | 空标题、错误 ID 会返回 400 |
| 会用 Apipost 测试 | 能保存 token 并跑通完整流程 |

## 九、小结

这一篇补的是项目落地阶段最关键的内容：

| 主题 | 核心要点 |
|------|----------|
| 运行闭环 | 创建目录、安装依赖、配置 `.env`、启动服务 |
| CORS | JWT 不能解决跨域，后端必须允许前端来源 |
| token 存储 | localStorage 适合学习，更安全方案可用 httpOnly Cookie |
| axios 联调 | 请求拦截器带 token，响应拦截器自动刷新 |
| refresh token 安全 | 真实项目建议存 token 哈希，不存明文 |
| 常见排错 | MongoDB、JWT、401、403、429、E11000、CastError |
| 毕业练习 | 把认证系统接到文章业务，验证是否真的掌握 |

到这里，接口与会话控制系列就从“理解认证原理”走到了“能把认证能力用进真实项目”。接下来继续写项目时，可以先复用第七篇认证系统，再按第八篇的方法接入自己的业务模块。
