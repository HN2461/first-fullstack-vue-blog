# 第 1 篇：HTML CSS 面试题详解：浏览器内核、DOCTYPE、布局、语义化、盒模型

这篇文章整理 HTML 和 CSS 里常见的面试题，目标是同时解决两个问题：

1. 第一次阅读时，用通俗解释快速理解“这道题到底在问什么”。
2. 面试回答时，用更严谨的结论、边界条件和场景化表达，避免只会背一句口号。

建议每道题按这个顺序复习：先看“快速理解”，再记“规范回答”，最后用“追问提醒”检查自己能不能继续解释。示例代码用于说明原理，实际项目还要结合浏览器兼容性、可访问性和性能要求判断。

> 面试表达原则：先给结论，再给原因，最后补适用场景或限制。不要为了显得专业堆术语；如果一个结论有前提，要把前提一起说出来。

### 推荐背诵方式

- **第一遍：**只看每题的“先说结论”和“小白理解”，先建立知识地图。
- **第二遍：**重点记“规范回答（可直接复述）”，练习用 30～60 秒完整说清楚。
- **第三遍：**遮住正文，只看题目，自己补充一个示例、一个常见坑和一个适用场景。
- **遇到追问：**不要急着继续堆概念，先说“这个结论有前提”，再解释前提和边界。

面试回答不要求把文章整段背下来。更好的目标是：**一句结论 + 两句原因 + 一个例子或限制**。这样既不会像背书，也能让面试官感受到你理解了原理。

## 1、主流浏览器的内核分别是什么？

先直接记结论：

- Chrome、现在的 Edge、Opera：Blink 渲染引擎
- Firefox：Gecko 渲染引擎
- Safari：WebKit 渲染引擎
- 旧版 IE：Trident；旧版 Edge：EdgeHTML

### 简单理解

浏览器内核，可以理解成浏览器内部真正负责“解析网页、渲染页面”的核心程序。我们平时写的 HTML、CSS、JavaScript，最终都要交给浏览器内核去理解和显示。

所以面试官问这个问题，本质上是在看您对浏览器基础有没有最起码的了解。

### 补充说明

- Chrome 早期基于 WebKit，后来从 WebKit 分支出了 Blink。
- Opera 早期使用过 Presto，后来改用 Blink。
- “浏览器内核”通常指渲染引擎，不要和 JavaScript 引擎混为一谈：Chrome/Edge 使用 V8，Firefox 使用 SpiderMonkey，Safari 使用 JavaScriptCore。

### 规范回答（可直接复述）

可以这样说：

“现代主流浏览器中，Chrome、Edge 和 Opera 主要使用 Blink，Firefox 使用 Gecko，Safari 使用 WebKit。IE 使用 Trident，旧版 Edge 使用 EdgeHTML。这里说的是渲染引擎，JavaScript 引擎还要另外区分。”

## 2、每个 HTML 文件开头都有 `<!DOCTYPE html>`，它的作用是什么？

### 先说结论

`<!DOCTYPE html>` 是 HTML5 的文档类型声明，用来让浏览器按标准模式解析文档，而不是进入怪异模式（quirks mode）。它不是普通 HTML 元素，也不会在页面中渲染出可见内容。

### 简单理解

它虽然看起来像一个标签，但其实不是普通的 HTML 标签，而是一个文档类型声明。

浏览器解析文档时会根据文档开头的声明选择兼容模式。HTML5 推荐写法就是 `<!DOCTYPE html>`；如果缺失或使用某些旧式声明，浏览器可能进入怪异模式，盒模型、表格尺寸和默认布局行为会出现历史兼容差异。

### 为什么它很重要

前端开发最怕的事情之一，就是“同一份代码在不同浏览器显示不一样”。  
而 `DOCTYPE` 的存在，就是为了尽量减少这种混乱。

### 面试里怎么说更稳

不要只说“它告诉浏览器用什么规范”。  
更完整一点可以说：

“`<!DOCTYPE html>` 是 HTML5 文档类型声明，必须放在文档最前面，用来触发标准模式解析。它不是标签；缺失或使用不兼容的旧声明时，浏览器可能进入怪异模式，导致盒模型等渲染行为出现差异。”

### 小白记忆

把它理解成浏览器的“开场提示”：先告诉浏览器按现代标准读这份 HTML，再开始解析正文。

### 规范回答（可直接复述）

“`<!DOCTYPE html>` 是 HTML5 文档类型声明，放在文档最前面，用于触发标准模式解析。它不是普通 HTML 元素；缺失或使用旧式声明时，浏览器可能进入怪异模式，造成盒模型和默认布局差异。”

## 3、`div + css` 布局较 `table` 布局有什么优点？

### 先说结论

现代页面通常使用语义化 HTML 描述结构，再使用 CSS 的正常文档流、Flex 或 Grid 负责布局。`table` 适合展示二维表格数据，不应承担普通页面的整体布局。

### 为什么以前很多人喜欢用 `table`

因为早年做网页时，CSS 布局能力没现在这么强，很多人就用 `table` 来拼页面。它的好处是“排版看起来比较规整”，尤其在老浏览器时代，效果有时还挺稳定。

但问题是：

- 页面结构会变得很臃肿
- 嵌套层级很多
- 修改起来很麻烦
- 不利于响应式布局
- 语义也不合适

### `div + css` 的主要优点

1. HTML 结构和 CSS 表现可以分别维护
2. 布局调整更灵活，也更适合响应式设计
3. 配合 `header`、`main`、`article` 等语义化标签，更利于 SEO 和无障碍
4. 更容易组件化和复用

### `table` 的适用场景

要注意，这不是说 `table` 没用。

如果页面里展示的是课程表、财务表、统计表这种“天然就是表格”的数据，那就应该优先考虑 `table`。  
不建议的是：拿 `table` 去做整个页面框架布局。

### 规范回答（可直接复述）

“页面结构应使用合适的语义化 HTML，样式和布局交给 CSS。这样结构与表现分离，便于维护、响应式适配和无障碍支持；`table` 应用于二维表格数据，不适合作为整页布局方案。”

## 4、`img` 的 `alt` 属性与 `title` 属性有何异同？

### 先说结论

- `alt`：图片的替代文本
- `title`：补充提示文本

### 小白理解法

您可以把 `alt` 理解成“图片的替身文字”。

什么意思？

如果图片加载失败了，或者用户用的是读屏软件、看不到图片内容，那这个时候 `alt` 就能代替图片，告诉别人这张图本来是什么。

而 `title` 更像一个“可选的补充提示”。桌面浏览器经常会在鼠标悬停时显示它，但这不是可靠的交互方式，触摸设备和屏幕阅读器也不一定以相同方式呈现。

### `alt` 为什么更重要

因为 `alt` 不只是“图片裂开时显示的字”这么简单，它还有两个很重要的作用：

1. 无障碍访问  
   屏幕阅读器会把 `alt` 读出来，帮助视障用户理解图片内容。
2. 搜索引擎理解图片  
   搜索引擎不能只靠图片像素理解内容，`alt` 可以提供文本语义，但它不是堆关键词的地方。

### `title` 的作用

`title` 更多是补充说明，不能替代 `alt`。如果图片只是装饰，应使用空的 `alt=""`，让读屏软件跳过它；如果图片包含信息，应写准确、简洁的替代文本。

### 示例代码

```html
<img src="image.jpg" alt="海边日落照片" title="拍摄于夏季傍晚">
```

### 规范回答（可直接复述）

“`alt` 是图片的替代文本，服务于图片无法显示时的降级体验和无障碍访问，也能帮助搜索引擎理解图片；装饰图片应使用空 `alt`。`title` 只是可选的补充提示，不能替代 `alt`，也不应承担关键交互说明。”

## 5、`strong` 标签与 `em` 标签的异同

### 先说结论

- 两者都表达语义，不只是“斜体”和“粗体”样式
- `em` 表示语气或重音上的强调，嵌套使用时可以表达更强的强调
- `strong` 表示内容具有重要性、严重性或紧迫性

### 不要只把它们当样式标签

很多初学者会把：

- `strong` = 粗体
- `em` = 斜体

这样记其实不够准确。

因为粗体、斜体只是浏览器的默认表现，真正重要的是它们表达的“语义”。

### 怎么理解两者区别

比如一句话：

“这个按钮千万不要乱点。”

如果您只是想语气上强调一下某个词，可以用 `em`。  
如果您是想表达“这个内容非常重要”，那更适合用 `strong`。

### 规范回答（可直接复述）

“`em` 和 `strong` 都是语义化元素。`em` 表示语气或重音强调，`strong` 表示重要性、严重性或紧迫性；浏览器默认常分别显示为斜体和粗体，但默认样式不是它们的核心定义。”

## 6、渐进增强和优雅降级之间的不同

### 先说结论

- 渐进增强：先保证基本可用，再逐步增强体验
- 优雅降级：先做完整功能，再向下兼容低版本环境

### 渐进增强怎么理解

可以把它理解成：

“先做最基础的版本，让所有用户至少都能正常使用，然后再给高版本浏览器增加更好的动画、交互、样式效果。”

这种思路更稳，更照顾兼容性和可访问性。

### 优雅降级怎么理解

它的思路是反过来的：

“先按照最理想、最完整的效果开发，然后再考虑低版本浏览器如果不支持，就做一些退化处理。”

### 举个生活化的例子

比如一个页面按钮有很炫的动画：

- 渐进增强：先保证按钮能点、能提交，再给支持的浏览器加动画
- 优雅降级：先把动画、阴影、特效全部做好，再想办法让旧浏览器至少别崩

### 规范回答（可直接复述）

“渐进增强是先保证核心功能可用，再针对高版本浏览器增强体验；优雅降级是先实现完整效果，再兼容低版本浏览器。前者更强调基础可用性，后者更强调现代环境下的完整体验。”

### 面试追问：怎么在项目里落地

可以补充“能力检测，而不是浏览器嗅探”：先用原生 HTML 和基础 CSS 保证内容可读、表单可提交，再用 `@supports`、特性检测或 polyfill 增强。例如不支持 Grid 的浏览器使用 Flex 回退，不支持某个 API 时提供按钮或服务端方案，而不是只根据浏览器名称写分支。

## 7、CSS3 新增伪类举例

### 先说什么是伪类

伪类就是：根据元素的状态、位置、结构关系，去选中某类元素。

它不是给元素真的加了一个类名，而是 CSS 根据规则“判断你符不符合这个条件”。

### 常见结构伪类

- `p:first-of-type`：选中同类型中的第一个 `<p>`
- `p:last-of-type`：选中同类型中的最后一个 `<p>`
- `p:nth-of-type(2)`：选中同类型中的第 2 个 `<p>`
- `p:only-of-type`：选中同类型里唯一的 `<p>`
- `p:first-child`：如果这个 `<p>` 是父元素的第一个子元素，就选中它
- `p:last-child`：如果这个 `<p>` 是父元素的最后一个子元素，就选中它
- `p:nth-child(2)`：如果这个 `<p>` 是父元素的第 2 个子元素，就选中它

### 常见表单伪类

- `:disabled`：选中禁用的表单控件
- `:checked`：选中被勾选的单选框或复选框
- `:focus`：选中获取焦点的元素
- `:enabled`：选中可用状态的表单控件
- `:required`、`:optional`：匹配是否必填的表单控件
- `:valid`、`:invalid`：匹配原生校验结果
- `:has()`：根据后代或兄弟关系反向筛选父级，使用时要注意浏览器支持和选择器复杂度
- `:is()`、`:where()`：把多个选择器组合起来；其中 `:where()` 权重恒为零，适合降低覆盖成本

### 容易混淆的点

很多人会把“伪类”和“伪元素”混了。

比如：

- `:hover`、`:focus`、`:nth-child()` 这些是伪类
- `::before`、`::after` 这些才是伪元素

### `:nth-child()` 和 `:nth-of-type()` 的区别

`:nth-child(2)` 先数父元素的所有子元素，再判断第二个是不是目标标签；`:nth-of-type(2)` 只在同类型元素中计数。面试时最好用一个包含 `h2`、`p`、`p` 的例子解释，避免把两者都说成“第二个元素”。

### 规范回答（可直接复述）

“伪类描述元素的状态或结构条件，例如 `:hover`、`:focus`、`:nth-child()`、`:checked`；伪元素描述元素的一部分或由 CSS 生成的内容，例如 `::before`、`::after`。CSS3 常见新增伪类包括 `:nth-of-type()`、`:enabled`、`:disabled`、`:checked`、`:required`、`:valid` 等，现代选择器还包括 `:is()`、`:where()` 和 `:has()`。”

## 8、简述一下 `src` 与 `href` 的区别

### 先说结论

- `src`：表示把外部资源引入当前元素中使用
- `href`：表示建立当前文档和目标资源之间的关联关系

### 小白理解法

`src` 更像“把资源本体拿过来用”。  
比如：

- `<img src="...">`
- `<script src="...">`
- `<iframe src="...">`

这些标签都是真的要去拿那个资源本身。

而 `href` 更像“建立一个关系”。

比如：

- `<a href="...">` 是建立跳转关系
- `<link href="...">` 是建立外部资源引用关系

### 为什么很多人会背错

以前有些资料喜欢一股脑地说：

“`src` 会阻塞，`href` 不会阻塞。”

这个说法太粗糙了。

更准确地说：

- 不同标签的行为不完全一样
- 比如 `<script src>` 是否阻塞解析，还和 `async`、`defer` 有关
- `<img src>` 会发请求，但不等于像同步脚本那样阻塞整个页面解析

### 规范回答（可直接复述）

“`src` 一般用于把外部资源本身引入当前元素，比如 `img`、`script`、`iframe`；`href` 一般用于建立当前文档和目标资源之间的关联关系，比如 `a` 和 `link`。两者语义不同，不能简单粗暴地按‘谁一定阻塞谁不阻塞’来背。”

## 9、网页制作会用的图片格式有哪些？

### 常见格式

- `jpg/jpeg`
- `png`
- `gif`
- `svg`
- `webp`
- `avif`

### 分别怎么理解

#### 1. `jpg/jpeg`

特点：

- 有损压缩
- 体积通常较小
- 不支持透明

适合：

- 照片
- 风景图
- 色彩丰富的大图

#### 2. `png`

特点：

- 无损压缩
- 支持透明
- 画质比较稳定

适合：

- Logo
- 图标
- 边缘要求比较高的图片

#### 3. `gif`

特点：

- 支持简单动画
- 颜色数量有限

适合：

- 简单动图
- 表情图

#### 4. `svg`

特点：

- 矢量图
- 放大缩小不失真
- 非常适合图标和线稿

适合：

- 图标
- 图形
- 简单插画

#### 5. `webp`

特点：

- 支持有损和无损压缩
- 通常体积更小
- 现代浏览器兼容性已经比较好了

适合：

- 需要兼顾画质和体积的大多数网页图片场景

#### 6. `avif`

通常能提供更高的压缩效率，适合现代浏览器中的高质量图片，但编码成本、工具链和兼容性仍要结合项目判断。实际项目可以通过 `<picture>` 提供格式回退。

### 额外补充

`base64` 严格来说不是图片格式，而是一种编码方式。  
它常被用来把很小的图片直接写进代码里，从而减少额外请求，但体积一大就不划算。

### 规范回答（可直接复述）

“JPEG 适合照片等连续色调图片；PNG 适合需要无损和透明通道的图形；GIF 适合简单动画但颜色有限；SVG 是可缩放矢量格式，适合图标和线稿；WebP 和 AVIF 通常能在体积和画质之间取得更好平衡，但要结合浏览器支持和编码成本选择。Base64 是编码方式，不是图片格式，适合很小的内联资源。”

## 10、一个页面上有大量图片，加载很慢，你有哪些方法优化这些图片的加载？

### 先说思路

图片优化不要只盯着“压缩图片”这一件事，而是要从：

- 什么时候加载
- 加载什么尺寸
- 用什么格式
- 怎么让用户感觉更快

这几个方向一起考虑。

### 常见优化方式

#### 1. 图片懒加载

滚动到可视区域附近再加载图片。  
这样首屏不会一次性请求太多资源。

#### 2. 合理预加载

像轮播图、相册这种场景，可以提前加载下一张图，提高切换体验。

#### 3. 选择合适格式

- 照片类优先考虑 `jpg` 或 `webp`
- 图标类优先考虑 `svg`
- 简单透明图可以用 `png`

#### 4. 大图不要小用

明明页面只显示 300px 的图，却加载 3000px 的原图，这就是典型浪费。

#### 5. 使用缩略图、占位图

先给用户看一个模糊小图或者缩略图，再慢慢替换成高清图，感知速度会更好。

#### 6. 小图标方案优化

可以根据场景考虑：

- SVG Sprite
- Iconfont
- CSS Sprite

#### 7. 控制加载优先级并预留尺寸

- 首屏关键图片可以考虑 `fetchpriority="high"`，不要给所有图片都加高优先级
- 非首屏图片可使用 `loading="lazy"` 和 `decoding="async"`
- 给图片设置 `width`、`height` 或 `aspect-ratio`，避免加载后布局跳动
- 使用 `srcset` 和 `sizes` 按屏幕尺寸、像素密度选择资源

#### 7. 配合缓存和 CDN

图片资源配合缓存策略和 CDN，能明显减轻服务器压力，也能提升用户访问速度。

### 规范回答（可直接复述）

“图片优化要从资源本身、加载时机、尺寸适配和缓存分发一起考虑：选择 WebP/AVIF 等合适格式，生成多尺寸资源，用 `loading`、`fetchpriority` 控制优先级，用 `srcset/sizes` 做响应式选择，并设置尺寸预留空间避免布局偏移，最后配合缓存和 CDN。核心目标是减少无效字节、降低首屏压力和改善用户感知速度。”

## 11、以前端角度出发，有哪些注意事项有利于 SEO？

### 先说结论

SEO 不是只靠“堆关键词”，而是要让搜索引擎更容易理解页面内容，同时让页面本身质量更高、速度更快、结构更清晰。

### 常见做法

#### 1. 保持内容质量和持续更新

内容才是 SEO 的基础。  
如果页面本身没价值，光做标签和关键词优化意义有限。

#### 2. 页面结构清晰

层级不要太乱，导航、标题、正文最好一眼能看懂。

#### 3. 合理使用语义化标签

比如：

- `header`
- `main`
- `article`
- `section`
- `nav`
- `h1` 到 `h6`

这样更有助于搜索引擎理解页面结构。

#### 4. 写好 `title` 和 `meta description`

- `title` 概括页面主题
- `description` 概括页面内容摘要

#### 5. 图片写好 `alt`

搜索引擎不直接“看懂”图片，所以 `alt` 能帮助它理解图像内容。

#### 6. 提升页面加载速度

减少不必要请求、压缩资源、优化首屏速度，这些都对 SEO 有帮助。

#### 7. 保证重要内容不是完全靠图片或脚本表达

如果核心内容全藏在图片里，或者必须执行脚本才能看到，那搜索引擎理解起来会更困难。

### 容易踩坑的点

- `meta keywords` 现在价值已经很低，不要把它当重点
- `display: none` 不是绝对不能用，但不要拿它隐藏大量关键词做作弊

### 规范回答（可直接复述）

“SEO 的前端基础包括清晰的语义化结构、合理的标题层级、准确的 `title` 和 `description`、图片 `alt`、可抓取的链接、良好的移动端体验和页面性能。不要把重要内容只放在图片或必须执行脚本后才出现，也不要通过隐藏关键词作弊；最终还要结合服务端渲染、站点地图、规范链接和内容质量。”

## 13、CSS 选择器有哪些，选择器的权重优先级是什么？

### 常见选择器

1. ID 选择器：`#id`
2. 类选择器：`.class`
3. 标签选择器：`p`
4. 通配选择器：`*`
5. 属性选择器：`[type="text"]`
6. 伪类选择器：`a:hover`
7. 伪元素选择器：`::before`、`::after`
8. 子选择器：`ul > li`
9. 相邻兄弟选择器：`h1 + p`
10. 后代选择器：`li a`

### 权重怎么理解

权重可以理解成“谁说了更算数”。

比较时不能只背一个十进制数字。可以用三列记忆选择器部分的权重：`(ID, 类/属性/伪类, 类型/伪元素)`，从左到右逐列比较；前一列不同，后一列再大也不能反超。例如 `(0, 11, 0)` 仍然小于 `(1, 0, 0)`。

还要先考虑层叠规则：来源、`!important`、级联层（cascade layer）和作用域等会影响最终结果。`!important` 不是“让所有样式都赢”的万能开关，应该尽量少用。

补充几个现代选择器规则：

- `:where(...)` 的权重恒为零
- `:is(...)`、`:not(...)`、`:has(...)` 的权重取其参数列表中权重最高的一项
- 通配符、组合符和 `:where()` 本身不增加选择器权重

### 一个容易误解的点

在层叠条件和选择器权重都相同的情况下，才通常由源码中后出现的声明覆盖前面的声明。不要把“就近原则”理解成 DOM 距离越近就一定优先。

### 规范回答

“CSS 最终生效值由层叠规则决定。先比较来源、重要性和级联层，再比较选择器权重；选择器权重按 ID、类/属性/伪类、类型/伪元素逐列比较，不能简单按十进制相加。权重相同才比较作用域和源码顺序。”

## 14、CSS 中，对 DOM 元素设置不显示的方式有哪些？

### 常见方式

#### 1. `display: none`

特点：

- 元素直接不参与布局
- 不占位置

#### 2. `visibility: hidden`

特点：

- 元素看不见
- 但还占着原来的位置

#### 3. `opacity: 0`

特点：

- 元素完全透明
- 还占位置
- 不会自动禁止鼠标、键盘或触摸事件；如果需要“看不见也不能点”，要结合 `pointer-events`、焦点管理或条件渲染处理

#### 4. 宽高设为 `0`

可以配合 `overflow: hidden` 使用，用于某些特殊隐藏场景。

#### 5. 移出可视区域

通过绝对定位把元素移到屏幕外，常见于某些无障碍场景。

### 面试里容易加分的说法

不要只会背“隐藏”。  
最好顺手补一句：

“它们的区别主要在于是否占位、是否参与布局、是否还能响应交互。”

### 规范回答

“`display: none` 会从布局树中移除；`visibility: hidden` 通常保留布局占位但不可见；`opacity: 0` 只是透明，仍可能参与交互和辅助技术访问。实际选择要同时考虑布局、焦点、读屏和事件行为，不能只看视觉效果。”

## 15、超链接访问过后，`hover` 样式就不出现的问题是什么，如何解决？

### 原因

通常是因为伪类顺序不对，或者 `:visited` 的规则覆盖了 `:hover`。另外，浏览器出于隐私保护只允许 `:visited` 修改有限的颜色相关属性。

### 正确顺序

- `:link`
- `:visited`
- `:hover`
- `:active`

也就是常说的 `LVHA`。如果同时设置了多个状态，通常把 `:hover` 写在 `:link`、`:visited` 后面。

### 规范回答

“链接状态伪类常按 LVHA 顺序书写：`:link`、`:visited`、`:hover`、`:active`。这样悬停状态不会被前面的规则覆盖；同时要注意 `:visited` 可修改的 CSS 属性受浏览器隐私限制。”

### 示例

```css
a:link { color: #1677ff; }
a:visited { color: #722ed1; }
a:hover { color: #0958d9; }
a:active { color: #cf1322; }
```

如果样式仍不生效，还要检查是否有更高权重的选择器、内联样式或 `!important` 覆盖，而不只是盯着 LVHA 顺序。

### 怎么记

您可以把它理解成：

先是普通链接，再是访问过的链接，然后是鼠标移上去，最后是点击那一瞬间。

## 16、行内元素和块级元素的具体区别是什么？行内元素的 `padding` 和 `margin` 可设置吗？

### 块级元素的特点

- 默认独占一行
- 默认会尽量撑满父容器可用宽度
- 可以设置宽高、内外边距

### 行内元素的特点

- 默认不独占一行
- 宽度通常由内容决定
- 普通情况下 `width`、`height` 不太生效

### 行内元素的 `padding` 和 `margin` 能不能设置？

能设置。

但是要注意：

- 左右方向通常表现更明显
- 上下方向即使设置了，很多时候对布局影响不像块元素那样直观

所以不能简单粗暴说“行内元素上下 `margin` 和 `padding` 不能设置”，更准确的说法应该是“可以设置，但布局表现有限”。

### `inline-block`

它可以理解成一种折中：

- 不独占一行
- 但又可以设置宽高

常见行内块元素有：

- `img`
- `input`
- `button`
- `textarea`
- `select`

### 规范回答（可直接复述）

“块级和行内是默认的外部显示类型，不是 HTML 元素永远固定的属性。块级盒通常独占一行，行内盒参与文本行布局；行内元素可以设置左右 `padding` 和 `margin`，上下方向也能设置但对周围布局的影响受行盒规则限制。需要同时拥有行内排列和宽高控制时可以使用 `inline-block`，但现代项目更多使用 Flex/Grid。”

## 17、什么是外边距重叠？重叠的结果是什么？

### 先说结论

外边距重叠，也叫 margin collapse，通常发生在垂直方向上的相邻块级元素之间。发生后，两个外边距不会简单相加，而是会合并。

### 常见场景

#### 1. 相邻兄弟元素

上下两个块级元素相邻时，垂直外边距可能发生合并。

#### 2. 父子元素

如果父元素没有：

- `border`
- `padding`
- 行内内容

那子元素的垂直外边距可能和父元素发生塌陷。

### 重叠后的结果

两个正外边距通常取较大值；两个负外边距取绝对值较大的负值；正负混合时通常是最大正值加上最小负值。浮动元素、绝对定位元素、Flex/Grid 子项等场景不会按普通块格式化上下文发生这种折叠。

### 解决方式

1. 让父元素形成 BFC
2. 给父元素加 `padding`
3. 给父元素加 `border`
4. 用伪元素或内容把它们隔开

### 示例

```css
.mc::before {
  content: '';
  display: table;
}
```

### 规范回答

“外边距折叠主要发生在普通块格式化上下文中的垂直外边距之间，常见于相邻兄弟、父子首尾外边距和空块元素。它不是简单相加；可以通过 `padding`、`border`、建立 BFC 或使用 `display: flow-root` 隔开折叠。”

## 18、`rgba()` 和 `opacity` 的区别

### `opacity`

它是一个 CSS 属性。

例如：

```css
.box {
  opacity: 0.5;
}
```

它的特点是：整个元素最终渲染出来都会一起变透明，包括里面的文字、图片、子元素。

### `rgba()`

它不是一个单独属性，而是一种颜色写法。

例如：

```css
.box {
  background-color: rgba(0, 0, 0, 0.5);
}
```

这样只会让背景色半透明，不会让里面的文字也跟着一起透明。

### 一句话总结

- `opacity`：整个元素一起透明
- `rgba()`：只让某个颜色值带透明度

### 规范回答（可直接复述）

“`opacity` 作用于整个元素及其子元素，最终合成结果一起透明，还可能创建新的层叠上下文；`rgba()` 或现代 `rgb()` 的 alpha 只作用于具体颜色值，例如背景色，不会自动让子元素文字透明。需要控制交互时，还要额外处理 `pointer-events` 和焦点。”

## 19、CSS 中可以让单行文字在垂直和水平居中显示吗？

可以。

### 常见做法

- 垂直方向：`line-height` 设成和容器高度一样
- 水平方向：`text-align: center`

### 示例

```css
.title {
  height: 40px;
  line-height: 40px;
  text-align: center;
}
```

### 注意

这种方式更适合单行文字。  
如果是多行文本，或者更复杂的布局，通常更推荐用 Flex。

`line-height` 等于 `height` 只是利用单行文本的行盒高度实现视觉居中，不是真正的通用垂直居中方案。多行文本应使用 Flex/Grid，并根据内容设置 `padding`、`align-items` 或 `place-items`。

### 规范回答（可直接复述）

“单行文字可以用 `text-align: center` 实现水平居中，再让 `line-height` 接近容器高度实现视觉上的垂直居中；多行文字不应依赖这个技巧，应使用 Flex/Grid 或内边距，并考虑文本溢出和动态高度。”

## 20、如何水平垂直居中一个元素？

这个问题是面试高频题，常见方法很多。

### 方法一：绝对定位 + `transform`

```css
.parent {
  position: relative;
}

.child {
  position: absolute;
  top: 50%;
  left: 50%;
  transform: translate(-50%, -50%);
}
```

这是最常见也最好记的一种方式。

### 方法二：绝对定位 + 负边距

前提是子元素宽高已知。

```css
.parent {
  position: relative;
}

.child {
  width: 100px;
  height: 100px;
  position: absolute;
  top: 50%;
  left: 50%;
  margin-top: -50px;
  margin-left: -50px;
}
```

### 方法三：绝对定位 + `margin: auto`

```css
.parent {
  position: relative;
}

.child {
  width: 100px;
  height: 100px;
  position: absolute;
  top: 0;
  right: 0;
  bottom: 0;
  left: 0;
  margin: auto;
}
```

### 方法四：Flex 布局

```css
.parent {
  display: flex;
  justify-content: center;
  align-items: center;
}
```

这是现代开发里最常用的一种。

### 方法五：`table-cell`

```css
.parent {
  display: table-cell;
  vertical-align: middle;
  text-align: center;
}

.child {
  display: inline-block;
}
```

### 面试建议

如果面试官问这个题，您最稳的答法是：

“常见方案有绝对定位配合 `transform`、Flex 居中、绝对定位加 `margin: auto` 等。现代项目里最常用的是 Flex。”

### 规范回答（可直接复述）

“元素居中要先确认父容器尺寸和子元素是否已知。现代项目优先使用 Flex 的 `justify-content: center` 和 `align-items: center`；绝对定位可以配合 `transform: translate(-50%, -50%)` 处理未知尺寸，也可以在四边设为 0 后使用 `margin: auto` 处理已知尺寸。选择方案要考虑元素是否应脱离文档流。”

## 22、`px` 和 `em`、`rem` 的区别

### `px`

`px` 是绝对长度单位。  
写多少，通常就按多少来计算，直观、好理解。

### `em`

`em` 是相对单位，它相对于当前元素的字体大小来计算。  
如果当前元素自己没有设置字体大小，就会继续往父级那里找。

这就导致一个特点：`em` 容易受嵌套影响。

### `rem`

`rem` 也是相对单位，但它永远相对于根元素 `html` 的字体大小来计算。

这就让它比 `em` 更适合做整站统一缩放。

### 简单理解

- `px`：固定、直观
- `em`：跟当前元素字号走
- `rem`：跟根元素字号走

### 补充

浏览器默认根字号通常是 `16px`，所以很多场景下：

- `1rem = 16px`

但这是默认情况，不是永远固定不变。

### 规范回答（可直接复述）

“`px` 是 CSS 像素，直观但不代表物理屏幕像素；`em` 通常相对当前元素的字体大小计算，容易受嵌套影响；`rem` 相对根元素 `html` 的字体大小，适合统一缩放。实际项目通常混合使用：边框等细节用 `px`，字体和间距可根据设计系统使用 `rem`、`em` 或现代的 `clamp()`。”

## 23、Sass、LESS 是什么？大家为什么要使用它们？

### 先说结论

Sass 和 Less 都是 CSS 预处理器。

它们本质上是：在 CSS 基础上增加了一些更方便开发的能力，最后再编译成浏览器能识别的普通 CSS。

### 它们带来什么好处

#### 1. 变量

比如颜色、字号、间距这些值，可以统一管理。

#### 2. 嵌套

写起来更有层级感，结构更清楚。

#### 3. 混入

能把重复样式封装起来复用。

#### 4. 更适合大项目

当项目样式很多时，预处理器能明显减少重复代码，提高维护效率。

### 现在还要不要用

要看团队和项目。  
因为现代 CSS 自身也越来越强了，比如变量、`calc()`、层级能力都在提升。

所以面试回答时不必把 Sass、Less 吹得太神，重点说它们“提高开发效率、便于维护”就够了。

### 规范回答（可直接复述）

“Sass 和 Less 是 CSS 预处理器，在 CSS 基础上提供变量、嵌套、混入和函数等能力，构建时会编译成普通 CSS。它们可以减少重复、统一设计值并提升维护效率，但现代 CSS 变量、`calc()`、嵌套和容器查询也在增强，是否使用要看团队工具链和项目复杂度。”

## 24、CSS 中 `link` 和 `@import` 的区别

### 先说结论

1. `<link>` 是 HTML 标签，`@import` 是 CSS 规则，归属不同
2. `<link>` 出现在 HTML 中时，浏览器更早发现资源，通常可以和 HTML 解析并行发起请求
3. `@import` 要等包含它的 CSS 被下载并解析到对应规则后才发现，容易形成串行依赖，延迟样式资源加载
4. `<link>` 可以直接作为 DOM 节点查询、禁用、替换；`@import` 是样式表内部规则，不能当作独立 DOM 元素操作
5. 实际开发中页面主样式通常优先使用 `<link>`，`@import` 更适合在 CSS 内部拆分样式模块

### 为什么一般推荐 `link`

因为它更早被浏览器发现，资源依赖关系更清晰，也便于通过 `media`、`disabled`、DOM API 和预加载策略进行控制。现代浏览器都支持 `@import`，所以推荐 `<link>` 主要是加载性能、可控性和工程维护方面的考虑，不是因为 `@import` 在现代浏览器中“不兼容”。

### 加载时机怎么准确说

可以把它想成两条路径：

- `<link>`：HTML 解析器读到标签后就能发现 CSS 资源，通常较早发起请求；多个资源能否真正并行，还要看浏览器调度、缓存、连接和优先级。
- `@import`：浏览器必须先拿到父 CSS，解析到 `@import` 才能发现子 CSS，因此常形成“先父后子”的瀑布依赖。

`@import` 必须出现在 CSS 文件允许的位置，通常放在其他样式规则之前；如果在普通样式规则之后声明，浏览器可能忽略该导入规则。

### 一个常见误区

不要再背：

“`@import` 一定要等页面加载完成后才加载。”

这个说法太绝对。  
更准确的说法是：它依赖 CSS 的解析过程触发加载，不如 `<link>` 那么直接。

### 优先级怎么准确回答

不能简单说“`link` 的优先级高于 `@import`”。样式最终谁生效，要看样式表在文档或 CSS 中的顺序、`@import` 在所属样式表中的位置、级联层、选择器权重、`!important` 和源码顺序。

在同一父 CSS 中，`@import` 导入的规则会先于该文件后面的普通规则参与层叠，因此后面的同等条件规则通常可以覆盖它；但不同 `<link>` 样式表之间仍要结合它们在 HTML 中的顺序和层叠规则判断。

### 规范回答（可直接复述）

“`<link>` 是 HTML 标签，浏览器解析 HTML 时通常可以更早发现并加载外部 CSS，还能通过 DOM、`media` 和 `disabled` 控制；`@import` 是 CSS 规则，要等父 CSS 下载并解析到它之后才能发现子 CSS，容易形成串行加载。两者都能引入样式，最终覆盖关系不是由标签名字决定，而是由级联层、重要性、选择器权重和样式顺序共同决定。页面主样式通常优先使用 `<link>`，`@import` 更适合 CSS 内部模块拆分。”

### 小白记忆

**`link` 是 HTML 里直接告诉浏览器“这里有一份 CSS”；`@import` 是 CSS 下载后再告诉浏览器“还要继续找另一份 CSS”。**

## 25、简述盒子模型

### 盒子模型是什么

CSS 会把页面中的元素都看成一个个矩形盒子。  
这个盒子主要由四部分组成：

1. `content` 内容区
2. `padding` 内边距
3. `border` 边框
4. `margin` 外边距

### 标准盒模型

在默认情况下，`width` 和 `height` 只表示内容区大小，不包含 `padding` 和 `border`。

### `border-box`

如果设置：

```css
box-sizing: border-box;
```

那 `width` 和 `height` 就会把 `padding` 和 `border` 也算进去。  
这在现代开发里非常常见，因为更容易控制布局尺寸。

### 规范回答（可直接复述）

“盒子模型由内容区、内边距、边框、外边距组成。默认标准盒模型下，`width` 和 `height` 只表示内容区大小；如果使用 `box-sizing: border-box`，则会把 `padding` 和 `border` 也计算在内。”

## 26、为什么要初始化样式？

### 原因

不同浏览器对某些标签会有默认样式差异。  
比如：

- `h1` 的大小
- `p` 的上下边距
- `ul` 的缩进

如果不做统一处理，不同浏览器里页面就可能出现细微差别。

### 常见方案

- `reset.css`
- `normalize.css`

### 两者简单区别

- `reset.css` 更激进，基本把默认样式都清掉
- `normalize.css` 更温和，尽量保留合理默认值，同时统一差异

初始化并不意味着把所有语义样式全部清空。生产项目通常只重置确实需要统一的部分，例如 `box-sizing`、标题和列表间距、图片最大宽度、按钮字体继承；否则可能损害标题层级、表单可用性和无障碍表现。

### 规范回答（可直接复述）

“初始化样式是为了减少浏览器默认样式差异，让团队从可控的基础开始开发。`reset.css` 通常激进地清除默认样式，`normalize.css` 更倾向于保留合理语义并修正差异；现代项目应按需重置，不能为了统一而破坏原生控件、标题层级和可访问性。”

## 27、对 BFC 规范（块级格式化上下文）的理解

### 先说什么是 BFC

BFC 全称是 Block Formatting Context，中文常叫“块级格式化上下文”。

刚学的时候这个词会觉得很绕，您可以先把它简单理解成：

“一个相对独立的布局区域。”

在这个区域里，内部元素怎么排版，和外部元素之间会有一定隔离。

### BFC 常见作用

#### 1. 解决垂直外边距重叠

也就是常说的 margin 塌陷问题。

#### 2. 包含内部浮动元素

有时候父元素里全是浮动子元素，父元素高度会塌掉。  
让父元素形成 BFC，往往就能把浮动包住。

#### 3. 隔离布局影响

内部布局一般不会直接影响到外部同级区域。

### 常见触发方式

1. `float` 不为 `none`
2. `position: absolute`
3. `position: fixed`
4. `overflow` 不为 `visible`
5. `display: inline-block`
6. `display: table-cell`
7. `display: flow-root`

### 容易背错的点

很多旧资料会写：

“`position` 不是 `static` 或 `relative` 就行”

这种说法不够严谨。  
更安全的回答方式，是直接记上面这些常见触发条件。

### 规范回答（可直接复述）

“BFC 是一块相对独立的块级格式化上下文，内部布局和外部有一定隔离。它常用于包含浮动、隔离外边距折叠和避免普通流内容与浮动互相覆盖。常见创建方式包括 `display: flow-root`、非 `visible` 的 `overflow`、浮动、绝对/固定定位等；实际项目优先使用职责明确的 `flow-root`，避免为了清除浮动随意使用 `overflow: hidden`。”

## 28、HTML/CSS 常见兼容性问题有哪些？

### 常见问题

1. 浏览器默认 `margin`、`padding` 不一致
2. 某些 CSS 新特性在旧浏览器支持不一致
3. 表单控件在不同浏览器或系统外观不同
4. 字体渲染效果不同
5. 老项目里可能遇到盒模型、浮动、定位兼容问题

### 常见解决方式

- 样式初始化
- 按需写兼容代码
- 尽量优先使用成熟稳定的方案

### 面试里怎么说

不要只答一句“加个 `* { margin: 0; padding: 0; }`”。  
这个回答太浅了。  
更好的是顺带提一下“新特性支持差异、表单控件差异、默认样式差异”。

### 更完整的回答

“兼容性问题通常来自浏览器默认样式、HTML/CSS 新特性支持差异、字体和表单控件渲染差异，以及旧浏览器对盒模型、浮动和定位的历史行为。处理时先明确支持的浏览器范围，再通过标准写法、`@supports` 特性查询、渐进增强、自动化测试和必要的 polyfill 解决，不建议无依据地堆浏览器前缀。”

### 规范回答（可直接复述）

“HTML/CSS 兼容性主要来自默认样式、特性支持差异、表单控件和字体渲染差异，以及旧浏览器历史行为。解决时要先明确目标浏览器范围，再使用标准写法、特性检测、渐进增强和自动化回归测试，必要时按需使用 polyfill；不能只靠全局 reset 或堆浏览器前缀。”

## 30、前端页面的基本构成，分别是什么？作用是什么？

通常可以分成三层：

1. 结构层：HTML
2. 表现层：CSS
3. 行为层：JavaScript

### 分别负责什么

#### HTML

负责页面内容和结构，是网页的骨架。

#### CSS

负责页面样式和布局，是网页的外观。

#### JavaScript

负责交互和动态行为，让网页“动起来”。

### 小白理解法

可以把网页想成一个人：

- HTML 是骨架
- CSS 是穿衣打扮
- JavaScript 是动作和行为

### 规范回答（可直接复述）

“前端页面可以从结构、表现和行为三个层次理解：HTML 描述内容结构和语义，CSS 控制布局与视觉表现，JavaScript 负责交互、状态和动态行为。三者分工有助于维护、测试、无障碍和渐进增强，但现代框架会把它们组织在组件中，并不意味着必须拆成三个完全独立的文件。”

## 31、列出 `display` 的值，并说明它们的作用

### 常见值

- `none`：元素不显示，也不参与布局
- `block`：块级显示
- `inline`：行内显示
- `inline-block`：行内块显示
- `flex`：弹性布局容器
- `grid`：网格布局容器
- `table`：按表格模型显示
- `table-cell`：按表格单元格显示
- `contents`：元素自身不生成盒子，但子元素仍参与布局；使用时要留意无障碍和事件调试影响
- `flow-root`：创建一个新的 BFC，常用于隔离浮动和外边距折叠

### 不要写错的点

有些旧资料会把 `normal` 写进常见 `display` 值里，这不适合作为这里的标准答案。

### 规范回答（可直接复述）

“`display` 决定元素如何生成盒子以及内部子元素如何布局。常见值包括 `none`、`block`、`inline`、`inline-block`、`flex`、`grid`、`table`、`contents` 和 `flow-root`。回答时要说明 `display: none` 会移除布局占位，而 `visibility: hidden` 仍通常保留占位。”

现代 CSS 的 `display` 还可以使用双值语法，例如 `display: block flow` 表示外部显示类型为 block、内部布局为普通流。面试初级阶段先掌握 `block`、`inline`、`flex`、`grid`、`none`、`flow-root` 即可，不必把所有枚举值死记。

## 32、列出 `position` 的值，注意它们的定位参照原点

### 1. `static`

默认值，不开启定位。

### 2. `relative`

相对于元素原本所在的位置进行偏移。  
元素原来的位置仍然保留。

### 3. `absolute`

相对于最近的已定位祖先元素定位。  
如果祖先都没定位，则相对于初始包含块定位。

### 4. `fixed`

相对于浏览器视口定位。  
滚动页面时，元素通常不会跟着文档流一起移动。

需要补充：如果祖先元素设置了某些会建立包含块的属性，例如 `transform`、`filter` 或 `perspective`，`fixed` 的参照对象可能不再是视口，排查定位问题时要检查祖先样式。

### 规范回答（可直接复述）

“`static` 是默认普通流；`relative` 保留原位置并相对自身原位置偏移；`absolute` 相对最近的定位祖先或初始包含块定位并脱离普通流；`fixed` 通常相对视口固定，但可能受祖先建立的包含块影响；`sticky` 在滚动到阈值前类似相对定位，之后在滚动容器范围内吸附。”

### 5. `sticky`

可以理解成“粘性定位”。  
在达到某个阈值前像 `relative`，达到后会表现出类似固定效果。

## 33、`i` 标签与 `em` 标签、`b` 标签与 `strong` 标签的区别

### `b` 和 `i`

更偏视觉表现：

- `b` 偏加粗
- `i` 偏倾斜

### `strong` 和 `em`

更偏语义表达：

- `strong` 表示更强的重要性
- `em` 表示语气上的强调

### 实际开发建议

如果您只是想改样式，最好用 CSS 控制；  
如果您是想表达“这里内容很重要”或者“这里要强调语气”，那就优先用 `strong`、`em`。

`b` 表示引起注意但不代表更重要的文字，例如关键词、产品名；`i` 表示与普通正文区分的内容，例如术语、外文短语或思想活动。它们不是完全没有语义，只是语义强度不同于 `strong` 和 `em`。如果只是为了加粗或倾斜，应该使用 CSS，而不是为了样式滥用语义标签。

### 规范回答（可直接复述）

“`b` 和 `i` 不是简单的无语义样式标签：`b` 用于引起注意，`i` 用于区分术语、外文或其他不同语气内容；`strong` 表示重要性，`em` 表示语气强调。若没有对应语义，只想改变粗细或倾斜，应使用 CSS。”

## 34、`title` 与 `h1` 的区别

### `title`

### `h1`

- 写在页面正文中
- 是页面内容中的一级标题

### 面试里不要说得太死

不要简单说：

“`title` 一定比 `h1` 重要。”

更稳妥的说法是：

“两者都重要，但作用不同。`title` 更偏页面整体主题概括和搜索结果展示，`h1` 更偏正文结构中的主标题表达。”

### 规范回答（可直接复述）

“`title` 位于 `head` 中，是页面文档级标题，会影响浏览器标签页、历史记录和搜索结果展示；`h1` 位于正文结构中，是页面内容的一级标题，帮助用户和辅助技术理解正文主题。两者作用不同，不能简单说谁绝对更重要。”

## 35、`b` 与 `strong` 的区别

### `b`

- 更偏视觉加粗
- 语义较弱

### `strong`

- 更偏语义强调
- 表示内容更重要

### 一句话记忆

`b` 更像“长粗了”，`strong` 更像“真的重要”。

### 规范回答（可直接复述）

“`b` 用于吸引注意，但不表示内容具有更高的重要性；`strong` 表示内容重要、严重或紧迫。两者默认都可能显示为粗体，但应先根据语义选择，再用 CSS 控制视觉效果。”

## 36、`i` 与 `em` 的区别

### `i`

- 更偏视觉斜体
- 也常用于术语、外文片段、图标等

### `em`

- 更偏语义强调
- 表示说话语气上的重点

### 规范回答（可直接复述）

“`i` 用于把术语、外文、思想活动等与周围正文区分开；`em` 表示语气或重音强调，强调的是句子表达重点。默认斜体只是浏览器样式，不是两者的核心区别。”

## 37、从浏览器地址栏输入 URL 到显示页面的步骤

### 大致流程

1. 浏览器先解析 URL
2. 进行 DNS 查询，找到目标服务器 IP
3. 和服务器建立连接
4. 发起 HTTP 或 HTTPS 请求
5. 服务器返回 HTML、CSS、JS、图片等资源
6. 浏览器解析 HTML，构建 DOM
7. 浏览器解析 CSS，构建 CSSOM
8. 合成渲染树，进行布局和绘制
9. 页面显示出来

### 小白理解法

就是：

“先找到服务器，再把网页资源拿回来，然后浏览器把这些资源翻译成人类看得懂的页面。”

### 如果面试官继续追问

后面还可能继续问到：

- 回流和重绘
- 缓存
- TCP / HTTPS
- 渲染阻塞

### 规范回答

“输入 URL 后，浏览器会先解析 URL 并检查内存、磁盘缓存和 Service Worker，再通过 DNS 获取地址；随后根据协议建立 TCP 连接并在 HTTPS 场景完成 TLS 握手，发送 HTTP 请求。拿到 HTML 后，浏览器边解析 HTML 边构建 DOM，并解析 CSS 构建 CSSOM，合成渲染树后进行布局、绘制和合成；脚本、样式和图片还会继续触发后续资源请求。实际时序会受到缓存、协议版本、脚本属性和资源优先级影响。”

### 小白记忆

可以记成：**找地址 → 建连接 → 拿资源 → 读 HTML/CSS → 算布局 → 画到屏幕上**。

所以这题通常是一个引子。

## 38、写出常用的 CSS 传统布局

### 常见布局方式

1. 表格布局
2. 浮动布局
3. 定位布局
4. 流式布局
5. 弹性布局
6. 网格布局

### 如果题目强调“传统布局”

那主要回答：

- 表格布局
- 浮动布局
- 定位布局
- 流式布局

Flex 和 Grid 更偏现代布局方式。

### 常见布局的取舍

- 正常文档流：适合内容自然排列，最不容易维护
- 浮动布局：历史兼容性好，但需要处理父元素高度和清除浮动
- 定位布局：适合徽标、弹层、角标等局部叠放，不适合承担整个页面的自适应布局
- 表格布局：适合表格数据或兼容旧系统，不应用于普通页面框架
- Flex：适合一维排列、对齐和剩余空间分配
- Grid：适合二维行列布局和页面分区

### 规范回答（可直接复述）

“传统布局包括正常流、浮动、定位和表格布局。现在工程中通常优先使用正常流、Flex 和 Grid：正常流负责内容结构，Flex 解决一维排列，Grid 解决二维网格，定位只处理局部叠放；浮动和表格布局主要用于兼容旧代码或特定场景。”

## 39、简单描述一下什么是 Flex 布局及常用属性说明

### 什么是 Flex

Flex 是弹性布局，它特别适合处理“一维方向上的排列和对齐问题”。

比如：

- 一行排多个按钮
- 左右分布
- 垂直居中
- 元素自动分配剩余空间

这些场景，用 Flex 都非常方便。

### 容器常见属性

#### 1. `flex-direction`

决定主轴方向：

- `row`
- `row-reverse`
- `column`
- `column-reverse`

#### 2. `flex-wrap`

决定一行放不下时要不要换行：

- `nowrap`
- `wrap`
- `wrap-reverse`

#### 3. `flex-flow`

是 `flex-direction` 和 `flex-wrap` 的简写。

#### 4. `justify-content`

控制主轴方向对齐方式。

#### 5. `align-items`

控制交叉轴方向对齐方式。

#### 6. `align-content`

多行内容时，在交叉轴上的整体分布方式。

### 常见坑

- `justify-content` 管主轴，`align-items` 管交叉轴；主轴方向由 `flex-direction` 决定，不要死记“左右”或“上下”。
- Flex 子项默认 `min-width: auto`，长文本或大图片可能导致项目不收缩，常见修复是给子项设置 `min-width: 0`。
- `flex: 1` 常被浏览器解析为 `1 1 0%`，它不等于简单的 `width: 100%`。
- `align-content` 只有在多行并且交叉轴有剩余空间时才明显生效，单行容器通常看不到效果。

### 子项常见属性

#### 1. `flex-grow`

有剩余空间时，项目放大的比例。

#### 2. `flex-shrink`

空间不足时，项目缩小的比例。

#### 3. `flex-basis`

项目在分配剩余空间之前的基础尺寸。

#### 4. `align-self`

单个子项覆盖容器的对齐方式。

#### 5. `order`

控制项目排序。

#### 6. `flex`

是 `flex-grow`、`flex-shrink`、`flex-basis` 的简写。

### `flex: 1` 怎么理解

很多面试会问这个。

通常可以理解成：

- 这个元素可以放大
- 可以缩小
- 会积极参与剩余空间分配

常见记法会写成：

```css
flex: 1 1 0%;
```

### 面试里一句话总结

“Flex 是一种一维弹性布局模型，擅长解决元素排列、对齐、剩余空间分配的问题。常用属性有 `flex-direction`、`justify-content`、`align-items`、`flex-wrap`、`flex-grow`、`flex-shrink`、`flex-basis` 等。”

### 规范回答（可直接复述）

“Flex 是一维布局模型，由 Flex 容器和 Flex 项目组成。容器通过主轴、交叉轴控制方向和对齐，常用 `flex-direction`、`flex-wrap`、`justify-content`、`align-items`；项目通过 `flex-grow`、`flex-shrink`、`flex-basis`、`align-self` 和 `order` 参与空间分配。它适合导航、工具栏、两列区域和居中，但复杂二维网格更适合 Grid。”

## 40、CSS 哪些属性可以继承？

### 常见可继承属性

- `font-size`
- `font-family`
- `color`
- `line-height`
- `text-align`
- `visibility`

### 常见不可继承属性

- `width`
- `height`
- `margin`
- `padding`
- `border`
- `background`

### 怎么理解“继承”

继承就是：父元素上设置的某些样式，子元素如果自己没写，就会自动跟着用。

最典型的就是字体和文字颜色。

### 需要注意的边界

继承不是“父元素所有 CSS 都传给子元素”。`font-family`、`font-size`、`color`、`line-height` 等文字相关属性常会继承，而 `width`、`height`、`margin`、`padding`、`border` 通常不会。每个属性都有自己的初始值、继承规则和计算方式，也可以显式使用 `inherit`、`initial`、`unset` 或 `revert` 控制。

### 规范回答（可直接复述）

“CSS 继承是指子元素在没有指定值时，部分属性可以使用父元素的计算值。常见可继承属性有字体、颜色、行高和文字对齐；盒模型、尺寸、边框和背景通常不继承。实际排查时要区分继承来的值和浏览器默认值，必要时使用 `inherit` 或 `revert` 明确控制。”

## 41、用 CSS 画一个三角形

### 原理

把一个元素的宽高都设为 `0`，然后只保留某一边的边框颜色，其他边透明，就会形成三角形。

### 示例

```css
.triangle {
  width: 0;
  height: 0;
  border: 50px solid transparent;
  border-left-color: yellowgreen;
}
```

### 为什么能形成三角形

因为当元素本身没有内容区大小时，边框在视觉上会向四个方向展开，保留一边颜色，其他边透明，看起来就像一个三角形。

### 另一种现代写法

也可以使用 `clip-path: polygon(...)` 或 CSS 旋转矩形实现三角形。边框法兼容性好、代码短，适合简单箭头；`clip-path` 更灵活，适合复杂形状，但要结合项目浏览器支持范围。

### 规范回答（可直接复述）

“经典边框画三角形的原理是把元素内容区设为 0，让四条透明边框形成三角区域，只保留目标方向的边框颜色。它不是真正的几何元素，而是边框交汇后的视觉效果；如果需要复杂形状，可以使用 `clip-path`。”

## 42、清除浮动有哪些方式？

### 为什么要清除浮动

因为子元素浮动之后，可能脱离普通文档流，导致父元素高度塌陷。

### 常见方式

#### 1. 让父元素形成 BFC

比如给父元素设置：

```css
overflow: hidden;
```

#### 2. 在后面加一个清除元素

新增一个块级元素并设置：

```css
clear: both;
```

#### 3. 使用伪元素清除浮动

这是开发里非常常见的写法。

```css
.clearfix::after {
  content: '';
  display: block;
  clear: both;
}
```

### 面试建议

如果面试官问“清除浮动”，您最好顺带说一下“为什么要清除”，这样回答会显得更完整。

### 规范回答（可直接复述）

“浮动元素会脱离普通块布局的高度计算，可能导致父元素高度塌陷。可以让父元素建立 BFC（更推荐 `display: flow-root`），也可以在末尾使用 `clear: both` 或 clearfix 伪元素。`overflow: hidden` 虽然能建立 BFC，但可能意外裁剪阴影和下拉内容，所以要根据场景选择。”

## 43、什么是 CSS Sprite？有什么优缺点？

### 什么是 CSS Sprite

CSS Sprite 通常叫“雪碧图”。

它的核心思路是：

把多张小图合成一张大图，然后通过 `background-position` 去显示其中某一块区域。

### 优点

1. 可以减少 HTTP 请求数量
2. 适合一批固定小图标的管理

### 缺点

1. 制作和维护麻烦
2. 图标改动时可能要重新合图
3. 在高分辨率、多倍图、自适应场景下管理成本更高

### 现代项目里常见替代方案

- SVG
- SVG Sprite
- Iconfont
- 组件化图标方案

所以现在雪碧图不像以前那样普遍了，但面试里还是会问，因为它代表的是一种经典优化思路。

### 规范回答（可直接复述）

“CSS Sprite 把多张小图合并为一张图片，再通过固定元素尺寸和 `background-position` 显示其中区域，早期主要用于减少 HTTP 请求。缺点是制作维护成本高、响应式和高分辨率适配麻烦；现代项目通常优先使用 SVG、SVG Sprite 或组件化图标。”

## 44、`line-height` 和 `height` 有什么区别？

### `line-height`

表示行高，控制的是一行文字所占的高度。

### `height`

表示元素内容区本身的高度。

### 一个典型应用

单行文字垂直居中时，经常把：

- `height`
- `line-height`

设置成一样。

但要注意，这更适合单行文本，不适合复杂多行文本布局。

### 追问要点

- `height` 描述盒子的内容区高度，可能受 `box-sizing` 影响
- `line-height` 描述行盒高度，继承时要注意单位写法
- `line-height: 1.5` 是无单位数，会根据当前元素字体大小计算，通常比写死 `24px` 更适合响应式
- 多行文本的实际高度还会受到字体、换行、`padding` 和 `min-height` 影响

### 规范回答（可直接复述）

“`height` 控制元素盒子的内容区高度，`line-height` 控制文本行盒高度。单行文字常通过让两者接近实现视觉居中，但多行文本不能依赖这种技巧，应使用 Flex、Grid 或合理的内边距和行高。”

## 45、CSS 的三大特性

CSS 的三大特性是：

1. 层叠性
2. 继承性
3. 优先级

### 1. 层叠性

多个样式都作用在同一个元素上时，最终会按照规则决定谁生效。

### 2. 继承性

某些样式会从父元素传给子元素，比如字体、颜色。

### 3. 优先级

不同选择器命中同一个元素时，要比较谁的优先级更高。

### 一句话总结

层叠性解决“都在改时谁生效”，继承性解决“父亲的样式孩子会不会继承”，优先级解决“谁更有话语权”。

### 三者怎么配合

可以把它们理解成三个步骤：先看哪些声明属于同一层叠过程，再看属性是否从父元素继承，最后在多个命中同一元素的声明之间比较重要性、层叠层、选择器权重和源码顺序。`inherit`、`initial`、`unset`、`revert` 是控制属性值来源的关键字，面试中知道它们的用途会比死记“三大特性”更有用。

### 规范回答（可直接复述）

“CSS 的层叠性决定多个声明冲突时谁生效，继承性决定子元素是否使用父元素的部分属性值，优先级决定同一层叠条件下不同选择器的比较结果。现代 CSS 还要考虑来源、级联层、`!important`、作用域和源码顺序，不能只用‘后写覆盖先写’概括。”

## 46、`defer` 和 `async` 的区别

### 先说结论

它们都是给 `<script>` 用的属性，作用都是尽量减少脚本对页面解析的阻塞，但行为不一样。

- `async`：下载脚本时不阻塞 HTML 解析，下载完马上执行
- `defer`：下载脚本时不阻塞 HTML 解析，等 HTML 解析完成后再按顺序执行

### 为什么会有这两个属性

默认情况下，浏览器解析到普通 `<script>` 时，通常会停下来先下载并执行脚本，然后再继续解析后面的 HTML。  
这就可能影响页面首屏渲染速度。

所以后来就有了 `async` 和 `defer`，用来减少这种阻塞。

### `async` 的特点

- 谁先下载完谁先执行
- 执行顺序不一定和书写顺序一致
- 更适合彼此独立、不依赖别的脚本的资源
- 下载完成后执行脚本时仍可能暂停 HTML 解析

比如统计脚本、广告脚本这类场景，常常可以考虑 `async`。

### `defer` 的特点

- 会等 HTML 全部解析完成后再执行
- 多个 `defer` 脚本会按照它们在文档中的顺序执行
- 更适合主业务脚本
- 主要适用于带 `src` 的经典外部脚本；内联经典脚本上的 `defer` 不起同样作用
- `defer` 脚本会在 HTML 解析完成后、`DOMContentLoaded` 之前执行

`type="module"` 脚本默认具有类似 `defer` 的非阻塞解析行为，但模块还会按照依赖图加载和执行，不能简单等同于普通 `defer`。

### 规范回答（可直接复述）

“`async` 和 `defer` 都能减少外部脚本对 HTML 解析的影响。`async` 下载完成就执行，多个脚本完成顺序不确定，适合彼此独立的脚本；`defer` 会等 HTML 解析完成后、`DOMContentLoaded` 前按文档顺序执行，适合依赖 DOM 或有顺序要求的主业务脚本。模块脚本默认也有类似 `defer` 的行为。”

## 51、`srcset` 和 `sizes` 是做什么的？

### 先说结论

它们主要是为了响应式图片服务的，让浏览器根据设备宽度、屏幕像素密度等条件，自动选择更合适的图片资源。

### 为什么会需要它

同一张图片，在手机、小平板、大屏电脑上实际需要的尺寸往往不一样。  
如果永远只加载一张大图，会浪费流量；如果永远只加载一张小图，在高清屏上又可能发虚。

### `srcset`

用来告诉浏览器：“我这边有几张不同规格的图，你自己选一个更合适的。”

### `sizes`

用来告诉浏览器：“这张图在不同视口下，大概会占多宽。”

### 示例

```html
<img
  src="small.jpg"
  srcset="small.jpg 480w, medium.jpg 800w, large.jpg 1200w"
  sizes="(max-width: 600px) 100vw, 50vw"
  alt="示例图片"
>
```

### 规范回答（可直接复述）

“`srcset` 和 `sizes` 主要用于响应式图片。`srcset` 提供多种图片资源备选，`sizes` 告诉浏览器图片在不同视口下大概会显示多宽，浏览器再自动选择更合适的资源。”

## 52、`cookie`、`localStorage`、`sessionStorage` 的区别

### 先说结论

这三个都能在浏览器端存数据，但用途和特性不一样。

### `cookie`

特点：

- 体积较小
- 会随着 HTTP 请求自动带给服务器
- 常用于登录状态、会话标识等场景
- 可以通过 `HttpOnly` 限制 JavaScript 读取，通过 `Secure` 要求 HTTPS 发送，通过 `SameSite` 降低跨站请求风险

### `localStorage`

特点：

- 长期保存，除非手动清除
- 不会自动随请求发送到服务器
- 适合存一些前端持久化数据

### `sessionStorage`

特点：

- 生命周期通常跟当前标签页会话一致
- 关闭当前标签页后一般会消失
- 也不会自动随请求发送到服务器

### 规范回答（可直接复述）

“`cookie` 会按域名、路径和安全属性参与请求，适合需要服务端参与的会话信息，并可结合 `HttpOnly`、`Secure`、`SameSite` 降低风险；`localStorage` 通常持久保存但不会自动随请求发送；`sessionStorage` 通常只在当前标签页会话内有效。三者都不适合直接存放高敏感明文，具体方案要结合 XSS、CSRF 和登录架构判断。”

## 53、`iframe` 有什么作用？它有什么缺点？

### 作用

`iframe` 可以在当前页面里嵌入另一个页面。

常见场景：

- 第三方页面嵌入
- 某些独立内容隔离展示
- 历史系统兼容

### 缺点

#### 1. 性能开销

它相当于又嵌了一个独立页面，会增加资源加载和渲染成本。

#### 2. SEO 不友好

搜索引擎对 `iframe` 内内容的处理通常不如普通正文直接。

#### 3. 交互和样式控制麻烦

父子页面之间不是像普通 DOM 那样直接操作。

#### 4. 安全问题

如果来源不可信，可能有安全风险，所以经常要配合 `sandbox`、同源策略等一起考虑。

### 规范回答（可直接复述）

“`iframe` 的作用是在当前页面嵌入另一个页面，但它会带来性能、SEO、样式控制和安全方面的问题，所以现代开发中通常会谨慎使用。”

## 54、`box-sizing: content-box` 和 `border-box` 的区别

### `content-box`

这是默认盒模型。

在这种模式下：

- `width` / `height` 只表示内容区
- `padding` 和 `border` 要额外往外加

### `border-box`

在这种模式下：

- `width` / `height` 会把 `padding` 和 `border` 也算进去

### 为什么现代开发常用 `border-box`

因为布局更容易控制。

比如一个盒子您就想让它总宽度是 `200px`，那用 `border-box` 更直观，不容易一不小心算超。

### 示例

```css
* {
  box-sizing: border-box;
}
```

### 规范回答（可直接复述）

“默认的 `content-box` 下，`width` 和 `height` 只表示内容区；`border-box` 下，`width` 和 `height` 会包含 `padding` 和 `border`。现代项目里经常统一使用 `border-box`，这样布局更好控制。”

## 55、`position: sticky` 是什么？和 `fixed` 有什么区别？

### `sticky`

`sticky` 可以理解成“带条件的固定”。

它在没到阈值前，表现有点像 `relative`；  
当滚动到指定位置后，它会像吸附住一样。

### 典型写法

```css
.nav {
  position: sticky;
  top: 0;
}
```

### 和 `fixed` 的区别

- `fixed`：直接相对视口固定
- `sticky`：先跟着正常文档流走，到了阈值后才表现出吸附效果

### `sticky` 为什么有时不生效

- 必须至少设置一个阈值，例如 `top: 0`；否则没有可吸附的位置
- 最近的滚动祖先决定它在哪个滚动容器内吸附
- 祖先的 `overflow`、容器高度不足或自身所在区域太短，都可能让吸附范围看起来失效
- 吸附元素仍占据文档流位置，和 `fixed` 的脱离文档流不同

### 规范回答

“`sticky` 是相对定位和固定定位的结合：滚动到阈值前保留在普通文档流中，达到阈值后在最近滚动容器的范围内吸附；`fixed` 则通常直接相对视口定位并脱离普通文档流。使用 `sticky` 时要检查阈值、滚动容器和祖先的 `overflow`。”

### 典型场景

- 吸顶导航
- 分组标题吸附

## 56、回流和重绘是什么？有什么区别？

### 先说结论

- 回流：布局重新计算
- 重绘：外观重新绘制

一般来说，回流的成本比重绘更高。

### 怎么理解回流

如果一个改动影响到了元素的几何信息，比如：

- 宽高
- 位置
- 布局

那浏览器就可能要重新计算布局，这就是回流。

### 怎么理解重绘

如果只是外观变了，比如：

- 颜色
- 背景
- 边框颜色

但元素大小和位置没变，那通常主要是重绘。

### 为什么面试爱问

因为它和性能优化关系很大。  
如果频繁触发布局变化，就更容易造成页面卡顿。

### 规范回答（可直接复述）

“回流是浏览器重新计算元素布局，重绘是浏览器重新绘制元素外观。回流通常比重绘成本更高，因为它往往伴随着重新计算位置和尺寸。”

## 57、`z-index` 为什么有时候不生效？

### 常见原因

#### 1. 没有检查元素是否处于适用的层叠上下文

对普通块元素来说，`z-index` 常需要配合定位；但 Flex/Grid 子项即使未定位也可以使用 `z-index`。更重要的是要确认元素是否处于同一个层叠上下文。

- `position: relative`
- `position: absolute`
- `position: fixed`
- `position: sticky`

#### 2. 受父级层叠上下文影响

有时候不是您的 `z-index` 数值小，而是它被困在了父级的层叠上下文里。

常见会创建层叠上下文的条件包括定位元素配合非 `auto` 的 `z-index`、`opacity < 1`、`transform`、`filter`、`isolation: isolate` 等。

#### 3. 兄弟元素和父级关系判断错了

同一个层叠上下文里的比较，和跨层叠上下文的比较，逻辑不一样。

### 小白理解法

不是所有元素都在同一张“平面图”上比大小。  
有时候它们已经被分到不同的“楼层”里了，您在小楼层里把数字写很大，也不一定能盖过大楼层外面的元素。

### 规范回答

“`z-index` 的比较是在层叠上下文内部进行的。子元素的 `z-index` 再大，也不能跳出父级层叠上下文与外部元素直接比较；排查时要先检查定位、Flex/Grid 子项资格以及 `transform`、`opacity`、`filter` 等是否创建了新的层叠上下文。”

## 58、`overflow: hidden`、`auto`、`scroll` 的区别

### `hidden`

- 超出内容会被裁掉
- 不显示滚动条

### `auto`

- 超出时才显示滚动条
- 不超出时通常不显示

### `scroll`

- 无论内容有没有超出，通常都会预留滚动机制

### 规范回答（可直接复述）

“`overflow: hidden` 会裁剪溢出内容，`auto` 会在内容超出时自动出现滚动条，`scroll` 通常总是提供滚动机制。”

### 追问要点

- `overflow-x` 和 `overflow-y` 可以分别控制两个方向
- `overflow: hidden` 不等于元素完全不能滚动，脚本或键盘仍可能改变滚动位置
- 作为滚动容器时要注意滚动链、触摸滚动和焦点可见性
- `overflow: clip` 更强调裁剪且不提供滚动机制，是否使用要看浏览器支持和场景

## 59、`transition` 和 `animation` 的区别

### `transition`

更适合“状态变化时的过渡”。

比如：

- 鼠标移入按钮，颜色平滑变化
- 宽度从小变大

它通常需要一个触发条件。

### `animation`

更适合“主动播放的一整段动画”。

它依赖 `@keyframes`，可以做更复杂、更完整的动画过程。

### 一句话区别

- `transition`：从一个状态过渡到另一个状态
- `animation`：按关键帧播放一段完整动画

### 规范回答（可直接复述）

“`transition` 描述属性从一个状态到另一个状态的过渡，通常需要 hover、class 切换或脚本改变属性来触发；`animation` 依赖 `@keyframes`，可以自动播放、循环、延迟和控制多个关键帧。动画属性优先选择 `transform` 和 `opacity`，并考虑 `prefers-reduced-motion`，避免给不需要动态效果的用户造成不适。”

## 60、媒体查询是什么？有什么用？

### 先说结论

媒体查询是响应式设计的核心手段之一，它可以让我们根据不同设备条件，写不同的 CSS。

### 常见场景

- 手机和电脑布局不同
- 小屏和大屏字号不同
- 某些区域在窄屏下改成单列

### 示例

```css
@media (max-width: 768px) {
  .container {
    flex-direction: column;
  }
}
```

### 怎么理解

可以把它理解成：

“如果屏幕满足某个条件，就应用这一套样式。”

### 规范回答（可直接复述）

“媒体查询根据视口尺寸、方向、分辨率、颜色模式或用户偏好应用条件样式，是响应式设计的重要工具。实际开发通常采用移动优先，并根据内容临界点设置断点；除了布局切换，还可以用它适配深色模式和减少动态效果偏好。”

## 61、响应式布局和自适应布局的区别

### 响应式布局

一套页面结构，随着屏幕尺寸变化自动流动和调整。

特点是更灵活、更连续。

### 自适应布局

通常是针对几个固定尺寸区间，准备几套相对明确的布局方案。

特点是分档更明显。

### 简单理解

- 响应式：像水一样，连续变化
- 自适应：像换挡一样，到某个区间切一次方案

### 规范回答（可直接复述）

“响应式布局通常是一套布局随屏幕连续变化，自适应布局则更像针对几个固定区间切换不同方案。现代前端里两者常常会结合使用。”

### 面试追问

响应式不代表所有尺寸都必须完全相同，而是页面结构和内容能够在不同空间中合理重排；自适应也不一定是多套完全独立页面，常见做法是同一套组件在断点处切换列数、导航形态和间距。

## 62、圣杯布局和双飞翼布局是什么？

### 它们解决的核心问题

这两种都是经典三栏布局方案，目标一般是：

- 左右两栏固定宽度
- 中间主内容自适应
- 还希望主内容优先加载或优先展示

### 圣杯布局

一般通过：

- 浮动
- 负外边距
- 父元素 `padding`

等方式实现。

### 双飞翼布局

思路和圣杯布局很像，但通常会在中间主内容里再包一层，借此处理左右两栏位置问题。

### 为什么中间内容优先

经典方案会把中间主内容写在 HTML 中更靠前的位置，再通过负外边距把左右栏放到两侧。这样在早期网络条件下，浏览器可以更早解析主要内容；现代项目通常直接用 Flex/Grid，除非面试官明确要求手写传统方案。

### 现在还常用吗

现在实际开发中，Flex 和 Grid 更常见。  
但圣杯布局、双飞翼布局在面试里仍然常被问，因为它们能反映您对传统布局思路是否理解。

### 规范回答（可直接复述）

“圣杯布局和双飞翼布局都是经典三栏布局，目标是中间自适应、左右固定，并让中间内容在结构上优先。它们主要依赖浮动、负外边距和额外包裹层；现代开发优先使用 Flex/Grid，但面试中仍可用它们说明传统布局、文档顺序和空间分配原理。”

## 63、Grid 布局是什么？和 Flex 有什么区别？

### Grid 是什么

Grid 是网格布局，它更适合做二维布局，也就是同时处理行和列。

### Flex 和 Grid 的区别

- Flex 更适合一维布局，主要处理一行或者一列
- Grid 更适合二维布局，同时处理多行多列

### 什么时候用 Flex

比如：

- 一排按钮
- 水平垂直居中
- 导航排列

### 什么时候用 Grid

比如：

- 宫格卡片
- 仪表盘
- 比较复杂的整体页面分区

### 规范回答（可直接复述）

“Flex 更偏一维布局，擅长解决一条主轴上的排列和对齐；Grid 更偏二维布局，适合同时控制行和列。简单线性布局更适合 Flex，复杂网格布局更适合 Grid。”

### Grid 最小示例

```css
.cards {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(220px, 1fr));
  gap: 16px;
}
```

这里 `auto-fit` 会根据可用空间自动决定列数，`minmax(220px, 1fr)` 表示每列最小 220px、剩余空间按比例分配。面试时可以用这个例子说明 Grid 不只是“表格”，还适合做响应式卡片和页面分区。

前面的题目覆盖了 HTML/CSS 基础。下面补充几道经常和基础题连着问的题，重点放在“为什么”和“实际怎么选”。

## 64、什么是 CSS 层叠上下文？它和 `z-index` 有什么关系？

### 快速理解

可以把层叠上下文理解成浏览器建立的一个“独立图层”。同一个图层里的元素可以比较前后顺序，但子图层里的数字不能直接拿出去和外部图层比较。

### 规范回答

“层叠上下文是浏览器进行绘制顺序计算的独立上下文。`z-index` 主要是在同一个层叠上下文内部比较；如果两个元素属于不同的父级层叠上下文，要先比较父级上下文的层级，子元素的 `z-index` 不能越过父级上下文。定位元素配合非 `auto` 的 `z-index`、`opacity` 小于 1、`transform`、`filter` 和 `isolation: isolate` 等都可能创建层叠上下文。”

### 追问提醒

不要只说“`z-index` 越大越靠前”。先确认元素是否在同一个层叠上下文，以及是否被父级 `overflow` 裁剪。

### 排查顺序

1. 确认目标元素确实渲染出来，没有被 `display: none`、`visibility` 或条件渲染移除。
2. 检查目标和遮挡元素是否属于不同层叠上下文。
3. 检查父级是否通过 `overflow` 裁剪了内容。
4. 再比较同一上下文中的 `z-index`、定位和源码顺序。

## 65、Flex 布局中 `flex: 1` 和 `min-width: 0` 为什么常被一起问？

### 快速理解

`flex: 1` 表示项目愿意分配和收缩剩余空间；但 Flex 子项默认最小尺寸可能由内容撑开，长文本就可能把布局撑破。`min-width: 0` 是告诉浏览器“允许它真的缩小”。

### 规范回答

“`flex: 1` 通常等价于 `flex: 1 1 0%`，表示项目可以增长、可以收缩，并以 `0%` 作为基础尺寸参与空间分配。Flex 子项默认 `min-width: auto`，最小宽度可能由内容决定，因此长文本、长 URL 或大图片会阻止收缩；在需要截断或换行的布局中，常给子项设置 `min-width: 0`，再配合 `overflow-wrap` 或省略号处理内容。”

### 可直接运行的例子

```css
.row { display: flex; width: 320px; }
.main { min-width: 0; flex: 1; }
.main-title { overflow: hidden; text-overflow: ellipsis; white-space: nowrap; }
```

这里 `min-width: 0` 允许 `.main` 真正缩小，省略号负责处理超长文本；如果去掉它，内容的最小尺寸可能把右侧按钮挤出容器。

## 66、如何区分回流、重绘和合成？如何优化？

### 快速理解

- 回流：重新计算“摆在哪里、占多大地方”
- 重绘：位置不变，只重新画颜色、阴影等外观
- 合成：把已经绘制好的图层重新组合，通常比重新布局和绘制更轻

### 规范回答

“改变几何尺寸、位置或布局关系可能触发回流，回流通常会连带后续重绘；只改变颜色、背景等不影响几何的信息通常主要触发重绘；某些动画会在独立合成层上完成合成。优化时应批量读写 DOM，避免强制同步布局，优先使用 `transform` 和 `opacity` 做动画，并通过性能面板验证，而不是机械地把所有元素都提升为合成层。”

### 追问提醒

`transform` 和 `opacity` 通常更适合动画，但不代表绝对不会产生额外开销；过多合成层也会增加内存和合成成本。

### 常见触发示例

- 修改 `width`、`height`、`padding`、字体大小，可能影响布局并触发回流
- 修改 `color`、`background-color`，通常只需要重绘
- 使用 `transform: translate()` 移动元素，通常可以避免重新计算周围布局
- 连续读取 `offsetWidth` 后立即写入样式，可能强制浏览器同步计算布局

面试时不要绝对化地说“某个属性一定只触发某一种过程”，最终结果会受到元素、浏览器和当前渲染状态影响，最好用性能面板验证。

## 67、HTML 语义化和无障碍具体应该怎么做？

### 快速理解

语义化就是让标签表达它的真实用途，让浏览器、搜索引擎和读屏软件都能更容易理解页面。

### 规范回答

“优先使用原生语义元素，例如用 `<button>` 表示按钮、用 `<a href>` 表示链接、用 `<label>` 关联表单控件、用 `<main>`、`<nav>`、`<article>` 表示页面区域。只有原生元素无法满足需求时才使用 ARIA，并且不能用 ARIA 把一个普通 `div` 伪装成完整按钮后就忽略键盘、焦点和默认行为。图片要提供合适的 `alt`，交互控件要支持键盘访问，标题层级和表单错误提示要清晰。”

### 小白检查清单

- 能点击的操作优先使用 `<button>`，能跳转的内容使用带 `href` 的 `<a>`
- 输入框有可见 `<label>` 或等价的可访问名称
- 键盘可以通过 Tab 到达交互控件，焦点状态不能被无脑去掉
- 图片按“信息图片 / 装饰图片”分别填写描述或空 `alt`
- 不用颜色作为唯一状态提示，错误信息要能被读屏软件感知

## 68、浏览器缓存常见的强缓存和协商缓存是什么？

### 快速理解

强缓存命中时浏览器直接使用本地文件，不发请求；协商缓存会向服务器确认“本地这份还能不能用”，服务器说没变化就返回 `304`。

### 规范回答

“强缓存主要由 `Cache-Control` 和历史上的 `Expires` 控制，命中时不会向服务器发起验证请求。协商缓存常使用 `ETag/If-None-Match` 或 `Last-Modified/If-Modified-Since`，请求到服务器后由服务器判断资源是否变化，未变化返回 `304 Not Modified`。生产环境通常给带内容哈希的静态资源设置较长缓存，而 HTML 使用较短缓存或协商缓存，避免更新后用户拿到旧入口文件。”

### 常见误区

- `304` 不是“没有请求”，而是已经发起了协商请求，只是服务器确认本地副本仍可用
- `no-cache` 通常表示使用前要重新验证，不等于完全禁止缓存
- `no-store` 才是明确要求不要存储响应
- 带文件哈希的 JS/CSS 可以长缓存，但入口 HTML 不能盲目永久缓存

## 69、CSS 如何实现移动端响应式适配？

### 快速理解

不要只靠某一个媒体查询。响应式适配通常是“可伸缩布局 + 合理断点 + 图片和文字不溢出”一起完成。

### 规范回答

“先使用移动优先的正常文档流、Flex 或 Grid，让布局具备伸缩能力；再通过媒体查询处理结构变化，并使用相对单位、`clamp()`、`minmax()` 等控制尺寸。图片使用 `srcset/sizes`，页面头部配置 `meta viewport`，同时检查触摸目标、长文本、横向滚动和安全区域。断点应根据内容何时无法继续排布来确定，而不是机械套用某几个设备宽度。”

### 一个可执行的检查顺序

1. 先写移动端基础布局，确认内容在窄屏不会横向溢出。
2. 用 Flex/Grid 处理结构，不用固定宽度堆叠页面。
3. 对图片设置 `max-width: 100%`、尺寸预留和响应式资源。
4. 在内容真正放不下时增加断点，调整列数、导航和间距。
5. 检查 320px、390px、768px 和桌面宽度，重点看长标题、表单、表格和弹窗。

面试时可以补一句：“我不会只按 iPhone、iPad 这些设备名称写断点，而是根据内容临界点和真实设备测试结果确定断点。”

## 70、HTML 表单中 `label`、`name`、`value`、`disabled` 和 `readonly` 有什么作用？

### 小白理解

表单控件不只是“画出来能输入”就够了：`label` 让用户和读屏软件知道这个输入框是什么，`name` 决定提交给服务器时的字段名，`value` 是提交值；`disabled` 表示控件不可操作且通常不会提交，`readonly` 表示不能修改但通常仍会提交。

### 示例

```html
<label for="email">邮箱</label>
<input id="email" name="email" type="email" value="a@example.com" readonly>
<button type="submit">提交</button>
```

### 规范回答（可直接复述）

“`label` 通过 `for` 或包裹关系与控件建立可访问名称；`name` 是表单提交时的字段名，没有 `name` 的控件通常不会出现在提交数据中；`value` 是控件当前值。`disabled` 控件不可聚焦、不可编辑且通常不会提交；`readonly` 主要限制文本修改，仍可聚焦并参与提交。提交按钮要明确使用 `type`，避免默认行为造成误提交。”

## 71、HTML 表格怎样写才语义正确并兼顾无障碍？

### 小白理解

`table` 不是拿来排版的，而是表示“行和列都有明确关系的数据”。表头、表体和表格标题写清楚，读屏软件才知道每个数据对应哪一列。

### 规范回答（可直接复述）

“表格数据应使用 `<table>`，用 `<caption>` 描述表格主题，用 `<thead>`、`<tbody>`、`<tfoot>` 区分结构，用 `<th>` 表示表头，并在复杂表格中通过 `scope="col"` 或 `scope="row"` 明确表头作用范围。不要用一堆 `div` 模拟表格，也不要用 `table` 承担普通页面布局。”

## 72、CSS 自定义属性和 Sass 变量有什么区别？

### 小白理解

Sass 变量像“编译前的替换工具”，编译完成后浏览器看不到变量；CSS 自定义属性是真正留在浏览器里的变量，可以在运行时继承、覆盖和切换主题。

### 示例

```css
:root { --brand-color: #1677ff; }
.button { color: var(--brand-color, #1677ff); }
.dark { --brand-color: #69b1ff; }
```

### 规范回答（可直接复述）

“Sass/Less 变量在构建阶段处理，适合复用静态设计值；CSS 自定义属性在运行时参与级联和继承，可以通过选择器、媒体查询或 JavaScript 动态修改，适合主题切换、组件配置和响应式场景。`var()` 可以提供回退值，但变量本身无效时要注意整条声明可能回退。”

## 73、CSS 中如何处理长文本、长 URL 和内容溢出？

### 小白理解

布局被撑破通常不是“宽度不够”这么简单，还要决定文本是换行、截断，还是允许横向滚动。

### 常用方案

```css
.single-line {
  overflow: hidden;
  text-overflow: ellipsis;
  white-space: nowrap;
}

.article {
  overflow-wrap: anywhere;
  word-break: break-word;
}
```

### 规范回答（可直接复述）

“单行文本省略通常需要同时设置 `overflow: hidden`、`text-overflow: ellipsis` 和 `white-space: nowrap`；长 URL 或不可断词内容要用 `overflow-wrap: anywhere` 等规则避免撑破布局；多行截断可结合 `-webkit-line-clamp`，但要考虑兼容性和可访问性，不能把被截断的关键信息只藏在视觉层。”

## 74、媒体查询和容器查询有什么区别？

### 小白理解

媒体查询看“整个浏览器窗口有多宽”，容器查询看“组件自己能分到多宽”。组件放在不同父容器里时，容器查询更适合复用。

### 示例

```css
.panel { container-type: inline-size; }

@container (max-width: 520px) {
  .panel-content { grid-template-columns: 1fr; }
}
```

### 规范回答（可直接复述）

“媒体查询根据视口或设备特征切换样式，适合页面级布局；容器查询根据祖先容器的尺寸切换组件样式，适合组件化和多栏复用。使用容器查询前要在容器上声明 `container-type` 或命名容器，并检查浏览器支持范围。”

## 75、CSS 逻辑属性解决什么问题？

### 小白理解

`margin-left` 只认识左右方向，但国际化页面可能从右向左书写。逻辑属性用“行内开始/结束、块开始/结束”描述方向，页面切换 RTL 时不需要大量改样式。

### 示例

```css
.card {
  padding-inline: 16px;
  margin-block: 12px;
  border-inline-start: 3px solid #1677ff;
}
```

### 规范回答（可直接复述）

“CSS 逻辑属性根据书写模式描述布局方向，例如 `margin-inline`、`padding-block`、`inset-inline-start` 和 `border-block`。它们比固定的 left/right、top/bottom 更适合国际化、RTL 语言和可复用组件；使用时要确认团队浏览器支持和设计系统约定。”
