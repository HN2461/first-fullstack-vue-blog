# 陈浩南前端开发工程师简历面试问答：小白背诵版

## 使用方法

这份问答只使用简历里出现过的项目和技术，不额外编造性能数据。每道题分为三层：

- **先背一句**：面试紧张时先说这一句，保证不跑题。
- **再补两句**：面试官继续听时，用两三句话解释做法和原因。
- **追问接法**：遇到更深的问题，按这句继续回答；没有做过的内容要诚实说明“我负责的是前端这一段”。

回答时尽量遵循：**背景 -> 我的工作 -> 解决办法 -> 结果/收获**。不要一上来背技术名词，先说业务，再说技术。

## 一、30 秒自我介绍

### 1. 请你先做一下自我介绍

**先背一句：**

面试官您好，我叫陈浩南，本科是计算机科学与技术专业，有约一年前端开发经验，主要使用 Vue 3 和 uni-app，做过智慧校园 PC 中后台、移动端小程序、MaxKB 智慧校园 AI 和电子班牌项目。

**再补两句：**

我比较擅长把复杂业务拆成可复用的前端模块，例如动态路由和权限、统一登录与请求、WebSocket 实时消息、动态表单和 SSE 流式回答。我也接触过 Node.js、Express、Python、FastAPI、MySQL 和 MongoDB，遇到接口或环境问题时能和后端一起定位。

**追问接法：**

我目前最希望继续做 Vue 生态下的中后台和多端业务，把已经做过的登录、权限、实时通信和跨端适配经验做得更扎实。

### 2. 你的优势是什么？

**先背一句：**

我的优势是能跟着真实业务走完整链路，不只写页面，也会关注登录、权限、接口、异常和发布后的稳定性。

**再补两句：**

例如 PC 项目里，我参与了菜单驱动的动态路由、登录会话、WebSocket 消息和公共组件；移动端项目里还处理了多平台登录、SSE、弱网和原生能力接入。这样排查问题时，我会从页面、请求、权限、设备和服务端返回一起看。

**追问接法：**

我不会把“接触过”说成“完全掌握”。对于后端或原生部分，我能完成接口联调、参数分析和前端接入，复杂服务端实现会和对应同事配合。

### 3. 你为什么选择前端？

**先背一句：**

前端能把业务规则直接变成用户看得见、用得上的功能，我喜欢这种反馈快、又需要持续思考交互和工程质量的工作。

**再补两句：**

在智慧校园项目中，同一套系统要服务老师、学生、家长和管理员，不同角色看到的菜单和功能不同。我从中体会到前端不只是写样式，还要理解权限、数据和用户流程。

## 二、智慧校园 PC 中后台项目

### 4. 请介绍一下智慧校园 PC 中后台项目

**先背一句：**

这是一个面向学校的统一管理后台，承载教务、学生、审批、实习、访客和消息等业务，同一套代码通过学校配置和角色权限服务多个学校。

**再补两句：**

技术栈是 Vue 3、Element Plus、Vue Router、Vuex、Axios、SCUI 和 WebSocket/STOMP。我主要负责动态路由权限、账号和第三方登录、统一请求、实时消息、动态表单和公共能力复用。

**追问接法：**

这个项目的难点不是某个单页面，而是公共链路很多：用户登录后要先拿到身份和学校信息，再根据后端菜单决定能访问什么页面，同时还要保证消息、缓存和退出清理不互相影响。

### 5. 你在 PC 项目中具体负责哪些模块？

**先背一句：**

我负责四类公共模块：动态路由与权限、登录与请求治理、WebSocket/STOMP 实时消息，以及请求层、上传、选人和任务中心等公共能力。

**再补两句：**

动态路由解决“不同角色显示不同页面”；登录请求治理解决 token、schoolID 和失效退出；实时消息负责连接、订阅和未读数；公共能力复用则减少业务页面重复代码。

**追问接法：**

我会优先把跨页面、规则稳定、重复出现的逻辑抽成公共模块；一次性且强绑定页面的逻辑仍留在页面里，避免过度抽象。

### 6. 什么是动态路由？你是怎么做权限控制的？

**先背一句：**

动态路由就是登录后根据后端返回的菜单和角色权限，生成当前用户能看到、能访问的路由，而不是所有路由都写死给每个人。

**再补两句：**

登录成功后先获取用户、学校和菜单数据，再把菜单节点映射到前端已有的路由组件。路由守卫负责判断登录状态和路由是否已注入，角色过滤由后端权限结果决定，前端只做必要的组件映射和兜底。

**追问接法：**

前端隐藏菜单不等于真正安全，后端接口仍然必须校验角色和权限。前端权限主要解决展示和导航体验，后端权限才是最终边界。

### 7. 为什么要处理 `keep-alive`、`iframe` 和 404 延后注入？

**先背一句：**

动态路由还没加载完成时，不能让路由器立刻把未知地址判成 404；`keep-alive` 和 `iframe` 则分别解决页面状态保留和外部页面嵌入。

**再补两句：**

我会在菜单和路由注入完成后再放开正常导航，并给动态页面补充 404 兜底。缓存页面要根据菜单的缓存标记决定是否保留，iframe 页面还要处理地址、加载和返回状态。

**追问接法：**

如果出现“刷新后白屏或误进 404”，我会先看路由注入时机，再看守卫是否重复执行、组件映射是否为空，以及浏览器控制台是否有异步错误。

### 8. 统一登录为什么比每个页面自己判断更好？

**先背一句：**

统一登录把身份、token、学校信息、失效处理和退出清理集中管理，页面只关心业务，不需要重复写一套登录判断。

**再补两句：**

PC 端支持账号密码、微信、钉钉和企业微信等入口。无论从哪个入口进来，最终都归一成统一会话；请求层集中添加 `Authorization`、`schoolID` 等公共参数，失效时统一清理并跳转登录。

**追问接法：**

统一不代表所有平台完全一样。平台差异放在登录适配层，公共层只接收标准化后的用户身份和会话结果。

### 9. `token` 和 `schoolID` 为什么要一起处理？

**先背一句：**

`token` 解决“你是谁”，`schoolID` 解决“你当前在哪个学校数据域”，两者缺一都可能拿到错误数据或无法通过接口校验。

**再补两句：**

请求发送前统一注入这两个值，切换学校或退出时同步更新和清理。不能只依赖页面上的变量，否则刷新、并发请求或跨端切换时容易出现旧身份串数据。

**追问接法：**

真正的数据隔离仍由后端完成，前端传 schoolID 只是业务上下文，不是安全凭证。

### 10. Axios 请求拦截器通常做什么？

**先背一句：**

请求拦截器统一加公共请求头和参数，响应拦截器统一处理成功格式、登录失效和错误提示。

**再补两句：**

我会避免在拦截器里写具体页面业务。它只负责标准化请求、记录必要日志、识别 401 或业务失效码，并把错误交给页面或全局错误处理。

**追问接法：**

文件上传、下载和不需要登录的公共接口要有明确例外，不能无条件给所有请求加同样的头和序列化方式。

### 11. 如果 token 过期，你会怎么处理？

**先背一句：**

先停止继续使用失效会话，再统一清理本地身份信息，最后跳转登录并避免重复弹窗或重复跳转。

**再补两句：**

响应拦截器识别 401 或约定的失效码，使用一个全局处理状态防止多个并发请求同时触发跳转。清理内容包括 token、schoolID、用户信息、缓存页面和实时连接。

**追问接法：**

如果后端提供 refresh token，可以设计刷新队列；如果没有，就按项目约定重新登录，不能擅自无限重试。

### 12. WebSocket 和 STOMP 在项目中分别负责什么？

**先背一句：**

WebSocket 提供浏览器和服务端的长连接，STOMP 在长连接上规定连接、订阅、发送和消息确认的格式。

**再补两句：**

项目里用它做实时提醒、审批变化、未读数和协同消息。前端要处理连接、订阅、保活、断线重连、主动退出和未读消息映射。

**追问接法：**

WebSocket 断开时不能无限快速重连，要有退避或次数限制；页面销毁时必须取消订阅并关闭连接，避免重复消息和内存泄漏。

### 13. 实时消息重复或未读数不准，你会怎么排查？

**先背一句：**

我会按“连接是否重复、订阅是否重复、消息 ID 是否去重、字段映射是否正确、页面是否重复消费”这五步排查。

**再补两句：**

先在连接和订阅入口打印唯一标识，再检查路由切换和热更新是否建立了多条连接。收到消息后统一转换成前端消息模型，按消息 ID 或业务键去重，未读数由统一状态源更新。

**追问接法：**

如果是服务端重复推送，前端去重只能缓解，仍要把样例消息、订阅主题和时间线交给后端一起确认。

### 14. 动态表单和普通表单有什么不同？

**先背一句：**

普通表单的字段写在模板里，动态表单把字段定义放在 JSON 配置里，由渲染器根据类型生成控件、校验和提交结构。

**再补两句：**

动态表单适合多个学校字段不同的招生业务。渲染器需要处理字段类型、默认值、依赖显示、实时或失效状态、必填校验、附件和最终数据转换。

**追问接法：**

配置驱动不等于不校验。前端负责及时提示，后端必须再次校验字段类型、长度、权限和业务规则。

### 15. 你如何设计一个可复用的公共组件？

**先背一句：**

先确认重复场景和稳定边界，再用清晰的 props、事件和插槽抽出组件，页面只传数据和业务回调。

**再补两句：**

例如上传、选人、任务中心和复杂列表都可能复用。组件内部处理通用交互和状态，业务差异通过配置或插槽传入，同时保留加载、空状态、错误和禁用状态。

**追问接法：**

如果只有一个页面使用且变化很大，我不会为了减少行数强行抽象，先保证职责清楚和容易测试。

## 三、智慧校园 Uni-app 移动端

### 16. PC 端和 uni-app 移动端最大的差异是什么？

**先背一句：**

PC 端重点是复杂中后台和大屏操作，移动端重点是多平台运行、触摸交互、登录环境差异和设备能力。

**再补两句：**

移动端同一套代码要适配微信小程序、H5、钉钉和企业微信，平台 API、授权流程、页面生命周期和返回行为都不同。我把公共业务状态保留在 Pinia，平台差异集中在适配层和条件编译中。

**追问接法：**

不能只在真机上临时修补。开发时要先列出平台差异表，再分别验证登录、扫码、WebSocket、文件和页面返回。

### 17. 多角色登录为什么复杂？

**先背一句：**

移动端可能同时面对老师、学生、家长等身份，还可能来自微信、钉钉、企业微信，所以必须把“身份”和“登录平台”分开管理。

**再补两句：**

我会先识别当前平台和登录场景，再完成授权回流；拿到用户身份、业务身份和 token 后统一存储。切换身份或退出时，旧 token、用户信息和实时连接要一起清理。

**追问接法：**

双 token 不是越多越好，关键是明确每个 token 的用途、来源、有效期和发送位置，避免把不该给某接口的 token 发出去。

### 18. 移动端为什么要做会话 `ready` 判断？

**先背一句：**

页面启动时登录态可能还在异步恢复，如果请求过早发出，就会出现公共接口带着空 token 的问题。

**再补两句：**

我会让会话层暴露一个 ready 状态或 Promise，请求层在需要登录时等待会话恢复完成；公开接口可以按白名单直接访问。这样能避免首屏竞态和重复登录。

**追问接法：**

ready 只表示本地会话恢复完成，不代表 token 永远有效，接口返回失效后仍要走统一失效处理。

### 19. uni-app 中如何处理平台差异？

**先背一句：**

通用业务写一次，平台专属 API 放在适配层，必要时用条件编译隔离微信、H5、钉钉和 App-Plus 代码。

**再补两句：**

例如扫码、授权、文件选择和原生能力不能直接在所有平台调用。我会先定义统一方法，如 `login()`、`scanCode()`，各平台实现自己的分支，返回统一数据结构给页面。

**追问接法：**

条件编译只能解决编译分支，不能替代真实平台测试；还要验证权限、生命周期和返回值是否一致。

### 20. 移动端的 WebSocket 生命周期怎么处理？

**先背一句：**

进入需要实时消息的页面时连接和订阅，页面隐藏或退出时按业务决定保留连接，但订阅必须可管理，断线要重连。

**再补两句：**

项目用 `uni.connectSocket` 加 STOMP，处理连接、订阅、保活、断线重连、强制下线和未读刷新。连接管理放在公共层，避免每个页面各建一条连接。

**追问接法：**

重连前先判断当前会话和页面是否仍然有效；用户退出后不能因为定时器又自动连回来。

## 四、职业院校招生小程序与 SSE

### 21. 请介绍招生小程序项目

**先背一句：**

这是面向职业院校招生报名、信息查询和在线咨询的小程序，页面内容和表单通过配置适配不同学校，咨询部分接入 MaxKB 智能体。

**再补两句：**

技术栈是 uni-app、Vue 3、Pinia、uv-ui、微信小程序、MaxKB、LLM 和 SSE。我主要负责 JSON 动态表单、招生客服接入、SSE 流式文本展示和轮播、分类、新资讯等内容配置化。

**追问接法：**

这个项目的重点是“学校差异由配置表达”，而不是复制多套页面；但配置仍要有版本、校验和异常兜底。

### 22. SSE 是什么？和 WebSocket 有什么区别？

**先背一句：**

SSE 是服务端通过 HTTP 持续向客户端单向推送文本事件，适合 AI 逐字返回；WebSocket 是双向长连接，更适合双方实时通信。

**再补两句：**

招生咨询主要是用户发一次问题，服务端连续返回回答，所以 SSE 接入简单、符合文本流场景。WebSocket 则适合聊天双方都可能主动发消息、协同和实时通知。

**追问接法：**

SSE 断线后是否自动续传取决于服务端是否支持事件 ID 和重放；前端不能把重连当成一定不会丢数据。

### 23. 小程序为什么不能直接像浏览器一样收 chunk？

**先背一句：**

小程序网络 API 对流式响应的能力和浏览器不同，不能假设能直接使用浏览器的 `ReadableStream`，所以要按平台能力选择客户端或后端中转方案。

**再补两句：**

项目中我会解析后端约定的 SSE 数据格式，兼容分片、事件边界和结束标记；如果目标平台不能逐块接收，就让后端转成平台可消费的消息或采用 WebSocket。

**追问接法：**

排查流式问题时先确认服务端 `Content-Type`、代理是否缓冲、平台 API 是否真的回调增量，而不是只改前端字符串拼接。

### 24. SSE 分片解析要注意什么？

**先背一句：**

一次网络回调不一定等于一条完整消息，必须缓存未完成的片段，按 SSE 的换行边界拼接后再解析。

**再补两句：**

解析器要处理多个事件粘在一起、一个事件被拆开、JSON 中包含换行、结束事件和错误事件。展示层只接收已经解析好的文本增量，不直接处理原始网络片段。

**追问接法：**

如果服务端返回的不是标准 SSE，而是自定义 JSON 流，我会先让前后端确认协议，再写针对协议的解析器，并保留原始片段日志方便复现。

### 25. 动态表单的三段校验是什么？

**先背一句：**

我理解为输入中、输入失效和提交前三段校验：先给用户即时反馈，再在字段失效时阻止明显错误，最后提交前做完整校验。

**再补两句：**

例如手机号可以在输入时做格式提示，失焦时显示具体错误，提交时再统一检查必填、格式、文件和字段依赖。服务端必须重复校验，防止绕过前端。

**追问接法：**

校验规则应来自字段配置和业务规则，不能把 13 种字段类型的判断散落在多个页面。

### 26. MaxKB 在招生项目中负责什么？

**先背一句：**

MaxKB 负责知识库检索和大模型回答，前端负责把用户问题、会话身份和学校上下文传过去，再把结果展示出来。

**再补两句：**

不同学校使用不同资料，前端会传递学校标识或业务上下文，后端或 MaxKB 应用据此选择正确知识范围。前端还要处理会话创建、提问、流式回答、错误和结束状态。

**追问接法：**

不能把前端当成知识库权限边界；敏感身份、应用密钥和真正的数据过滤必须由后端控制。

### 27. 为什么要做内容配置化？

**先背一句：**

招生页面的轮播图、分类入口和资讯经常变化，配置化可以让换学校或改内容时少发版本。

**再补两句：**

配置要定义字段结构、默认值、版本和无数据兜底，渲染前先做数据清洗。这样内容变化和页面代码解耦，但关键字段仍要有类型校验。

## 五、电子班牌设备端应用

### 28. 请介绍电子班牌项目

**先背一句：**

这是运行在校园固定终端上的班牌应用，覆盖班级端和教室端两种模式，展示课表、考勤、通知、班级风采并支持设备维护。

**再补两句：**

技术栈是 uni-app、Vue 3、JavaScript、DCloud App-Plus、Android、Java 和 RESTful API。我负责前端落地、设备初始化绑定、模式切换、接口联调、弱网稳定性和 Android 原生能力接入。

**追问接法：**

固定终端和手机不同，不能只考虑一次打开成功，还要考虑开机自启、长期运行、网络抖动、token 过期和远程维护。

### 29. JS 如何调用 Android 原生能力？

**先背一句：**

通过统一的 JS 适配层调用 Android/Java 暴露的方法，页面只调用业务方法，不直接到处写原生判断。

**再补两句：**

项目里涉及摄像头、扫码、开机自启、Launcher、导航栏、截图和重启等能力。我会统一处理参数、回调、超时和异常，再把结果转换成前端能理解的成功或失败状态。

**追问接法：**

原生能力要区分“方法不存在、调用失败、调用超时和业务返回失败”，不能把所有情况都当成成功。

### 30. 固定终端为什么要做缓存和 token 刷新？

**先背一句：**

设备可能长期运行且网络不稳定，适当缓存能减少重复请求，token 刷新能避免运行中突然变成空白页。

**再补两句：**

我会给请求增加超时、重试边界和缓存降级；检测到 token 临近过期时刷新，刷新失败再进入可恢复的登录或绑定状态。展示层要保留上一次可信数据，而不是直接清空。

**追问接法：**

缓存必须有时间和版本边界，不能无限使用旧课表；涉及权限的数据更不能只相信本地缓存。

### 31. 如何避免设备接口失败时出现空白页？

**先背一句：**

把页面状态拆成加载中、成功、空数据、失败和可重试，不让异常直接打断整个页面渲染。

**再补两句：**

接口失败时展示上次缓存或明确的维护提示，关键请求可以有限重试；原生回调超时要结束 loading，页面销毁后不再回写状态。

**追问接法：**

我会记录设备编号、接口、错误类型和时间，便于区分网络、服务端、权限和原生桥接问题，同时不把敏感信息直接展示给用户。

### 32. 设备运维交付包括哪些内容？

**先背一句：**

除了页面功能，还要交付设备心跳、远程指令入口、真机回归、安装升级验证和交付资料。

**再补两句：**

固定设备的验收要覆盖首次绑定、重启、断网恢复、接口超时、权限变化、摄像头和截图等真实场景。前端需要和硬件、后端、实施人员共同确认。

## 六、MaxKB 智慧校园 AI 业务智能体

### 33. 请介绍你做的 MaxKB AI 项目

**先背一句：**

公司把开源 MaxKB 部署到服务器，我在应用层搭建智慧校园业务智能体，接入 OA 工作发起、审批查看、成绩查询和教师调代课等能力，并接入 PC 端和小程序端。

**再补两句：**

我负责应用路由、Prompt、Python 工具、接口绑定、前端入口和调试回归，不涉及 MaxKB 平台源码开发。关键是让自然语言意图经过工具解析、字段校验和接口调用后，返回可控的业务结果。

**追问接法：**

大模型只负责理解和生成，真正的权限、字段校验和数据修改仍由后端接口负责，不能让模型直接决定最终写库结果。

### 34. `Prompt Engineering` 在项目中做了什么？

**先背一句：**

Prompt 是给模型的任务说明和约束，我用它约定角色、输出格式、字段要求、缺失信息时的询问方式和禁止越权的边界。

**再补两句：**

好的 Prompt 不只是“回答得像人”，还要让输出能被后续工具稳定解析。例如要求模型按固定 JSON 表达意图和参数，缺少必填字段就先追问，不要猜值。

**追问接法：**

Prompt 不能代替程序校验。模型输出进入 Python 工具前，还要做 JSON 解析、类型检查、白名单校验和权限确认。

### 35. `userTicket`、`schoolID`、`businessBaseUrl` 分别是什么？

**先背一句：**

可以分别理解为用户会话凭证、学校数据上下文和业务接口地址配置，用来让同一个 AI 应用知道“谁在什么学校调用哪套业务接口”。

**再补两句：**

这些参数通过 PC 端和小程序端的入口传入，再由应用层或后端安全地转发。不同环境、不同学校和不同终端可以使用不同的打开策略。

**追问接法：**

真正的密钥不能放在前端或 Prompt 里长期暴露；参数必须有签名、过期时间和服务端权限校验。

### 36. AI 业务链路是怎样的？

**先背一句：**

用户提问 -> 模型识别意图 -> Python 工具解析参数 -> 字段和权限校验 -> 调业务接口 -> 把结果整理后返回给用户。

**再补两句：**

如果字段不全，先通过多轮会话补齐；如果接口失败，返回可理解的错误；如果是查询结果，再按前端需要的结构展示，而不是直接把原始 JSON 全部丢给用户。

**追问接法：**

我会把每一环的输入和输出记录清楚，这样模型理解问题、工具解析、接口返回和前端展示任何一环出错都能定位。

### 37. 如何防止 AI “胡说”或越权？

**先背一句：**

让模型只负责理解和组织语言，所有真实数据和写操作都必须经过后端接口、字段校验和权限校验。

**再补两句：**

知识库限定可检索内容；工具使用白名单接口；必填参数缺失时追问；接口返回为空或失败时明确告知，不用模型自行补数据。高风险操作可以增加确认步骤。

**追问接法：**

日志里要能关联用户、学校、会话和接口调用，但要脱敏 token、手机号等敏感信息。

## 七、Vue 3、状态管理与工程基础

### 38. Vue 3 的 Composition API 解决什么问题？

**先背一句：**

Composition API 让同一业务逻辑可以集中组织和复用，复杂页面比按 `data`、`methods` 分散更容易维护。

**再补两句：**

我会用 `ref` 管简单值，用 `reactive` 管对象，用 `computed` 表示派生值，用 `watch` 处理需要监听的副作用。请求、权限和页面交互要按职责拆开。

**追问接法：**

`computed` 适合有缓存的派生结果，`watch` 适合异步请求、日志或需要副作用的变化，不能看到数据变化就全部用 `watch`。

### 39. `ref` 和 `reactive` 怎么选？

**先背一句：**

单个值或需要整体替换的状态优先 `ref`，对象内部字段很多且不需要整体替换时可以用 `reactive`。

**再补两句：**

`ref` 在脚本中通过 `.value` 访问，模板会自动解包；解构 `reactive` 对象可能丢失响应式，所以需要时使用 `toRefs` 或保留对象引用。

### 40. Pinia 和 Vuex 有什么区别？

**先背一句：**

两者都是全局状态管理，Pinia API 更简洁、对 TypeScript 和组合式写法更友好，Vuex 是项目中已有的成熟方案。

**再补两句：**

简历里的 PC 项目使用 Vuex，移动端使用 Pinia，我会按项目现有架构来用，不为了追新技术强行替换。全局状态只放跨页面共享且有明确生命周期的数据。

**追问接法：**

表单临时值和单页面弹窗状态不必放全局，否则状态来源不清、退出清理也更复杂。

### 41. Vue Router 导航守卫做什么？

**先背一句：**

导航守卫在路由进入前检查登录、权限、路由是否已加载和必要的重定向。

**再补两句：**

我会先放行公开路由，再判断会话；动态路由未注入时先加载菜单，完成后重新进入目标地址；权限不足进入 403，未知地址进入 404。

**追问接法：**

守卫里要避免重复 `next` 或重复跳转，也要避免每次切换页面都重复请求菜单。

### 42. Axios 和 `fetch` 怎么选？

**先背一句：**

项目已经使用 Axios 时，我会利用它的实例、拦截器、超时和取消能力统一治理请求；`fetch` 更原生，但需要自己补齐这些约定。

**再补两句：**

选择重点不是库名，而是请求格式、错误处理、取消、重试和登录失效是否统一。SSE 流式场景还要确认客户端对流的支持，不能只看普通 JSON 请求能否发送。

### 43. 你如何理解前端性能优化？

**先背一句：**

先找到真实瓶颈，再做优化；常见方向是减少重复请求和渲染、合理缓存、按需加载和控制大列表。

**再补两句：**

动态路由项目可以按菜单或页面懒加载，列表用分页和虚拟滚动的合适方案，图片和大资源按需加载。优化前后要用网络面板、性能面板或日志验证，不能只凭感觉。

**追问接法：**

如果是设备端，我会优先保证长期运行、内存释放和失败恢复；如果是 PC 中后台，我会优先保证首屏、表格交互和重复请求控制。

### 44. 常见前端问题你如何排查？

**先背一句：**

先稳定复现，再按页面、请求、数据、权限、平台和版本逐层缩小范围。

**再补两句：**

我会记录复现步骤、设备和浏览器、接口状态码、请求参数、响应内容和控制台错误；修复后补同路径回归，确认没有把一个问题换成另一个问题。

## 八、后端与接口协作

### 45. 你了解 Node.js、Express 和 FastAPI 到什么程度？

**先背一句：**

我能读懂并配合 Node.js/Express、Python/FastAPI 的接口开发，理解路由、参数校验、鉴权、错误处理和前后端联调流程。

**再补两句：**

我的主职责仍是前端，但遇到接口问题可以从请求方法、参数、响应结构、状态码和服务日志入手定位，并和后端确认修复边界。

**追问接法：**

如果让我独立写复杂后端服务，我会先明确接口契约、数据模型、鉴权和测试范围，再逐步实现，不会把“会联调”夸大成“后端专家”。

### 46. MySQL 和 MongoDB 怎么理解？

**先背一句：**

MySQL 更适合结构明确、关联和事务要求强的数据；MongoDB 以文档形式存储，字段更灵活，适合配置或结构变化较快的数据。

**再补两句：**

前端不应依赖数据库细节，而应依赖稳定的 API。接口字段变化时，优先通过适配层和版本兼容保护页面，避免把数据库字段直接散落在组件里。

### 47. 你如何和后端约定接口？

**先背一句：**

先约定请求方法、路径、参数类型、成功结构、错误码、分页、鉴权和空数据，再开始联调。

**再补两句：**

对动态表单、SSE 和 WebSocket 这类协议，我会额外确认字段字典、事件边界、结束标志、重试和幂等规则，并保留一份可复现的样例数据。

### 48. 你如何保证前端提交不会重复？

**先背一句：**

提交按钮在请求中禁用，前端生成或携带业务幂等标识，后端再做最终幂等控制。

**再补两句：**

网络超时不代表服务端没收到，所以不能简单点击重试；要根据接口是否支持幂等键、查询结果或状态确认来决定下一步。

### 57. JavaScript、ES6+、HTML5、CSS3、SCSS 分别用在哪里？

**先背一句：**

JavaScript 负责交互和业务逻辑，ES6+ 提供模块化和异步写法，HTML5 负责页面结构，CSS3 和 SCSS 负责布局与样式组织。

在项目中我会用 `let/const`、箭头函数、解构、Promise、async/await 和模块导入组织代码；用 Flex、Grid、媒体查询和 CSS 变量处理响应式布局；SCSS 用于变量、嵌套和公共样式复用。表单、列表、弹窗、加载、空状态和错误状态都由 JS 驱动。

**追问接法：**

我不会为了“用了 ES6”而堆语法，重点是代码可读、异步错误可处理、样式不污染其他页面，并根据项目构建工具确认浏览器兼容范围。

### 58. 你如何完成组件化页面开发？

**先背一句：**

我会把页面拆成布局、业务区块和可复用组件，组件通过 props 接收数据，通过 emit 或回调通知父组件，页面负责组合业务流程。

**再补两句：**

例如表格筛选、上传、选人、任务中心、消息列表和动态表单都有独立状态，适合单独封装；页面只保留查询条件、提交动作和页面级状态。组件还要处理加载、空数据、错误、禁用和权限状态。

**追问接法：**

组件边界要稳定。如果两个页面只是偶然长得像、业务规则却不同，我会先复用基础组件，不强行抽成一个巨大业务组件。

### 59. 你如何处理接口联调和常见问题排查？

**先背一句：**

联调时先确认接口契约，再用浏览器网络面板对照请求、响应、状态码和页面状态逐层排查。

**再补两句：**

我会核对请求方法、路径、请求头、token、schoolID、参数类型、分页字段和错误码；遇到问题会保存复现步骤和样例数据，区分是前端组装错误、跨域、后端异常、权限不足还是平台 API 限制。

**追问接法：**

不要只说“接口有问题”。我会把最小复现请求、响应内容和服务端日志时间点交给后端，确认修复后再做同路径回归。

**先背一句：**

我做过表单校验、列表筛选、分页、弹窗、上传、扫码、消息未读、审批动作和流式文本展示等交互。

**再补两句：**

交互设计会覆盖进行中、成功、失败、空数据和重复点击等状态。例如提交时禁用按钮并显示 loading，接口失败给出下一步动作，流式回答结束后恢复输入，设备断网时显示缓存或重试。

### 61. PC 后台如何支持多学校、多角色和多平台交付？

同一套代码通过 `schoolID`、后端菜单、角色权限和配置数据表达学校与身份差异，平台登录则通过适配层接入。

**追问接法：**

**先背一句：**

**再补两句：**

**再补两句：**

公共模块统一处理参数、错误和状态，业务页面通过配置传入字段和回调。这样新业务主要关注自己的接口和展示，减少复制粘贴，也方便统一修复问题。

### 64. 移动端如何处理老师、学生、家长等多身份？

**先背一句：**

先区分登录平台，再区分业务身份；用户身份、业务身份、家长信息和 token 分开保存，切换时整体清理旧会话。

**再补两句：**

同一用户可能以家长身份查看孩子信息，也可能以教师或学生身份进入业务。页面不要只判断一个 `isLogin`，还要确认当前身份是否有权访问当前模块，并在切换身份后刷新菜单、数据和实时订阅。

**追问接法：**

身份选择只是前端体验，后端仍需根据 token 和业务关系校验是否能查看对应学生或执行对应动作。

### 65. 移动端的双 token、历史接口兼容和登录失效怎么处理？

**先背一句：**

双 token 要明确用途和发送位置；历史接口通过适配层兼容字段；登录失效统一清理并回到可恢复的登录态。

**再补两句：**

请求层在会话 ready 后注入 Authorization、schoolID 和身份 token；旧接口如果字段名或返回结构不同，在请求/响应适配层转换，不让页面到处写兼容判断。失效时停止重试、清理缓存和 WebSocket，再跳转登录。

**先背一句：**

在线文档、签名和审批都属于“先准备数据，再提交动作，再等待结果”的流程，页面要明确每一步状态。

**再补两句：**

打开文档前确认权限和资源地址，签名要处理签名开始、完成、取消和失败，审批要根据后端返回的可执行动作展示同意、驳回或转交。动作提交中要防重复点击，成功后刷新详情和消息未读数。

**追问接法：**

签名图片或文件不能只放本地就算完成，最终是否有效由后端保存、校验和审计。

**先背一句：**

未知字段类型不能让页面崩溃，应该降级为不可用提示并记录配置问题；后端也要校验字段白名单。

## 十四、面试官可能连续追问的完整示范

### 81. 从“动态路由”一路追问到“安全”，你怎么连续回答？

**第一问：动态路由是什么？**

登录后根据后端菜单和角色权限生成当前用户的前端路由。

**第二问：前端隐藏菜单是不是安全？**

不是。前端只负责展示和导航，后端接口必须再次校验 token、角色、学校和业务权限。

**第三问：刷新页面会不会丢路由？**

会先恢复会话并重新获取菜单，完成路由注入后再进入目标地址，同时延后 404 兜底，避免误判。

**第四问：多个请求同时发现 token 过期怎么办？**

用统一失效处理状态或刷新队列，避免重复跳转；没有 refresh token 时清理会话并重新登录。

### 82. 从“SSE”一路追问到“异常”，你怎么连续回答？

**第一问：SSE 是什么？**

基于 HTTP 的服务端单向事件流，适合 AI 连续返回文本。

**第二问：一段 chunk 是一条消息吗？**

不一定，要缓存片段，按协议边界拼接后解析。

**第三问：网络断了怎么办？**

先展示已收到的内容和可重试状态，是否续传要看服务端是否支持事件 ID；不能假设重连后一定不丢内容。

**第四问：小程序不能流式读取怎么办？**

按平台能力改用 WebSocket 或后端转发协议，先保证协议与客户端能力匹配。

### 83. 从“AI”一路追问到“越权”，你怎么连续回答？

**第一问：模型怎么调用业务？**

模型识别意图，工具解析参数，后端接口执行真实业务。

**第二问：模型说自己审批成功了怎么办？**

以业务接口真实返回为准，模型文本不能作为事实证明。

**第三问：怎么防止越权？**

工具白名单、后端鉴权、学校和用户上下文校验、必填字段校验，高风险写操作增加确认。

**第四问：会话中“把刚才的时间改成下午”怎么处理？**

从会话状态取当前草稿和当前业务，把“下午”解析成待修改字段，修改后重新校验，不直接提交。

## 十六、简历细节补漏题

### 84. 动态路由中的面包屑怎么生成？

**先背一句：**

面包屑根据当前路由匹配到的父子菜单链生成，显示用户当前所在层级，并支持返回可访问的上级页面。

**再补两句：**

动态菜单注入时保留菜单标题、路径、父级关系和隐藏状态，进入页面后从当前路由向上找到完整链路。无页面的菜单分组只用于展示层级，跳转时还要检查该节点是否真的有可访问路径。

### 85. HTTP 状态码正常，但业务码失败怎么办？

**先背一句：**

HTTP 200 只表示请求成功到达并得到响应，业务是否成功还要看后端约定的 `code`、`success` 或错误字段。

**再补两句：**

响应拦截器统一识别登录失效等公共业务码，页面再处理余额不足、状态不可操作等具体业务错误。不能把所有非成功业务码都弹同一个“系统错误”。

### 86. 统一扫码如何复用到会议签到、课堂签到、进出校和 PC 登录？

**先背一句：**

扫码公共层只负责调起平台扫码并返回标准结果，业务层再根据二维码类型进入会议、课堂、进出校或 PC 登录流程。

**再补两句：**

标准结果可以包含二维码内容、平台、扫码时间和取消状态；业务层解析场景码并调用对应接口。PC 登录还要校验一次性票据和确认状态，签到类还要校验用户、时间和场景权限。

**追问接法：**

二维码内容不能被前端直接当成可信指令，服务端必须校验签名、有效期、使用次数和用户权限。

### 87. 什么是签名请求？它和登录 token 有什么不同？

**先背一句：**

token 主要证明用户或设备身份，签名请求通常还会对时间戳、随机数和请求内容计算摘要，用来防止参数被篡改或请求被重放。

**再补两句：**

固定终端发请求时按后端约定拼接参数并生成签名，同时携带时间戳和设备标识。签名算法和密钥管理应由服务端协议决定，前端只按约定接入，不能把生产密钥硬编码在公开代码里。

### 88. AI 回答为什么需要富文本展示？如何保证安全？

**先背一句：**

AI 回答可能包含标题、列表、代码或链接，所以需要富文本或 Markdown 渲染；渲染前必须过滤危险 HTML 和不可信链接。

**再补两句：**

展示层先拼好完整或稳定的文本片段，再交给经过配置的 Markdown 渲染器。禁止直接用未经清洗的 `v-html` 展示模型输出，以免产生 XSS 风险。

### 89. Element Plus、uv-ui 和 SCUI 分别怎么用？

**先背一句：**

Element Plus 和 SCUI 主要用于 PC 中后台，uv-ui 主要用于 uni-app 移动端；我会在现有设计体系上组合业务页面，不重复造基础控件。

**再补两句：**

组件库解决表格、表单、弹窗、选择器和反馈等基础交互，业务代码负责权限、请求和数据转换。需要扩展时优先使用 props、插槽和主题变量，确实不满足再封装业务组件。

### 90. 什么是协议驱动的表单、附件、文档、签名和审批动作？

**先背一句：**

后端返回当前流程节点允许展示的内容和动作，前端按协议渲染并回传标准结果，而不是把每条流程写死在页面里。

**再补两句：**

协议通常描述字段、附件、文档地址、签名要求、按钮名称和下一步动作。前端需要校验协议、处理未知类型、限制重复提交，并在动作成功后刷新流程状态。

## 十七、JavaScript 高频基础题

### 91. `var`、`let`、`const` 有什么区别？

**先背一句：**

`var` 是函数作用域并存在变量提升，`let` 和 `const` 是块级作用域；`const` 不能重新赋值，但对象内部属性仍可以修改。

**再补两句：**

项目中默认使用 `const`，确实需要重新赋值再用 `let`，避免使用 `var` 带来的作用域和重复声明问题。

### 92. 箭头函数和普通函数有什么区别？

**先背一句：**

箭头函数没有自己的 `this`，它继承外层作用域的 `this`；普通函数的 `this` 由调用方式决定。

**再补两句：**

箭头函数适合回调和不依赖动态 `this` 的逻辑，不能作为构造函数。需要事件对象时仍从参数接收，不要依赖隐式全局变量。

### 93. Promise 和 async/await 是什么关系？

**先背一句：**

async/await 是基于 Promise 的更直观异步写法，`await` 等待 Promise 完成，但仍要用 `try/catch` 处理失败。

**再补两句：**

多个互不依赖的请求可用 `Promise.all` 并行，前后依赖的请求再顺序 `await`。无论成功失败，都要在 `finally` 里恢复 loading 等页面状态。

### 94. 什么是事件循环？

**先背一句：**

JavaScript 主线程先执行同步任务，再处理微任务，最后进入下一轮宏任务；Promise 回调通常属于微任务，定时器属于宏任务。

**再补两句：**

这能解释为什么 `Promise.then` 往往比 `setTimeout(..., 0)` 先执行。项目中更重要的是避免长时间同步计算阻塞页面，以及理解异步状态回写的先后顺序。

### 95. 防抖和节流有什么区别？

**先背一句：**

防抖是在连续触发结束后只执行一次，节流是在一段时间内最多执行一次。

**再补两句：**

搜索输入适合防抖，滚动、拖拽或高频上报适合节流。提交按钮不能只靠防抖，还应在请求中禁用并由后端保证幂等。

### 96. 浅拷贝和深拷贝有什么区别？

**先背一句：**

浅拷贝只复制第一层，嵌套对象仍共享引用；深拷贝递归复制嵌套数据。

**再补两句：**

扩展运算符只做浅拷贝；`structuredClone` 能处理多种结构，但函数等类型不支持。JSON 序列化会丢失 `undefined`、函数和特殊对象，不能无条件当万能深拷贝。

### 97. `==` 和 `===` 有什么区别？

**先背一句：**

`==` 会做类型转换，`===` 同时比较类型和值，项目中通常优先使用 `===`。

### 98. `null` 和 `undefined` 有什么区别？

**先背一句：**

`undefined` 常表示未赋值或不存在，`null` 常表示主动设置为空；接口契约中要统一两者语义。

### 99. 如何判断数组和对象？

**先背一句：**

数组使用 `Array.isArray(value)`，普通对象还要排除 `null` 和数组，不能只用 `typeof` 判断数组。

### 100. 本地存储有哪些选择？

**先背一句：**

浏览器常用 `localStorage`、`sessionStorage`、Cookie 和 IndexedDB；uni-app 使用统一存储 API，再由平台实现底层存储。

**再补两句：**

长期配置可放 localStorage，标签页会话可用 sessionStorage，Cookie 常参与服务端会话，较大结构化数据可用 IndexedDB。敏感 token 的存储方式要结合 XSS、Cookie 属性和后端认证方案决定。

## 十八、Vue 高频基础题

### 101. Vue 3 响应式原理是什么？

**先背一句：**

Vue 3 主要通过 Proxy 代理对象，在读取时收集依赖，在修改时触发相关更新。

**再补两句：**

模板渲染、computed 和 watch 都建立在依赖追踪上。不是任何普通变量变化都会更新页面，必须让它进入 Vue 响应式系统。

### 102. `computed`、`watch`、`watchEffect` 怎么选？

**先背一句：**

`computed` 用于派生值，`watch` 明确监听某个来源并执行副作用，`watchEffect` 自动收集回调中使用的响应式依赖。

**再补两句：**

金额合计适合 computed，筛选条件变化后请求列表适合 watch，依赖很多且关系简单的同步副作用可以考虑 watchEffect。异步请求还要处理竞态和组件卸载。

### 103. `v-if` 和 `v-show` 有什么区别？

**先背一句：**

`v-if` 会真正创建和销毁节点，`v-show` 只切换 CSS 显示；很少变化用 `v-if`，频繁切换可考虑 `v-show`。

### 104. `v-for` 为什么要加 `key`？

**先背一句：**

`key` 帮助 Vue 稳定识别每个节点，列表更新时能正确复用和移动 DOM，避免状态错位。

**再补两句：**

优先使用业务唯一 ID，不要在可增删排序的列表中随意用数组下标，否则输入框、组件状态和动画可能对应错行。

### 105. Vue 生命周期怎么讲？

**先背一句：**

常用阶段是创建并执行 `setup`、挂载、更新和卸载，对应的组合式钩子包括 `onMounted`、`onUpdated` 和 `onUnmounted`。

**再补两句：**

页面初始化请求常放在 mounted 或路由进入逻辑中，事件监听、定时器、订阅和 WebSocket 要在卸载时清理。uni-app 还有 `onLoad`、`onShow`、`onHide` 等页面生命周期，不能完全照搬 Web 页面。

### 106. 父子组件如何通信？

**先背一句：**

父传子用 props，子通知父用 emit，跨多层可用 provide/inject，跨页面共享状态可用 Pinia 或 Vuex。

**再补两句：**

不要为了少写一个事件就直接修改 prop；全局状态也不应替代所有组件通信，先选最小范围的方式。

### 107. `nextTick` 有什么作用？

**先背一句：**

响应式数据修改后，Vue 会批量更新 DOM，`nextTick` 用于等待这次 DOM 更新完成后再读取或操作页面元素。

### 108. 什么是路由懒加载？

**先背一句：**

路由懒加载让页面组件在访问时才下载，减少首屏一次加载的代码量。

**再补两句：**

动态路由映射组件时也可以保留动态 `import`。懒加载不是越碎越好，过多小文件会增加请求和管理成本，要结合打包结果判断。

## 十九、CSS、浏览器和网络高频题

### 109. Flex 和 Grid 怎么选？

**先背一句：**

Flex 更适合单行或单列的一维布局，Grid 更适合同时控制行和列的二维布局。

### 110. 如何做移动端适配？

**先背一句：**

使用弹性布局、相对单位、安全区和平台组件，并在不同屏幕和真机上检查文字、按钮、弹窗和滚动区域。

**再补两句：**

uni-app 中还要注意 `rpx`、状态栏、导航栏、小程序胶囊和 App 端差异。不能只看开发工具预览，关键流程需要真机验证。

### 111. 什么是 CSS 盒模型？

**先背一句：**

盒模型由 content、padding、border 和 margin 组成；使用 `box-sizing: border-box` 时声明宽高包含 padding 和 border。

### 112. 什么是 CSS 样式优先级？

**先背一句：**

通常行内样式高于 ID，高于类和属性选择器，高于标签；相同优先级时后写的生效，`!important` 要谨慎使用。

### 113. 什么是跨域？如何解决？

**先背一句：**

浏览器同源策略限制页面读取不同协议、域名或端口的响应，常用服务端 CORS、开发代理或同源网关解决。

**再补两句：**

跨域不是前端在请求头里随便加一个字段就能解决，服务端要返回正确的允许来源、方法和请求头；带 Cookie 时还要处理凭证和来源不能为通配符的问题。

### 114. HTTP 常见状态码有哪些？

**先背一句：**

200 成功，201 创建成功，204 成功但无响应体，400 参数错误，401 未认证，403 无权限，404 不存在，500 服务端错误。

**再补两句：**

接口还可能使用业务码表达更细的失败原因，前端要区分网络失败、HTTP 失败和业务失败。

### 115. GET 和 POST 有什么区别？

**先背一句：**

GET 通常用于读取资源，POST 通常用于创建或提交数据；是否安全和幂等由接口语义决定，不是只看参数放在哪里。

### 116. 什么是 XSS？如何防止？

**先背一句：**

XSS 是不可信内容被当成脚本执行，防护重点是输出转义、富文本白名单过滤、避免危险 `v-html` 和保护敏感凭证。

### 117. 什么是 CSRF？如何防止？

**先背一句：**

CSRF 利用浏览器自动携带身份凭证，诱导用户向已登录网站发请求；可用 SameSite Cookie、CSRF Token 和来源校验防护。

### 118. 页面请求发生竞态怎么办？

**先背一句：**

给每次请求建立标识或取消旧请求，只接受最新一次结果，避免慢的旧请求覆盖快的新请求。

**再补两句：**

搜索、身份切换和路由切换都容易出现竞态。组件卸载后也要阻止旧请求继续回写已经销毁的页面状态。
