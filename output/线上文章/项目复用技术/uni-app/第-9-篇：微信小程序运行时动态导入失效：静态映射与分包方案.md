# 第 9 篇：微信小程序运行时动态导入失效：静态映射与分包方案

## 1. 适用问题

代码在 H5 中使用 `import()` 正常，但编译到微信小程序后出现以下现象：

- Promise 不执行或结果为 `undefined`。
- 真机报模块不存在、模块未定义或加载失败。
- 开发者工具偶尔可用，真机不可用。
- 使用变量拼接模块路径后，目标文件没有进入构建产物。

## 2. 先区分三种 import

### 静态导入

```javascript
import recorder from './recorder'
```

静态导入在编译期可被分析。uni-app 构建器可以把它转换成小程序支持的模块形式，通常最稳定。

### 运行时动态导入

```javascript
const module = await import('./recorder')
```

它要求运行时支持 ESM loader 和代码分块映射。H5/Vite 通常支持，但小程序逻辑层不是标准浏览器 ESM 运行时，构建结果和分包边界也会限制它。

### JSDoc 类型导入

```javascript
/** @type {import('vue').Ref<string>} */
const value = ref('')
```

这只是编辑器类型提示，不会在运行时加载模块。排查动态导入时不要误删这类注释。

## 3. 最稳定方案：静态导入

如果模块体积不大或页面必然使用，直接静态导入：

```javascript
import RecorderFactory from './recorder'

export function createRecorder(options) {
  return RecorderFactory(options)
}
```

这是默认首选。不要为了“看起来按需”而引入运行时不确定性。

## 4. 同包兼容方案：显式 require

目标模块位于主包或当前分包，且构建器能静态看到路径时，可以使用：

```javascript
function loadRecorder() {
  const imported = require('./recorder')
  return imported.default || imported.Recorder || imported
}

export async function createRecorder(options) {
  const Recorder = loadRecorder()
  return Recorder(options)
}
```

兼容 `default`、命名导出和 CommonJS 直接导出，是因为不同构建链对模块包装方式可能不同。

不要写：

```javascript
const moduleName = 'recorder'
const imported = require(`./${moduleName}`)
```

变量路径可能无法被构建器静态收集，目标文件不会进入产物。

## 5. 多模块按需选择：静态映射

如果业务需要按类型选择模块，使用显式映射，确保每个依赖都能被构建器发现：

```javascript
const moduleLoaders = {
  mp3: () => require('./recorder-mp3'),
  wav: () => require('./recorder-wav'),
  pcm: () => require('./recorder-pcm')
}

export function loadRecorder(type) {
  const loader = moduleLoaders[type]
  if (!loader) {
    throw new Error(`不支持的录音类型: ${type}`)
  }

  const imported = loader()
  return imported.default || imported.Recorder || imported
}
```

这不是网络级按需下载，但可以解决动态路径不可分析的问题。

## 6. H5 与小程序确实需要不同加载方式

使用条件编译让 H5 保留动态导入，小程序使用静态可分析的加载：

```javascript
export async function loadHeavyModule() {
  let imported

  // #ifdef H5
  imported = await import('./heavy-module')
  // #endif

  // #ifndef H5
  imported = require('./heavy-module')
  // #endif

  return imported.default || imported
}
```

条件编译块中不要再使用运行时变量拼路径。

## 7. 跨分包加载

跨分包不能按普通同包 `require` 理解。需要先完成：

1. 在页面配置中正确拆分主包和分包。
2. 检查公共模块是否应该上移到主包。
3. 确认目标微信基础库支持分包异步化。
4. 根据微信当前文档使用异步 `require` 或分包异步化配置。
5. 对不支持的基础库提供禁用或降级方案。

不要把分包 A 的业务文件直接作为分包 B 的普通依赖。真正跨业务复用的模块应进入公共层；只在某个分包使用的大模块留在该分包。

异步加载前做能力检测：

```javascript
export function loadPackageModule(modulePath) {
  return new Promise((resolve, reject) => {
    if (typeof require === 'undefined' || typeof require.async !== 'function') {
      reject(new Error('当前运行环境不支持异步模块加载'))
      return
    }

    require.async(modulePath)
      .then((imported) => resolve(imported.default || imported))
      .catch(reject)
  })
}
```

异步 `require` 的具体签名可能随微信基础库和构建产物变化，实施前必须核对当前官方文档，不能只根据旧项目代码判断。

## 8. AI 修改步骤

1. 全局搜索真正的运行时 `import(`，排除 JSDoc 类型表达式。
2. 判断目标模块是在主包、当前分包还是其他分包。
3. 判断是否真的需要网络级按需下载。
4. 同包优先改静态导入或显式 `require`。
5. 多模块选择改成静态 loader 映射。
6. 跨分包先调整归属，再评估异步化。
7. 检查模块的 `default` / 命名导出兼容。
8. 编译后确认目标文件确实进入产物。

## 9. 验证清单

- [ ] H5 首次进入、重复进入都能加载模块。
- [ ] 微信开发者工具清缓存重新编译后可用。
- [ ] 微信真机首次进入目标分包可用。
- [ ] 弱网下异步分包有加载态和失败提示。
- [ ] 不支持异步加载的基础库走降级逻辑。
- [ ] 构建产物不存在遗漏模块或重复打包异常。
- [ ] 模块导出兼容代码不会把合法的函数误当成对象。

## 10. 记忆结论

> 微信小程序中不要把浏览器的运行时 `import()` 当成可靠能力。能静态导入就静态导入；需要选择模块时使用显式映射；真正跨分包按需下载时，按当前微信基础库的分包异步化能力设计，并做真机验证。
