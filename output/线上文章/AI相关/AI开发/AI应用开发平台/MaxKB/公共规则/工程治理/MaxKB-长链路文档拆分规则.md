# MaxKB 长链路文档拆分规则

> 文档状态（2026-07-02）：用于约束 MaxKB 功能智能体的阶段文档组织方式，避免把工具代码、节点配置、提示词、调试记录和进度流水账全部塞进一个超长文档。

## 1. 核心结论

MaxKB 功能智能体文档按“入口导航 + 分链路文档 + 调试记录”拆分。

```text
README.md 只放目标、当前状态、文档导航和下一步。
节点链路文档只记录一段可执行链路。
工具代码单独成文。
AI 提示词单独成文或放在对应链路文档中。
调试过程单独成文，不混进稳定搭建手册。
```

## 2. 必须拆文档的条件

满足任意一条，就不要继续往同一个文档追加：

```text
1. 单文档超过 600 行。
2. 单文档包含超过 8 个 MaxKB 节点的逐节点配置。
3. 单文档同时包含 2 个及以上 Python 工具完整代码。
4. 单文档同时包含“工具代码 + 画布节点 + AI 提示词 + 调试记录”四类内容。
5. 一段链路已经跑通，后续开始新分支或新能力，例如从“列表查询”进入“详情查询”。
6. 文档需要频繁给用户按步骤执行，且用户已经反馈内容过长、不知道当前该改哪里。
```

## 3. 推荐目录结构

以某个阶段目录为例：

```text
01-待办列表与详情首批接口/
  README.md
  01-阶段目标与当前状态.md
  02-后端首批接口说明.md
  03-工具代码/
    README.md
    01-获取工作流任务列表.md
    02-解析任务候选编号.md
    03-获取工作流任务详情.md
  04-画布搭建/
    README.md
    01-入口与意图识别.md
    02-待办列表查询链路.md
    03-编号选择链路.md
    04-任务详情查询链路.md
    05-AI整理回复节点.md
  05-联调记录/
    README.md
    2026-07-02-列表与详情联调记录.md
  99-归档/
    旧版长文档.md
```

已有阶段如果已经存在超长文档，先不要强行拆迁正在使用的入口。
推荐先新增分文档，稳定后再把旧长文档移入 `99-归档/` 或标注“旧版入口”。

## 4. 单篇文档职责

| 文档类型 | 只写什么 | 不写什么 |
| --- | --- | --- |
| 阶段 README | 当前状态、已完成、下一步、文档导航 | 完整工具代码、完整节点配置 |
| 工具代码文档 | 工具入参、输出、完整 Python 代码、校验方式 | 画布接线全过程 |
| 画布链路文档 | 节点顺序、每个节点配置、变量绑定、返回内容开关 | 多个工具完整代码 |
| AI 提示词文档 | 系统提示词、用户提示词、变量模板、输出示例 | Python 工具代码 |
| 联调记录 | 问题现象、截图结论、修复动作、验证结果 | 稳定搭建教程正文 |
| 归档文档 | 旧方案、旧长文档、历史快照 | 当前必须执行的最新步骤 |

## 5. 节点数量拆分规则

一个画布链路文档建议控制在 4 到 8 个节点。

```text
入口与意图识别：开始、状态判断、意图识别、兜底回复。
列表查询链路：设置查询模式、获取列表、拆分列表、判断列表、保存候选、AI 整理列表、回复列表。
编号选择链路：解析编号、拆分编号结果、判断编号结果、保存选中任务、编号无效回复。
详情查询链路：获取详情、拆分详情、判断详情、保存详情、AI 整理详情、回复详情。
```

超过 8 个节点时，优先按业务闭环拆，不按组件类型硬拆。

## 6. 文档更新节奏

后续和用户一起搭 MaxKB 画布时，按下面节奏执行：

```text
1. 先口头教用户当前 1 到 3 个节点怎么配置。
2. 用户确认跑通后，再同步到对应分文档。
3. 不要在用户调试过程中连续大改文档结构。
4. 如果发现公共规则错误，先修公共规则，再回到当前阶段文档。
5. 文档里同时保留“选择器显示项”和“真实模板变量”，不要混用。
```

## 7. AI 对话节点提示词特殊规则

AI 对话节点提示词一旦超过 80 行，必须单独成文或放入独立小节。

提示词文档必须同时写：

```text
节点名称
返回内容开关
输出思考开关
系统提示词
用户提示词
提示词里的真实变量模板
指定回复如何引用 answer
最小测试输入和期望输出
```

变量模板必须写真实可运行形式：

```text
{{global.userTicket}}
{{chat.isSelectingTask}}
{{开始.question}}
{{拆分任务列表结果.taskItems}}
```

不要写：

```text
{{会话变量 > 是否正在选择任务 {isSelectingTask}}}
```
