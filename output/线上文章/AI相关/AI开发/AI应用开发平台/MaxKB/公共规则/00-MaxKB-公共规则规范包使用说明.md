# 00-MaxKB 公共规则规范包使用说明

> 文档状态（2026-07-19）：本文是 `02-公共规则/` 的跨项目使用入口。目标是把本目录整理成可复制、可检索、可复用的 MaxKB 规范包，供其他项目的 AI 或开发者快速理解 MaxKB 节点创建、参数传递、变量引用、工具绑定和前端接入规则。
>
> 公司已部署环境下首次开发新项目时，先读 [`../01-实战开发指南/README.md`](../01-实战开发指南/README.md)。本规范包负责配置细节，不替代版本、权限、依赖、安全和发布流程判断。

## 1. 规范包定位

本目录优先沉淀这些内容：

```text
MaxKB 节点真实配置项
接口传参和会话变量边界
变量引用写法
判断器、变量拆分、变量赋值、工具节点等节点规则
跨环境导入的参数治理方法
发布网址和原生 API 接入边界
长链路文档拆分和阶段演进规则
```

本目录不应长期沉淀这些内容：

```text
某个项目的真实后端接口路径
某个项目的字段协议和表单编码
某个学校、租户、环境地址、内网 IP、测试账号
某个功能智能体的完整推进流水账
某次联调截图、导出画布节点清单、临时排查记录
```

如果公共规则里必须举例，应使用“可替换示例”，并明确说明哪些字段需要按实际项目替换。

## 2. AI 使用顺序

其他项目接入本规范包时，AI 必须按这个顺序阅读：

```text
1. 先读 ../01-实战开发指南/README.md，确认版本、版本类型、权限和责任边界。
2. 再读本文件，确认哪些内容可复用、哪些必须替换。
3. 再读 README.md，选择具体主题入口。
4. 如果是创建 MaxKB 节点，先读 02-节点创建手册/00-AI创建节点必读.md。
5. 再读对应节点文档，不要把别的节点字段套到当前节点。
6. 如果涉及业务接口、字段协议、用户身份、租户隔离，必须先读取目标项目自己的接口文档或代码，不允许把规范包示例字段当成目标项目真实字段。
```

AI 回答用户“怎么配置”时，必须区分：

```text
MaxKB 内置字段：文档中确认存在的配置项。
规范包示例字段：本目录用于说明方法的示例参数。
目标项目字段：必须来自目标项目文档、接口或代码。
```

没有在目标项目中确认的字段，不要直接说成“必须配置”。

## 3. 字段解释总原则

### 3.1 MaxKB 内置配置项

接口传参添加弹窗只讲下面字段：

```text
参数
描述
是否必填
默认值
```

会话变量添加弹窗只讲下面字段：

```text
参数
显示名称
```

不要给这两个弹窗补不存在的字段，例如：

```text
类型
组件类型
显示名称（接口传参没有）
默认值（会话变量没有）
是否必填（会话变量没有）
描述（会话变量没有）
```

### 3.2 规范包示例字段

本规范包里常见的下面 5 个字段，是规范包用于说明环境 / 用户参数分层的示例，不是 MaxKB 内置字段：

```text
businessBaseUrl
agentBaseUrl
schoolID
serviceSecret
userTicket
```

跨项目复用时必须先做字段映射：

| 示例字段 | 通用含义 | 其他项目如何处理 |
| --- | --- | --- |
| `businessBaseUrl` | 业务后端根地址 | 如果项目没有业务后端调用，可删除；如果叫 `apiBaseUrl`，按目标项目统一命名 |
| `agentBaseUrl` | 智能体服务根地址 | 只有需要从智能体侧下载文件或访问 MaxKB 资源时才保留 |
| `schoolID` | 学校 / 租户 / 组织隔离标识 | 其他项目可能是 `tenantId`、`orgId`、`corpId`；不要照搬字段名 |
| `serviceSecret` | 服务端调用校验值 | 只有后端启用内部校验时才保留；不要放在发布 URL |
| `userTicket` | 当前用户登录态 | 可替换为目标项目真实登录凭证字段，例如 `accessToken`、`sessionToken` |

字段名一旦确定，应在开始节点接口传参、工具输入参数、前端拼参或原生 API `form_data` 中保持一致。

## 4. 公共规则和项目案例的边界

下面内容可以留在公共规则：

```text
如何创建接口传参
如何绑定全局变量
工具输入参数为什么不要写死环境值
serviceSecret 为空时不要传空请求头
userTicket 缺失时应提前返回错误
URL 参数需要覆盖旧值并编码
```

下面内容应放到具体功能智能体目录：

```text
`/your/business/api/path` 这类真实接口路径
`{attachmentId}::{url}::{fileName}` 这类项目附件协议
`field123` 这类真实字段编码
`流程 A`、`业务事项 B` 这类真实流程名
某个业务状态码后怎么接目标项目的下一步接口
某次导出画布里有多少节点、多少工具、哪些复制节点未核对
```

这类案例应统一归档到目标项目自己的功能智能体、业务专题或项目进度目录，不放在规范包里。

当前规范包成员：

| 文档 | 当前定位 | 跨项目复用方式 |

| `03-工程治理/02-长链路文档拆分规则.md` | 长链路文档治理 | 可复制；示例目录按项目调整 |

## 6. 迁移规则

当发现公共规则文档里出现强项目化内容时，按下面方式处理：

```text
1. 保留可复用结论，例如“工具入参绑定接口传参，不写死启动参数”。
2. 把真实接口路径、字段协议、流程名、环境值迁移到对应功能智能体阶段目录。
3. 在公共规则里改成占位示例，例如 /your/api/path、tenantId、业务附件协议。
4. 如果项目案例仍有参考价值，只在目标项目自己的索引中记录，不放入跨项目规范包。
```

## 7. 跨项目复制前检查

复制本规范包到其他项目之前，至少检查：

```text
1. 目标项目是否真的使用 MaxKB 高级智能体。
2. 当前 MaxKB 版本是否有相同节点和配置项。
3. 业务登录凭证字段是什么。
4. 是否需要租户 / 学校 / 组织隔离字段。
5. 是否有后端内部校验密钥。
6. 是否需要业务后端根地址。
7. 是否需要智能体服务根地址。
8. 前端是发布网址嵌入、原生 API、自定义后端中转，还是三者组合。
9. 工具返回 JSON 字段是否来自真实接口，不要沿用示例字段。
10. 文档里的所有真实路径、真实流程名、真实字段编码是否已经替换。
```
