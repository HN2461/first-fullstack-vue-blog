# 02-跨环境参数配置清单

> 文档状态（2026-07-03）：本文是 MaxKB 智能体导出、复制或导入新环境时的通用参数治理模板。本文不记录单个项目的真实接口路径、字段编码或联调流水账。

## 1. 当前结论

跨服务器导入时，环境态配置优先放到：

```text
基本信息 -> 接口传参
```

接口传参添加弹窗只按下面字段配置：

```text
参数
描述
是否必填
默认值
```

不要给接口传参配置“显示名称”“类型”“组件类型”，MaxKB 这个弹窗没有这些字段。

## 2. 参数分层规则

### 2.1 环境态参数

环境态参数适合配置默认值，并在复制智能体到新环境时统一替换。

| 参数类型 | 示例字段 | 说明 |
| --- | --- | --- |
| 业务后端根地址 | `businessBaseUrl` / `apiBaseUrl` | 工具调用业务接口的根地址，不包含具体接口路径 |
| 智能体服务根地址 | `agentBaseUrl` | 需要下载 MaxKB 文件或访问智能体资源时使用 |
| 租户 / 组织标识 | `schoolID` / `tenantId` / `orgId` | 用于业务数据隔离；字段名必须按目标项目确定 |
| 服务调用校验值 | `serviceSecret` | 后端启用内部校验时使用；不要放发布 URL |

注意：

```text
businessBaseUrl、agentBaseUrl、schoolID、serviceSecret 是目标项目的示例命名。
其他项目必须先完成字段映射，不要照搬 schoolID 这类项目字段。
```

### 2.2 用户态参数

用户态参数不建议写默认值，应由前端发布 URL、后端中转或原生 API `form_data` 按当前登录用户动态传入。

| 参数类型 | 示例字段 | 说明 |
| --- | --- | --- |
| 当前用户票据 | `userTicket` / `accessToken` / `sessionToken` | 工具透传给业务后端，用于识别当前用户 |

规则：

```text
1. 用户态参数默认值留空。
2. 不要把真实用户票据写死在 MaxKB 默认值里。
3. 不要把服务端内部密钥和用户票据混成一个字段。
4. 如果项目改为后端中转，可由中转层注入用户态参数。
```

### 2.3 会话态参数

会话态参数随当前对话、当前流程或当前提交变化，不应做成固定接口传参默认值。

常见例子：

| 参数类型 | 示例字段 | 原因 |
| --- | --- | --- |
| 当前业务对象 ID | `flowDefineID` / `recordId` / `taskId` | 用户选择不同对象时会变化 |
| 表单草稿 | `submitFields` / `draftJson` | 每轮填写都会变化 |
| 幂等请求 ID | `clientRequestID` | 应按提交内容或动作生成 |
| 候选项列表 | `currentCandidatesJson` | 随业务接口返回变化 |
| 显式状态开关 | `isSelectingApprover` / `isEditingDraft` | 由变量赋值节点动态写入 |

会话变量创建时只填：

```text
参数
显示名称
```

不要给会话变量补写类型、默认值、必填或描述。

## 3. 推荐接口传参模板

如果项目需要“前端打开 MaxKB，MaxKB 工具再调用业务后端”，可以参考下面模板：

| 参数 | 描述 | 是否必填 | 默认值建议 |
| --- | --- | --- | --- |
| `businessBaseUrl` | 业务后端根地址，不包含具体接口路径 | 是 | 当前环境业务后端根地址 |
| `agentBaseUrl` | 智能体服务根地址 | 按需 | 当前 MaxKB / 智能体服务根地址 |
| `tenantId` | 租户、学校、组织或企业标识 | 按需 | 当前环境租户标识 |
| `serviceSecret` | 服务调用校验值 | 否 | 后端未启用时留空 |
| `userTicket` | 当前用户登录态 | 是 | 留空，由前端或中转层动态传入 |

如果沿用目标项目字段名，可以把 `tenantId` 映射为：

```text
schoolID
```

但其他项目不要在没有学校语义时继续使用 `schoolID`。

## 4. 工具节点绑定口径

工具节点不要依赖写死的启动参数，优先把动态值做成“输入参数 使用工具时显示”，再在智能体画布中绑定接口传参或会话变量。

常见绑定：

| 工具入参 | 推荐绑定来源 | 说明 |
| --- | --- | --- |
| `baseUrl` / `businessBaseUrl` | 全局变量 `businessBaseUrl` | 业务后端根地址 |
| `agentBaseUrl` | 全局变量 `agentBaseUrl` | 需要访问智能体资源时绑定 |
| `tenantId` / `schoolID` | 全局变量中的租户字段 | 按目标项目真实字段命名 |
| `serviceSecret` | 全局变量 `serviceSecret` | 空值时工具代码不传密钥请求头 |
| `userTicket` | 全局变量 `userTicket` | 当前用户票据 |
| 业务对象 ID | 上游节点输出或会话变量 | 不要做成固定默认值 |
| 提交字段数组 | 上游变量拆分 / 变量聚合结果 | 类型必须按工具要求配置 |

工具代码只拼接具体接口路径，不在代码里覆盖入参传来的根地址。

## 5. 工具代码统一要求

### 5.1 根地址处理

工具可以保留兜底值方便单独调试，但正式运行必须优先使用工具入参。

```python
base_url = (baseUrl or "").rstrip("/")
if not base_url:
    return {
        "success": False,
        "code": "MISSING_BASE_URL",
        "message": "baseUrl 不能为空，请检查接口传参默认值或工具入参绑定"
    }
```

如果确实要保留调试兜底，必须在注释中写清楚：

```python
# 仅用于工具单独调试；正式画布应由接口传参传入。
```

### 5.2 用户票据处理

工具必须先校验用户态参数：

```python
if not userTicket:
    return {
        "success": False,
        "code": "MISSING_USER_TICKET",
        "message": "userTicket 不能为空，请检查 MaxKB 接口传参或工具入参绑定"
    }
```

请求头名称由目标项目后端决定，不要跨项目照搬。

示例：

```python
headers = {"X-User-Ticket": userTicket}
```

其他项目可能是：

```python
headers = {"Authorization": "Bearer " + accessToken}
```

### 5.3 服务密钥处理

内部服务密钥必须空值跳过：

```python
if serviceSecret:
    headers["X-Service-Secret"] = serviceSecret
```

如果目标项目后端约定使用专用密钥请求头，只在目标项目工具代码中使用该请求头。其他项目应按自己的后端协议命名。

不要在 `serviceSecret` 为空时仍传空字符串请求头，避免后端启用校验后出现误判。

### 5.4 接口路径处理

根地址和接口路径分开维护：

```python
api_url = base_url + "/your/api/path"
```

不要把完整接口路径写进 `businessBaseUrl` 默认值，避免不同工具重复拼接时出错。

## 6. 导入新服务器后的最小回归

每次复制智能体或导入新服务器后，至少回归：

| 序号 | 回归项 | 预期 |
| --- | --- | --- |
| 1 | 环境参数读取 | 工具实际请求地址指向新环境根地址 |
| 2 | 用户态参数 | 当前用户票据能被业务后端识别 |
| 3 | 租户 / 组织隔离 | 查询和提交的数据属于当前租户或组织 |
| 4 | 服务密钥 | 密钥为空时不传请求头，密钥不为空时后端校验通过 |
| 5 | 业务对象选择 | 用户选择不同对象时不会复用旧 ID |
| 6 | 提交字段类型 | 数组、对象、字符串等类型保持工具要求 |
| 7 | 文件或附件 | 如有文件转存，访问的是新智能体服务根地址 |
| 8 | 失败提示 | 缺少关键参数时给出可排查的错误，不直出不可读 JSON |

## 7. 排查清单

### 7.1 仍然请求旧域名

优先检查：

```text
1. 工具节点的 baseUrl 是否绑定了接口传参。
2. 工具是否还保留并依赖旧启动参数。
3. 工具代码是否在有入参时仍覆盖成写死地址。
4. 是否有同名复制节点没有同步改。
```

### 7.2 用户身份不对

优先检查：

```text
1. 用户态参数默认值是否误写了某个测试用户票据。
2. 前端发布 URL 或原生 API form_data 是否传入当前用户票据。
3. 工具请求头名称是否符合目标项目后端协议。
4. 后端是否要求 Bearer 前缀，前端或工具是否重复添加。
```

### 7.3 租户或组织不对

优先检查：

```text
1. 租户字段是否来自接口传参默认值或用户票据解析。
2. 是否仍写死旧 schoolID / tenantId / orgId。
3. 目标项目是否已经能从用户票据解析租户；如果可以，评估是否移除工具侧租户字段。
```

### 7.4 文件仍然访问旧智能体地址

优先检查：

```text
1. 文件转存工具的 agentBaseUrl 是否绑定接口传参。
2. 是否还有自定义固定内网地址或旧域名。
3. 子智能体或复制工具是否也同步修改。
```

### 7.5 字段类型错误

如果工具报类型转换错误，优先检查：

```text
1. 工具输入参数类型是否被改成 string。
2. 上游变量拆分或变量聚合输出是否仍是 array / object。
3. 是否把 JSON 字符串当作数组传入。
4. 是否需要在工具代码中兼容字符串并解析 JSON。
```

## 8. 迁移提醒

跨项目复用本文时，只复制参数分层、绑定口径和排查方法。

真实链路、接口路径、附件字段协议、复制节点核对清单，应写到目标项目自己的进度目录或功能智能体目录中，不写回本规范包。
