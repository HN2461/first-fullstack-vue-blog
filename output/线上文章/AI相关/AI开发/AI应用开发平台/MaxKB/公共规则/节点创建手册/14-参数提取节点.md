# 14：参数提取节点
> 文档状态（2026-07-01）：根据空白高级智能体验证截图、MaxKB 官方文档和参数提取通用实践，记录参数提取节点配置、AI 提取参数能力和使用边界。

## 1. 节点定位

`参数提取` 属于添加组件面板中的：

```text
基础组件 -> 数据处理 -> 参数提取
```

官方节点说明：

```text
从非结构化文本或半结构化文本中提取结构化参数。
```

通用理解：

```text
参数提取是一个利用 AI 模型做字段抽取的节点。
它更适合处理用户自然语言、半结构化文本、文档片段，而不是已经稳定的 JSON。
```

和变量拆分的区别：

| 节点 | 适合输入 | 核心方式 | 典型用途 |
| --- | --- | --- | --- |
| 参数提取 | 自然语言、半结构化文本 | AI 理解并抽取字段 | 从用户一句话里提取请假时间、事由、金额、人员等 |
| 变量拆分 | 标准 JSON 对象或数组 | JSON Path 精确取值 | 从工具返回 JSON、表单 form_data 中拆字段 |

## 2. 节点初始配置

当前截图中，参数提取节点包含：

| 配置项 | 当前可见内容 | 说明 |
| --- | --- | --- |
| AI 模型 | 默认显示 `自定义`，下方选择 AI 模型 | 必填，用于执行参数抽取 |
| 输入变量 | 下拉选择变量 | 必填，选择要抽取参数的文本 |
| 提取参数 | `+` 添加 | 必填，定义要提取哪些字段 |
| 输出参数 | `结果(result)` | 默认输出全部提取结果 |

输出区域默认显示：

```text
结果(result)
```

官方文档补充：

```text
结果{result}：输出所有提取参数的内容。
提取参数{参数名}：单个提取参数的内容，随提取参数更新。
```

也就是说：

```text
添加提取参数后，节点会额外生成每个参数对应的单独输出。
```

## 3. AI 模型

当前截图中，AI 模型区域可见：

```text
自定义
请选择 AI 模型
模型配置按钮
```

官方口径：

```text
AI 模型是大语言模型，用于提取结构化参数。
```

使用建议：

```text
1. 选择稳定、低幻觉、结构化输出能力好的模型。
2. 如果只是简单正则字段，不一定需要参数提取，可以用工具节点或变量拆分。
3. 参数提取依赖模型理解，结果需要后续判断器校验关键字段。
```

## 4. 输入变量

`输入变量` 是需要被 AI 提取参数的文本来源。

适合选择：

```text
1. 开始.question
2. 问题优化.answer
3. AI 对话整理后的文本
4. 文档内容提取的文本片段
5. 语音转文本结果
6. 图片理解 / 视频理解得到的文本描述
```

常见链路：

```text
开始.question
  -> 问题优化
  -> 参数提取
  -> 判断器
```

或：

```text
用户上传文件
  -> 文档内容提取
  -> 参数提取
  -> 变量赋值 / 工具节点
```

注意：

```text
如果输入已经是标准 JSON，优先用变量拆分。
如果输入是自然语言、不规范回答、半结构化内容，才优先考虑参数提取。
```

## 5. 添加提取参数

点击 `提取参数` 右侧 `+` 后，弹出添加参数窗口。

当前截图中字段为：

| 字段 | 说明 |
| --- | --- |
| 参数 | 输出变量名，最多 64 字符 |
| 显示名称 | 画布展示名称，最多 64 字符 |
| 参数类型 | 下拉选择字段类型 |
| 描述 | 告诉 AI 这个字段要提取什么 |

参数类型下拉可见：

```text
string
number
object
boolean
array
```

字段建议：

```text
1. 参数：用英文变量名，例如 leaveStartTime、amount、reason。
2. 显示名称：用中文，例如 请假开始时间、金额、事由。
3. 参数类型：按后续工具或判断器真实需要选择。
4. 描述：写清楚字段含义、格式要求、缺失时怎么处理。
```

示例：

| 参数 | 显示名称 | 参数类型 | 描述 |
| --- | --- | --- | --- |
| `leaveStartTime` | 请假开始时间 | `string` | 从用户输入中提取请假开始时间，尽量保留日期和时分；未提到则为空 |
| `leaveEndTime` | 请假结束时间 | `string` | 从用户输入中提取请假结束时间；未提到则为空 |
| `reason` | 请假事由 | `string` | 提取请假原因，用简短中文概括；未提到则为空 |
| `days` | 请假天数 | `number` | 提取用户明确给出的请假天数；没有明确数字则为空 |

## 6. 参数类型选择建议

| 参数类型 | 适合内容 | 使用建议 |
| --- | --- | --- |
| `string` | 文本、日期、编号、名称 | 最常用，日期也建议先用 string，后续工具再标准化 |
| `number` | 金额、数量、天数 | 只在输入里确实可能有明确数字时使用 |
| `object` | 复杂对象 | 谨慎使用，后续最好接变量拆分或工具校验 |
| `boolean` | 是否类字段 | 谨慎使用，判断器里不要过度依赖 true/false |
| `array` | 多个字段、多个附件、多个事项 | 适合用户一次说多个条目，后续可接循环节点 |

项目经验：

```text
1. 日期时间先提成 string，再交给工具节点按业务格式转换。
2. 金额、数量可以提 number，但要注意用户写“一百”“三天半”等自然语言。
3. boolean 容易出现 true 字符串和布尔 true 混用，后续判断要谨慎。
4. array 适合后续接循环节点逐项处理。
```

## 7. 输出参数

默认输出：

```text
结果(result)
```

添加提取参数后，还会生成每个参数的独立输出。

示例：

```text
{{参数提取.result}}
{{参数提取.leaveStartTime}}
{{参数提取.leaveEndTime}}
{{参数提取.reason}}
```

使用建议：

```text
1. 后续工具节点需要完整对象时，可传 result。
2. 判断器只判断某个字段时，引用单个提取参数。
3. 需要跨轮保存时，用变量赋值保存单个关键参数或 result。
```

## 8. 后续优化场景

### 8.1 用户不规范回答字段补全

业务项目里，用户可能不会按字段逐项回答，而是一次性说：

```text
我明天下午请假，家里有事，大概半天。
```

可尝试链路：

```text
开始.question
  -> 问题优化
  -> 参数提取：开始时间、结束时间、天数、事由
  -> 判断器：关键字段是否齐全
  -> 缺失字段提示 / 草稿更新工具
```

优点：

```text
减少纯 AI 对话里自由发挥，把字段抽取变成更明确的结构化步骤。
```

### 8.2 组件字段批量抽取

用户一次回答多个字段时：

```text
姓名张三，电话 138xxxx，部门信息中心，附件我等下传。
```

可尝试：

```text
问题优化
  -> 参数提取：姓名、电话、部门、附件意图
  -> 变量赋值 / 工具节点
```

如果用户一次回答多条明细：

```text
第一项买电脑 5000，第二项买显示器 1200。
```

可尝试：

```text
参数提取：items(array)
  -> 循环节点
  -> 变量拆分 / 工具节点
```

### 8.3 文件信息或文档内容抽取

官方示例中，参数提取适合从合同文本中提取：

```text
签订日期
合同金额
服务内容
```

后续可用于：

```text
1. 从上传文档文本中提取标题、日期、金额、人员。
2. 从图片理解结果中提取票据信息。
3. 从语音转文本结果中提取流程字段。
4. 从附件元信息中提取 file_id、file_name 等字段。
```

## 9. 与相关节点配合

### 9.1 与问题优化配合

推荐链路：

```text
问题优化 -> 参数提取
```

原因：

```text
问题优化先把用户口语化、断裂表达整理成更清楚的文本。
参数提取再从整理后的文本中抽字段，稳定性可能更好。
```

注意：

```text
问题优化不能改变用户原意，尤其不能把“可以、嗯、没错”误优化成“正式提交”。
```

### 9.2 与判断器配合

推荐：

```text
参数提取 -> 判断器
```

判断：

```text
关键字段不为空
```

不推荐优先判断：

```text
boolean 字段等于 true
```

原因：

```text
MaxKB 中布尔 true 和字符串 true 可能混用。
更稳的做法是判断关键业务字段是否不为空。
```

### 9.3 与变量赋值配合

推荐：

```text
参数提取 -> 变量赋值
```

用于：

```text
1. 把提取到的字段保存到会话变量。
2. 把 result 保存成 json 类型状态。
3. 缺失或重新开始时用 null 清空提取结果。
```

### 9.4 与变量拆分配合

如果参数提取输出了复杂对象或数组：

```text
参数提取.result / object / array
  -> 变量拆分
  -> 判断器 / 工具节点 / 循环节点
```

注意：

```text
如果输入本来就是标准 JSON，直接变量拆分更稳，不需要参数提取。
```

## 10. 易错点

```text
1. 把参数提取当成变量拆分使用，输入明明是标准 JSON 却让 AI 再理解一遍。
2. 参数描述写得太短，AI 不知道缺失字段应该返回空还是猜测。
3. boolean 字段后续直接判断等于 true，可能受字符串 true 影响。
4. number 字段遇到中文数字、区间、模糊数量时结果不稳定。
5. 输入变量选择错，把上一个工具 JSON 说明文案而不是用户文本传进去。
6. AI 模型没选或模型能力弱，导致提取结果缺失、猜测或格式不稳。
7. 提取多个复杂字段时没有后续校验，直接提交业务系统。
8. 用户确认类短句被错误提取成完整动作，需要结合意图识别或判断器二次确认。
```

## 11. 推荐用法

```text
1. 参数提取适合自然语言字段抽取，不适合标准 JSON 精确取值。
2. 每个提取参数都写清楚描述，尤其写明“未提到则为空”。
3. 日期、时间、金额等关键字段提取后，再用工具节点做格式校验和标准化。
4. 提取结果进入正式提交前，必须经过判断器或工具节点校验。
5. 复杂数组可以提成 array，再接循环节点逐项处理。
6. 重要状态要用变量赋值保存，不要只依赖当前节点即时输出。
```

```text
1. AI 模型“自定义”旁边的配置按钮具体可设置哪些参数。
```
