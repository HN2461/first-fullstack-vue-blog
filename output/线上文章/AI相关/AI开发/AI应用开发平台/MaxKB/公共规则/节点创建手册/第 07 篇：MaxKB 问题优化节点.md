# 第 07 篇：MaxKB 问题优化节点
> 文档状态（2026-07-01）：根据空白高级智能体验证截图和资料说明，记录问题优化节点配置、输出与可能用途。

## 1. 节点定位

`问题优化` 属于添加组件面板中的：

```text
基础组件 -> AI 能力 -> 问题优化
```

资料说明里，问题优化可理解为一种带默认角色和场景的 AI 对话节点，用来结合上下文把用户问题改写得更准确。

通用判断：

```text
这个节点后续可能有用，尤其适合处理用户输入不规范、口语化、缺主语、缺上下文的场景。
```

推荐链路形态：

```text
开始 -> 问题优化 -> 意图识别 / AI 对话 / 工具解析
```

## 2. 初始配置项

当前截图中，问题优化节点初始配置区包含：

| 配置项 | 初始状态 / 可见内容 | 说明 |
| --- | --- | --- |
| AI 模型 | 右侧模型来源为 `自定义`，下方需要选择 AI 模型 | 必填 |
| 系统提示词 | 默认已有较完整提示词 | 可打开弹窗编辑 |
| 用户提示词 | 默认填入 `{{开始.question}}` | 用户原始输入 |
| 历史聊天记录 | 数量为 `1` | 用于结合上下文优化问题 |
| 返回内容 | 默认关闭 | 当前截图显示为关闭 |
| 输出参数 | `问题优化结果(answer)` | 后续节点可引用 |

## 3. 默认系统提示词

当前截图弹窗中的默认系统提示词：

```text
# 角色
你是一位问题优化大师，擅长根据上下文精准揣测用户意图，并对用户提出的问题进行优化。

## 技能
### 技能 1：优化问题
1. 接收用户输入的问题。
2. 依据上下文仔细分析问题含义。
3. 输出优化后的问题。

## 限制：
- 仅返回优化后的问题，不进行额外解释或说明。
- 确保优化后的问题准确反映原始问题意图，不得改变原意。
```

## 4. 输出参数

当前截图中输出参数为：

| 显示名称 | 变量名 | 用途 |
| --- | --- | --- |
| 问题优化结果 | `answer` | 优化后的问题文本 |

常用引用写法示例：

```text
{{问题优化.answer}}
```

注意：

```text
节点重命名后变量前缀会变化，必须从变量选择器复制。
```

## 5. 适合优化的场景

问题优化适合放在“理解用户话术”之前。

可能适合的场景：

| 场景 | 用法 |
| --- | --- |
| 用户输入很口语化 | 先优化成更完整的办理表达，再交给意图识别 |
| 用户省略上下文 | 结合历史聊天记录补全主语和动作 |
| 草稿确认阶段短句 | 将“就这个”“可以”规范成“确认当前草稿内容” |
| 字段修改片段 | 将“日期改后天”规范成“将请假日期修改为后天” |
| 附件补充 | 将“我传一下材料”规范成“用户想上传附件材料” |

## 6. 与意图识别配合

推荐试验链路：

```text
开始
  -> 问题优化
  -> 意图识别
  -> 判断器
  -> 指定回复
```

意图识别输入可尝试绑定：

```text
问题优化 -> 问题优化结果(answer)
```

对照实验：

```text
1. 意图识别直接读取 `开始.question`。
2. 意图识别读取 `问题优化.answer`。
```

验收标准：

```text
1. 分类准确率是否提升。
2. 是否把“可以、嗯、没错”错误优化成“正式提交”。
3. 是否改变用户原意。
4. 是否引入不存在的字段或流程。
```

## 7. 与字段解析配合

问题优化可以作为字段解析前的轻量清洗，但要谨慎。

建议：

```text
1. 对字段解析节点，不要让问题优化自行补造字段值。
2. 系统提示词必须强调“不得改变原意，不得补充用户未提供的信息”。
3. 时间、选项、附件等关键字段仍应由字段解析工具或 AI 解析节点按表单元数据处理。
```

## 8. 易错点

```text
1. 忘记选择 AI 模型。
2. 问题优化结果改变了用户原意。
3. 在提交/确认场景中，把“可以”优化成“正式提交”，导致动作过激。
4. 历史聊天记录带入旧流程，污染当前问题。
5. 返回内容打开后，把优化后的内部文本直接展示给用户。
6. 后续节点继续读取 `开始.question`，导致问题优化节点没有实际作用。
```

## 9. 当前建议

当前不直接改正式主链路。

优先在空白高级智能体里做小链路验证：

```text
开始 -> 问题优化 -> 指定回复
开始 -> 问题优化 -> 意图识别 -> 判断器 -> 指定回复
```

优先测试这些输入：

```text
可以
嗯
就这个
保存一下
日期改后天
我要上传材料
下午三点到五点
```

如果实测稳定，再考虑用于：

```text
1. 草稿确认意图识别前。
2. 附件补充意图识别前。
3. 首句预受理或快捷流程匹配前。
```
