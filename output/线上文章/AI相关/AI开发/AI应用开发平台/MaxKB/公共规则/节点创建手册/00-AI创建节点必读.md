# 00-AI创建节点必读

> 文档状态（2026-07-01）：给 AI 使用的 MaxKB 节点创建防忘清单。目的不是写教程，而是防止后续教用户创建节点时少说参数、乱补不存在的参数、混淆相似节点。

## 1. AI 回答创建节点时必须按这个格式

当用户问“这个节点怎么创建 / 这个节点怎么配置”时，必须按下面顺序回答：

```text
1. 创建入口
2. 必填配置项
3. 可选配置项
4. 输入参数
5. 输出参数
6. 返回内容是否开启
7. 后续通常接什么节点
8. 不能多写或容易写错的地方
```

如果某个节点没有某一项，直接说：

```text
当前截图未看到该配置项。
```

不要凭经验补字段。

## 2. 两个最容易混淆的基础配置

### 2.1 接口传参

位置：

```text
基本信息 -> 接口传参
```

添加弹窗字段只有：

```text
参数
描述
是否必填
默认值
```

不要说有：

```text
显示名称
类型
组件类型
```

### 2.2 会话变量

位置：

```text
基本信息 -> 会话变量
```

添加弹窗字段只有：

```text
参数
显示名称
```

不要说有：

```text
描述
类型
默认值
是否必填
组件类型
```

## 3. 常用节点一句话和必说参数

| 节点 | 一句话用途 | 创建时必须说明 |
| --- | --- | --- |
| 指定回复 | 链路最后给用户展示内容 | 回复内容：自定义 / 引用变量；返回内容通常开启；输出 `answer` |
| 判断器 | 按条件分支 | IF / ELSE IF / ELSE；条件变量；条件类型；多条件“所有 / 任一” |
| 变量赋值 | 保存或清空变量 | 目标变量；赋值方式：引用变量 / 自定义 / null；自定义类型 string/num/json/bool |
| 变量拆分 | 从 JSON 里拆字段 | 输入变量；拆分变量：变量、显示名称、JSON Path 表达式；输出 `result` 和拆分字段 |
| 变量聚合 | 多个变量合成一个输出 | 聚合策略：第一非空值 / Array / Dict；分组变量名和显示名称；组内变量 |
| 参数提取 | 用 AI 从自然语言抽字段 | AI 模型；输入变量；提取参数：参数、显示名称、参数类型、描述；输出 `result` 和参数字段 |
| 意图识别 | 用 AI 识别用户意图 | AI 模型；输入；历史聊天记录；意图分类；输出 `category/reason` |
| 问题优化 | 规范用户不标准输入 | AI 模型；输入；系统提示词；返回内容通常关闭；输出优化结果 |
| AI 对话 | 生成内容或整理文案 | AI 模型；系统提示词；用户提示词；历史聊天记录；返回内容；输出 `answer` |
| 表单收集 | 让用户填表或上传文件 | 表单项参数、显示名称、提示、是否必填、组件类型、显隐条件；输出 `form_data` 和各字段 |
| 循环节点 | 重复执行固定流程 | 循环类型：数组 / 指定次数 / 无限；循环数组或次数；循环开始输出 `index/item`；Continue/Break |
| 工具节点 | 调用工具页签已有工具 | 输入参数按工具创建时定义绑定；返回内容通常关闭；输出 `result` |
| 智能体节点 | 调用已有智能体 | 按被调用智能体要求绑定输入参数；确认返回内容；输出通常看 `result` |
| MCP 调用 | 调用 MCP Server 工具 | MCP Server Config；获取工具；工具参数；输出 `result` |
| 自定义工具 | 当前画布直接写 Python | 输入参数；Python 内容；返回内容通常关闭；输出 `result` |

高频入口纠错：

```text
变量赋值入口是：基础组件 -> 数据处理 -> 变量赋值。
不要说成：基础组件 -> 业务逻辑 -> 变量赋值。
```

变量选择器写法硬规则：

```text
1. 讲判断器、工具入参、变量赋值时，不能只写英文变量名。
2. 必须写成“来源分组 > 显示名称 {变量名}”，例如：会话变量 > 是否正在选择任务 {isSelectingTask}。
3. 变量赋值的目标变量也必须写选择器路径，不能只写 selectedTaskID。
4. 如果不知道显示名称，先查当前智能体会话变量表或相关进度文档，不要凭英文名让用户反查。
5. AI 提示词才使用 {{chat.xxx}} / {{开始.question}} / {{节点名称.xxx}}；选择器路径不要包进 {{ }}。
```

## 4. 返回内容开关统一口径

```text
指定回复：通常开启。
工具节点：通常关闭。
自定义工具：通常关闭。
解析类 AI：通常关闭。
文案整理 AI：可关闭，再接指定回复。
```

原因：

```text
最终给用户看的内容优先走指定回复。
工具 JSON、变量拆分结果、参数提取结果不要直接展示给用户。
```

## 5. JSON 和自然语言不要混用节点

```text
标准 JSON：用变量拆分。
自然语言：用参数提取、意图识别、AI 对话。
多个变量合并：用变量聚合。
跨轮保存状态：用变量赋值。
数组逐项处理：用循环节点。
```

不要让 AI 对标准 JSON 再猜一遍。

## 5.1 多分支共用链路和执行条件

当前 MaxKB 节点在多条前置连线汇入时，可以通过节点右上角的执行条件控制是否执行：

```text
所有：所有前置节点都执行完成后，才执行当前节点。
任一：任意一个前置节点执行完成后，就执行当前节点。
```

重要规则：

```text
1. 多个互斥分支要共用后续查询、变量拆分、判断等中间链路时，汇合节点执行条件必须设为“任一”。
2. 如果误设为“所有”，互斥分支不可能同时完成，汇合节点会一直不执行。
3. 并行汇总类节点才考虑“所有”，例如确实要等待多个前置工具都完成后再统一整理。
4. 这属于节点执行条件，不是判断器内部多条件的“所有 / 任一”，两者不要混淆。
5. 最终指定回复节点是否共用要谨慎；历史上多个判断器分支共用同一个最终回复节点出现过前台兜底异常，必要时仍建议最终回复分支独立。
```

## 5.2 导出包禁止保留孤立节点

MaxKB 导出包里不能保留未接入流程的独立节点。

规则：

```text
1. 除“基本信息”和“开始”节点外，任何节点都必须至少有一条前置连线或后续连线。
2. 废弃的 AI 节点、工具节点、变量拆分节点、指定回复节点，不能只拖在画布上不接线。
3. 孤立节点可能导致导入后“能保存但不能运行”，尤其是复制试验、替换工具链、删除旧 AI 链路后最容易残留。
4. 优化导出包前必须巡检入度和出度：入度=0 且出度=0 的非基础节点必须删除；只剩入度或只剩出度的旧节点也要确认是否仍在真实路径上。
5. 如果只是暂时保留旧节点作参考，不要留在正式导出包里，应写入文档或另存试验包。
```

修包检查口径：

```text
开始节点 DFS 可达路径里不应出现废弃节点。
最终导出包不应出现“未在流程中的节点”提示。
```

## 6. 判断器常用口径

每次讲判断器节点时必须同时说明：

```text
1. IF / ELSE IF 分支里的多条件关系要明确选“所有”或“任一”。
2. 多个同义词、同义短语命中同一个分支时，用“符合以下任一条件”。
3. 状态 + 动作必须同时满足时，用“符合以下所有条件”。
4. 判断器每个分支出口都必须接入后续节点；未做完的分支也要先接指定回复占位，否则调试或发布会报分支未连接。
5. 不要只让用户创建判断器而不说明 IF / ELSE 分别接哪里。
```

优先判断：

```text
关键字段不为空
```

例如：

```text
selectedFlowDefineID 不为空
selectedKeys 不为空
draftRunID 不为空
isSelectingApprover 等于 true
```

谨慎判断：

```text
success 等于 true
```

原因：

```text
布尔 true 和字符串 true 在 MaxKB 里容易混。
```

审批人状态不要判断：

```text
currentApproversJson 不为空
```

因为：

```text
字符串 "[]" 也可能被判断为不为空。
```

应使用：

```text
isSelectingApprover
```

## 7. null 清空规则

清空变量时，变量赋值节点必须选择：

```text
赋值方式：null
```

不要说：

```text
自定义 string，输入 null
```

这可能得到字符串：

```text
"null"
```

## 8. 工具和自定义工具不要混淆

```text
工具页签工具：外面“工具”页面创建好的共享工具，画布里只绑定输入参数。
自定义工具：当前画布里直接写 Python，偏当前智能体专用。
MCP 调用：调用 MCP Server 里的工具。
智能体节点：调用另一个已有智能体。
```

如果用户说“外面设置好的工具”，优先查：

```text
17-工具页签与智能体节点.md
```

如果用户说“当前画布直接写 Python”，优先查：

```text
16-MCP调用与自定义工具节点.md
```

## 9. 需要复制时拿哪些文件

如果只想让 AI 以后别忘节点怎么创建，复制：

```text
README.md
00-AI创建节点必读.md
```

如果要配置某个具体节点，再复制对应节点文件，例如：

```text
07-判断器节点.md
12-变量赋值节点.md
13-变量拆分节点.md
17-工具页签与智能体节点.md
```

如果要保留完整 MaxKB 节点配置防忘清单，复制整个目录：

```text
02-节点创建手册/
```

复制后需要按实际项目替换：

```text
工具名称
智能体名称
会话变量名称
接口传参名称
业务字段协议
```

不要照搬目标项目专属工具名、流程字段和接口参数值。

## 10. AI 应该怎么阅读本目录

当用户问某个 MaxKB 节点怎么创建时，AI 必须：

```text
1. 先读本文件。
2. 再读对应节点文件。
3. 只按文件里写到的实际配置项回答。
4. 不读取整个目录。
5. 不把其他节点的字段套到当前节点。
```

示例：

```text
用户问变量赋值：
先读 00-AI创建节点必读.md
再读 12-变量赋值节点.md
回答目标变量、赋值方式、null、自定义类型、输出和返回内容。
```
