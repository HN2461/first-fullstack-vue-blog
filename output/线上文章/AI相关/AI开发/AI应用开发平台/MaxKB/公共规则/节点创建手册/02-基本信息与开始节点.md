# 02-基本信息与开始节点

> 文档状态（2026-07-19）：根据空白高级智能体验证截图和 MaxKB v2.10.4 官方高级智能体文档，记录基本信息与开始节点配置。目标环境版本不同或界面字段不一致时，以目标环境变量选择器和官方对应版本为准。
>
> 官方依据：[高级智能体](https://maxkb.cn/docs/v2/user_manual/app/workflow_app/)

## 1. 基本信息定位

`基本信息` 是高级智能体的应用级配置区，不是普通业务流程节点。

当前截图中左侧面板展示：

```text
名称
描述
开场白
长期记忆
文件上传
用户输入
接口传参
会话变量
语音输入
语音播放
```

当前截图示例：

```text
名称：节点配置验证
描述：用于验证 MaxKB 节点配置项和输出参数
```

## 2. 基本信息创建入口

创建高级智能体后，`基本信息` 默认存在，一般不需要手动创建。

常规步骤：

```text
1. 进入 MaxKB 高级智能体画布。
2. 点击左侧或画布中的“基本信息”卡片。
3. 在左侧配置面板中维护名称、描述、开场白和各类输入配置。
```

## 3. 开场白

当前截图里的开场白仍是通用模板：

```text
您好，我是 xxx 小助手，您可以向我提出 xxx 使用问题。
- xxx 主要功能有什么？
- xxx 如何收费？
- 需要转人工服务
```

业务智能体建议改成目标项目自己的场景文案，例如：

```text
您好，我可以协助你办理 xxx。
你可以直接输入事项名称，或描述要处理的问题。
```

如果需要在开场白中展示快捷入口，优先使用 MaxKB 开场白支持的短横线列表写法：

```text
您好，我是智慧校园工作流助手。

您可以直接说出要办理的事项，例如“我要请假”“我要报销”“我要报修”。

也可以先选择下面的快捷入口：

- 我要发起申请
- 查看待办审批
- 查询我的流程
```

说明：

```text
1. 开场白里的 `- 快捷入口` 会被发布页或自定义前端识别为开场快捷问题。
2. 开场白不需要写 `<quick_question>` 标签；`<quick_question>` 主要用于普通回复节点、AI 回复或工具渲染后的快捷按钮。
3. 开场白快捷入口建议 2 到 4 个，优先放总入口最高频动作。
4. 不要把“退出当前流程”放进开场白快捷入口，因为用户刚进入时通常还没有当前流程，容易误导。
5. 开场白正文仍要写清楚用户可以直接输入自然语言，不要只依赖快捷入口。
```

注意：

```text
1. 开场白不要写死真实用户 token、学校 ID、接口地址。
2. 开场白只做引导，不替代后续 `获取工作流流程目录`、`快捷流程名称匹配` 或 `首句预受理`。
3. 如果智能体当前只用于测试，应在名称或描述中体现测试用途，避免用户误以为是正式入口。
```

## 4. 长期记忆、文件上传与语音

当前截图状态：

```text
长期记忆：关闭
文件上传：关闭
语音输入：关闭
语音播放：关闭
```

通用建议：

```text
1. 强业务办理链路优先依赖本轮会话变量和业务后端状态，不依赖长期记忆。
2. 普通主链路不应默认依赖基本信息里的文件上传。
3. 附件、图片等组件字段优先通过 `表单收集` 节点、工具节点或组件处理子智能体处理。
4. 语音输入和语音播放先保持关闭，后续单独验证。
```

注意：

```text
不要误以为开启“文件上传”后，工作流附件字段就会自动变成业务系统附件。
如果业务系统有自己的附件协议，仍需要 MaxKB 附件信息 -> 业务附件上传接口 -> 目标业务附件字段协议值。
```

官方 v2.10.4 文档补充：开启长期记忆后，可按对话轮次或时间周期生成用户记忆，并通过 `memory` 变量注入后续提示词。强业务流程仍不应把权限、审批状态或实时业务数据放入长期记忆。

## 5. 用户输入

`用户输入` 是问答页面在会话开始或对话过程中提供给用户填写、选择的参数。当前官方文档确认组件包括：

```text
文本框、密码框、单选框、多选框、选项卡、日期、开关、
单行选项卡、多行文本框、单行多选卡、模型、知识库、树形选择器。
```

使用边界：

```text
1. 用户输入参数可以作为后续节点可引用的变量。
2. 模型组件可供 AI 节点按变量选择模型，知识库组件可供检索节点按变量选择知识库。
3. 适合用户主动选择的稳定上下文，不适合保存对话过程中不断变化的状态。
4. 密码组件只代表界面输入类型，业务后端仍必须独立鉴权；不要用它收集生产密码或长期密钥。
5. 显隐条件只能引用排在当前参数之前且已配置完成的用户输入参数，避免循环引用。
```

## 6. 接口传参

当前截图中 `接口传参` 右侧有“添加”入口。

添加接口传参时，弹窗字段固定按下面 4 项理解：

| 弹窗字段 | 是否需要填写 | 说明 |
| --- | --- | --- |
| 参数 | 必填 | 英文参数名，后续工具节点按这个名字引用 |
| 描述 | 建议填写 | 写清楚参数用途，便于导出导入后核对 |
| 是否必填 | 按参数决定 | 必填参数打开；可空参数关闭 |
| 默认值 | 必填项会出现必填标识 | 测试期可填默认值；敏感或运行时传入的值不要写死 |

注意：

```text
接口传参弹窗没有“显示名称”字段。
不要把会话变量的“显示名称”配置方式套到接口传参上。
官方当前文档还明确：`token` 是 MaxKB 内部保留字段，不能添加为接口传参。
```

通用接口传参模板：

| 参数 | 描述 | 是否必填 | 默认值建议 |
| --- | --- | --- | --- |
| `businessBaseUrl` / `apiBaseUrl` | 业务后端根地址，不包含具体接口路径 | 按需 | 当前环境业务后端根地址 |
| `agentBaseUrl` | 智能体服务根地址，用于附件下载或转存 | 按需 | 当前智能体服务根地址 |
| `tenantId` / `orgId` / `schoolID` | 租户、组织、学校等隔离标识 | 按需 | 当前环境租户标识 |
| `serviceSecret` | 服务调用校验值 | 否 | 后端未启用时留空 |
| `userTicket` / `accessToken` | 当前用户票据 | 是 | 留空，不要写死真实用户票据 |

目标项目映射示例：

```text
businessBaseUrl：业务后端根地址，只写到 /api
agentBaseUrl：智能体服务根地址
schoolID：学校标识
serviceSecret：服务调用校验值
userTicket：当前用户票据
```

正式入口规则：

```text
环境态参数放在 MaxKB 默认值里。
用户态参数不填默认值，由前端、后端中转或原生 API 按当前登录用户动态传入。
复制智能体到新租户或新环境时，优先只改环境态默认值，不改前端代码。
```

## 7. 会话变量

当前截图中 `会话变量` 右侧有“添加”入口。

会话变量用于保存当前对话中的业务状态。它和接口传参不同：

```text
接口传参：环境、用户、入口上下文。
会话变量：流程办理中的临时状态。
```

添加会话变量时，弹窗字段只有下面 2 项：

| 弹窗字段 | 是否需要填写 | 说明 |
| --- | --- | --- |
| 参数 | 必填 | 英文变量名，后续变量赋值和判断器使用 |
| 显示名称 | 必填 | MaxKB 下拉选择时显示的中文名 |

注意：

```text
会话变量弹窗没有“描述、是否必填、默认值”。
不要再给会话变量补写必填、默认值或类型配置。
如果需要表达默认状态，应通过变量赋值节点在流程中写入，例如 `isSelectingApprover=false`。
```

业务办理类智能体常见会话变量示例：

| 参数 | 显示名称 |
| --- | --- |
| `selectedFlowDefineID` | 当前已选择流程 ID |
| `selectedFlowName` | 当前已选择流程名称 |
| `currentFormMetaJson` | 当前流程表单元数据 JSON |
| `currentStandardFormMetaJson` | 当前标准化流程表单元数据 JSON |
| `filledFieldsJson` | 已填写字段列表 JSON |
| `missingRequiredFieldsJson` | 缺失必填字段列表 JSON |
| `unsupportedFieldsJson` | 当前不支持字段列表 JSON |
| `currentSubmitFieldsJson` | 当前提交字段列表 JSON |
| `draftRunID` | 后端草稿 runID |
| `draftPrcsID` | 后端草稿 prcsID |
| `draftNodeID` | 后端草稿 nodeID |
| `currentApproversJson` | 当前候选审批人列表 JSON |
| `isSelectingApprover` | 是否正在选择审批人 |
| `currentQuickCandidatesJson` | 当前快捷候选流程列表 JSON |
| `isChoosingQuickCandidate` | 是否正在选择快捷候选流程 |

关键稳定性规则：

```text
1. 状态判断优先使用显式开关，例如 `isSelectingApprover=true`。
2. 不要用 `currentApproversJson 不为空` 判断是否正在选择审批人。
3. 字符串 `"[]"` 在 MaxKB 判断器里仍可能被视为“不为空”。
4. 快捷候选状态也应使用 `isChoosingQuickCandidate=true/false`。
5. 其他项目应按自己的业务状态命名，不要照搬业务会话变量。
```

## 8. 开始节点定位

`开始` 是高级智能体工作流真正执行的起点。

当前截图中，开始节点展示两组变量：

```text
全局变量
输出参数
```

## 9. 开始节点全局变量

当前截图显示的全局变量包括：

| 显示名称 | 变量名 | 用途 |
| --- | --- | --- |
| 当前时间 | `time` | 当前时间 |
| 历史聊天记录 | `history_context` | 当前会话历史 |
| 对话 ID | `chat_id` | 当前对话 ID |
| 对话用户 ID | `chat_user_id` | 当前对话用户 ID |
| 对话用户类型 | `chat_user_type` | 当前对话用户类型 |
| 对话用户组 | `chat_user_group` | 当前对话用户组 |
| 对话用户 | `chat_user` | 当前对话用户 |

在提示词中引用全局变量时，按项目当前规范使用：

```text
{{global.time}}
```

如果 MaxKB 变量选择器复制出的写法不同，应以变量选择器为准。

## 10. 开始节点输出参数

当前截图显示开始节点输出参数：

| 显示名称 | 变量名 | 用途 |
| --- | --- | --- |
| 用户问题 | `question` | 用户本轮输入 |

官方 v2.10.4 文档确认，开启文件上传后还可能输出：

| 显示名称 | 变量名 | 用途 |
| --- | --- | --- |
| 文档 | `document` | 用户上传的文档文件 |
| 图片 | `image` | 用户上传的图片文件 |
| 音频 | `audio` | 用户上传的音频文件 |
| 视频 | `video` | 用户上传的视频文件 |
| 其他文件 | `other` | 用户上传的其他自定义文件 |

常用引用写法：

```text
{{开始.question}}
```

业务办理类智能体常见绑定示例：

| 使用位置 | 绑定方式 |
| --- | --- |
| `快捷流程名称匹配.userQuestion` | 引用 `开始 -> 用户问题` |
| `首句预受理` | 引用 `开始 -> 用户问题` |
| `AI 对话` | 引用 `开始 -> 用户问题` |
| `口语化字段解析` | 引用 `开始 -> 用户问题` |
| `识别草稿确认意图` | 引用 `开始 -> 用户问题` |
| `解析审批人选择` | 引用 `开始 -> 用户问题` |

## 11. 已核验与待环境确认

```text
已由官方文档核验：
1. 用户输入参数、接口传参和会话变量都可供后续流程引用，实际模板以变量选择器复制结果为准。
2. 文件上传开启后可输出 document/image/audio/video/other。
3. 用户输入支持模型、知识库和树形选择器等组件。

仍需目标环境确认：
1. 公司实际版本中各类参数在变量选择器的分组名称和最终引用模板。
2. 不同客户端、嵌入方式下用户输入显隐、默认值和文件上传行为。
3. 公司版本对上传数量、单文件大小和后缀的实际限制。
```
