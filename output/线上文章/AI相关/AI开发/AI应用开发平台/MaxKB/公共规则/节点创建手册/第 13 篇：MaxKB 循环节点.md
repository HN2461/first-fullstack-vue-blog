# 第 13 篇：MaxKB 循环节点
> 文档状态（2026-07-19）：根据空白高级智能体验证截图、MaxKB v2.10.4 官方文档和组件处理通用实践，记录循环节点、循环体、循环开始、Continue、Break 的基础配置和使用边界。
>
> 官方依据：[高级智能体 - 循环节点](https://maxkb.cn/docs/v2/user_manual/app/workflow_app/#234)

## 1. 节点定位

`循环节点` 属于添加组件面板中的：

```text
基础组件 -> 业务逻辑 -> 循环节点
```

节点作用：

```text
把一段固定流程放进循环体中重复执行。
```

它不是普通判断分支，而是一组组合能力：

```text
循环节点
  -> 循环体画布
      -> 循环开始
      -> 循环体内的业务节点
      -> Continue / Break
```

可能用途：

```text
1. 批量处理多个组件字段。
2. 批量处理多个附件、图片、音频或视频文件。
3. 对数组里的每个待补字段逐个生成提示或转换结构。
4. 对明细表、子表、审批人列表等集合数据逐项标准化。
5. 对固定次数的补充信息收集或内容生成做试验。
```

## 2. 循环节点配置

当前截图中，循环节点包含：

| 配置项 | 当前可见内容 | 说明 |
| --- | --- | --- |
| 循环类型 | 下拉选择 | 必填 |
| 循环数组 | 选择循环数组组 | 数组循环时必填 |
| 循环次数 | 数字步进器，默认 `1` | 指定次数循环时必填 |

循环类型下拉中可见：

```text
数组循环
指定次数循环
无限循环
```

### 2.1 数组循环

适合：

```text
1. 已有一个数组变量，需要逐项处理。
2. 每次循环都要拿到当前元素和下标。
3. 处理文件列表、组件列表、字段列表、候选项列表。
```

配置项：

```text
循环类型：数组循环
循环数组：选择一个数组变量
```

循环开始默认输出：

| 显示名称 | 变量名 | 说明 |
| --- | --- | --- |
| 下标 | `index` | 当前循环项的下标，通常从 0 开始 |
| 循环元素 | `item` | 当前循环项本身 |

官方示例口径：

```text
数组 array=[23,26,37,88,90] 时，array[0] 的 index 是 0，item 是 23。
```

项目理解：

```text
如果附件数组里有 3 个文件，循环体会按顺序处理每个文件。
循环开始.item 就是当前文件对象，循环开始.index 就是当前文件序号。
```

注意：

```text
循环数组必须真的是数组结构。
如果前置节点输出的是 JSON 字符串，通常要先用工具节点或变量拆分转成数组。
```

### 2.2 指定次数循环

适合：

```text
1. 明确知道要重复几次。
2. 每次执行同一段流程，但不一定依赖数组元素。
3. 测试循环体连线、Continue、Break 是否符合预期。
```

配置项：

```text
循环类型：指定次数循环
循环次数：数字步进器设置次数
```

截图中循环次数初始为：

```text
1
```

使用建议：

```text
指定次数循环适合做确定次数的重复任务，不适合等待用户无限补充信息。
```

### 2.3 无限循环

适合：

```text
1. 不知道需要循环几次。
2. 需要通过 Break 条件主动跳出。
3. 需要持续追问、收集或处理，直到满足结束条件。
```

官方资料提示与当前冲突：

```text
当前官方高级智能体同一页面前文写“无限循环默认最大 500 次”，注意事项又写“默认最大 1000 次”。
因此不能把 500 或 1000 当成跨版本稳定契约。
如需确认上限，应在目标环境小规模调试；如需修改服务端配置，由平台管理员改 MaxKB .env 并重新加载配置。
```

项目建议：

```text
除非非常明确退出条件，否则不要在正式链路里优先使用无限循环。
无限循环必须设计 Break 节点或明确的结束条件。
```

## 3. 循环体画布

添加循环节点后，会出现一个单独的循环体区域，截图标题为：

```text
循环体
```

循环体内默认生成：

```text
循环开始
```

官方口径：

```text
循环体画布用于编排循环逻辑，每次循环时都会执行循环体画布中的工作流。
```

注意：

```text
循环体内不支持再添加循环节点，避免造成死循环。
```

## 4. 循环开始节点

循环开始节点位于循环体内，是每次循环的入口。

当前截图中包含：

```text
节点设置
循环变量
输出参数
```

默认输出参数：

| 显示名称 | 变量名 | 说明 |
| --- | --- | --- |
| 下标 | `index` | 当前循环序号 |
| 循环元素 | `item` | 当前循环元素 |

截图中还支持添加循环变量：

```text
循环变量 -> + 添加
```

添加参数弹窗字段为：

| 字段 | 说明 |
| --- | --- |
| 参数 | 变量名，最多 64 字符 |
| 显示名称 | 画布上显示的名称，最多 64 字符 |

使用理解：

```text
循环开始的变量可以作为循环体内各节点的输入来源。
数组循环最常用的是 index 和 item。
额外添加的循环变量需要继续实测：它更像是为循环体内流程补充可引用变量名。
```

常见引用写法示例：

```text
{{循环开始.index}}
{{循环开始.item}}
```

注意：

```text
实际使用时不要手写节点前缀，优先从变量选择器复制。
节点重命名后，变量前缀会变化。
```

## 6. Continue 节点

`Continue` 用于：

```text
终止当前这一轮循环，直接进入下一轮循环。
```

当前截图中 Continue 节点配置为条件判断式：

| 配置项 | 当前可见内容 | 说明 |
| --- | --- | --- |
| 符合以下 | `所有` / 下拉 | 多条件关系 |
| 条件行 | 请选择变量 / 请选择条件 / 请输入值 | 条件成立时执行 Continue |
| 添加条件 | `+ 添加条件` | 可增加条件行 |

官方资料补充：

```text
Continue 不能作为结束节点。
```

使用场景：

```text
1. 当前 item 为空，跳过这一项。
2. 当前文件类型不支持，跳过这一项。
3. 当前组件字段已处理过，跳过这一项。
4. 当前字段不需要提交，进入下一项。
```

示例口径：

```text
循环开始.item 为空 -> Continue
```

或：

```text
当前附件类型 不包含 pdf/docx/jpg -> Continue
```

注意：

```text
Continue 是“跳过当前轮”，不是“结束整个循环”。
```

## 7. Break 节点

`Break` 用于：

```text
终止当前循环，跳出循环体，继续执行循环节点后面的工作流。
```

当前截图中 Break 节点配置也为条件判断式：

| 配置项 | 当前可见内容 | 说明 |
| --- | --- | --- |
| 符合以下 | `所有` / 下拉 | 多条件关系 |
| 条件行 | 请选择变量 / 请选择条件 / 请输入值 | 条件成立时执行 Break |
| 添加条件 | `+ 添加条件` | 可增加条件行 |

使用场景：

```text
1. 找到目标流程后停止遍历候选流程。
2. 已经识别到用户明确结束补充信息。
3. 累计结果达到上限。
4. 某个关键工具返回失败，需要停止后续批处理。
```

示例口径：

```text
已找到目标 = true -> Break
```

项目经验提醒：

```text
不要优先依赖布尔 true 判断，MaxKB 中布尔 true / 字符串 true 可能不稳定。
更稳的方式是判断关键字段不为空，例如 targetId 不为空。
```

## 8. 项目可能优化方向

### 8.1 批量组件字段处理

可能链路：

```text
识别待处理组件字段
  -> 循环节点（数组循环：待处理组件字段数组）
      -> 循环开始
      -> 判断器：当前组件类型
      -> 不同组件处理工具 / AI 整理
      -> 变量赋值或变量聚合
  -> 指定回复
```

适合解决：

```text
用户一次性回答多个组件字段，格式不规范，需要逐项处理。
```

### 8.2 批量附件处理

可能链路：

```text
表单收集 / 文件上传
  -> 附件数组
  -> 循环节点（数组循环）
      -> 判断文件类型
      -> 导入 MaxKB 附件到业务系统
      -> 聚合目标业务附件字段值
  -> 后续提交工具
```

注意：

```text
MaxKB 表单收集拿到的是内部 file_id。
提交到业务系统前，需要转成目标项目自己的附件字段协议。
```

### 8.3 批量候选项筛选

可能链路：

```text
候选流程数组
  -> 循环节点
      -> 判断是否匹配用户问题
      -> 匹配成功后保存 selectedFlowDefineID
      -> Break
  -> 判断器：selectedFlowDefineID 不为空
```

适合：

```text
候选项数量较多，但只需要找到第一个或最优一个。
```

## 9. 易错点

```text
1. 把循环节点当普通分支用，忘记循环体里必须从循环开始往后编排。
2. 数组循环时绑定了 JSON 字符串，而不是真数组。
3. 无限循环没有 Break 条件，导致流程执行次数过多。
4. Continue 和 Break 混淆：Continue 是下一轮，Break 是跳出循环。
5. Continue 不能作为结束节点，后面需要有合理流转。
6. 循环体内试图再添加循环节点，官方资料提示不支持。
7. 循环内生成的结果没有聚合或赋值，循环结束后外部拿不到完整结果。
8. 循环中直接指定回复，可能导致多轮内容连续输出，正式链路要谨慎。
```

## 10. 循环结果如何带出

循环内每轮处理后的结果，如果要在循环结束后继续使用，通常需要显式保存。

可选方式：

```text
1. 使用会话变量保存累计结果。
2. 使用变量赋值更新累计字符串或累计对象。
3. 使用变量聚合把多轮结果合并成数组或结构。
4. 使用工具节点处理“读取旧值 -> 追加新值 -> 返回新值”。
```

社区资料中也有类似经验：

```text
循环体内通过获取会话变量、拼接结果、再赋值回会话变量，循环外即可拿到合并结果。
```

通用建议：

```text
如果循环用于组件字段或附件处理，优先让工具节点输出结构化结果，再在循环体内聚合，避免靠 AI 拼字符串。
```
