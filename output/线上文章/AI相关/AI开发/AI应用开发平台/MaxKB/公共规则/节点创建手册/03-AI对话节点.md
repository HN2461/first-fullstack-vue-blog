# 03-AI对话节点

> 文档状态（2026-07-19）：根据空白高级智能体验证截图和 MaxKB v2.10.4 官方高级智能体文档，记录 AI 对话节点配置、输出参数和易错点。
>
> 官方依据：[高级智能体 - AI 对话](https://maxkb.cn/docs/v2/user_manual/app/workflow_app/#211-ai)

## 1. 节点定位

`AI 对话` 属于添加组件面板中的：

```text
基础组件 -> AI 能力 -> AI 对话
```

节点作用：

```text
调用指定 AI 模型，根据系统提示词、用户提示词、历史聊天记录和可选工具能力生成回答。
```

通用常见用途：

```text
1. 标准流程选择：根据流程目录和用户问题整理候选流程。
2. 口语化字段解析：把用户自然语言解析成字段草稿 JSON。
3. 字段说明整理：把表单元数据整理成用户可读说明。
4. 草稿确认文案：把当前字段草稿整理成确认文案。
5. 缺失字段提示：把缺失项和已填项整理成人话提示。
6. 审批人选择文案：把审批人列表整理成编号选择文案。
```

## 2. 初始配置项

| 配置项 | 初始状态 / 可见内容 | 说明 |
| --- | --- | --- |
| AI 模型 | 右侧有模型来源下拉，当前为 `自定义`；下方需要选择 AI 模型 | 必填，未选择模型时不能正常运行 |
| 系统提示词 | 文本框占位提示：`系统提示词，可以引用系统中的变量：如{{开始.question}}` | 用于设置模型扮演的角色或遵循的指令 |
| 用户提示词 | 默认示例包含 `已知信息：{{知识库检索.data}}` 和 `问题：{{开始.question}}` | 用于放入本轮任务、用户问题和前置节点数据 |
| 历史聊天记录 | 下拉显示 `工作流`，下方数值为 `1` | 控制是否及如何携带历史上下文 |
| 视觉 | 开关关闭 | 需要图片理解类能力时再开启 |
| 技能 | 展示 MCP、工具、Skills、智能体分组；`输出执行过程` 默认勾选 | 可给 AI 节点挂工具或子能力 |
| 输出思考 | 开关关闭 | 打开后可能输出模型思考相关内容 |
| 返回内容 | 开关打开 | 打开后该节点回答可能直接展示到前台 |
| 输出参数 | 展示 `AI 回答内容(answer)`、`思考过程(reasoning_content)`、`历史聊天记录(history_message)` | 后续节点可引用这些输出 |
| 异常捕获 | 输出参数区域右侧可见开关，当前关闭 | 官方当前文档确认开启后可提供 `exception_message`，用于接异常分支 |

## 3. 提示词配置

### 3.1 系统提示词

系统提示词旁的提示说明为：

```text
设定模型扮演的角色或遵循的指令
```

当前占位示例说明系统提示词可以引用变量：

```text
{{开始.question}}
```

通用建议：

```text
1. 系统提示词写稳定规则、角色边界和输出格式要求。
2. 不要把用户本轮问题主要内容只放在系统提示词里。
3. 输出 JSON 的 AI 节点，必须在系统提示词里明确“只输出 JSON，不要输出解释”。
4. 文案整理类 AI 节点，系统提示词应明确“不展示 fieldName、JSON、数组对象结构”。
```

### 3.2 用户提示词

用户提示词旁的提示说明为：

```text
用户向模型提出的问题或输入的指令
```

当前默认示例：

```text
已知信息：
{{知识库检索.data}}
问题：
{{开始.question}}
```

注意：

```text
1. `{{知识库检索.data}}` 只是知识库问答模板示例。
2. 空白实验智能体默认没有“知识库检索”前置节点，直接保留这个变量会导致取不到数据。
3. 工作流场景应按真实前置节点替换，例如 `{{获取工作流流程目录.result}}`、`{{chat.currentStandardFormMetaJson}}` 或 `{{开始.question}}`。
4. 节点名称必须与画布真实名称一致，重命名后要从变量选择器重新复制。
5. 不要把变量选择器显示名直接包进 `{{ }}`，例如 `{{会话变量 > 当前任务查询模式 {currentTaskMode}}}` 是错误写法；AI 提示词必须使用 `{{chat.currentTaskMode}}` 或 `{{节点名称.输出变量名}}`。
6. 已实测可用的提示词变量形态包括：`{{拆分任务列表结果.taskListCode}}`、`{{拆分任务编号解析结果.selectTaskMessage}}`、`{{global.history_context}}`、`{{global.userTicket}}`、`{{chat.isSelectingTask}}`、`{{开始.question}}`。
```

## 4. 技能、输出思考与返回内容

当前截图中技能区包含：

```text
MCP
工具
Skills
智能体
```

每组右侧都有 `+` 入口。

当前截图状态：

```text
输出执行过程：勾选
输出思考：关闭
返回内容：开启
```

使用建议：

```text
1. 如果 AI 对话节点只是整理文案，通常不需要额外挂工具。
2. 如果 AI 节点挂工具，必须确认工具输入来源和返回内容是否会影响用户前台展示。
3. 正式面向用户的最终回复链路，通常应关闭不必要的执行过程展示，避免暴露中间信息。
4. 解析类 AI 节点，例如 `口语化字段解析`，最终不应直接把原始 JSON 展示给用户。
5. 文案整理类 AI 节点可以产出 `answer`，再由指定回复节点展示。
```

## 5. 输出参数

当前截图中 AI 对话节点输出参数包括：

| 显示名称 | 变量名 | 用途 |
| --- | --- | --- |
| AI 回答内容 | `answer` | 模型最终回答 |
| 思考过程 | `reasoning_content` | 模型思考过程或推理内容，是否有值取决于模型和配置 |
| 历史聊天记录 | `history_message` | AI 节点处理后的历史消息 |
| 异常信息 | `exception_message` | 启用异常捕获后输出，供自动重试、默认值或失败分支使用 |

常用引用写法示例：

```text
{{AI 对话.answer}}
{{AI 对话.reasoning_content}}
{{AI 对话.history_message}}
{{AI 对话.exception_message}}
```

注意：

```text
1. `AI 对话` 是画布节点名，复制或重命名后变量前缀会变化。
2. 比如节点名改成 `口语化字段解析`，则后续应从变量选择器复制对应的 `answer`，不要继续写 `{{AI 对话.answer}}`。
3. 指定回复节点展示上一 AI 节点内容时，优先引用对应 AI 节点的 `answer`。
```

## 6. 项目使用边界

AI 对话节点适合：

```text
1. 需要理解自然语言的地方。
2. 需要把复杂结构整理成用户可读文案的地方。
3. 需要轻量意图判断但没有必要写工具的地方。
```

AI 对话节点不适合：

```text
1. 做最终字段完整性硬校验。
2. 做接口请求。
3. 做幂等请求 ID 生成。
4. 做附件协议拼接。
5. 做必须稳定返回的 JSONPath 拆分。
```

通用建议：

```text
1. 能用工具稳定完成的校验和数据转换，优先工具化。
2. AI 对话主要负责理解、整理和生成自然语言。
3. 正式提交前的必填校验已改为 `提交前字段完整性检测` 工具硬闸门，不再依赖 AI 判断字段是否完整。
```

## 7. 易错点

```text
1. 新建 AI 对话节点后忘记选择 AI 模型。
2. 空白实验智能体里保留默认 `{{知识库检索.data}}`，但画布中没有知识库检索节点。
3. 节点重命名后继续手写旧变量，例如 `{{AI 对话.answer}}`。
4. 解析类节点打开返回内容，导致 JSON 直接展示给用户。
5. 文案整理节点没有接指定回复，或者工具节点返回内容没关，导致前台混入原始 JSON。
6. 历史聊天记录带太多，导致旧流程、旧字段污染当前解析。
7. 输出思考打开后，把不适合给用户看的 reasoning 内容暴露出去。
```

## 8. 已核验与待环境确认

```text
已由官方文档核验：
1. 历史聊天记录可按“节点”或“工作流”口径携带上下文。
2. 视觉开启后可使用图片、视频等多模态输入，但所选模型必须支持多模态。
3. 技能区可添加 MCP、工具、Skills 和子智能体；MCP/工具调用要求模型支持函数调用。
4. 异常捕获可输出 exception_message，并为异常分支配置重试或兜底。

仍需目标环境确认：
1. 选择 AI 模型后的模型参数面板具体有哪些字段。
2. 当前模型是否稳定返回 `reasoning_content`，以及是否允许展示。
3. 返回内容关闭后，不同发布页、嵌入和 API 客户端是否都不展示该节点回答。
4. 公司实际授权下可选择的 MCP、工具、Skills 和子智能体范围。
```
