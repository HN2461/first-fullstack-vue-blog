# 17-工具页签与智能体节点

> 文档状态（2026-07-01）：根据空白高级智能体验证截图、工具管理页面截图、MaxKB 官方文档和工具使用通用实践，记录从工具页签添加外部已创建工具、从智能体页签添加已存在智能体，以及工具创建页的基础配置。

## 1. 节点定位

高级智能体添加组件面板除了 `基础组件`，还有：

```text
工具
智能体
```

通用理解：

```text
工具页签：添加工具管理中已经创建好的工具，通常可被多个智能体复用。
智能体页签：添加系统中已经存在的智能体，作为子智能体调用。
```

和基础组件中的自定义工具区别：

| 类型 | 创建位置 | 添加位置 | 复用范围 | 项目定位 |
| --- | --- | --- | --- | --- |
| 工具页签工具 | 顶部导航 `工具` 页面创建 | 添加组件面板 -> 工具 | 更像共享工具，可被多个智能体复用 | 正式链路高频使用 |
| 自定义工具节点 | 当前高级智能体画布内直接写 Python | 基础组件 -> 其他 -> 自定义工具 | 更像当前流程专用 | 临时、局部、实验 |
| 智能体节点 | 顶部导航 `智能体` 页面创建 | 添加组件面板 -> 智能体 | 调用已有智能体 | 子任务委派、复杂能力拆分 |

注意：

```text
工具页签中的工具名称、描述、输入参数、输出参数都来自外部工具管理页面。
添加到画布后，一般只需要给这些已经定义好的输入参数绑定值。
```

## 2. 工具页签节点

### 2.1 添加后的节点配置

截图示例中工具页签添加了一个工具节点：

```text
生成工作流请求ID
```

节点中可见：

| 配置项 | 示例 | 说明 |
| --- | --- | --- |
| 输入参数 | `prefix`、`action`、`flowDefineID`、`submitFields`、`selectedKeys` | 来自工具创建时定义的输入参数 |
| 参数类型 | `string`、`array` 等灰色标签 | 来自工具输入参数的数据类型 |
| 参数值 | 输入框或下拉选择 | 画布里为该工具参数绑定值 |
| 返回内容 | 开关 | 是否把工具结果直接返回给用户 |
| 输出参数 | `结果(result)` | 工具执行返回结果 |

官方文档口径：

```text
在高级编排流程中，可以添加工具中的工具作为组件节点。
节点设置：即工具的输入参数。
参数输出：即工具的返回结果。
```

常用引用：

```text
{{生成工作流请求ID.result}}
```

实际使用时：

```text
不要手写节点前缀，优先从变量选择器复制。
变量选择器里优先显示“显示名称”，英文变量名通常放在大括号中。
写配置文档时必须写成“会话变量 > 是否正在选择任务 {isSelectingTask}”这类格式，不要只写 isSelectingTask。
```

### 2.2 输入参数绑定

工具参数可能有两种输入形态：

```text
1. 文本输入框：适合自定义固定值。
2. 下拉选择参数：适合引用前置节点、全局变量、会话变量。
```

截图示例：

| 参数 | 类型 | 画布输入形态 | 建议 |
| --- | --- | --- | --- |
| `prefix` | `string` | 输入框 | 固定前缀时可直接写 |
| `action` | `string` | 输入框 | 固定动作可直接写，例如 submit / draft |
| `flowDefineID` | `string` | 下拉选择参数 | 通常引用会话变量或前置拆分结果 |
| `submitFields` | `array` | 下拉选择参数 | 通常引用工具或变量拆分得到的字段数组 |
| `selectedKeys` | `array` | 下拉选择参数 | 通常引用前置选择结果 |

通用经验：

```text
1. 接口环境类参数优先来自接口传参，例如 businessBaseUrl、agentBaseUrl、userTicket、tenantId。
2. 流程状态类参数优先来自会话变量，例如 selectedFlowDefineID、draftFormDataJson。
3. 工具参数类型是 array / dict / object 时，前置变量最好保持真实结构，不要传 JSON 字符串。
4. 配置文档必须写清楚下拉里要选的中文显示项，例如“会话变量 > 当前任务查询模式 {currentTaskMode}”。
5. 示例字段必须按目标项目替换；没有学校语义的项目不要照搬 schoolID。
```

### 2.3 返回内容开关

截图中：

```text
生成工作流请求ID：返回内容开启
流程字段填写智能...：返回内容关闭
```

通用建议：

```text
工具节点一般关闭返回内容。
```

原因：

```text
工具返回通常是 JSON、中间状态或业务结构，直接展示给用户容易暴露内部格式。
```

适合开启的情况：

```text
1. 调试工具输出。
2. 工具返回本身就是最终用户可读文案。
3. 该工具节点就是当前分支最终回复出口。
```

正式链路推荐：

```text
工具节点返回内容关闭
  -> 变量拆分 / AI 文案整理 / 指定回复
```

## 3. 智能体页签节点

### 3.1 添加后的节点配置

截图示例中智能体页签添加了一个智能体节点：

```text
流程字段填写智能...
```

节点中可见输入参数：

```text
用户问题
businessBaseUrl
agentBaseUrl
tenantId
serviceSecret
userTicket
```

特点：

```text
这些参数都来自被调用智能体自身已经定义好的输入要求。
当前画布只负责绑定值。
```

截图中部分参数带红色 `*`：

```text
用户问题 *
businessBaseUrl *
agentBaseUrl *
tenantId *
userTicket *
```

说明：

```text
红色星号表示必填。
```

### 3.2 参数绑定建议

常见绑定：

| 参数 | 推荐来源 | 文档应写的选择器显示项 |
| --- | --- | --- |
| 用户问题 | 开始节点 | 开始 > 用户问题 `{question}`，或变量选择器实际显示的 `开始.question` |
| `businessBaseUrl` | 接口传参 | 接口传参 > `businessBaseUrl {businessBaseUrl}` |
| `agentBaseUrl` | 接口传参 | 接口传参 > `agentBaseUrl {agentBaseUrl}` |
| `tenantId` / `schoolID` | 接口传参 | 按目标项目字段选择，例如接口传参 > `tenantId {tenantId}` |
| `serviceSecret` | 接口传参或系统配置，注意敏感信息 | 接口传参 > `serviceSecret {serviceSecret}` |
| `userTicket` | 接口传参 | 接口传参 > `userTicket {userTicket}` |

注意：

```text
智能体节点参数通常不是当前节点里临时创建的，而是被调用智能体已定义好的输入。
如果参数缺失，需要回到被调用智能体或当前智能体基本信息中补齐。
```

### 3.3 使用边界

适合：

```text
1. 把复杂子流程拆到另一个智能体里。
2. 复用已有智能体能力，例如附件处理、组件处理、字段填写。
3. 当前智能体只做路由，把专项任务交给子智能体。
```

风险：

```text
1. 同名或相似智能体很多，必须确认完整名称、描述和版本。
2. 子智能体输入参数变更后，当前画布节点绑定可能失效。
3. 子智能体返回结构不清楚时，后续变量拆分容易出错。
4. 子智能体如果返回内容开启，可能和当前主链路指定回复混在一起。
```

通用建议：

```text
正式链路添加智能体节点前，先确认被调用智能体的输入、输出、返回内容开关和版本。
```

## 5. 创建工具页面

截图中点击创建工具后，页面结构包括：

```text
基础信息
启动参数
输入参数（使用工具时显示）
工具内容（Python）（使用工具时不显示）
输出参数（使用工具时显示）
```

底部按钮：

```text
取消
调试
创建
```

### 5.1 基础信息

字段：

| 字段 | 说明 |
| --- | --- |
| 名称 | 工具名称，最多 64 字符 |
| 描述 | 工具说明，最多 128 字符 |

建议：

```text
名称写成动作 + 对象，例如“生成请求ID”“提交前字段完整性检测”。
描述写清楚工具用途、输入依赖和返回内容，会显示在工具列表和智能体组件中。
```

导入或半自动生成工具时也按同一标准处理：

```text
1. .tool 或 .mk 里的工具必须写入描述字段，描述控制在 128 字符以内。
2. 导入后要到工具页列表人工核对描述是否显示；不能只看导出包里的 desc 字段。
3. 已实测：部分 MaxKB 环境中，带 desc 的工具导入后再从工具页导出，新的 .tool 可能变成 desc 为空；以工具页最终显示为准。
4. 如果 MaxKB 导入后卡片描述为空，保留当前功能不动，人工编辑工具描述或在交付说明中给出补录文案。
5. 新增或替换工具的巡检报告中，应列出工具名称、描述是否非空，以及导入后是否需要人工补录。
```

### 5.2 启动参数

截图中启动参数表头为：

```text
参数
组件类型
必填
操作
```

添加启动参数弹窗字段为：

| 字段 | 说明 |
| --- | --- |
| 参数 | 参数名，最多 64 字符 |
| 显示名称 | 页面展示名称，最多 64 字符 |
| 参数提示说明 | 输入提示说明，最多 128 字符 |
| 是否必填 | 开关 |
| 组件类型 | 启动配置项在工具创建或调试时展示的输入组件 |
| 文本长度 | 文本框组件时显示，截图为 1 到 200 |
| 默认值 | 可设置默认值 |
| 显示默认值 | 控制默认值是否显示 |

组件类型截图可见：

```text
文本框
滑块
密码框
单选框
多选框
选项卡
日期
开关
JSON 文本框
```

另一张截图中还可见：

```text
多行文本框
```

说明：

```text
启动参数偏工具初始化或工具运行环境配置，添加项比较复杂，通常不需要频繁配置。
这里的“组件类型”决定启动配置项怎么填写，不等同于 Python 输入参数的数据类型。
```

适合：

```text
1. 内置工具或第三方工具需要配置启动信息。
2. 工具运行前需要固定环境参数。
3. 某些工具依赖外部连接、模型、知识库、数据源等组件。
```

通用经验：

```text
普通 Python 脚本工具大多数时候不需要启动参数。
业务接口地址、用户票据、租户 ID 等动态值更常作为输入参数，由智能体接口传参绑定。
只有确实是工具固定启动配置、调试默认配置或不随每次调用变化的值，才考虑放启动参数。
```

### 5.3 输入参数

截图中输入参数区域标注：

```text
输入参数 使用工具时显示
```

也就是说：

```text
这里定义的参数，会在高级智能体工具节点中显示出来，要求调用方绑定值。
```

添加输入参数弹窗字段为：

| 字段 | 说明 |
| --- | --- |
| 参数名 / 参数 | Python 工具接收的参数名，最多 64 字符 |
| 数据类型 | 参数的数据类型 |
| 参数提示说明 | 输入提示说明，最多 128 字符 |
| 来源 | 参数值来源，截图已见 `引用参数`，实际绑定时通常从接口传参、会话变量、前置节点或自定义值中选择 |
| 是否必填 | 开关 |

数据类型截图已确认包含：

```text
string
int
dict
array
float
boolean
```

注意：

```text
不要把启动参数里的“显示名称 / 组件类型 / 默认值”套到输入参数上。
输入参数关注 Python 工具实际接收什么字段、什么类型、从哪里取值。
```

常用输入参数建议：

| 参数名 | 数据类型 | 是否必填 | 来源建议 | 参数提示说明 |
| --- | --- | --- | --- | --- |
| `businessBaseUrl` | `string` | 是 | 接口传参 | 业务后端根地址 |
| `agentBaseUrl` | `string` | 否 | 接口传参 | 智能体服务根地址 |
| `tenantId` | `string` | 否 | 接口传参 | 租户、学校或组织标识 |
| `userTicket` | `string` | 是 | 接口传参 | 当前登录用户票据 |
| `flowDefineID` | `string` | 是 | 会话变量或前置节点 | 流程定义 ID |
| `submitFields` | `array` / `dict` | 是 | 前置工具或变量拆分 | 已整理的提交字段 |
| `selectedKeys` | `array` | 否 | 前置工具或变量拆分 | 用户选择的字段 key 列表 |

### 5.4 工具内容（Python）

截图中区域为：

```text
工具内容（Python） 使用工具时不显示
```

说明：

```text
工具创建者在这里写 Python 逻辑。
调用工具的智能体节点中不会显示源码，只显示输入参数和输出参数。
```

使用建议：

```text
1. 工具输入先做空值和类型兜底。
2. 返回稳定 JSON，方便后续变量拆分。
3. 不要把用户可读文案和结构化数据混成一段文本。
4. 异常时返回明确 error/message，而不是直接抛出不可读错误。
5. 敏感参数不要写死在代码里，优先通过接口传参或安全配置传入。
```

### 5.5 输出参数

截图中输出参数区域显示：

```text
结果 {result}
```

当前真实界面规则：

```text
输出参数区域不是手动新增区域。
不要让用户添加 success、code、message、data 等输出参数。
工具创建后只有系统固定的“结果 {result}”。
如果后续要取 success/code/message/data，必须在画布里接“变量拆分”节点，从 工具节点.result 中拆。
```

官方工具文档说明：

```text
输出参数：工作流执行返回的结果。
```

工具节点添加到画布后，也会显示：

```text
输出参数
结果 {result}
```

使用建议：

```text
1. 工具返回结构尽量固定。
2. 后续需要多个字段时，接变量拆分。
3. 后续只需要用户文案时，可接指定回复或 AI 文案整理。
4. result 里不要塞过大的无关数据，避免后续上下文膨胀。
```

导入版本建议：

```text
1. 如果是在已有工具基础上修改代码并重新导入，优先使用新工具名称，不要沿用旧名称。
2. 部分 MaxKB 环境导入同名工具时可能不会覆盖旧工具，导致画布仍执行旧代码。
3. 推荐命名为“原工具名-版本目标”，例如“渲染申请草稿确认文案-正式统一版”。
4. .mk 包里的工具节点也要同步更新为新工具名称和新工具 ID，不能只改工具列表。
5. 旧工具确认不再被其他智能体依赖后，再在工具页人工清理。
6. 如果半自动改包把 AI 节点替换成工具节点，新工具节点的 `node_data` 必须可 JSON 序列化；`user_id` 这类 UUID 对象建议转成字符串。
7. 工具源码中需要把对象兜底转文本时，`json.dumps` 建议加 `default=str`，避免 UUID、时间对象导致运行时报错。
```

## 6. 输入参数里的来源

输入参数弹窗或工具节点参数绑定中能看到来源：

```text
引用参数
自定义
```

含义：

```text
引用参数：从当前智能体已有变量、前置节点、接口传参、会话变量中选择。
自定义：直接填写固定值或默认值。
```

通用建议：

```text
1. 环境和身份类参数优先引用接口传参。
2. 用户输入类参数优先引用开始.question 或问题优化结果。
3. 状态类参数优先引用会话变量。
4. 测试固定值可临时用自定义，正式链路尽量减少硬编码。
5. 启动参数弹窗使用“组件类型 / 默认值”口径，不按这里的来源口径配置。
```

## 7. 高频工具节点使用方式

常用链路：

```text
前置 AI / 参数提取 / 变量拆分 / 变量赋值
  -> 工具节点
  -> 变量拆分
  -> 判断器
  -> 指定回复
```

示例：

```text
生成工作流请求ID
  -> 变量拆分：clientRequestID
  -> 保存草稿 / 提交流程工具
```

或：

```text
提交前字段完整性检测
  -> 变量拆分：missingFields、canSubmit、message
  -> 判断器：missingFields 不为空
  -> 指定回复
```

注意：

```text
工具节点返回内容通常关闭。
如果工具节点已经返回用户可读文案，才考虑开启或直接指定回复引用。
```

## 8. 易错点

```text
1. 工具管理中改了输入参数，画布里已有工具节点绑定可能需要重新检查。
2. 工具名称被省略号截断时，不能凭猜测选工具，必须点开确认完整名称和描述。
3. array / dict 参数传成字符串，Python 工具里类型不符合预期。
4. 启动参数和输入参数混淆：启动参数使用“显示名称 / 组件类型 / 默认值”配置启动表单，输入参数使用“数据类型 / 来源 / 是否必填”定义 Python 工具入参。
5. 工具返回内容开启，导致 JSON 中间结果直接展示给用户。
6. 智能体节点参数缺失，子智能体运行失败或拿不到环境变量。
7. 子智能体版本或参数变化，主智能体没有同步更新。
8. 工具 result 结构不稳定，后续变量拆分 JSON Path 容易失效。
9. 误以为工具创建页可以手动新增输出参数；当前真实界面只有系统固定的 `结果(result)`，细字段必须后接变量拆分。
```

## 9. 推荐用法

```text
1. 正式可复用业务逻辑优先创建为工具管理中的共享工具。
2. 画布里添加工具后，只做参数绑定，不在节点里重新定义工具协议。
3. 接口传参优先承载环境参数，例如 businessBaseUrl、agentBaseUrl、tenantId、userTicket。
4. 工具返回稳定 JSON，后续用变量拆分取字段。
5. 工具节点默认关闭返回内容，最终展示交给指定回复。
6. 智能体节点添加前先确认完整名称、描述、输入参数、输出结果和返回内容策略。
7. 工具创建页不要配置 success/code/message/data 等输出参数；这些都从 `result` 里拆。
```
