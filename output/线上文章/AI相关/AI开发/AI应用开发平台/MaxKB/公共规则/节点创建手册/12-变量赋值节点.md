# 12-变量赋值节点

> 文档状态（2026-07-01）：根据空白高级智能体验证截图、MaxKB 官方文档和会话状态通用实践，记录变量赋值节点配置、`null` 清空语义和高频用法。

## 1. 节点定位

`变量赋值` 属于添加组件面板中的：

```text
基础组件 -> 数据处理 -> 变量赋值
```

官方节点说明：

```text
更新全局变量的值。
```

通用理解：

```text
变量赋值是保存和清空流程状态的高频节点。
常用于把前置节点输出写入全局变量 / 会话变量，供后续分支、下一轮对话或循环体继续使用。
```

典型用途：

```text
1. 保存当前流程 ID、流程名称、表单元数据。
2. 保存草稿状态、提交状态、审批人状态。
3. 保存用户已选择的候选项。
4. 保存工具节点计算后的中间结果。
5. 在流程结束、重新选择、异常兜底时把旧状态清空为 null。
```

## 2. 初始配置项

当前截图中，变量赋值节点支持一组或多组赋值配置。

每一组包含：

| 配置项 | 当前可见内容 | 说明 |
| --- | --- | --- |
| 变量 | 下拉选择变量 | 必填，选择要被更新的目标变量 |
| 赋值 | 下拉选择赋值方式 | 必填，支持 `引用变量` / `自定义` / `null` |
| 删除 | 右上角垃圾桶图标 | 删除当前赋值配置组 |

节点底部支持：

```text
+ 添加
```

用途：

```text
在一个变量赋值节点里同时更新多个变量。
```

## 3. 赋值方式

当前截图中，`赋值` 下拉可见：

```text
引用变量
自定义
null
```

官方文档口径：

```text
赋值：给变量赋值的相关内容，可引用变量、自定义和赋值为空。
```

### 3.1 引用变量

选择 `引用变量` 后，下方出现变量选择框。

截图中变量选择器可见来源分组：

```text
全局变量
开始
AI 对话
意图识别
语音转文本
图片理解
...
```

适合：

```text
1. 把开始节点的用户问题保存到某个状态变量。
2. 把 AI 对话、意图识别、工具节点、变量拆分等前置节点输出写入变量。
3. 在循环体内把本轮处理结果写回循环变量或会话变量。
```

示例：

```text
变量：selectedFlowDefineID
赋值：引用变量
值：{{解析快捷候选编号.selectedFlowDefineID}}
```

注意：

```text
不要手写复杂路径，优先从变量选择器复制。
节点重命名后，变量前缀可能变化。
```

### 3.2 自定义

选择 `自定义` 后，下方出现：

```text
类型下拉 + 输入框
```

当前截图中类型下拉可见：

```text
string
num
json
bool
```

适合：

```text
1. 写入固定字符串。
2. 写入固定数字。
3. 写入固定 JSON 对象或数组。
4. 写入布尔值。
```

示例：

```text
变量：draftAction
赋值：自定义
类型：string
值：save_draft
```

或：

```text
变量：retryCount
赋值：自定义
类型：num
值：0
```

或：

```text
变量：selectedKeys
赋值：自定义
类型：json
值：[]
```

注意：

```text
自定义类型会影响后续判断器和工具节点拿到的数据类型。
如果想保存 JSON 数组或对象，应选 json，不要用 string 存 JSON 字符串。
```

### 3.3 null

选择 `null` 后，当前赋值组不需要再填写值。

项目语义：

```text
null 表示把目标变量清空为空值。
```

高频用途：

```text
1. 用户重新选择流程时，清空旧流程状态。
2. 正式提交成功后，清空草稿、审批人、缺失字段等临时状态。
3. 用户取消、重置、重新开始时，清空上一次对话残留。
4. 工具节点失败后，清空不可信的中间变量。
5. 循环或批处理结束后，清空临时变量。
```

示例：

```text
变量：selectedFlowDefineID
赋值：null
```

```text
变量：currentApproversJson
赋值：null
```

```text
变量：pendingComponentFieldsJson
赋值：null
```

重要区别：

```text
null 不是字符串 "null"。
如果选择自定义 string 并输入 null，后续很可能得到字符串 "null"。
如果目标是清空变量，应选择赋值方式里的 null。
```

## 4. 一次赋值多个变量

变量赋值节点支持点击：

```text
+ 添加
```

在同一个节点里配置多组变量更新。

适合：

```text
1. 同一个分支进入时初始化多个状态。
2. 流程结束时一次性清空多个临时变量。
3. 工具成功后同时保存 ID、名称、JSON、提示文案。
```

示例：重新选择流程前清空旧状态

```text
selectedFlowDefineID -> null
selectedFlowName -> null
formMetaJson -> null
draftFormDataJson -> null
currentApproversJson -> null
pendingComponentFieldsJson -> null
```

使用建议：

```text
同一个业务动作里的状态更新可以放在一个变量赋值节点。
不同业务动作不要全塞到一个节点，避免后续排查时看不清哪个分支改了状态。
```

## 5. 与全局变量 / 会话变量的关系

截图中目标变量通过下拉选择，不是在变量赋值节点里新建任意变量。

结合前文规则：

```text
全局变量常来自基本信息中的接口传参、用户输入、系统全局变量等。
会话变量在基本信息中创建，弹窗字段只有：参数、显示名称。
```

因此变量赋值节点要先有可选目标变量：

```text
1. 如果要保存跨节点状态，先在基本信息里创建对应会话变量。
2. 如果要使用接口参数，先在接口传参里配置参数。
3. 变量赋值节点负责更新已有变量的值，不负责定义完整变量元数据。
```

注意：

```text
不要给会话变量补“类型、默认值、是否必填”等不存在字段。
当前会话变量创建只需要参数和显示名称。
```

## 6. 与判断器配合

变量赋值常用于给判断器提供稳定条件。

推荐判断：

```text
selectedFlowDefineID 不为空
selectedKeys 不为空
draftFormDataJson 不为空
pendingComponentFieldsJson 不为空
```

谨慎判断：

```text
success 等于 true
```

原因：

```text
MaxKB 中布尔 true 和字符串 true 容易混用。
项目里更稳的方式是判断关键字段是否不为空。
```

特殊提醒：

```text
不要只用 currentApproversJson 不为空判断审批人状态。
字符串 "[]" 也可能被视为不为空。
如果要表示没有审批人，优先设置为 null 或让工具返回明确字段。
```

## 7. 与循环节点配合

官方循环节点说明中提到：

```text
循环变量通常与变量赋值搭配使用，在每次循环结束后为中间变量设置一个新的值，并在下次循环中使用新的值。
```

通用可用场景：

```text
1. 循环处理附件时，每轮把当前转换结果追加到累计变量。
2. 循环处理组件字段时，每轮更新当前组件处理状态。
3. 循环查找候选流程时，匹配成功后写入 selectedFlowDefineID，再 Break。
```

注意：

```text
循环内如果要把每轮结果带到循环外，必须显式赋值或聚合。
只在循环体中生成结果，但不写入变量，循环结束后外部可能拿不到完整结果。
```

## 8. 项目高频状态变量建议

以下变量名是业务口径示例，实际以当前智能体已创建变量为准：

| 变量 | 常见赋值方式 | 用途 |
| --- | --- | --- |
| `selectedFlowDefineID` | 引用变量 / null | 当前选中的流程 ID |
| `selectedFlowName` | 引用变量 / null | 当前选中的流程名称 |
| `formMetaJson` | 引用变量 / json / null | 当前流程表单元数据 |
| `draftFormDataJson` | 引用变量 / json / null | 当前草稿字段 |
| `currentApproversJson` | 引用变量 / json / null | 当前审批人状态 |
| `pendingComponentFieldsJson` | 引用变量 / json / null | 待处理组件字段 |
| `lastAction` | 自定义 string / null | 最近一次用户动作 |
| `retryCount` | 自定义 num / 引用变量 | 重试次数 |

## 9. 易错点

```text
1. 想清空变量却选择自定义 string 并输入 null，导致保存成字符串 "null"。
2. 想保存 JSON 数组，却选择 string，后续变量拆分或工具节点拿到字符串。
3. 同一个变量在多个分支都被赋值，后续排查不清最终是哪条分支写入。
4. 一个变量赋值节点里更新太多无关状态，导致节点职责不清。
5. 保存工具节点结果前没有判断工具是否成功，导致失败结果覆盖了旧的有效状态。
6. 重置流程时只清空流程 ID，忘记清空表单元数据、草稿、审批人和组件字段。
7. 判断器依赖布尔 true，而变量赋值时写入的是字符串 true。
8. 目标变量还没有在基本信息中创建，变量赋值节点下拉里找不到。
```

## 10. 推荐用法

```text
1. 保存状态时，变量名按业务含义命名，不要使用 temp1、data1 这类难排查名称。
2. 清空状态时优先使用赋值方式 null。
3. JSON 结构优先用 json 类型，不要把 JSON 当 string 存。
4. 布尔值只在非常明确时使用 bool；判断器更推荐判断关键字段不为空。
5. 同一业务动作的一组状态更新可以放在同一个变量赋值节点。
6. 流程重新开始、重新选择、正式提交成功、异常兜底，都要考虑清空旧状态。
```

## 11. 待继续核对

```text
1. 目标变量下拉中是否只展示全局变量 / 会话变量，还是也能展示部分节点变量。
2. null 赋值后，判断器“为空 / 不为空”的实际结果。
3. 自定义 json 输入非法 JSON 时，节点是否保存失败或运行时报错。
4. 自定义 bool 的可选值是 true/false 下拉，还是输入框。
5. 变量赋值节点是否有独立输出参数。
6. 同一个节点中多组赋值的执行顺序是否从上到下。
7. 多轮对话里会话变量被 null 后，下一轮是否仍保持空值。
```
