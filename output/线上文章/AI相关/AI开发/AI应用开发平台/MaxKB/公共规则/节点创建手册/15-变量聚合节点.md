# 15-变量聚合节点

> 文档状态（2026-07-01）：根据空白高级智能体验证截图、MaxKB 官方文档和多分支收束通用实践，记录变量聚合节点配置、聚合策略和使用边界。

## 1. 节点定位

`变量聚合` 属于添加组件面板中的：

```text
基础组件 -> 数据处理 -> 变量聚合
```

官方节点说明：

```text
将多个变量整合为一个参数进行输出。
```

通用理解：

```text
变量聚合不是“拆字段”，也不是“保存状态”。
它更像把多个来源的变量按分组和策略整理成一个统一输出，减少后续节点需要分别引用多个变量的复杂度。
```

常见用途：

```text
1. 多个分支只会执行其中一个，把不同分支的结果统一成一个变量。
2. 把同一类变量整理成数组，交给循环节点或工具节点。
3. 把多个字段整理成字典对象，交给工具节点或后续 AI 节点。
4. 把多个候选文案收束成统一的回复内容。
```

## 2. 初始配置项

当前截图中，变量聚合节点包含：

| 配置项 | 当前可见内容 | 说明 |
| --- | --- | --- |
| 聚合策略 | 下拉选择 | 必填，决定每组变量如何合并 |
| 分组 | 默认 `Group1` | 每个分组会生成一个输出参数 |
| 变量行 | `请选择变量` | 在组内添加要参与聚合的变量 |
| 添加 | `+ 添加` | 给当前分组添加变量行 |
| 添加分组 | `+ 添加分组` | 新增一个独立聚合分组 |
| 输出参数 | `Group1 {Group1}` | 当前分组聚合后的输出 |

默认输出参数：

```text
Group1 {Group1}
```

官方口径：

```text
显示名称{变量}：聚合后的参数名称，随聚合变量更新。
```

## 3. 分组配置

截图中默认分组为：

```text
Group1
```

点击分组右侧编辑按钮，会打开编辑分组弹窗。

当前截图中编辑分组字段为：

| 字段 | 说明 |
| --- | --- |
| 变量 | 分组输出变量名，最多 64 字符 |
| 显示名称 | 画布展示名称，最多 64 字符 |

使用建议：

```text
默认 Group1 可以用于临时测试。
正式链路建议改成有业务含义的变量名和显示名称，例如 replyText、submitPayload、attachmentList。
```

示例：

| 变量 | 显示名称 | 用途 |
| --- | --- | --- |
| `replyText` | 最终回复文案 | 汇聚不同分支产生的回复文案 |
| `submitPayload` | 提交参数 | 聚合提交工具需要的字段 |
| `attachmentList` | 附件列表 | 聚合多个附件变量 |
| `fieldValues` | 字段值对象 | 聚合多个表单字段 |

注意：

```text
分组变量名决定后续节点引用名。
分组重命名后，后续变量引用要重新从变量选择器复制。
```

## 4. 聚合策略

当前截图中，聚合策略下拉可见：

```text
返回每组的第一个非空值
返回每组变量的数组（Array）
返回每组变量的字典（Dict）
```

### 4.1 返回每组的第一个非空值

官方说明：

```text
取每组首个非空项作为该组结果，其余舍弃。
```

适合：

```text
1. 多分支收束，只有一个分支会有值。
2. 多个候选来源按优先级兜底。
3. 优先使用工具生成文案，如果为空再使用 AI 兜底文案。
```

示例：

```text
Group：replyText
变量顺序：
1. {{工具生成成功文案.message}}
2. {{AI整理成功文案.answer}}
3. {{兜底回复.answer}}
策略：返回每组的第一个非空值
```

输出理解：

```text
哪个变量最先不为空，就输出哪个。
后面的非空变量会被舍弃。
```

项目高频场景：

```text
判断器多个分支各自产生回复文案，最后统一接一个指定回复。
```

链路：

```text
分支 A 文案
分支 B 文案
分支 C 文案
  -> 变量聚合：replyText，第一非空值
  -> 指定回复：引用 {{变量聚合.replyText}}
```

注意：

```text
变量顺序很重要。
把最可信、最优先的变量放前面。
```

### 4.2 返回每组变量的数组（Array）

官方说明：

```text
将同组内所有变量按字段名组装，保留完整结构输出。
```

适合：

```text
1. 后续需要循环处理多个变量。
2. 要把多个同类结果交给工具节点统一处理。
3. 要保留多个候选项，而不是只取第一个非空。
```

示例：

```text
Group：attachmentList
变量：
{{表单收集.attachment_test}}
{{图片上传.fileList}}
{{历史附件.attachmentList}}
策略：返回每组变量的数组（Array）
```

后续可能链路：

```text
变量聚合.attachmentList
  -> 循环节点（数组循环）
  -> 附件转换工具
```

注意：

```text
Array 策略适合保留多个值。
如果后续只需要一个最终值，不要用 Array，优先用第一非空值。
```

### 4.3 返回每组变量的字典（Dict）

官方说明：

```text
将同组内所有变量按字典类型组装，需输入 Key 值。
```

适合：

```text
1. 给工具节点组装一个对象参数。
2. 把多个字段聚合成 payload。
3. 把多个上下文变量整理成一个结构化对象。
```

示例：

```text
Group：submitPayload
策略：返回每组变量的字典（Dict）
变量：
selectedFlowDefineID -> key: flowDefineId
draftFormDataJson -> key: formData
currentApproversJson -> key: approvers
attachmentBusinessList -> key: attachments
```

输出理解：

```json
{
  "flowDefineId": "...",
  "formData": {},
  "approvers": [],
  "attachments": []
}
```

注意：

```text
Dict 策略需要为每个变量配置 Key 值。
当前截图没有展示 Key 输入界面，后续需要点选 Dict 策略后继续核对。
```

## 5. 多分组输出

变量聚合支持：

```text
+ 添加分组
```

每个分组会独立生成输出参数。

适合：

```text
1. 同时聚合回复文案和提交参数。
2. 同时聚合附件列表和字段值对象。
3. 同时聚合多个不同类型的下游输入。
```

示例：

```text
Group1：replyText，第一非空值
Group2：submitPayload，Dict
Group3：attachmentList，Array
```

使用建议：

```text
一个变量聚合节点可以有多个分组，但不要把无关业务强行放一起。
如果分组太多，后续排查会困难。
```

## 6. 与其他节点配合

### 6.1 与判断器配合

变量聚合很适合放在多个判断器分支之后。

链路：

```text
判断器分支 A -> 生成 A 文案
判断器分支 B -> 生成 B 文案
判断器分支 C -> 生成 C 文案
  -> 变量聚合：第一非空值
  -> 指定回复
```

好处：

```text
后续指定回复只需要引用一个变量，不用为每个分支都复制一套回复节点。
```

注意：

```text
如果不同分支本身需要不同后续流程，不要强行聚合。
变量聚合适合“不同来源，统一下游处理”的场景。
```

### 6.2 与指定回复配合

常见用法：

```text
变量聚合.replyText
  -> 指定回复
```

适合：

```text
多个分支都生成一段最终文案，最后统一回复。
```

注意：

```text
如果使用第一非空值，聚合变量顺序要按优先级排列。
```

### 6.3 与循环节点配合

Array 策略可用于给循环节点准备数组输入。

链路：

```text
变量聚合：Array
  -> 循环节点：数组循环
```

适合：

```text
1. 多来源附件列表统一处理。
2. 多个待处理字段统一循环。
3. 多个候选项统一遍历。
```

注意：

```text
如果 Array 输出结构不是预期数组，可能需要先变量拆分或工具节点标准化。
```

### 6.4 与工具节点配合

Dict 策略可用于组装工具入参对象。

链路：

```text
变量聚合：Dict
  -> 工具节点
```

适合：

```text
把多个散落变量整理成一个 payload，再交给 Python 工具处理。
```

注意：

```text
如果工具节点要求严格字段名，Dict 的 Key 必须和工具入参协议一致。
```

### 6.5 与参数提取配合

谨慎：

```text
变量聚合 Array / Dict 输出再交给参数提取，可能受版本兼容影响。
```

已见社区 issue：

```text
MaxKB 2.8.1 有用户反馈参数提取节点处理变量聚合 Array / Dict 输出时报错。
```

项目建议：

```text
参数提取优先处理自然语言文本。
变量聚合出的 Array / Dict 更适合交给变量拆分、循环节点或工具节点。
```

## 7. 项目可能用法

### 7.1 多分支回复收束

场景：

```text
判断器有多个分支，每个分支生成不同回复文案，但最后都只是回复用户。
```

链路：

```text
分支 A：整理缺失字段提示
分支 B：整理草稿确认文案
分支 C：整理提交成功文案
  -> 变量聚合 replyText：返回每组的第一个非空值
  -> 指定回复：引用 replyText
```

### 7.2 提交参数组装

场景：

```text
正式提交前，需要把流程 ID、表单字段、审批人、附件组装成一个对象。
```

链路：

```text
变量聚合 submitPayload：Dict
  -> 提交工具
```

### 7.3 附件批处理

场景：

```text
附件可能来自表单收集、历史草稿、用户补充上传。
```

链路：

```text
变量聚合 attachmentList：Array
  -> 循环节点
  -> 导入 MaxKB 附件到业务系统
```

### 7.4 候选字段统一处理

场景：

```text
普通字段、组件字段、AI 提取字段都可能参与草稿更新。
```

链路：

```text
变量聚合 fieldValues：Dict 或 Array
  -> 工具节点标准化
  -> 变量赋值保存草稿
```

## 8. 易错点

```text
1. 以为变量聚合会自动智能合并，其实它按选择的策略固定合并。
2. 第一非空值策略下，变量顺序错误导致低优先级值被先选中。
3. Array 策略输出结构不符合后续循环节点预期，需要实测。
4. Dict 策略忘记配置 Key，或 Key 与工具入参字段名不一致。
5. 把不同业务类型变量放进同一组，后续输出难以理解。
6. 分组名保持 Group1，正式链路后续很难知道它代表什么。
7. 多个分支可能都非空时，用第一非空值会丢弃后面的值。
8. 把变量聚合当变量赋值使用，误以为它会保存会话状态。
```

## 9. 推荐用法

```text
1. 多分支统一出口优先用“返回每组的第一个非空值”。
2. 多个同类结果要保留时用 Array。
3. 组装工具入参对象时用 Dict。
4. 正式链路把 Group1 改成业务名，例如 replyText、submitPayload。
5. 聚合后如果要跨轮使用，再接变量赋值保存到会话变量。
6. 聚合变量顺序和 Key 值都要按业务协议明确写，不要临时凑。
```

## 10. 与变量赋值 / 变量拆分的区别

| 节点 | 作用 | 常见输入 | 常见输出 |
| --- | --- | --- | --- |
| 变量赋值 | 保存或清空变量状态 | 前置节点输出 / 自定义 / null | 更新后的全局变量或会话变量 |
| 变量拆分 | 从 JSON 中取字段 | JSON 对象 / 数组 | 多个拆分字段 |
| 变量聚合 | 把多个变量合成一个输出 | 多个变量 | 第一非空值 / Array / Dict |

简单记法：

```text
变量赋值：存起来。
变量拆分：拆出来。
变量聚合：合起来。
```

## 12. 待继续核对

```text
1. Dict 策略切换后，每个变量行的 Key 输入界面长什么样。
2. Array 策略实际输出是数组值，还是带字段名的数组对象。
3. 第一非空值策略里，空字符串、null、[]、{} 分别是否算空。
4. 多个分组时输出参数命名是否严格跟随分组变量名。
5. 聚合后输出是否保留原始变量类型。
6. 同一组内变量类型不一致时，节点是否报错。
7. 变量聚合是否有异常捕获配置。
8. 聚合输出能否直接作为循环节点数组输入。
```
