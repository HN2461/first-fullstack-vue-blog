# 工具、API 接入与安全规范

## 1. 选择接入方式

| 方式 | 适合场景 | 关键风险 |
| --- | --- | --- |
| MaxKB 公开链接 | 快速上线官方聊天页面 | URL 参数、访问限制、客户端适配 |
| 嵌入第三方代码 | 业务系统内嵌官方页面 | 域名白名单、身份与页面样式 |
| API Key + 服务端中转 | 自定义聊天 UI、统一鉴权 | 中转层开发、流式解析和会话管理 |
| 浏览器直连 API | 仅内部调试和原型 | API Key 暴露、CORS、滥用 |

生产自定义 UI 优先使用后端中转，不把长期 API Key 打进前端包或浏览器网络请求。

## 2. 当前官方 API 基线

MaxKB v2 当前官方文档确认智能体支持 OpenAI 兼容调用和系统 API。系统 API 的具体 Swagger 地址与 API Key 应从目标智能体“概览”页面获取。

本资料库已经验证的 v2 路径形态包括：

```text
GET  /chat/api/application/profile
GET  /chat/api/open
POST /chat/api/chat_message/{chatId}
POST /chat/api/{applicationId}/chat/completions  # OpenAI 兼容入口以概览给出的 Base URL 为准
```

API 路径属于版本敏感事实。不要仅凭历史文档手写 `/api/application/...` 或固定域名；每个目标智能体都从概览复制 Swagger、Base URL 和 API Key 后再联调。

## 3. 参数与密钥分层

| 数据 | 推荐位置 | 禁止做法 |
| --- | --- | --- |
| 当前用户身份 | 业务后端签发，运行时动态传入 | 写死在智能体默认值或文档 |
| 业务 API 根地址 | 环境配置或受控接口传参 | 散落在多个工具代码中 |
| 服务密钥/API Key | 工具启动参数、服务端密钥管理 | 放公开 URL、AI 提示词、前端包 |
| 租户/组织标识 | 由可信后端或受控环境注入 | 完全信任用户可修改的 URL 参数 |
| 会话业务状态 | 会话变量 | 放长期记忆或让模型自行回忆 |

接口传参是数据入口，不天然可信。业务后端必须重新验证用户、租户、权限和资源归属。

## 4. 工具设计规范

官方工具支持启动参数、输入参数、Python 内容和输出参数。实战中建议：

```text
启动参数：API Key、数据库连接信息、固定服务配置。
输入参数：当前问题、资源 ID、分页、业务字段等运行时数据。
输出参数：稳定 JSON 信封，不直接返回不可控对象。
```

工具代码必须处理：

- URL 拼接和编码，避免重复 `/api` 或双斜杠。
- 超时，不允许请求无限等待。
- 可重试与不可重试错误的区别。
- 写操作幂等键，防止用户重发、网络重试或模型重复调用。
- 响应 Content-Type、HTTP 状态和 JSON 解析失败。
- UUID、datetime 等对象的可序列化转换。
- 日志脱敏，不打印 token、Cookie、Authorization 和完整敏感响应。
- 返回给用户的错误与开发追踪错误分离。

## 5. 自定义工具依赖

官方文档允许进入 MaxKB 容器使用 `pip install` 安装第三方依赖，但在公司服务器场景中这属于平台运维变更：

```text
1. 开发者不要自行进入容器或修改全局 Python 环境。
2. 优先使用当前环境已有依赖或 Python 标准库。
3. 确需依赖时提交包名、版本、许可证、用途和安全风险给管理员。
4. 管理员安装后记录环境版本，并验证升级或重建容器后依赖仍存在。
5. 不允许工具在运行时自动 pip install 或下载执行未知代码。
```

## 6. MCP 使用边界

MCP 适合复用标准化外部工具，但必须确认：

- 目标模型支持函数调用。
- MCP 服务地址、协议和工具参数与当前 MaxKB 版本兼容。
- MaxKB 到 MCP 的网络可达，MCP 有独立鉴权和授权。
- 工具描述不会诱导模型调用高风险动作。
- 高风险 MCP 工具仍需要业务确认、权限和幂等校验。

官方 `v2.8.0` 和 `v2.10.4-lts` 发布说明都包含 MCP、工具沙箱、权限或命令执行相关安全修复。版本不足时不要扩大 MCP 和自定义工具的公开使用范围，应先由管理员评估升级。

## 7. 文件与附件

MaxKB 文件上传结果不等于业务附件。标准链路：

```text
用户上传文件
  -> MaxKB 产生文件对象/内部标识
  -> 受控工具读取或转存
  -> 业务后端校验类型、大小、权限与病毒风险
  -> 业务系统返回自己的附件 ID
  -> 后续提交只使用业务附件协议
```

本地文档记录的 `/admin/oss/file/{file_id}` 属于当前环境内部路径实测，不是官方公开稳定 API。其他项目不能直接依赖；优先使用目标版本 Swagger、公开 API 或由公司提供的文件代理接口。

## 8. HTML、图表和快捷问题安全

`quick_question` 只会把文本再次发送给智能体，不等于执行后端动作或页面跳转。

`html_rander`、`echarts_rander` 属于增强渲染能力。官方 `v2.8.0` 发布说明修复过相关 XSS 和代码注入漏洞，因此必须：

```text
1. 先确认目标环境版本和官方安全修复状态。
2. HTML 模板由固定节点或工具生成，不让模型自由生成任意标签、脚本和事件。
3. 对变量内容做 HTML/URL 转义和允许列表校验。
4. 不把 token、内网 URL、文件内部 ID 或隐私数据拼入页面。
5. 正式提交、审批、支付、签名、人脸和附件上传由真实业务链路完成。
6. 在公司嵌入容器、移动端和公开页面分别回归渲染行为。
```
