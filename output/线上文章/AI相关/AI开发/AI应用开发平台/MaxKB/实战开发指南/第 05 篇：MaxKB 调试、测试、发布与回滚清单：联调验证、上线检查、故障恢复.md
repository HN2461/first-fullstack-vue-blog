# 第 05 篇：MaxKB 调试、测试、发布与回滚清单：联调验证、上线检查、故障恢复

## 1. 调试分层

| 层级 | 目标 | 主要工具 |
| --- | --- | --- |
| 节点级 | 单个工具、模型、检索或转换是否正确 | 节点调试、工具调试、命中测试 |
| 分支级 | 条件、变量和状态是否正确流转 | 执行详情、会话变量、异常分支 |
| 端到端 | 从用户输入到最终结果是否可用 | 高级智能体调试 |
| 发布入口 | 公开链接、嵌入或 API 是否与调试一致 | 正式入口、网络请求、业务日志 |
| 回归 | 修改没有破坏旧能力 | 固定测试集、历史问题集 |

不要只看最终回复。执行详情中的节点状态、输入输出、耗时和异常才是定位问题的主要证据。

## 2. 基础功能测试矩阵

每个功能至少覆盖：

```text
正常输入
缺少必填
错误类型
空字符串/空数组/null
超长文本
特殊字符与中文
用户取消或退出
同一会话连续操作
新会话重新开始
重复点击/重复发送
并发或快速切换会话
```

## 3. 业务 API 异常矩阵

```text
401：用户登录态失效。
403：用户无权访问目标资源。
404：资源已删除或 ID 错误。
409：重复提交、状态冲突或幂等命中。
400/422：字段或业务规则不通过。
429：模型、接口或平台限流。
5xx：业务服务异常。
超时：MaxKB 到业务服务不可达或响应过慢。
非 JSON：网关错误页、代理页或异常文本。
HTTP 200 + 空数据：不是系统异常，应走明确空结果分支。
```

每种异常都验证：用户提示、状态是否清理、是否可重试、是否产生重复副作用、是否保留 requestId。

## 4. 状态与分支测试

- 互斥分支汇合节点是否使用“任一”。
- 并行汇总是否真的需要“所有”。
- 退出、取消、成功和失败后旧会话变量是否清理。
- 字符串 `"false"`、布尔 `false`、字符串 `"[]"`、数组 `[]` 是否被正确区分。
- 节点重命名后所有变量引用是否重新绑定。
- 历史聊天记录是否把上一个任务的上下文带入当前任务。
- 禁用节点后后续节点是否按预期不执行。
- 循环一定存在 Break、上限和异常出口。

## 5. 知识库测试

- 真实问题集命中正确文档和分段。
- 无答案时不会编造，也不会命中过期或无权文档。
- 向量、全文、混合检索的结果有对比记录。
- 标签筛选没有排除正确文档或放入错误租户文档。
- 文档替换、重新向量化、禁用和删除后的行为已验证。
- 回答展示知识来源时，来源链接和下载权限正确。

## 6. 安全测试

```text
1. URL 或 form_data 篡改 tenantId、userId、resourceId。
2. 使用 A 用户身份读取 B 用户数据。
3. 让模型输出提示词、启动参数、API Key 或内部 URL。
4. 在用户输入、知识库、工具返回中注入 HTML、脚本和特殊标签。
5. 上传超大、错误类型、伪造后缀或无权限文件。
6. 重放同一个高风险写请求。
7. 使用过期、禁用或错误 API Key。
8. 调用未授权工具、知识库、子智能体或 MCP。
```

任何越权问题都应停止发布并交给管理员或后端修复，不能只用提示词“禁止访问”处理。

## 7. 发布前检查

```text
[ ] 记录当前 MaxKB 版本和智能体发布历史版本。
[ ] 保存并调试通过，画布无孤立和不可达业务节点。
[ ] 模型、知识库、工具、MCP、子智能体已启用并有权限。
[ ] 接口传参默认值不包含真实用户 token 和不应暴露的密钥。
[ ] AI/工具中间输出按需关闭，异常堆栈不展示给用户。
[ ] 写操作具备权限、确认、幂等和失败恢复。
[ ] 完成正常、异常、重复、退出和新会话回归。
[ ] 使用正式公开链接/嵌入/API 再验证一次。
[ ] 发布历史命名可识别，例如“2026-07-19-附件与异常处理修复”。
[ ] 导出 .mk、.tool、知识库或依赖说明，不覆盖稳定备份。
```

## 8. 发布后冒烟

建议选择 5 到 10 个最高风险用例：

1. 一个最常用正常流程。
2. 一个需要补充字段或选择的流程。
3. 一个知识库有答案问题和一个无答案问题。
4. 一个业务 API 空结果。
5. 一个鉴权或权限失败。
6. 一个写操作确认和重复提交。
7. 一个文件或附件场景。
8. 一个移动端/嵌入页面场景。

检查对话日志、工具执行记录和业务后端 requestId 是否对应。

## 9. 回滚策略

优先使用官方发布历史恢复已验证版本。回滚前记录：

```text
当前问题版本
目标恢复版本
问题复现输入
是否涉及模型、知识库、工具或后端变化
是否存在新数据或副作用
回滚后验证用例
```

仅恢复智能体历史版本不一定能恢复外部依赖。如果同时更改了工具、知识库、模型、接口或公司前端，还要分别回滚或兼容。

## 10. 导出包注意事项

```text
1. .mk 是应用配置交付物，不是完整环境快照。
2. 官方说明模型和知识库选择信息不随高级智能体导出。
3. 导入后逐项重新绑定并调试模型、知识库和权限。
4. .mk 内部序列化结构不是公开稳定协议；半自动改包只处理可信来源和复制包。
5. 工具 .tool 导入后默认可能处于禁用状态，需要核对启动参数和权限。
6. 知识库导入后复核向量模型、文档、标签、来源权限和命中效果。
```
