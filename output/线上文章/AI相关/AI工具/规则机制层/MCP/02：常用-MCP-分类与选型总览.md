# 02：常用 MCP 分类与选型总览

复核日期：2026-07-04

> 2026-07 复核结论：分类方法仍然成立，但要补一个版本提醒：MCP 当前稳定规范是 `2025-11-25`，draft 规范仍在演进。本文按“前端开发能力分类”选型，不等同于 MCP 官方 primitive 分类。

## 一、先定规则：按能力分类，不按热度堆列表

这份清单的目标是长期可维护。  
所以第一层先看“能力类别”，第二层再看“具体工具”。

建议你今后都按这个顺序判断：

1. 我当前任务缺什么能力
2. 这类能力是否需要 MCP 接入
3. 在这类 MCP 里选哪一个实现

## 二、前端开发最常用的 MCP 能力分类

先说明一个容易混淆的点：  
本篇这里的“浏览器类、文件类、搜索类”，是按业务场景做的能力分类，不是 MCP 官方 primitive 分类。

官方更关心的是 server 暴露出来的能力原语，例如：

1. `tools`：执行动作
2. `resources`：读取内容
3. `prompts`：复用模板

所以一个“搜索与知识检索类 MCP server”内部，往往既会有搜索 tool，也可能有可直接阅读的 resource。

## 2.1 浏览器自动化类 MCP

- 作用：页面读取、点击、输入、截图、抓日志、看网络请求
- 典型用途：UI 故障复现、前端联调排障、回归巡检
- 常见示例：Chrome DevTools MCP、Playwright MCP
- 适配建议：先在测试环境跑通，再决定是否纳入常规流程

## 2.2 文件系统与代码仓库类 MCP

- 作用：读取文件、搜索代码、修改内容、组织文档资产
- 典型用途：批量文档更新、脚本化修订、知识库整理
- 常见示例：本地文件系统型 server、仓库上下文型 server
- 适配建议：严格目录权限，避免不必要的全盘访问

## 2.3 命令执行与开发环境类 MCP

- 作用：运行终端命令、执行构建/测试脚本、采集运行输出
- 典型用途：自动化验证、快速定位构建错误、脚本编排
- 常见示例：shell/terminal 能力型 server
- 适配建议：高风险命令必须加审批与白名单

## 2.4 数据库与数据查询类 MCP

- 作用：结构化查询、读写受控数据、分析结果回传
- 典型用途：联调数据核验、报表排查、业务数据对齐
- 常见示例：SQL/NoSQL 对接型 server
- 适配建议：默认只读账号，写操作单独审批

## 2.5 搜索、阅读与知识检索类 MCP

- 作用：联网搜索、阅读资料、文档查询、内部知识库问答
- 典型用途：查最新规范、核对 API 变更、阅读官方文档、快速补全背景信息
- 常见示例：搜索引擎型、文档检索型、企业知识库型 server
- 适配建议：高时效问题先查证据，再给结论

如果你想更细分，可以这样理解：

1. “搜索资料”更偏 `tools`，因为它需要主动发起查询动作
2. “阅读内容”更偏 `resources`，因为它是在读取已有材料
3. “知识问答”通常是前两者组合后，再由模型做总结

## 2.6 设计与多媒体处理类 MCP（扩展）

- 作用：图像生成、素材处理、页面截图标注、文稿/PDF/表格处理
- 典型用途：前端协作产出、演示材料自动生成、资料整理
- 常见示例：图片处理型、文档处理型 server
- 适配建议：关注数据脱敏和版权边界

## 三、前端开发者的实用选型策略

如果你只想先接一类 MCP，优先顺序建议：

1. 浏览器自动化类
2. 文件系统/仓库类
3. 命令执行类
4. 搜索检索类
5. 数据库类

原因很简单：

1. 这几类最贴近日常前端问题闭环
2. 学会后能立刻提升排障和交付效率
3. 面试里也最容易讲出真实案例

## 四、面试可直接复述的回答框架

当被问“你常用哪些 MCP”时，建议不要背工具名清单，直接按分类回答：

1. 我先按能力分类选 MCP，而不是按流行度
2. 我常用的是浏览器、文件系统、命令执行三类
3. 浏览器类负责复现问题，文件类负责改与查，命令类负责验证
4. 所有接入都要做最小权限与审计策略

这套回答比“我会 XX 工具”更像工程化思维。
