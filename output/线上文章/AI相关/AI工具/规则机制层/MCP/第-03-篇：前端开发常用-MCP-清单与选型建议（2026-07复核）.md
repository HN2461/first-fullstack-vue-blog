# 第 03 篇：前端开发常用 MCP 清单与选型建议（2026-11复核）

复核日期：2026-11-18。本文核对官方文档和仓库，推荐组合属于工程建议；软件版本、套餐、认证方式与宿主支持范围仍需在实际安装时确认。

前端常见需求是查文档、看仓库、定位页面问题、读取设计上下文和保留回归测试。先找当前工作流缺的能力，再决定增加 MCP、CLI 或插件。

## 一、按任务选择工具

| 工具 | 主要用途 | 本轮核验的接入与边界 |
| --- | --- | --- |
| Context7 | 按库与版本检索文档 | 官方支持 setup、远程 MCP 和插件；结果仍需核对版本与原始来源 |
| GitHub MCP | 仓库、Issue、PR、Release 上下文 | 官方远程服务与本地实现分开配置；限制工具集与账号权限 |
| Chrome DevTools | 控制台、网络、DOM、性能排障 | 同时提供 MCP、CLI、Skills；默认按需启动浏览器 |
| Playwright MCP | 页面探索与连续交互 | 官方建议编码代理同时评估 CLI + Skills；持久上下文也有成本 |
| shadcn MCP | 搜索、查看、安装注册表项目 | 只在 shadcn/注册表工作流中引入，不代替已有组件系统 |
| Figma MCP Server | 设计上下文与设计协作 | 官方优先推荐远程服务；桌面版与远程版能力范围不同 |
| Exa MCP | 网页与代码检索、研究 | 官方提供托管入口；认证、额度与工具范围按当前文档确认 |
| Tavily MCP | 搜索、正文提取、专题研究 | 官方支持远程 HTTP/OAuth，stdio 客户端可使用桥接 |
| Brave Search MCP | 搜索、新闻、图片等信息查询 | 使用 Brave 官方维护实现；需要 API 凭据和对应服务额度 |

不建议为了凑齐清单同时启用多个作用相近的浏览器或搜索 server。工具定义、页面快照和结果也占用上下文；少量明确分工的工具更便于排障。

## 二、文档与仓库上下文

### 2.1 Context7

- 官方入口：[安装指南](https://context7.com/docs/installation)。
- 当前安装指南提供 `npx ctx7 setup`，自动发现支持的代理并引导 OAuth 登录；其他客户端可连接 `https://mcp.context7.com/mcp`。
- 文档检索常见流程是先 `resolve-library-id` 确认库，再 `query-docs` 查询具体概念。问题应写清框架、版本和任务，避免一次混入多个无关主题。
- 已有插件或连接器提供 Context7 时，直接复用该入口。不要重复安装多个相同 server。
- 对升级或兼容结论，继续打开命中的官方文档，确认对应版本；检索工具不保证每个项目的每次发布都已收录。

适合查 Vue/React、构建工具和组件库的新参数。查询中不要携带私有源码、凭据或内部业务数据。

### 2.2 GitHub MCP

- 官方入口：[GitHub MCP Server](https://github.com/github/github-mcp-server)。
- 官方托管入口为 `https://api.githubcopilot.com/mcp/`；OAuth 可用性取决于宿主集成，PAT 是另一条接入方式。
- 本地实现与远程服务在网络、认证和运维成本上不同。当前本地官方实现也提供 OAuth 登录路径，不能继续概括为“本地只能 PAT”。
- 优先开启只读模式、限制工具集；底层 GitHub token/App 权限同样要收紧。服务器只读开关不能替代账号授权管理。
- GitHub Enterprise Server 的支持方式需按官方企业说明配置，不能直接套用 github.com 的托管入口。

典型用法是核查 breaking changes、追踪 Issue/PR 或查看真实实现。已有 `git` / GitHub CLI 足够完成任务时，可继续使用已有工具。

## 三、浏览器调试与回归

### 3.1 Chrome DevTools MCP / CLI

官方入口：[Chrome DevTools for agents](https://github.com/ChromeDevTools/chrome-devtools-mcp)。

MCP 的常见启动方式：

```text
npx -y chrome-devtools-mcp@latest
```

默认在首次调用需要浏览器的工具时启动 Chrome，建立 MCP 连接本身不会打开浏览器。已有浏览器连接需要另行配置 `--browser-url` 或满足 `--autoConnect` 的前提。

项目同时提供 `chrome-devtools` CLI，以及页面调试、CLI、无障碍、Cookie、LCP、内存泄漏和连接排障等 Skills。使用插件时一起维护服务器和 Skills 的版本；手动复制 Skills 后，升级工具也应更新说明文件。

适合抓控制台错误、检查失败请求、分析性能 trace。性能分析可能查询 CrUX；`--no-performance-crux` 与 `--no-usage-statistics` 控制不同的数据收集通道，不能混为一个开关。Windows 配置见第 07 篇。

### 3.2 Playwright MCP 与 CLI + Skills

官方入口：[Playwright MCP](https://github.com/microsoft/playwright-mcp)、[Playwright CLI](https://github.com/microsoft/playwright-cli)。

MCP 安装入口仍为：

```text
npx -y @playwright/mcp@latest
```

官方 README 明确区分两种用途：

- MCP 适合需要持续浏览器状态、结构化页面观察和交互推理的探索流程。
- CLI + Skills 适合已有终端的编码代理，用简洁命令减少工具 schema 和页面树占用的上下文。

通过 MCP 点完一次流程，不等于建立了稳定回归。需要长期重复执行时，把关键步骤固化为 Playwright 测试或团队现有自动化脚本，补上断言、测试数据和失败诊断。

## 四、设计与组件交付

### 4.1 shadcn MCP

官方入口：[shadcn MCP](https://ui.shadcn.com/docs/mcp)。它用于连接注册表、搜索/查看组件与安装项目。常见 server 入口是：

```text
npx shadcn@latest mcp
```

接入前检查项目的 `components.json`、框架和现有组件约定。对 Vue + Ant Design Vue 这类已有组件语言的项目，不应因为 MCP 能生成组件就引入另一套 UI 系统。

### 4.2 Figma MCP Server

官方入口：[Figma MCP Server](https://developers.figma.com/docs/figma-mcp-server/)。

当前官方优先推荐远程入口 `https://mcp.figma.com/mcp`，无需运行 Figma 桌面应用；桌面服务器是另一条接入路径。官方文档已包含写入画布、代码到画布等能力，因此不能再笼统称为“只读设计信息桥梁”。具体工具、文件权限、席位和调用额度以当前账户与服务说明为准。

前端常见用途仍是读取布局、变量和组件映射，再落实到项目设计规范。写入设计文件时应明确目标与变更范围；拿到设计上下文也不代表页面已满足可访问性、响应式和业务验收。

## 五、外部搜索按需选一个

| 服务 | 官方入口 | 适合的任务与限制 |
| --- | --- | --- |
| Exa | [Exa MCP](https://exa.ai/docs/reference/exa-mcp) | 托管入口 `https://mcp.exa.ai/mcp`；当前文档允许在免费限额内试用 search/fetch，Agent 等能力需要相应认证 |
| Tavily | [Tavily MCP](https://docs.tavily.com/documentation/mcp) | `https://mcp.tavily.com/mcp/`，远程 HTTP 支持 OAuth；正文提取、批量研究仍受额度和访问权限约束 |
| Brave | [Brave 官方 MCP](https://github.com/brave/brave-search-mcp-server) | 官方包 `@brave/brave-search-mcp-server`，使用 `BRAVE_API_KEY` 或受支持的密钥文件；旧参考实现已归档 |

搜索结果和网页正文可能包含错误、过期内容及提示注入。来源中的操作要求不是用户授权；技术事实优先追溯到官方文档、发行说明和对应源码。

## 六、前端实用组合

| 场景 | 建议起点 | 增加能力的条件 |
| --- | --- | --- |
| 日常编码 | 文档检索 + 已有文件/终端工具 | 页面问题确实需要观察时增加一种浏览器入口 |
| 开源升级排障 | 文档检索 + GitHub 上下文 | 需要复现交互时再加入浏览器 |
| 设计交付 | Figma + 对应组件库文档 | 项目使用 shadcn 注册表时再加入 shadcn MCP |
| UI 自动化维护 | Playwright CLI/测试，或已有回归体系 | 探索式交互需要连续状态时使用 MCP |

安装版本、MCP 协议版本和插件版本分别记录。演示可使用 `@latest`；团队需要可复现环境时，固定经过验证的版本，升级后检查配置、工具参数与 Skills 是否匹配。

## 七、UI 资料搜索到落地

搜索可以组合这些主题：`design tokens spacing typography`、`admin table filter pagination accessibility`、`mobile form error states`、`figma code connect component mapping`。时间限定只用于查近期变更，不把文章新旧当成正确性的唯一依据。

1. 先明确实际组件、状态、响应式与可访问性要求。
2. 有 Figma 时读取相关设计节点，缺少时使用项目现有规范。
3. 通过官方文档核对当前框架/组件库用法。
4. 实现后执行项目构建和必要测试；需要真实页面验收时按项目授权使用浏览器。
5. 把需要重复验证的流程保存为可维护测试或脚本。
