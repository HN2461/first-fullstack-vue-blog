# 第 01 篇：AI 工具规则文档是什么，为什么需要它

> 核验日期：2026-11-18。本文根据各工具当前官方文档整理；支持情况必须同时看产品、客户端、版本和加载条件。文末列出一手来源。

[[toc]]

## 一、规则文档解决什么问题

你让 AI 给现有项目增加一个接口，它却用了错误的包管理器、过时的测试框架，或者把文件放进错误目录。问题通常在于：项目的约定没有在这次任务中成为可见上下文。

规则文档把长期有效的信息放在仓库或用户配置目录，让工具在启动、处理匹配文件或判断任务相关时读取。它可以是 `AGENTS.md`、`CLAUDE.md`，也可以是带 frontmatter 的目录规则。

它不要求模型永久记住整段对话。即使工具已经提供自动记忆、会话恢复或上下文压缩，团队仍需要一个能审阅、能版本控制的项目规范入口。

规则最适合解决三类问题：

- **重复告知**：构建命令、项目结构和禁改目录不必每次重新解释。
- **团队一致性**：成员从同一仓库读取相同约定，规范修改可以走代码审阅。
- **任务边界**：明确改哪些目录、怎样验证，以及哪些操作需要当前任务授权。

规则有助于减少纠错，但不能把没有出处的“每周节省多少次修改”当作研究结论，也不能把遵守率当作固定保证。

## 二、一个可维护的最小规则文件

下面是项目模板，技术栈和命令需要替换成仓库实际值：

```markdown
# 项目约定

## 技术栈与入口
- 前端使用 Vue 3，后端使用 Node.js。
- frontend 与 backend 分别安装依赖和运行命令。
- 包管理器使用 npm；以各目录 package.json 为准。

## 修改边界
- 新接口沿用现有业务模块目录与参数校验方式。
- 不修改生成文件，不把凭证写入源码或日志。
- 涉及数据库数据变更时先预览影响范围，并保留可恢复备份。

## 代码约定
- JavaScript 使用 2 空格缩进、单引号、不加分号。
- 所有源码与配置使用 UTF-8 无 BOM。

## 验证与交付
- 前端修改运行 npm run build。
- 后端修改运行 npm test；实际命令以对应 package.json 为准。
- 交付时说明改动、验证结果及尚未解决的问题。
```

文件应写“为什么需要这条边界”，而不只是堆砌“必须”“永远”。可以把详细流程链接到单独文档，但**普通 Markdown 链接不等于所有工具都会自动加载被链接内容**。

## 三、规则如何进入上下文

理解规则时要区分三个步骤：

1. **发现**：工具支持哪些文件名，扫描哪些目录，是否信任工作区。
2. **激活**：启动即读、匹配文件时读、模型按描述选择，还是用户手动指定。
3. **执行**：模型根据上下文完成任务，真实命令仍受工具权限、沙箱和服务端授权限制。

因此，规则文件存在，不代表已经加载；已经加载，也不代表能够绕过权限。`AGENTS.md` 中写“可以部署”不会自动获得服务器凭证，也不会替代平台的权限策略。

## 四、七类工具的当前入口

| 工具 / 使用面 | 主要入口 | 加载特点与边界 |
| --- | --- | --- |
| Codex | `AGENTS.md`、`AGENTS.override.md` | 结合全局指导与项目目录链；同目录候选文件有选择顺序，见第 02 篇 |
| Claude Code | `CLAUDE.md`、`.claude/rules/*.md`、`AGENTS.md` | v2.1.277+ 可直接读取 AGENTS；默认是否读取取决于项目路径上是否有 CLAUDE 文件 |
| Cursor Agent | `.cursor/rules/*.mdc`、`AGENTS.md` | 支持项目根和子目录 AGENTS；MDC 支持始终、文件匹配、智能选择、手动四种激活方式 |
| Devin Local / Devin CLI | `AGENTS.md`、`.devin/rules/*.md` | 新版读取 Devin 规则并兼容旧 Windsurf 文件；旧客户端不能反向假定支持所有新路径 |
| Kiro | `.kiro/steering/*.md`、`AGENTS.md` | Steering 有 inclusion 模式；AGENTS 不支持这些模式，作为 always included 指导 |
| Gemini CLI | `GEMINI.md` | 全局、工作区与 JIT 上下文；可用 `context.fileName` 配置 AGENTS 等名称 |
| GitHub Copilot | `.github/copilot-instructions.md`、`.github/instructions/**/*.instructions.md`、Agent 指令文件 | GitHub.com、IDE、CLI、cloud agent、code review 的支持矩阵不同 |

本表刻意不写一个跨工具统一的“优先级”。例如，Cursor 明确给出 Team → Project → User 的规则优先关系；Claude 的多份 CLAUDE 内容是组合上下文；Copilot 多数客户端不定义统一覆盖顺序。这些行为不能互相套用。

## 五、AGENTS.md 能共享什么

AGENTS.md 是开放的 Markdown 指令格式，官方入口是 [agents.md](https://agents.md/) 和 [agentsmd/agents.md](https://github.com/agentsmd/agents.md)。它提供一个容易协作的公共文件名，没有要求所有客户端使用同一个配置解析器。

适合共享的内容包括：

- 项目目录和业务边界。
- 依赖安装、构建、测试的真实命令。
- 团队已经确认的语言、编码和提交规范。
- 可公开到仓库的业务背景与验收标准。

需要单独确认的内容包括：

- 子目录文件是启动时加载还是按需加载。
- 同目录 `AGENTS.override.md`、`CLAUDE.md` 与 `AGENTS.md` 的关系。
- `@文件路径` 是导入语法、提示性引用，还是普通文本。
- 大文件是否截断，以及组织规则是否有额外优先权。

截至本次核验，不能再笼统写“Claude Code 不支持 AGENTS.md”或“Cursor 只支持根目录”。同样不能写“所有工具都支持 Codex 的 override 文件”。

## 六、Rules、Memory、Skill、MCP、Plugin 的分工

| 机制 | 主要职责 | 适合放什么 |
| --- | --- | --- |
| Rules / 项目指令 | 持久提供项目约定与边界 | 目录、编码、验证要求 |
| Memory | 保存工具允许持久化的经验和偏好 | 用户纠正、项目背景、外部信息位置 |
| Skill | 提供按需使用的工作流程及配套资料 | 迁移步骤、文档生成、审查流程 |
| MCP | 以协议连接工具与上下文能力 | 查询系统、调用外部操作 |
| Plugin | 分发一组可安装的扩展能力 | Skills、MCP、Hooks 等组合，内容取决于宿主 |
| 当前对话 | 说明这次任务的目标和约束 | 修改范围、交付格式、临时限制 |

规则中可以提示“涉及发布时阅读发布流程”，流程本身则适合按需加载。把所有流程、API 参考和历史记录都常驻上下文，会使真正需要的约定更难定位。

## 七、规则与强制控制的界线

“禁止泄露密钥”值得写入规则，但密钥仍应由权限、环境变量管理和日志脱敏保护。“提交前必须测试”值得写入规则，但团队要求的强制门禁应由 CI 实现。

Hooks 可以在宿主支持的事件执行程序检查；是否能阻断操作，要看事件、退出码协议和客户端配置。它也不能取代服务端 RBAC、数据库权限或生产保护。

对第三方仓库、下载的规则与插件，审阅它们会引导读取和执行什么。项目文字描述不应成为扩大授权范围的依据。

## 八、怎样落地并检查有效性

1. 从一个短文件开始，先解决团队反复遇到的三到五个问题。
2. 为目录专属规则选用该工具实际支持的嵌套文件或 glob。
3. 通过客户端的已加载文件列表、上下文检查或小任务确认发现与激活。
4. 把稳定结论提交仓库；个人偏好按宿主规则保存在用户或忽略文件里。
5. 工具升级、目录移动、构建命令变化时同步复核。
