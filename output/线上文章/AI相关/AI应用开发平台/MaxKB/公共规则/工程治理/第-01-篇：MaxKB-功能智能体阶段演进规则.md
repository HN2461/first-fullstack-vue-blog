# 第 01 篇：MaxKB 功能智能体阶段演进规则

> 文档状态（2026-07-01）：本文记录 MaxKB 功能智能体的阶段演进规则。目的类似代码分支管理：复杂改造先复制智能体、单独开阶段目录、保留稳定基线，避免新功能或新试验把已跑通链路改乱。

## 1. 核心原则

MaxKB 智能体开发按下面方式推进：

```text
一个功能智能体
  -> 多个阶段目录
  -> 每个阶段有自己的目标、节点配置、工具配置、联调记录和结论
  -> 阶段稳定后再决定是否合并为新基线
```

不要把所有阶段都写进一个大文件，也不要把不同功能智能体的阶段混在一起。

## 2. 什么是功能智能体

功能智能体指一个相对独立的业务能力，例如：

```text
业务办理智能体
审核查看智能体
组件处理智能体
总智能体
其他后续业务智能体
```

每个功能智能体都应该有自己的目录。

推荐目录结构：

```text
10-功能智能体/01-某功能智能体/
  README.md
  00-智能体基线/
  01-第一阶段/
  02-第二阶段/
  03-第三阶段/
  90-优化试验/
```

## 3. 什么时候必须新开阶段目录

遇到下面情况，不要直接改稳定智能体和稳定文档，应新开阶段目录：

```text
复制当前智能体继续改造
新增一个大功能
重构关键链路
引入新的后端接口
替换多个节点或大提示词
引入新的子智能体调用
性能优化可能影响稳定链路
用户体验改造可能改变主流程
当前方案不确定，需要 A/B 或试验线
```

简单文案、单个变量名修正、单个工具参数修正，可以补到当前阶段文档，不必新开阶段。

## 4. 阶段目录命名

推荐命名：

```text
00-智能体基线/
01-阶段名称/
02-阶段名称/
03-阶段名称/
80-总智能体契约/
90-优化试验/
91-专项试验名称/
99-归档/
```

命名规则：

```text
00：当前功能智能体基线、总览、稳定版本说明
01-79：功能阶段
80-89：对接总智能体、子智能体协作阶段
90-98：优化、提速、试验线
99：归档、废弃方案、历史说明
```

目录名应表达阶段目标，不要只写日期。

## 5. 每个阶段目录建议包含

每个阶段目录至少建议有：

```text
README.md
01-目标与边界.md
02-后端接口说明.md
03-MaxKB工具配置.md
04-智能体编排配置.md
05-联调记录.md
06-阶段结论与是否合并.md
```

不是每个阶段都必须全量创建。原则是：

```text
用到什么写什么。
但 README 必须有。
阶段目标、边界、当前状态必须写清楚。
```

## 6. 复制智能体后的记录要求

复制 MaxKB 智能体继续改造时，阶段 README 必须写清：

```text
原智能体名称
新智能体名称
复制原因
本阶段目标
不改动的稳定链路
允许改动的节点范围
回退方式
验收用例
是否计划合并回主线
```

示例：

```text
原智能体：业务办理助手-稳定版
新智能体：业务办理助手-新能力试验版
复制原因：验证新能力，不影响稳定链路
不改动：已上线的查询、填写、提交等稳定链路
允许改动：新能力相关工具、节点、会话变量
回退方式：继续使用原稳定智能体
```

## 7. 稳定基线和试验线

每个功能智能体都要区分：

```text
稳定基线：当前可回归、可继续使用的版本。
试验线：复制出来验证新能力或新结构的版本。
废弃线：验证失败或成本太高，不再继续的版本。
```

文档必须明确：

```text
当前推荐使用哪个智能体。
哪个智能体只是历史参考。
哪个智能体已经废弃，不要按旧记忆恢复。
```

## 8. 阶段完成后怎么处理

阶段完成后，在阶段 README 写结论：

```text
1. 已跑通什么。
2. 没跑通什么。
3. 哪些节点或工具成为新稳定口径。
4. 哪些旧节点或旧分支废弃。
5. 是否合并回当前稳定智能体。
6. 是否需要更新 02-公共规则 共用规则。
7. 是否需要更新总智能体路由输入输出。
```

如果阶段结论变成通用规则，再提炼到：

```text
02-公共规则/
```

如果只是某个功能智能体内部经验，继续留在该功能智能体阶段目录。

## 9. 和总智能体的关系

总智能体只接入稳定子智能体，不直接接入试验线。

接入总智能体前，子智能体必须至少明确：

```text
输入参数
输出结构
失败返回
是否直接回复用户
是否需要总智能体二次收口
依赖哪些全局参数
```

这些内容放在对应功能智能体阶段目录，或总智能体目录：

```text
10-功能智能体/90-总智能体路由层/
```

## 10. AI 阅读规则

后续 AI 处理 MaxKB 文档时，必须先判断：

```text
用户要改哪个功能智能体？
用户要改哪个阶段？
当前是稳定基线还是复制试验线？
是否需要更新公共规则？
是否需要更新总智能体路由？
```

不要看到“MaxKB”就读取所有目录。

不要把发起智能体历史阶段当成审核查看智能体当前规则。

不要把试验线结论直接当成稳定基线。
