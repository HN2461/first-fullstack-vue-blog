# 第 11 篇：MaxKB 指定回复节点
> 文档状态（2026-07-01）：根据空白高级智能体验证截图和通用实测经验，记录指定回复节点配置、输出和使用边界。

## 1. 节点定位

`指定回复` 属于添加组件面板中的：

```text
基础组件 -> 业务逻辑 -> 指定回复
```

节点作用：

```text
在链路末尾或某个分支末尾，明确返回一段内容给用户。
```

通用定位：

```text
指定回复是最终用户展示节点。
它不做 AI 理解、不做工具调用、不做复杂计算，主要负责把已经整理好的文本稳定展示给用户。
```

常见链路：

```text
AI 对话 / 工具 / 变量拆分 / 判断器
  -> 指定回复
```

## 2. 初始配置项

当前截图中指定回复节点包含：

| 配置项 | 初始状态 / 可见内容 | 说明 |
| --- | --- | --- |
| 回复内容 | 右侧有模式下拉，支持 `自定义` / `引用变量` | 必填 |
| 返回内容 | 开关开启 | 控制是否返回给用户 |
| 输出参数 | `内容(answer)` | 后续节点可引用 |

输出参数：

| 显示名称 | 变量名 | 说明 |
| --- | --- | --- |
| 内容 | `answer` | 指定回复最终内容 |

常用引用写法示例：

```text
{{指定回复.answer}}
```

注意：

```text
节点重命名后变量前缀会变化，必须从变量选择器复制。
```

## 3. 回复内容模式

### 3.1 自定义

当前截图中，自定义模式显示一个多行文本框。

适合：

```text
1. 固定兜底文案。
2. 简单提示。
3. 测试判断器分支是否走通。
4. 不依赖前置节点动态内容的回复。
```

示例：

```text
我没有识别到你的操作，请重新描述一下。
```

或：

```text
当前还没有正式提交，也没有保存为草稿。
请继续回复“正式提交”或“保存草稿”。
```

### 3.2 引用变量

当前截图中，引用变量模式显示：

```text
请选择检索问题
```

点击下拉后，可见变量来源分组：

```text
全局变量
开始
AI 对话
意图识别
语音转文本
图片理解
...
```

适合：

```text
1. 展示上一个 AI 对话节点整理好的 `answer`。
2. 展示工具节点生成的人话文案。
3. 展示问题优化结果或其他前置节点输出。
```

常见项目用法：

```text
整理草稿确认文案 -> 回复草稿确认
回复草稿确认 引用 整理草稿确认文案.answer
```

或：

```text
再次整理正式提交成功文案 -> 再次回复正式提交成功
再次回复正式提交成功 引用 再次整理正式提交成功文案.answer
```

## 4. 返回内容开关

当前截图中：

```text
返回内容：开启
```

指定回复节点通常应保持开启，因为它的目标就是返回给用户。

注意：

```text
如果关闭返回内容，前台可能看不到该指定回复内容。
除非这个节点只是作为中间变量传递，否则不要关闭。
```

通用经验：

```text
1. 工具节点和解析类 AI 节点常常要关闭返回内容，避免 JSON 直出。
2. 指定回复节点通常开启返回内容，作为最终展示出口。
3. 一个分支最终最好只有一个面向用户的返回出口，避免多段内容混在一起。
```

## 5. 项目高频用法

指定回复在业务项目里高频用于：

| 场景 | 用法 |
| --- | --- |
| 字段说明展示 | 引用 `整理表单字段与自动字段说明.answer` |
| 缺失字段提示 | 引用 `整理缺失字段提示文案.answer` 或工具生成文案 |
| 草稿确认 | 引用 `整理草稿确认文案.answer` |
| 提交成功 | 引用 `整理正式提交成功文案.answer` |
| 需要审批人 | 引用 `整理审批人选择文案.answer` |
| 安全验证 | 展示固定或整理后的“请到小程序完成安全验证”文案 |
| 不支持字段 | 引用不支持字段提示文案 |
| 判断器测试 | 每个分支用固定文案确认路由是否正确 |

推荐正式版结构：

```text
AI / 工具整理文案
  -> 指定回复
```

不推荐：

```text
工具节点直接返回原始 JSON 给用户
```

## 6. 与 AI 对话节点的关系

AI 对话节点适合“生成内容”，指定回复适合“稳定展示内容”。

推荐：

```text
整理草稿确认文案（AI 对话，返回内容关闭或不作为最终展示）
  -> 回复草稿确认（指定回复，引用 AI answer，返回内容开启）
```

好处：

```text
1. 最终展示出口清晰。
2. 方便关闭 AI 节点或工具节点的原始返回内容。
3. 多分支体验一致。
4. 后续要改最终文案出口时更好定位。
```

## 7. 与工具节点的关系

工具节点适合生成结构化结果或稳定文案。

如果工具输出的是用户可读文案：

```text
工具节点 -> 指定回复引用工具文案字段
```

如果工具输出的是 JSON：

```text
工具节点 -> 变量拆分 / AI 文案整理 -> 指定回复
```

注意：

```text
指定回复不适合做数组下标提取。
项目已实测：指定回复不支持 `attachment_test[0].file_id` 这类数组下标取值。
复杂结构应先用 Python 工具或变量拆分处理。
```

## 8. 易错点

```text
1. 引用变量时选错前置节点，尤其多个同名 AI 节点时。
2. 节点重命名后继续手写旧变量。
3. 工具节点返回内容没关，导致指定回复之外又展示原始 JSON。
4. 指定回复里拼接复杂 JSON、数组或对象，用户体验差。
5. 用指定回复尝试取数组下标，容易失败。
6. 多个分支共用同一个指定回复节点，但引用变量来自不同分支，可能出现未执行节点为空。
7. 在指定回复里写死“已提交成功”，但前置工具实际可能失败。
```

## 9. 当前建议

```text
1. 分支最后优先用指定回复作为用户出口。
2. 指定回复内容优先引用已经整理好的人话文案。
3. 如果是测试分支路由，可先用自定义固定文案。
4. 正式链路不要让工具原始 JSON 和指定回复同时展示。
5. 不同分支需要不同动态变量时，优先各自使用独立指定回复节点。
```

```text
3. 返回内容关闭后，后续节点是否仍能引用 `answer`。
4. 指定回复是否支持 Markdown、换行、列表等格式。
5. 多个指定回复连续执行时前台展示顺序。
```
