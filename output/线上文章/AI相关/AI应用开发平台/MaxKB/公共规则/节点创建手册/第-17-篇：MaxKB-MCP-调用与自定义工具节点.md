# 第 17 篇：MaxKB MCP 调用与自定义工具节点
> 文档状态（2026-07-01）：根据空白高级智能体验证截图、MaxKB 官方文档和工具扩展通用实践，记录 MCP 调用、自定义工具两个扩展类节点的配置、定位和使用边界。

## 1. 节点定位

当前两个节点都属于添加组件面板中的：

```text
基础组件 -> 其他
```

节点包括：

```text
MCP 调用
自定义工具
```

通用理解：

```text
MCP 调用：调用外部或已配置的 MCP Server 中的工具。
自定义工具：在当前智能体画布中直接编写 Python 工具逻辑。
```

和工具页签的区别：

| 能力 | 入口 | 复用范围 | 适合场景 |
| --- | --- | --- | --- |
| 工具页签中的工具 | 添加组件面板 -> 工具 | 系统内已创建工具，通常可复用于多个智能体 | 业务稳定工具，例如附件转存、流程表单标准化 |
| 自定义工具节点 | 基础组件 -> 其他 -> 自定义工具 | 当前智能体 / 当前节点内直接编写 | 临时处理、专用逻辑、小范围试验 |
| MCP 调用节点 | 基础组件 -> 其他 -> MCP 调用 | 调用 MCP Server 暴露的工具 | 外部系统、远程能力、标准 MCP 工具 |

注意：

```text
这里的“共享范围”是当前理解：
工具页签更像外部创建好的共享工具；自定义工具更像当前流程里直接新增的专用 Python 节点。
后续需要用正式环境权限和工具管理页面继续核对。
```

工具页签和工具创建页的详细配置另见：

```text
17-工具页签与智能体节点.md
```

## 2. MCP 调用节点

### 2.1 节点作用

官方说明：

```text
通过 MCP 服务调用工具。
```

旧版官方文档口径：

```text
通过 SSE 协议调用 MCP 服务中的工具。
```

新版工具文档补充：

```text
MCP Server Config 使用 JSON 格式填写，支持通过 SSE / Streamable HTTP 协议调用 MCP 服务中的工具。
```

项目理解：

```text
MCP 调用适合把外部系统、数据库查询、地图、浏览器、其他应用等能力封装为 MCP Server，再在 MaxKB 工作流里按节点调用。
```

### 2.2 节点配置

当前截图中，MCP 调用节点包含：

| 配置项 | 当前可见内容 | 说明 |
| --- | --- | --- |
| MCP Server Config | 右侧下拉为 `引用MCP` | 必填，选择或配置 MCP Server |
| MCP 选择框 | `请选择` | 选择已配置 MCP 或配置来源 |
| 工具 | `+ 获取工具` / 下拉选择 | 从 MCP Server 获取并选择工具 |
| 工具参数 | 暂无数据 | 选择工具后展示工具入参 |
| 输出参数 | `结果(result)` | MCP 工具执行返回结果 |

输出参数：

```text
结果(result)
```

常用引用：

```text
{{MCP调用.result}}
```

注意：

```text
节点重命名后变量前缀会变化，实际使用时从变量选择器复制。
```

### 2.3 MCP Server Config

当前截图中，MCP Server Config 右侧下拉显示：

```text
引用MCP
```

官方资料补充：

```text
MCP 支持引用 MCP 和自定义 MCP Server Config 两种方式。
```

示例配置口径：

```json
{
  "maxkb-mcp": {
    "url": "http://hostip:port/mcp",
    "transport": "streamable_http"
  }
}
```

使用建议：

```text
1. 已在工具管理中创建并启用 MCP 时，优先使用引用 MCP。
2. 临时接入或测试外部 MCP Server 时，可考虑自定义 MCP Server Config。
3. 正式环境不要把 token、secret 等敏感信息散落在多个节点里。
```

### 2.4 获取工具和工具参数

当前截图中工具区域包含：

```text
+ 获取工具
请选择
```

理解：

```text
先配置 MCP Server，再点击获取工具，MaxKB 从 MCP Server 拉取可用工具列表。
选择具体工具后，工具参数区域会出现该工具需要的入参。
```

官方旧版说明：

```text
工具参数：MCP 工具对应的请求参数，可自定义，也可引用变量。
```

项目使用建议：

```text
1. 工具参数优先引用开始节点、接口传参、会话变量或前置节点结果。
2. 复杂对象参数先用变量聚合 Dict 或自定义工具整理，再传给 MCP。
3. MCP 返回复杂结果后，后续优先接变量拆分或自定义工具标准化。
```

风险提醒：

```text
社区早期 issue 中出现过 MCP 调用自定义工具参数默认字符串，导致 Boolean / 数字类型不匹配的问题。
当前版本是否已修复需实测。
```

## 3. 自定义工具节点

### 3.1 节点作用

当前截图中，自定义工具节点是在画布中直接新增 Python 代码节点。

节点适合：

```text
1. 写小段数据转换逻辑。
2. 处理 MaxKB 节点不方便表达的 JSON、数组、字符串。
3. 临时验证工具方案。
4. 当前智能体专用逻辑，不准备沉淀成系统共享工具。
```

不适合：

```text
1. 多个智能体都要复用的核心工具。
2. 大量业务逻辑长期维护。
3. 需要统一权限、日志、版本管理的正式工具。
```

正式链路建议：

```text
稳定工具优先创建到工具管理里，通过“工具”页签复用。
画布自定义工具适合临时、局部、一次性或实验性质的逻辑。
```

### 3.2 节点配置

当前截图中，自定义工具节点包含：

| 配置项 | 当前可见内容 | 说明 |
| --- | --- | --- |
| 输入参数 | 暂无数据 / `+ 添加` | 配置 Python 代码入参 |
| 工具内容（Python） | 代码编辑器 | 编写 Python 逻辑 |
| 返回内容 | 开关，默认关闭 | 是否把节点结果直接展示给用户 |
| 输出参数 | `结果(result)` | Python 执行返回结果 |

输出参数：

```text
结果(result)
```

常用引用：

```text
{{自定义工具.result}}
```

### 3.3 添加输入参数

点击 `输入参数 -> + 添加` 后，弹出添加参数窗口。

当前截图中字段为：

| 字段 | 当前可见内容 | 说明 |
| --- | --- | --- |
| 参数名 | 输入框，最多 64 字符 | Python 代码中使用的参数名 |
| 数据类型 | 默认 `string`，下拉 | 参数类型 |
| 参数提示说明 | 输入框，最多 128 字符 | 给配置者或模型看的说明 |
| 来源 | 下拉，默认 `引用参数` | 参数值来源 |
| 是否必填 | 开关，默认开启 | 参数是否必填 |

来源下拉可见：

```text
引用参数
自定义
```

使用建议：

```text
1. 参数名用英文，例如 flowDefineId、formData、attachments。
2. 数据类型按真实数据选择，不要全用 string。
3. 引用参数适合接前置节点输出。
4. 自定义适合固定配置值或测试值。
5. 必填参数缺失时可能导致工具执行失败，正式链路前加判断器校验。
```

截图中数据类型默认显示：

```text
string
```

其他可选类型需要后续展开下拉继续核对。

### 3.4 Python 工具内容

当前截图中工具内容区域标题为：

```text
工具内容（Python）
```

使用建议：

```text
1. Python 只做确定性处理，不让它承担 AI 理解任务。
2. 输入参数先做空值和类型兜底。
3. 返回值尽量是稳定 JSON 对象，方便后续变量拆分。
4. 不要在自定义工具里硬编码敏感 token。
5. 复杂工具成熟后，建议迁移到工具管理，变成共享工具。
```

示例用途：

```text
1. 把 MaxKB 附件 file_id 列表转成业务附件协议。
2. 把 AI 提取字段转换成业务字段 key/value。
3. 把 currentApproversJson 的 "[]"、空字符串、null 统一标准化。
4. 把多个来源的字段合并为提交 payload。
```

### 3.5 返回内容开关

当前截图中：

```text
返回内容：关闭
```

通用建议：

```text
自定义工具通常关闭返回内容。
```

原因：

```text
工具结果常常是 JSON 或中间结构，直接展示给用户体验不好。
正式展示优先交给 AI 文案整理或指定回复节点。
```

适合开启的情况：

```text
1. 调试工具输出。
2. 工具返回的就是最终用户可读文本。
3. 临时验证工具执行结果。
```

## 4. MCP 调用与自定义工具对比

| 对比项 | MCP 调用 | 自定义工具 |
| --- | --- | --- |
| 能力来源 | 外部或已配置 MCP Server | 当前画布中的 Python 代码 |
| 入参来源 | MCP 工具参数 | 自己添加输入参数 |
| 输出 | `result` | `result` |
| 复用性 | MCP Server 可跨应用复用 | 当前智能体内更方便，复用性弱 |
| 适合 | 外部系统、远程工具、标准 MCP 能力 | 局部数据处理、临时转换、小工具 |
| 风险 | 服务可用性、参数类型、鉴权、网络 | Python 代码质量、异常处理、维护分散 |

简单记法：

```text
MCP 调用：调用外面的工具。
自定义工具：当前流程里现写一个 Python 工具。
工具页签：调用系统里已经创建好的共享工具。
```

## 5. 项目可能用法

### 5.1 MCP 调用扩展外部能力

可用于：

```text
1. 外部数据库查询。
2. 地图、位置、天气等第三方能力。
3. 其他 MaxKB 应用发布为 MCP 后互相调用。
4. 浏览器自动化、文档处理、企业内部系统能力。
```

建议链路：

```text
参数提取 / 判断器
  -> MCP 调用
  -> 变量拆分 / 自定义工具
  -> 指定回复
```

### 5.2 自定义工具处理局部结构

可用于：

```text
1. 当前流程里临时合并字段。
2. 标准化用户输入和工具结果。
3. 处理表单收集附件结构。
4. 把变量聚合结果转成工具需要的 payload。
```

建议链路：

```text
变量拆分 / 变量聚合 / 表单收集
  -> 自定义工具
  -> 变量赋值 / 判断器 / 指定回复
```

### 5.3 何时沉淀为共享工具

自定义工具成熟后，如果满足下面任一条件，建议迁移到工具管理中：

```text
1. 多个智能体都需要复用。
2. 逻辑超过几十行，且后续要持续维护。
3. 涉及业务系统接口、鉴权、日志或异常处理。
4. 需要更清晰的版本管理和统一入口。
```

如果目标项目已有共享工具，正式链路优先复用工具页签中的共享工具。

## 6. 易错点

```text
1. 把画布自定义工具当成系统共享工具，后续其他智能体找不到。
2. 自定义工具返回内容开启，导致 JSON 中间结果直接展示给用户。
3. MCP 工具参数类型不匹配，尤其数字、布尔、数组被当成字符串。
4. MCP Server Config 中写死敏感信息，后续难以统一维护。
5. MCP 获取工具前没有确认服务可用，工具列表为空。
6. Python 自定义工具没有处理空值，前置节点为空时直接报错。
7. 工具返回结构不稳定，后续变量拆分 JSON Path 经常失效。
8. 复杂业务逻辑长期散落在画布自定义工具里，难以维护。
```

## 7. 推荐用法

```text
1. MCP 调用优先用于外部标准能力或远程工具。
2. 自定义工具优先用于当前智能体内的小范围数据处理。
3. 正式可复用能力优先沉淀到工具管理，通过工具页签添加。
4. 工具节点默认关闭返回内容，最终展示交给指定回复。
5. MCP 或自定义工具返回复杂 JSON 后，优先接变量拆分或变量赋值。
6. 工具入参先用判断器校验关键字段，避免空参数调用失败。
```

## 9. 待继续核对

```text
1. MCP Server Config 下拉是否包含“引用 MCP / 自定义”两种模式。
2. 自定义 MCP Server Config 的编辑框和 JSON 校验方式。
3. 点击“获取工具”后工具参数区域的真实字段类型展示。
4. MCP 工具参数是否支持 number、boolean、array、object。
5. 自定义工具输入参数的数据类型完整列表。
6. 自定义工具 Python 中参数变量如何引用，是否有固定函数签名。
7. 自定义工具执行异常时是否支持异常捕获或错误输出。
8. 画布自定义工具是否能被复制到其他智能体，或是否完全不共享。
9. 自定义工具和工具管理里创建的共享工具在权限、日志、依赖包上的差异。
```
