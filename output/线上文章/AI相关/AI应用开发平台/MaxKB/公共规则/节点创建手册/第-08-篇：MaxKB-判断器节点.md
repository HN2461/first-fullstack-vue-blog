# 第 08 篇：MaxKB 判断器节点
> 文档状态（2026-07-01）：根据空白高级智能体验证截图、通用实践和 MaxKB 官方资料，记录判断器节点配置、条件类型和项目使用规则。

## 1. 节点定位

`判断器` 属于添加组件面板中的：

```text
基础组件 -> 业务逻辑 -> 判断器
```

官方说明：

```text
根据不同的条件进行逻辑判断，每个判断分支后面必须有后置执行节点。
```

通用定位：

```text
判断器是 MaxKB 工作流里最常用的分流节点。
它不负责理解自然语言，只负责根据前置节点输出、会话变量或全局变量做条件判断。
```

典型链路：

```text
意图识别 -> 判断器 -> 指定回复 / 工具 / 变量赋值 / AI 对话
工具节点 -> 变量拆分 -> 判断器 -> 不同业务分支
会话变量状态 -> 判断器 -> 续办链路 / 新流程链路
```

## 2. 初始配置项

当前截图中判断器初始结构：

```text
IF
  请选择变量 | 请选择条件 | 请输入值
  + 添加条件
ELSE
+ 添加分支
输出参数
  分支名称(branch_name)
```

可见能力：

| 配置项 | 说明 |
| --- | --- |
| IF | 默认存在的首个条件分支 |
| ELSE IF | 点击 `+ 添加分支` 后出现，例如 `ELSE IF 1` |
| ELSE | 默认兜底分支 |
| 添加条件 | 同一个 IF 或 ELSE IF 内可增加多条条件 |
| 所有 / 任一 | 多条件时可选择“符合以下所有条件”或“符合以下任一条件” |
| 输出参数 | `分支名称(branch_name)` |

## 3. 条件行结构

每条条件由三部分组成：

```text
变量
条件
值
```

截图中的占位：

```text
请选择变量
请选择条件
请输入值
```

配置原则：

```text
1. 变量必须从下拉选择，不要手写。
2. 条件按变量类型和业务语义选择。
3. 值是右侧输入框；某些条件如“为空 / 不为空”可能不依赖值，但界面仍显示输入框。
4. 删除图标可删除当前条件行。
```

## 4. 多条件关系

当同一个 IF 或 ELSE IF 里添加多条条件时，右上角会出现：

```text
符合以下 [所有/任一] 条件
```

含义：

| 选项 | 含义 | 适合场景 |
| --- | --- | --- |
| 所有 | 所有条件都满足才进入该分支 | 同时判断状态和意图，例如 `isSelectingApprover=true` 且 `selectedKeys 不为空` |
| 任一 | 任意一个条件满足就进入该分支 | 多种同义状态或多个可接受 code |

通用建议：

```text
1. 默认优先用“所有”，避免误进分支。
2. 只有明确是并列同义条件时才用“任一”。
3. 复杂条件建议拆成多个 ELSE IF，不要堆太多条件。
```

## 5. 分支顺序

判断器按顺序判断：

```text
IF
ELSE IF 1
ELSE IF 2
...
ELSE
```

建议：

```text
1. 最精确的条件放前面。
2. 兜底条件放 ELSE。
3. 状态拦截类判断要放在普通意图判断前面。
4. 不要让泛化分支抢走具体分支。
```

项目示例：

```text
是否已有后端草稿
  -> 是否正在选择审批人
  -> 识别后端草稿后续意图
```

审批人选择必须先于普通草稿意图，否则用户回复 `2` 可能被误当成字段修改或普通输入。

## 6. 多分支汇合与节点执行条件

当多个分支出口连接到同一个后续节点时，后续节点右上角会出现或可配置：

```text
执行条件
前置 [所有 / 任一] 连线节点执行完，执行当前节点
```

含义：

| 选项 | 含义 | 适合场景 |
| --- | --- | --- |
| 所有 | 所有前置连线节点都执行完成后才执行当前节点 | 并行汇总，确实要等待多个前置工具结果 |
| 任一 | 任意一个前置连线节点执行完成后就执行当前节点 | 多个互斥分支共用同一条后续链路 |

通用规则：

```text
1. 多个互斥分支共用后续工具、变量拆分、判断器等中间链路时，汇合节点执行条件设为“任一”。
2. 例如“查待办 / 查已办 / 查我发起”三个分支都先设置 currentTaskMode，再汇入同一个“获取工作流任务列表”节点；该工具节点执行条件必须设为“任一”。
3. 如果设为“所有”，由于互斥分支不会同时执行，汇合节点会卡住不执行。
4. 最终指定回复节点共用要谨慎；如果引用变量来自不同分支或历史实测前台回复异常，仍建议最终回复节点分支独立。
5. 节点执行条件的“所有 / 任一”和判断器内部多条件的“所有 / 任一”不是同一个配置，不要混淆。
```

## 7. 条件类型

当前截图中可见条件包括：

```text
为空
不为空
包含
不包含
等于
不等于
大于等于
大于
小于等于
小于
长度等于
长度大于等于
长度大于
长度小于等于
长度小于
为真
不为真
startWith
endWith
正则匹配
通配符匹配
```

说明：

| 条件 | 常见用途 |
| --- | --- |
| 为空 / 不为空 | 判断变量是否有值 |
| 包含 / 不包含 | 判断字符串或列表中是否包含指定内容 |
| 等于 / 不等于 | 判断固定状态码、分类、开关值 |
| 大于 / 大于等于 / 小于 / 小于等于 | 判断数字大小 |
| 长度等于 / 长度大于等于 / 长度大于 / 长度小于等于 / 长度小于 | 判断字符串或列表长度 |
| 为真 / 不为真 | 判断布尔或类布尔值 |
| startWith / endWith | 判断字符串前缀或后缀 |
| 正则匹配 | 复杂文本规则 |
| 通配符匹配 | 简化模式匹配 |

## 8. 项目高频条件建议

### 7.1 判断意图识别结果

推荐：

```text
变量：意图识别.category
条件：等于
值：submit
```

不要：

```text
变量：意图识别.reason
条件：包含
值：提交
```

原因：

```text
reason 是解释文本，不稳定；category 是固定分类，更适合做业务分流。
```

### 7.2 判断工具返回 code

推荐：

```text
变量：拆分提交结果.code
条件：等于
值：NEED_SELECT_APPROVER
```

常见 code：

```text
SUBMITTED
NEED_SELECT_APPROVER
NEED_SECURITY_VERIFY
MISSING_REQUIRED_FIELDS
UNSUPPORTED_FIELDS
DRAFT_SAVED
```

### 7.3 判断显式状态开关

推荐：

```text
变量：chat.isSelectingApprover
条件：等于
值：true
```

或按 MaxKB 下拉变量显示选择：

```text
是否正在选择审批人 等于 true
```

不要：

```text
currentApproversJson 不为空
```

原因：

```text
字符串 "[]" 在 MaxKB 判断器里仍可能被视为“不为空”，导致状态残留。
```

### 7.4 判断解析是否成功

通用易错点：

```text
不要优先判断 success = true。
```

更推荐：

| 场景 | 推荐判断 |
| --- | --- |
| 快捷候选编号解析成功 | `selectedFlowDefineID 不为空` |
| 审批人选择解析成功 | `selectedKeys 不为空` |
| 意图识别命中 | `category 等于 固定分类` |
| 提交前硬检测放行 | `action 等于 allow_submit / allow_draft` |

原因：

```text
MaxKB 对布尔 true / 字符串 true 判断容易受类型影响；
业务关键字段不为空通常更稳定。
```

## 9. 与意图识别配合

推荐最小试验链路：

```text
开始
  -> 意图识别
  -> 判断器
       -> category = submit：指定回复“进入提交”
       -> category = draft：指定回复“进入保存草稿”
       -> category = modify：指定回复“进入修改”
       -> category = confirm：指定回复“只是确认内容”
       -> ELSE：指定回复“未识别”
```

判断器条件：

| 分支 | 变量 | 条件 | 值 |
| --- | --- | --- | --- |
| IF | `意图识别.category` | 等于 | `submit` |
| ELSE IF 1 | `意图识别.category` | 等于 | `draft` |
| ELSE IF 2 | `意图识别.category` | 等于 | `modify` |
| ELSE IF 3 | `意图识别.category` | 等于 | `confirm` |
| ELSE | - | - | 兜底 |

## 10. 输出参数

判断器输出参数：

| 显示名称 | 变量名 | 用途 |
| --- | --- | --- |
| 分支名称 | `branch_name` | 当前命中的分支名称 |

常用引用写法示例：

```text
{{判断器.branch_name}}
```

用途：

```text
1. 调试当前命中了哪个分支。
2. 后续节点需要知道分支来源时引用。
3. 一般不作为核心业务数据。
```

## 11. 易错点

```text
1. 变量选错，尤其多个同名节点输出时要看显示名称和来源。
2. IF / ELSE IF 顺序错误，泛化条件抢走具体分支。
3. 多条件时误选“任一”，导致条件过宽。
4. 用 `currentApproversJson 不为空` 这类列表字符串判断状态。
5. 用 `success = true` 判断工具成功，遇到布尔/字符串类型差异。
6. 没有 ELSE 兜底，异常输入没有明确去处。
7. 判断器分支后没有接后置执行节点，发布或运行时出问题。
8. 把自然语言理解交给判断器，判断器只适合判断已有结构化变量。
9. 多个互斥分支汇入同一个后续节点时，汇合节点执行条件误选“所有”，导致后续节点不执行。
```

## 12. 资料依据

MaxKB 官方文档说明：判断器用于根据不同条件进行逻辑判断，每个判断分支后面必须有后置执行节点；判断器输出参数为分支名称 `branch_name`。

MaxKB 更新日志记录过判断器增强：支持通过拖拽调整 IF / ELSE IF 分支顺序，并支持判断条件的值设置为“真”和“不为真”。

MaxKB v2 高级智能体文档还说明工作流节点在多前置连线场景下有“所有 / 任一”执行条件；注意这属于节点执行条件，不等同于判断器内部多条件的“所有 / 任一”，但理解上类似，都是控制是否满足全部条件或任一条件。
