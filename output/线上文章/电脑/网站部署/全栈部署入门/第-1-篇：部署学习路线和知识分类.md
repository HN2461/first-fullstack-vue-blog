# 第 1 篇：部署学习路线和知识分类

资料核对时间：2026-06-08。

如果你已经学了 `Node.js`、`Express`、`MongoDB` 和 `Vue`，下一步想学部署，最容易卡住的地方不是某一条命令，而是：

> 不知道这些新名词分别解决什么问题。

比如 SSH、Nginx、PM2、宝塔、HTTPS、域名、安全组、反向代理、静态资源、环境变量，这些词如果混在一起学，会很乱。

这一篇先不急着部署，先把知识分类讲清楚。

## 1. 部署到底是在做什么

开发阶段，你的项目可能是这样跑的：

```txt
Vue：npm run dev
Express：node app.js 或 npm run dev
MongoDB：本机数据库或云数据库
访问地址：http://localhost:5173
```

这里的 `localhost` 只代表“你自己的电脑”。

真正部署后，要变成：

```txt
任何用户的浏览器
  |
  | 访问 https://example.com
  v
你的云服务器
  |
  |-- 返回 Vue 页面
  |-- 转发 API 请求给 Express
  |-- Express 再读写 MongoDB
```

所以部署的本质是：

- 把项目放到一台公网能访问的机器上。
- 让前端页面能被访问。
- 让后端接口能稳定运行。
- 让数据库能安全连接。
- 让域名、HTTPS、防火墙、日志都能配好。

## 2. 第一类：服务器和 Linux

你买的云服务器通常会给你这些信息：

```txt
公网 IP：例如 1.2.3.4
系统：例如 Ubuntu
用户名：例如 root 或 ubuntu
密码或 SSH 密钥：用来登录
```

服务器不是“一个网站”，它更像一台远程电脑。你要先登录进去，才能上传代码、安装依赖、配置 Nginx。

你需要掌握的 Linux 基础不多，先会这些就够：

```bash
# 查看当前在哪个目录
pwd

# 查看当前目录下有什么
ls

# 进入项目目录
cd /var/www/my-app

# 查看磁盘空间，避免服务器满了
df -h

# 查看正在运行的进程
ps aux

# 查看日志文件最后 50 行
tail -n 50 /var/log/nginx/error.log
```

小白重点：

- 不要一开始学 Linux 大全。
- 先学“部署会用到的命令”。
- 会看路径、权限、进程、端口、日志，就已经能解决很多问题。

## 3. 第二类：SSH

SSH 是你登录服务器最常见的方式。

```bash
# user 是服务器用户名，server-ip 是服务器公网 IP
ssh user@server-ip
```

如果你用密钥登录，命令可能长这样：

```bash
# -i 后面是私钥文件路径
# 私钥相当于你的钥匙，不要发给别人
ssh -i ~/.ssh/my-server-key user@server-ip
```

SSH 要解决的问题是：

```txt
我怎么进入服务器？
我怎么执行服务器上的命令？
我怎么把本机代码传到服务器？
```

常见上传方式：

```bash
# 把本机 dist 目录上传到服务器
# -r 表示递归复制整个文件夹
scp -r ./dist user@server-ip:/var/www/my-app/
```

也可以在服务器上直接拉代码：

```bash
# 在服务器上从 Git 仓库拉项目
git clone https://github.com/your-name/your-project.git
```

小白重点：

- SSH 是入口。
- 没有 SSH，你通常无法管理服务器。
- 宝塔虽然有面板，但出问题时还是经常要用 SSH 看日志。

## 4. 第三类：前端静态资源

Vue 项目开发时由 Vite 提供本地开发服务：

```bash
npm run dev
```

但是上线时不是把 `npm run dev` 暴露给用户，而是先打包：

```bash
# 打包 Vue 项目
npm run build
```

打包后通常会得到：

```txt
dist/
  index.html
  assets/
    xxx.js
    xxx.css
```

这些文件是静态资源，Nginx 可以直接返回给浏览器。

小白重点：

- Vue 源码不是直接给用户访问。
- 用户访问的是构建后的 `dist`。
- Vite 官方文档也说明 `dist` 是默认构建输出目录，`vite preview` 是本地预览，不是正式生产服务器。

## 5. 第四类：Nginx

Nginx 在全栈部署里最常做两件事：

```txt
第一件：返回 Vue 打包后的静态文件。
第二件：把 /api 请求转发给 Express。
```

这叫反向代理。

一个最小理解：

```txt
浏览器访问：https://example.com/api/users
Nginx 收到请求
Nginx 转发到：http://127.0.0.1:3000/users
Express 真正处理接口
```

为什么不让用户直接访问 `http://server-ip:3000`？

- 3000 是应用端口，不适合直接暴露。
- HTTPS、域名、日志、压缩、静态资源这些更适合交给 Nginx。
- 多个服务可以共用一个 80/443 入口。

小白重点：

- Nginx 是公网入口。
- Express 可以只监听本机 `127.0.0.1:3000`。
- 用户访问域名，Nginx 决定返回前端还是转给后端。

## 6. 第五类：Node 生产运行

开发时你可能这样跑 Express：

```bash
npm run dev
```

但生产环境不能只开一个终端窗口一直挂着。因为：

- 你关掉 SSH 窗口，普通命令可能就停了。
- Node 进程崩了，需要有人拉起来。
- 服务器重启后，服务要能自动恢复。
- 日志要能查。

所以通常用 PM2 或 systemd。

PM2 常见命令：

```bash
# 启动 Express 入口文件，并命名为 my-api
pm2 start app.js --name my-api

# 查看应用列表
pm2 list

# 查看日志，排查接口报错非常常用
pm2 logs my-api

# 重启应用，例如修改环境变量或代码后使用
pm2 restart my-api
```

小白重点：

- PM2 不是 Express 的一部分。
- PM2 是帮 Node 服务“活着”的工具。
- Express 负责处理接口，PM2 负责守护进程。

## 7. 第六类：MongoDB 安全

本地学习时，你可能直接连接：

```txt
mongodb://127.0.0.1:27017/mydb
```

生产环境一定要更谨慎。

最基础的安全原则：

- 开启认证。
- 给项目创建专用数据库用户。
- 用户只给需要的权限。
- 不把 27017 直接暴露到公网。
- 定期备份。
- 连接字符串不要写死在代码里，而是放进 `.env`。

示例：

```bash
# .env 示例
# 这类文件不要提交到公开仓库
MONGODB_URI=mongodb://app_user:strong_password@127.0.0.1:27017/my_app?authSource=my_app
```

小白重点：

- 数据库不是“能连上就行”。
- 生产环境第一优先级是别裸奔。
- MongoDB 官方安全清单也强调访问控制、认证授权和网络暴露控制。

## 8. 第七类：域名、DNS、HTTPS

用户不可能一直访问：

```txt
http://1.2.3.4
```

一般会访问：

```txt
https://example.com
```

这里涉及：

| 名词 | 意思 |
|---|---|
| 域名 | 用户看到的网站地址 |
| DNS | 把域名解析到服务器 IP |
| HTTPS | 加密访问，浏览器不再提示不安全 |
| 证书 | HTTPS 所需的身份证明 |
| 80 端口 | HTTP 默认端口 |
| 443 端口 | HTTPS 默认端口 |

小白重点：

- DNS 解析生效可能需要一点时间。
- HTTPS 通常需要域名先解析正确。
- 证书配置常用 Certbot 或宝塔面板。

## 9. 第八类：宝塔面板

宝塔能帮你做很多事：

- 安装 Nginx。
- 配站点目录。
- 申请 SSL 证书。
- 管理数据库。
- 管理 Node 项目。
- 看日志。
- 配反向代理。

但宝塔不是“部署知识本身”。

更准确地说：

```txt
SSH / Linux / Nginx / PM2 / MongoDB / HTTPS 是底层能力。
宝塔是把这些能力做成图形界面。
```

建议学习方式：

1. 先手动部署一个最小项目。
2. 再用宝塔部署同一个项目。
3. 对比宝塔帮你生成了哪些 Nginx 配置、进程管理和证书配置。

这样你不会一出问题就只能看着面板发呆。

## 10. 学习路线总表

| 阶段 | 要学什么 | 能做到什么 |
|---|---|---|
| 第 1 阶段 | SSH、Linux 基础 | 能登录服务器、看目录、看日志 |
| 第 2 阶段 | Vue 打包、Nginx 静态站点 | 能让前端页面公网访问 |
| 第 3 阶段 | Nginx 反向代理 | 能让 `/api` 转发到 Express |
| 第 4 阶段 | PM2 或 systemd | 能让 Node 服务后台常驻 |
| 第 5 阶段 | MongoDB 安全和备份 | 能安全连接数据库 |
| 第 6 阶段 | 域名、DNS、HTTPS | 能用正式域名访问 |
| 第 7 阶段 | 宝塔 | 能用面板提速部署 |
| 第 8 阶段 | Docker、CI/CD | 能做更稳定的工程化发布 |

## 11. 这一篇的记忆口诀

部署全栈项目，可以按这一句记：

```txt
SSH 进服务器，Linux 放项目，Vue 打 dist，Nginx 管入口，Express 跑接口，PM2 保常驻，MongoDB 做安全，域名 HTTPS 给用户，宝塔只是提速工具。
```
