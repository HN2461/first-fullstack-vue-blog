## 小白先看

可以先把代理客户端想成一个“上网导航软件”：

- 有些网站走普通道路更快，比如国内网站。
- 有些网站需要绕一条特殊道路，比如国外服务。
- 有些软件不听系统导航，需要更强的接管方式。

所以代理设置的重点不是“全部打开、全部走代理”，而是让不同流量走合适的路。

最简单的选择：

| 你想做什么 | 选什么 |
| --- | --- |
| 日常浏览网页、看视频、查资料 | Rule（规则）模式 |
| 临时让所有流量都走同一个节点 | Global（全局）模式 |
| 排查是不是代理导致网络异常 | Direct（直连）模式 |
| 浏览器能走代理，但游戏/命令行不走 | 开 TUN |

大多数人长期使用时，优先选 **Rule（规则）模式 + 系统代理**。如果遇到命令行工具、游戏、部分桌面软件不走代理，再开启 **TUN** 或客户端里的增强模式。

## 这篇要解决的问题

很多人第一次打开 Clash、FlClash、Clash Verge、Clash Lite 这类客户端时，会看到 Rule、Global、Direct、System Proxy、TUN 这些词。它们看起来很技术，但其实只是在回答两个问题：

1. 哪些网站要走代理，哪些网站不走代理？
2. 客户端要用什么方式接管电脑或手机里的网络流量？

## 三种常见出站模式

出站模式可以理解为“流量怎么出门”。你访问一个网站，请求从设备发出去时，客户端要决定它走代理还是直连。

### Rule：规则模式

Rule 会根据配置文件中的规则自动分流。符合代理规则的请求走节点，符合直连规则的请求直接访问。

小白可以这样理解：Rule 就像导航自动选路线。去附近超市不用上高速，去远方城市才上高速。

它适合长期打开，因为它兼顾了访问体验和流量成本：

- 国内网站通常直连，速度更稳定。
- 海外服务按规则走代理，不需要手动切换。
- 局域网、路由器、打印机、NAS 等内网地址可以保持直连。

规则模式的关键在于配置质量。如果规则过旧或订阅维护不好，就可能出现该走代理的不走、该直连的却绕远路的问题。

### Global：全局模式

Global 会把流量统一交给选中的代理节点处理。它适合临时测试，比如想确认某个网站的问题是不是规则命中错误，或者短时间内需要让绝大多数请求都走同一个出口。

小白可以这样理解：Global 就是不管去哪，都强行先绕到同一个代理节点。

全局模式不适合作为默认状态，原因有三个：

- 访问国内网站会绕路，延迟和失败率可能上升。
- 所有流量都消耗节点额度。
- 某些本地服务、局域网服务可能出现异常，需要额外绕过规则。

### Direct：直连模式

Direct 等于让客户端不再代理流量。它常用于排查问题：如果直连正常、Rule 异常，问题多半在规则、DNS 或节点；如果直连也异常，问题可能在本机网络、运营商、目标服务或防火墙。

小白可以这样理解：Direct 就是暂时不走导航推荐路线，回到普通上网方式。

Direct 不是“退出客户端”的完全等价物。部分客户端在 Direct 下仍可能保留 DNS、系统代理开关或虚拟网卡状态，所以排障时要同时检查客户端是否仍在接管系统流量。

## System Proxy 和 TUN 的区别

这两个词回答的是“代理客户端怎么接管流量”。它们不是出站模式，而是接管方式。

### System Proxy：设置系统代理

系统代理通常是把操作系统的 HTTP/HTTPS/SOCKS 代理地址设置到本机客户端监听端口。浏览器、部分桌面软件会主动读取系统代理设置，然后把请求交给代理客户端。

小白可以这样理解：系统代理像是在系统公告栏贴了一张纸：“需要代理的应用请走这个入口。”愿意看公告的软件会走，不看的软件就不会走。

它的优点是简单、兼容性好、容易关闭。缺点是覆盖范围有限：有些程序不读系统代理，有些命令行工具需要单独设置环境变量，还有些游戏或客户端软件会直接发起连接。

### TUN：虚拟网卡接管

TUN 会创建虚拟网络接口，再通过系统路由把流量导入代理客户端。它比系统代理更接近“网络层接管”，能覆盖更多不支持系统代理的程序。

小白可以这样理解：TUN 像是在电脑里新建了一条“虚拟网线”，把更多软件的流量都先拉到代理客户端这里处理。

TUN 的优势是覆盖面广，但它也更容易碰到路由、DNS、权限和虚拟网卡冲突问题。开启 TUN 后，如果出现无法访问局域网、DNS 异常、某些软件断流，优先检查绕过网段、DNS 策略和客户端日志。

## 日常推荐组合

| 场景 | 推荐模式 | 是否开启 TUN | 说明 |
| --- | --- | --- | --- |
| 浏览器、聊天、文档、视频 | Rule | 可不开 | 系统代理通常足够 |
| 命令行工具、包管理器 | Rule | 视情况开启 | 也可以单独配置 `HTTP_PROXY` / `HTTPS_PROXY` |
| 游戏、桌面客户端 | Rule | 常需要 | 很多应用不会读取系统代理 |
| 临时确认节点是否可用 | Global | 可不开 | 用完及时切回 Rule |
| 排查本机网络问题 | Direct | 关闭或保持最小接管 | 确认问题是否来自代理链路 |

## 排障顺序

1. 先确认客户端是否有节点延迟、订阅是否过期。
2. 切到 Global 测试目标网站，如果能访问，说明 Rule 规则可能没有命中。
3. 切到 Direct 测试国内网站和局域网，如果异常，说明问题可能不在代理规则。
4. 如果浏览器正常但某个应用异常，检查该应用是否读取系统代理。
5. 如果开启 TUN 后异常，先关闭 TUN 复测，再检查绕过网段和 DNS 设置。
6. 如果只有某个节点异常，换节点，不要把单节点问题误判成客户端问题。

## 小白记忆版

- 不知道选什么：选 Rule。
- 国内网站变慢：不要长期用 Global。
- 想排查代理问题：切 Direct 试一下。
- 浏览器正常，其他软件不正常：检查系统代理或 TUN。
- 开了 TUN 后局域网、DNS 异常：先关 TUN 复测。

## 常见误区

### “全局模式一定更快”

不一定。全局只是让更多流量走代理，不代表链路更短。国内服务绕到海外再回来，通常只会更慢。

### “开了系统代理，所有应用都会走代理”

不会。系统代理更像是给应用提供一个推荐出口，应用愿不愿意用取决于它自己的实现。TUN 才能覆盖更多不读系统代理的程序。

### “TUN 越强，越应该一直开”

TUN 的确覆盖面更广，但它会介入路由和 DNS。稳定优先时，应按需开启，而不是无脑常开。

### “Direct 就是完全关闭代理”

不完全等同。Direct 是客户端内部出站策略，系统代理开关、TUN、DNS 模块可能仍影响网络行为。
