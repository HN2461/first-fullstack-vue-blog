# 16 高频面试题与命令速查

## 1. 高频面试题

### Redis 为什么快？

主要数据在内存、数据结构高效、核心命令执行路径简洁，并能通过 Pipeline 减少网络往返。不能只回答“单线程”，还应说明慢命令仍会阻塞。

### Redis 有哪些核心类型？

String、Hash、List、Set、Sorted Set。能分别给出缓存/计数、对象字段、最近列表、去重关系、排行榜场景比只背名称重要。

### 过期和淘汰有什么区别？

过期是 Key 达到 TTL 后逻辑失效并被删除；淘汰是内存达到 maxmemory 后根据策略主动移除 Key。持续淘汰通常意味着容量或模型有问题。

### 穿透、击穿、雪崩？

- 穿透：查不存在数据，缓存始终未命中。
- 击穿：单个热 Key 失效，大量请求回源。
- 雪崩：大量 Key 同时失效或 Redis 整体故障。

对应空值/布隆过滤器、请求合并/逻辑过期、TTL 抖动/高可用/熔断限流。

### MySQL 和 Redis 如何保持一致？

Cache-Aside 默认先提交 MySQL，再删除缓存；删除失败通过重试、Outbox/消息和 TTL 收敛。高一致场景使用版本、延迟双删、CDC 或关键读绕过缓存。两者不能天然组成普通本地事务。

### SETNX 可以直接实现锁吗？

完整锁至少需要单条 `SET key unique NX PX ttl`，释放时 Lua 比较 value 后删除，还要处理 TTL、续期、旧持有者、fencing 和业务幂等。高价值正确性不能只靠简单 Redis 锁。

### Pipeline 与事务区别？

Pipeline 主要减少网络往返，不保证原子；MULTI/EXEC 让排队命令连续执行，但没有 MySQL 式运行时回滚。读-判断-写通常用 Lua。

### RDB 与 AOF？

RDB 是时间点快照，紧凑、恢复快但快照间可能丢数据；AOF 记录写命令，数据丢失窗口更小但文件和重放成本更高。两者都会涉及持久化 IO、Fork/COW，且都不替代异地备份和恢复演练。

### Sentinel 与 Cluster？

Sentinel 为非分片主从提供监控和自动故障切换；Cluster 还负责数据分片和横向扩展。Cluster 多 Key 命令受 Hash Slot 限制。

### 大 Key 和热 Key？

大 Key 是单 Key 体积或元素数过大，影响延迟、网络、持久化和迁移；热 Key 是请求高度集中，造成单节点/分片过载和击穿。两者可能同时存在但不是同一个概念。

## 2. 通用命令

```redis
PING
EXISTS key
TYPE key
TTL key
PTTL key
EXPIRE key 300
PERSIST key
DEL key
UNLINK key
MEMORY USAGE key
SCAN 0 MATCH app:prod:* COUNT 100
```

## 3. 核心类型

```redis
SET key value NX EX 60
GET key
MGET key1 key2
INCR counter

HSET user:1 name Alice status active
HGET user:1 name
HMGET user:1 name status
HSCAN user:1 0 COUNT 100

LPUSH recent item1
LRANGE recent 0 9
LTRIM recent 0 99

SADD tags mysql redis
SISMEMBER tags mysql
SSCAN tags 0 COUNT 100

ZADD rank 100 user:1
ZINCRBY rank 1 user:1
ZREVRANGE rank 0 9 WITHSCORES
ZREVRANK rank user:1
```

## 4. 原子与批量

```redis
MULTI
INCR counter:a
INCR counter:b
EXEC

WATCH balance:1
GET balance:1
MULTI
SET balance:1 90
EXEC

EVAL "return redis.call('GET', KEYS[1])" 1 some:key
```

Pipeline 在客户端 API 中创建，不是一条保证原子的 Redis 命令。

## 5. Stream

```redis
XADD events * type order.created orderId 1001
XGROUP CREATE events workers 0 MKSTREAM
XREADGROUP GROUP workers worker-1 COUNT 10 BLOCK 5000 STREAMS events >
XPENDING events workers
XACK events workers 1785080000000-0
XAUTOCLAIM events workers worker-2 60000 0-0 COUNT 10
XTRIM events MAXLEN ~ 100000
```

```text
KEYS *
MONITOR
SAVE
FLUSHDB / FLUSHALL
DEBUG
对未知大集合执行 HGETALL、SMEMBERS、LRANGE 0 -1
```

## 7. 结业验收

- [ ] 能为会话、验证码、限流、详情缓存和排行榜设计 Key/TTL。
- [ ] 能实现 Cache-Aside，并解释脏数据窗口。
- [ ] 能用 Lua 写原子限流和安全解锁。
- [ ] 能识别缓存穿透、击穿、雪崩、大 Key 和热 Key。
