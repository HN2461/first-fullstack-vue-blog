# 13 安全、监控、性能与线上排障

## 1. Redis 不应暴露公网（P0）

基础防线：

- 部署在私网/VPC，安全组只允许应用和运维来源。
- 启用 ACL 和强认证，不只依赖网络边界。
- 跨不可信网络使用 TLS 并验证证书。
- 禁用/限制不需要的高风险命令应通过 ACL 实现，而不是只改命令名。
- 分离应用账号、只读监控账号和运维账号。
- Secret 不写进代码、镜像、日志和命令历史。

Redis 历史上出现过大量无认证公网实例被入侵。`bind`、protected mode、ACL、防火墙和云安全组应共同配置。

## 2. ACL 最小权限（P1）

概念示例：

```redis
ACL SETUSER blog-app on >strong-secret ~blog:prod:* +@read +@write -@dangerous
ACL LIST
ACL GETUSER blog-app
```

真实权限需按命令和 Key 模式收紧，且云服务语法可能不同。应用不应有 `FLUSHALL`、`CONFIG`、`SHUTDOWN`、ACL 管理等权限。

密码作为命令参数可能进入历史或审计输出，生产通过安全配置和部署系统管理。

## 3. 必看指标（P0）

### 资源

- 内存使用、RSS、碎片率、maxmemory。
- CPU、网络输入输出、磁盘延迟。
- Key 数、带 TTL Key 数、过期和淘汰速度。

### 延迟与流量

- 命令 QPS、P50/P95/P99。
- 慢命令数量。
- 缓存命中/未命中。
- 拒绝连接、阻塞客户端、错误率。

### 高可用

- 复制延迟、复制断开、全量同步次数。
- 主从角色、故障切换次数。
- Cluster Slot 状态和节点健康。
- RDB/AOF 最近成功时间与错误。

### 业务

- 缓存回源 QPS。
- 分布式锁等待/超时。
- 限流命中数。
- Stream lag、PEL、重试和死信。

## 4. INFO 与命令统计

```redis
INFO memory
INFO stats
INFO commandstats
INFO clients
INFO persistence
INFO replication
```

关键字段随版本变化，监控系统应显式适配，不要解析人类展示字符串后永不维护。

## 5. 慢日志（P0）

```redis
SLOWLOG LEN
SLOWLOG GET 20
```

Slow Log 记录命令在 Redis 服务端执行的时间，通常不包含网络传输和客户端排队。因此应用耗时高但 SLOWLOG 正常时，还要检查网络、连接、事件循环和客户端大响应解析。

慢日志可能包含 Key/参数片段，导出和共享时注意敏感数据。

## 6. 延迟诊断（P1）

```powershell
redis-cli --latency
redis-cli --latency-history
redis-cli --intrinsic-latency 10
```

`--intrinsic-latency` 会在运行它的机器上忙循环，应在 Redis 服务器受控执行并评估影响，不能在共享生产节点随意运行。

延迟尖峰常见原因：

- 大 Key 命令或高复杂度集合操作。
- KEYS、同步 SAVE、长 Lua。
- Fork、COW、AOF fsync、磁盘抖动。
- 内存交换或宿主机抢占。
- 大量连接建立或客户端输出缓冲堆积。
- 网络丢包、跨区访问。
- 热 Key 单分片过载。

## 7. 客户端连接问题

```redis
CLIENT LIST
INFO clients
```

关注：

- `connected_clients`。
- `blocked_clients`。
- 输入/输出缓冲。
- 长时间空闲连接。
- Pub/Sub、阻塞读取和普通命令是否错误共用连接。

连接不是越多越好。每个应用实例的连接数相加后必须在 Redis 能力内。Pub/Sub 和阻塞 Stream 读取通常使用专用连接。

## 8. CPU 高排查

1. 看 `INFO commandstats` 哪些命令频率和累计耗时高。
2. 看 SLOWLOG 是否出现慢命令。
3. 查大 Key、热 Key 和集合基数。
4. 检查 Lua、排序、集合运算和全量返回。
5. 检查是否发生持久化/重写。
6. Cluster 看是否单 Slot/节点过热。

不要直接重启掩盖证据，也不要生产开启高开销实时命令跟踪后无人关闭。

## 9. MONITOR 的风险（P0）

`MONITOR` 会持续输出服务器收到的命令，开销和敏感信息风险很高。生产默认禁止随意使用。优先使用指标、慢日志、命令统计和应用 Trace；确需使用必须短时、受控、脱敏并得到授权。

## 10. 应用侧可观测性

每类 Redis 操作记录：

- 操作名称/业务标签，不直接记录敏感 Key。
- 命中或未命中。
- 耗时和超时。
- 错误类别。
- 回源耗时。
- Pipeline 批次大小。
- 降级结果。

日志避免打印 Session、验证码、Token 和完整缓存 Value。

## 11. 故障降级（P0）

| 场景 | 常见降级 |
| --- | --- |
| 商品详情缓存不可用 | 限流后查 MySQL，或返回短期本地缓存 |
| 排行榜不可用 | 暂不展示或展示最近快照 |
| 限流 Redis 不可用 | 按风险 Fail-open/closed，并启用本地/网关限制 |
| Session Redis 不可用 | 短时拒绝敏感操作，不能无条件绕过认证 |
| 分布式锁不可用 | 停止该协调任务，或依赖数据库幂等兜底 |
| Stream 不可用 | Outbox 保留待发布，恢复后重试 |
