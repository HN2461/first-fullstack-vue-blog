# MaxKB 公司已部署环境实战开发指南

> 文档状态（2026-07-19）：基于本资料库既有实操记录、MaxKB v2 官方文档、官方更新日志和官方 GitHub `v2.10.4-lts` 发布说明整理。

## 1. 适用场景

本指南面向下面这种开发方式：

```text
公司负责部署和维护 MaxKB 服务器
  -> 公司分配账号、工作空间、模型、知识库或工具权限
  -> 开发者在 Web 管理界面搭建高级智能体
  -> 智能体调用公司业务 API、知识库、模型或子智能体
  -> 通过公开链接、嵌入代码或服务端 API 接入业务系统
```

本指南不把开发者假设为服务器管理员。涉及升级、容器、数据库、反向代理、系统依赖或日志目录的内容，只说明开发影响和协作边界。

## 2. 开发者真正需要掌握的六件事

1. 识别目标环境的版本、版本类型、权限和可用资源。
2. 把需求拆成确定性业务逻辑、AI 理解、知识检索和交互展示四部分。
3. 使用变量和显式状态构建可调试的工作流，而不是依赖长提示词维持状态。
4. 用工具或业务后端承载鉴权、校验、幂等和真实写操作。
5. 用执行详情、命中测试、对话日志和异常分支建立可重复的测试证据。
6. 发布时同时交付智能体包、工具包、依赖清单、版本记录、测试用例和回滚入口。

## 4. 开发方法总图

```text
环境确认
  -> 需求与风险分级
  -> 依赖与数据契约
  -> 工作流/知识库设计
  -> 复制稳定基线
  -> 节点级调试
  -> 端到端与异常回归
  -> 发布和接入验证
  -> 日志反馈与知识优化
  -> 导出归档和可回滚交付
```

## 5. 证据等级

为避免“上次能用”被误写成“任何版本都能用”，后续新增记录应标记证据等级：

| 等级 | 含义 | 写法示例 |
| --- | --- | --- |
| A | 当前版本官方文档或官方发布说明明确记载 | `官方 v2.10.4 文档确认` |
| B | 当前公司环境已实际调试、发布和回归 | `当前环境实测，版本 x.x.x` |
| C | 社区资料或同版本相近场景验证 | `社区资料，需目标环境复核` |
| D | 导出包逆向、内部接口或推测 | `内部实现，禁止作为稳定公开协议` |

结论冲突时采用下面顺序：

```text
目标环境真实行为
  > 与目标版本匹配的官方文档/发布说明
  > 当前版本源码
  > 社区文章
  > 历史项目经验
```

目标环境真实行为优先，只代表“当前环境如何工作”；如果它与官方口径不同，必须记录版本、复现步骤和差异，不能反过来宣称官方通用行为。

## 6. 文档维护模板

每次沉淀新的实战结论，至少记录：

```text
结论：解决什么问题。
环境：MaxKB 版本、社区版/X-Pack、入口类型。
配置：真实节点、参数来源和关键开关。
验证：输入、期望、实际、执行详情或日志证据。
边界：哪些情况未验证，哪些属于项目字段。
来源：官方链接、发布说明或当前环境截图日期。
```

不要只记录“这样配能用”，还要记录为什么、依赖什么、失败时如何判断和如何回滚。
