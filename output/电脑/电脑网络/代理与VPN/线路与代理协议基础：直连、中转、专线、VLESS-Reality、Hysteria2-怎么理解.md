## 小白先看

理解代理节点时，先记住一句话：**线路是路，协议是车。**

- 线路决定你的数据走哪条路。
- 协议决定你的数据坐什么车、怎么伪装、怎么传输。

路再好，车坏了也不行；车再高级，路堵了也跑不快。所以选节点时不要只看协议名字，也不要只看商家写的线路标签。更可靠的判断方式是：看路径、看拥塞、看丢包、看晚高峰、看目标服务实际表现。

一个粗略但实用的判断：

- **直连**：结构简单、成本低，但更依赖本地运营商和国际出口质量。
- **中转**：入口更近，体验通常更稳，但完整链路仍可能拥塞。
- **专线**：理论上更稳定，但真实成本高，低价“专线”要谨慎判断。
- **TCP 类协议**：稳定、兼容性好，丢包高时可能被重传拖慢。
- **QUIC/UDP 类协议**：弱网吞吐可能更好，但受 UDP 限制和网络策略影响更明显。

## 这篇要解决的问题

很多套餐会写一堆词：直连、中转、IPLC、IEPL、BGP、CN2、VLESS Reality、Hysteria2、Trojan、SS。新手最容易被这些词吓住。

其实可以拆成两类：

1. 直连、中转、专线：说的是“路”。
2. SS、Trojan、VLESS Reality、Hysteria2：说的是“车”。

## 先分清线路和协议

### 线路：数据走哪条路

线路描述的是你的流量从本机到目标服务之间经过哪些网络路径。它关心的是入口、落地、运营商、国际出口、拥塞和跨境链路质量。

小白可以这样理解：线路像道路，有普通路、高速路、专用通道，也有晚高峰堵车。

### 协议：数据穿什么外衣

协议描述的是代理客户端和服务端之间如何建立连接、认证、加密、转发 TCP/UDP 流量。它关心的是握手、封装、伪装、拥塞控制、兼容性和抗干扰能力。

小白可以这样理解：协议像交通工具和包装方式，有的稳、有的快、有的更不容易被认出来。

线路好但协议不合适，可能连不上；协议先进但线路拥塞，照样卡。两者要一起看。

## 常见线路类型

### 直连

直连是从本地网络直接连到海外服务器或目标节点。它结构简单，少一个中转环节，成本通常更低。

小白可以这样理解：直连就是你自己从家直接开到目的地，中间不换车。

直连的问题是，它高度依赖本地运营商、国际出口、晚高峰拥塞和目标机房质量。同一个节点，在电信、联通、移动上的体验可能完全不同。

### 中转

中转通常会先连接到较近的入口，再由入口把流量送到海外落地。它的优势是入口延迟低、可以做多线接入和链路优化。

小白可以这样理解：中转就是先坐车到附近车站，再由车站安排另一辆车送你去目的地。

中转不是魔法。入口到落地仍然要走某种承载链路，如果这段拥塞，用户看到的仍然是卡顿。测速时只看入口延迟，会严重低估完整链路成本。

### 专线

专线通常指更稳定、更受控的跨境链路，例如企业级点对点线路、运营商专用承载或类似产品。它的价值在于稳定、低抖动、少受公网拥塞影响。

小白可以这样理解：专线像专门修的一条通道，理论上人少、更稳，但成本更高。

但真专线成本很高。低价套餐里看到“专线”“IPLC”“IEPL”等字样时，要结合价格、晚高峰表现、丢包、抖动和服务商信誉判断，不要只看标签。

## 常见协议怎么理解

### SS / Trojan / VMess

这些协议在不同客户端和服务端生态里仍然常见。它们的优势是成熟、配置资料多、兼容性强。

小白可以这样理解：这些是比较常见的老牌车型，资料多、会修的人多，但在直连环境下不一定最稳。

但在直连场景中，老协议的流量特征、服务端暴露方式、TLS 伪装质量都可能影响稳定性。放在中转或受控链路里，协议本身对体验的影响会下降，线路质量反而更重要。

### VLESS + Reality

VLESS 是轻量代理协议，Reality 则通过 TLS 相关机制减少对自有域名和证书的依赖，并提高被主动探测识别的难度。

小白可以这样理解：VLESS + Reality 更像一辆轻量车，再套上更自然的外观，让它看起来不那么像代理流量。

它适合追求直连稳定、TCP 兼容性和较低协议开销的场景。局限也要看清：它不是永久免疫方案，网络环境、服务端配置、伪装目标、运营商策略都会影响结果。

### Hysteria2

Hysteria2 基于 QUIC，能够代理 TCP 和 UDP 流量。它常被用于高丢包、弱网或晚高峰环境，因为其拥塞控制策略更偏向吞吐表现。

小白可以这样理解：Hysteria2 更像一辆适合烂路和拥堵路况的车，跑得可能更猛，但前提是路上允许这种车通行。

它的限制同样明显：QUIC 基于 UDP，遇到运营商限制 UDP、网络设备对 UDP 不友好、或目标应用本身就是 QUIC/HTTP3 时，表现未必总是更好。Hysteria 官方文档也提醒，代理 HTTP/3 这类本身基于 QUIC 的流量不一定获得“加速”效果。

## TCP 和 UDP 的体验差异

TCP 可靠、有序、生态成熟。丢包时它会重传，但高丢包会让吞吐下降，表现为网页慢、视频缓冲、下载速度上不去。

UDP 不保证可靠和有序，应用或上层协议需要自己处理丢包、拥塞和重传。QUIC 在 UDP 上实现了加密、流和拥塞控制，所以它不是“裸 UDP”，而是更现代的传输层方案。

## 选型建议

| 场景 | 更该关注 | 建议 |
| --- | --- | --- |
| 日常浏览和视频 | 稳定、带宽、晚高峰 | 优先选稳定线路，不必迷信最低延迟 |
| 游戏和会议 | 延迟、抖动、丢包 | 优先选近入口、低抖动链路 |
| 移动网络或弱网 | 丢包、UDP 限制 | 可测试 Hysteria2 / TUIC 类方案 |
| 公司网络或校园网 | 防火墙策略、UDP 限制 | TCP/TLS 类协议通常更稳 |
| 账号敏感平台 | IP 类型、地区一致性 | 线路和协议之外，还要看出口 IP 风控 |

## 小白选择建议

- 不知道选什么：先选稳定、评价好的节点，不要只追最新协议。
- 家里宽带丢包少：TCP 类协议通常够用。
- 晚高峰卡、丢包多：可以测试 Hysteria2 这类 QUIC/UDP 方案。
- 公司、校园、移动网络：先确认 UDP 是否被限制。
- 套餐很便宜却写“真专线”：保持怀疑，用晚高峰真实体验判断。

## 常见误区

### “协议越新越好”

不一定。协议只是链路的一部分。网络环境限制 UDP 时，QUIC 类协议可能不如 TCP 稳定。

### “专线一定是真的”

不一定。专线是高成本资源，低价宣传要结合真实表现判断。

### “直连一定慢，中转一定快”

不一定。直连到优质机房可能很好，中转如果入口或落地拥塞也会很差。

### “UDP 一定比 TCP 快”

不一定。UDP 只是传输方式，真正决定表现的是上层协议、拥塞控制、网络设备策略和丢包情况。

## 实战判断清单

1. 看节点是直连、中转还是专线，不要只看协议名。
2. 分别测试 TCPing / RTT 和 URL Test，区分入口延迟与完整链路。
3. 晚高峰测试丢包和真实下载/播放表现。
4. 移动网络下单独测试 UDP 协议，不要默认可用。
5. 账号类业务同时检查 IP 类型、地区、DNS 出口和设备环境。
6. 保留多个协议和线路备选，不要把所有场景压在一个节点上。
