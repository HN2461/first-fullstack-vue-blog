# 第 6 篇：宝塔面板部署入门与避坑

资料核对时间：2026-06-08。

宝塔面板适合新手吗？

答案是：

```txt
适合，但不要只会点面板。
```

宝塔官方文档把它定位为服务器运维管理面板，可以管理网站、数据库、SSL、防火墙、计划任务等。它确实能让新手更快部署，但你要知道它背后实际还是在操作：

- Nginx。
- 站点目录。
- 反向代理。
- SSL 证书。
- Node 项目管理。
- 数据库。
- 防火墙。

## 1. 宝塔适合解决什么问题

宝塔适合：

- 不熟悉 Linux 命令时，快速创建网站。
- 用图形界面管理 Nginx 站点。
- 申请和续签 SSL 证书。
- 看网站日志。
- 配反向代理。
- 管理数据库。
- 管理 Node 项目。

宝塔不适合替代：

- SSH 基础。
- Nginx 基础。
- 端口和防火墙理解。
- PM2 / 进程管理理解。
- 数据库安全理解。
- 日志排查能力。

一句话：

```txt
宝塔是工具，不是底层知识。
```

## 2. 用宝塔部署 Vue 静态站点

一般流程：

1. 本地执行 `npm run build`。
2. 得到 `dist`。
3. 宝塔创建网站，绑定域名。
4. 把 `dist` 里的文件上传到网站根目录。
5. 配置伪静态或 Nginx 回退，解决前端路由刷新 404。

小白注意：

```txt
上传的是 dist 里面的内容，不是整个 Vue 源码目录。
```

比如网站根目录最终应该类似：

```txt
网站根目录/
  index.html
  assets/
    xxx.js
    xxx.css
```

不要变成：

```txt
网站根目录/
  dist/
    index.html
    assets/
```

否则访问域名时可能找不到首页。

## 3. 宝塔里配置 Vue Router 回退

如果你用 history 路由，需要让不存在的路径回到 `index.html`。

在宝塔网站的 Nginx 配置或伪静态中，核心是：

```nginx
location / {
  # 先找真实文件，再找目录，找不到交给 Vue 的 index.html
  try_files $uri $uri/ /index.html;
}
```

如果你的项目使用 hash 路由：

```txt
https://example.com/#/article/1
```

通常不会像 history 模式那样刷新 404。

但你仍然应该知道 `try_files` 的作用，因为以后做 history 模式或别的前端项目都会遇到。

## 4. 用宝塔部署 Express 后端

宝塔有 Node 项目管理能力，不同版本面板界面可能略有差异，但核心信息大体包括：

- 项目目录。
- 启动文件。
- 运行用户。
- Node 版本。
- 端口。
- 启动命令。
- 环境变量。

Express 项目需要准备：

```txt
/opt/my-express-api/
  package.json
  app.js
  .env
```

启动文件示例：

```js
import express from 'express'

const app = express()

app.use(express.json())

// 健康检查接口，用来确认宝塔里的 Node 项目是否启动成功
app.get('/api/health', (req, res) => {
  res.json({ ok: true })
})

const port = Number(process.env.PORT || 3000)

// 只监听本机，公网入口交给 Nginx 或宝塔反向代理
app.listen(port, '127.0.0.1', () => {
  console.log(`api listening on http://127.0.0.1:${port}`)
})
```

如果宝塔要求写启动命令，可以类似：

```bash
# 根据你的入口文件调整
node app.js
```

如果使用 PM2 管理，可以是：

```bash
# 使用 PM2 启动后端
pm2 start app.js --name my-api
```

实际以宝塔当前版本的 Node 项目管理文档和界面为准。

## 5. 宝塔里配反向代理

目标：

```txt
前端域名：https://example.com
后端本机：http://127.0.0.1:3000
用户访问：https://example.com/api/health
```

宝塔图形界面里通常可以配置反向代理：

```txt
代理目录：/api/
目标 URL：http://127.0.0.1:3000
```

背后的 Nginx 核心配置类似：

```nginx
location /api/ {
  # 保留 /api 前缀转给 Express
  proxy_pass http://127.0.0.1:3000;

  # 这些请求头帮助后端知道真实访问来源
  proxy_set_header Host $host;
  proxy_set_header X-Real-IP $remote_addr;
  proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
  proxy_set_header X-Forwarded-Proto $scheme;
}
```

配置完先测：

```bash
# 在服务器本机测 Express
curl http://127.0.0.1:3000/api/health

# 再测域名反向代理
curl https://example.com/api/health
```

如果本机通、域名不通，优先看宝塔/Nginx 反向代理。

如果本机不通，优先看 Node 项目是否启动。

## 6. 宝塔里申请 SSL

常见流程：

1. 域名先解析到服务器。
2. 宝塔网站里绑定域名。
3. 放行 80 和 443。
4. 在 SSL 功能里申请证书。
5. 开启强制 HTTPS。

小白注意：

- 域名没有解析到服务器，证书申请可能失败。
- 80 端口被拦截，证书验证可能失败。
- 证书成功后，还要确认 443 端口开放。

如果不用宝塔，也可以按 Certbot 官方说明给 Nginx 申请证书。

## 7. 宝塔部署的优点和坑

### 优点

- 上手快。
- 界面直观。
- 适合管理多个站点。
- SSL、反向代理、日志查看比较方便。

### 常见坑

| 坑 | 表现 | 排查 |
|---|---|---|
| 上传错目录 | 首页 404 或空白 | 确认 `index.html` 是否在网站根目录 |
| 反向代理路径不一致 | `/api` 404 | 对比 Nginx 和 Express 路由 |
| Node 项目没启动 | 接口 502 | 看 Node 项目日志 |
| 证书申请失败 | HTTPS 不可用 | 查域名解析、80 端口、安全组 |
| 数据库裸奔 | 安全风险 | 不要开放 27017 给公网 |
| 只会看面板 | 出问题不会定位 | 学会 SSH、Nginx、日志 |

## 8. 宝塔和手动部署怎么搭配学

推荐路线：

```txt
第一遍：手动部署最小项目。
第二遍：用宝塔部署同样项目。
第三遍：打开宝塔生成的 Nginx 配置，对照手动配置理解。
```

这样学的好处：

- 你知道每个配置为什么存在。
- 面板报错时，你知道该看哪里。
- 以后换服务器、换面板、换 Docker，也不会完全重新开始。

## 9. 宝塔部署前检查清单

- 服务器能 SSH 登录。
- 域名已解析到服务器 IP。
- 云安全组开放 80、443。
- 如需 SSH，22 端口可用。
- Vue 已完成 `npm run build`。
- Express 本机能 `curl http://127.0.0.1:3000/api/health`。
- MongoDB 已开启认证。
- `.env` 已放到后端项目目录。
- 数据库密码没有写在前端代码里。

## 10. 宝塔部署后检查清单

- 首页能访问。
- 刷新前端子路由不 404。
- `/api/health` 能访问。
- HTTPS 正常。
- 强制 HTTPS 生效。
- Node 项目重启后能恢复。
- 宝塔日志里没有明显错误。
- Nginx 日志里没有持续 502。
- MongoDB 没有公网裸露。
