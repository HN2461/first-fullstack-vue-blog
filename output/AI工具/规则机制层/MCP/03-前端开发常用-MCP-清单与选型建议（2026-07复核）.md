# 03：前端开发常用 MCP 清单与选型建议（2026-07复核）

复核日期：2026-07-04

> 2026-07 复核结论：前端日常闭环仍建议优先 `Context7 + Chrome DevTools MCP + GitHub MCP + Playwright MCP`；设计协作再补 `Figma Dev Mode MCP`，组件生成再补 `shadcn MCP`。注意 MCP draft 规范仍在演进，但具体 server 能力仍以各官方仓库和宿主支持为准。

这篇回答一个更贴近日常开发的问题：

**前端到底该先装哪些 MCP，才能形成“查资料 -> 改代码 -> 跑页面 -> 对照设计 -> 复查回归”的闭环。**

先给结论，再看细节：

1. 如果你只装 2 个：`Context7 + Chrome DevTools MCP`
2. 如果你装 4 个：`Context7 + GitHub MCP + Chrome DevTools MCP + Playwright MCP`
3. 如果你还要做组件落地：再补 `shadcn MCP`
4. 如果你经常从 Figma 到代码交付：再补 `Figma Dev Mode MCP`

## 一、前端高频 MCP 总览

| MCP | 核心定位 | 前端最常见用途 | 推荐级别 |
| --- | --- | --- | --- |
| Context7 | 最新、版本化文档检索 | 查 React/Vue/Next/Vite/Tailwind 官方写法 | S |
| GitHub MCP | 代码仓库上下文与变更信息 | 查源码、Issue、PR、Release | S |
| Chrome DevTools MCP | 真浏览器调试与性能排查 | 查 DOM、控制台、网络、性能、A11y | S |
| Playwright MCP | 跨页面自动化验收 | E2E 复现、回归检查、关键流程脚本化 | S |
| shadcn MCP | 组件生成与注册表接入 | 快速落地 UI 组件和区块 | A |
| Figma Dev Mode MCP | 设计稿到代码上下文桥接 | 拉取设计信息、减少视觉还原偏差 | A |
| Exa MCP | 全网资料与代码搜索 | 查最新实践、方案对比、外部博客 | A |
| Tavily MCP | 研究型搜索与正文抽取 | 批量整理专题资料 | B |
| Brave Search MCP | 时效型网页搜索与摘要 | 浏览器动态、规范更新、新闻类信息 | B |

## 二、先装这 4 个，闭环最稳

## 2.1 Context7（文档基线）

- 官方入口：
  - <https://context7.com/docs/overview>
  - <https://context7.com/docs/installation>
- 关键能力：官方文档强调可通过远程 MCP 拉取版本化库文档，并通过 `resolve-library-id`、`query-docs` 精准检索
- 为什么放第一位：
  1. 前端最怕“版本写法记错”，它正好解决这个问题
  2. 比泛搜索更不容易把旧写法混进来
  3. 对 React、Vue、Next、Vite、Tailwind 这类快迭代生态特别值钱

## 2.2 GitHub MCP（真实实现层）

- 官方入口：
  - <https://github.com/github/github-mcp-server>
  - <https://docs.github.com/en/copilot/how-tos/provide-context/use-mcp/use-the-github-mcp-server?tool=jetbrains>
- 关键能力：读仓库、查代码、看 Issue/PR/Release，支持只读与工具集约束
- 前端高频场景：
  1. 文档没写透时，直接看源码实现
  2. 升级前先读 Release 和 breaking change 讨论
  3. 真实项目结构参考，不再只看二手教程

## 2.3 Chrome DevTools MCP（页面真实状态层）

- 官方入口：
  - <https://developer.chrome.com/docs/devtools/agents/get-started>
- 关键能力：和 DevTools 能力对齐，适合做 DOM、控制台、网络、性能与可访问性排查
- 前端高频场景：
  1. “代码看着没问题，但页面就是不对”的定位
  2. 样式覆盖、层级冲突、布局溢出检查
  3. 关键请求失败、缓存行为异常、性能瓶颈初筛

## 2.4 Playwright MCP（可重复回归层）

- 官方入口：
  - <https://github.com/microsoft/playwright-mcp>
- 关键能力：把浏览器自动化步骤标准化，可重复执行
- 前端高频场景：
  1. 关键流程 smoke test（登录、列表、详情、提交）
  2. 复杂交互复现（弹层、表单联动、分步流程）
  3. 回归前验证“修复没有破坏旧链路”

这 4 个组合完成的是：

1. `Context7` 解决“写法是否正确”
2. `GitHub MCP` 解决“实现是否可信”
3. `Chrome DevTools MCP` 解决“页面当前为什么错”
4. `Playwright MCP` 解决“修完能否稳定复现验证”

## 三、按需求加装的 5 个补位 MCP

## 3.1 shadcn MCP（组件落地效率）

- 官方入口：
  - <https://ui.shadcn.com/docs/mcp>
- 适合谁：常做中后台、营销页、组件化页面的前端
- 价值点：
  1. 可以把组件生成与项目代码风格结合起来
  2. 降低重复搭壳工作量
- 边界：
  1. 它擅长“快搭组件”，不替代你的设计规范
  2. 项目已有成熟设计系统时，先定组件治理规则再大规模生成

## 3.2 Figma Dev Mode MCP（设计协作效率）

- 官方入口：
  - <https://developers.figma.com/docs/figma-mcp-server/>
- 适合谁：前端和设计协作密集、交付要求高还原度的团队
- 价值点：
  1. 减少“设计稿理解误差”
  2. 降低尺寸、间距、层级、状态切换的反复沟通
- 边界：
  1. 它是“设计信息接入”，不是“自动产出可上线页面”
  2. 仍然要通过你们组件系统和可维护结构落地

## 3.3 Exa MCP（外部研究补位）

- 官方入口：
  - <https://exa.ai/docs/reference/exa-mcp>
  - <https://github.com/exa-labs/exa-mcp-server>
- 适合场景：
  1. 需要查最新博客、最佳实践、社区对比
  2. 需要网页正文抓取再总结

## 3.4 Tavily MCP（专题资料整理）

- 官方入口：
  - <https://docs.tavily.com/documentation/mcp>
- 适合场景：
  1. 做技术分享、专题文章、竞品调研
  2. 批量抽取网页正文，做跨来源整理

## 3.5 Brave Search MCP（时效信息补位）

- 官方入口：
  - <https://github.com/brave/brave-search-mcp-server>
- 适合场景：
  1. 浏览器新特性、规范动态、近期发布信息
  2. 需要高时效搜索与摘要

## 四、前端最实用的 3 套组合

## 4.1 日常开发标准版

1. `Context7`
2. `GitHub MCP`
3. `Chrome DevTools MCP`
4. `Playwright MCP`

## 4.2 组件交付强化版

1. `Context7`
2. `Chrome DevTools MCP`
3. `Playwright MCP`
4. `shadcn MCP`

## 4.3 设计协作强化版

1. `Context7`
2. `GitHub MCP`
3. `Chrome DevTools MCP`
4. `Figma Dev Mode MCP`

## 六、前端 UI 设计资料搜索专项

如果你的重点是“前端设计/UI 资料搜索”，建议直接用下面这套：

1. `Figma Dev Mode MCP`：拿设计上下文和组件细节
2. `Context7`：查 UI 框架官方实现方式
3. `shadcn MCP`：快速生成可用组件骨架
4. `Exa MCP`：补充最新设计趋势和社区案例

这套组合的分工很明确：

1. 设计稿信息来源：`Figma Dev Mode MCP`
2. 实现规范来源：`Context7`
3. 落地速度来源：`shadcn MCP`
4. 外部灵感来源：`Exa MCP`

## 6.1 UI 搜索关键词模板（可直接套用）

1. `React dashboard card layout best practices 2026`
2. `B2B admin table UX patterns sticky columns pagination`
3. `mobile form error states accessible patterns`
4. `design token naming conventions spacing typography`
5. `shadcn ui data table filter toolbar patterns`
6. `figma to react handoff checklist components states`

## 6.2 UI 资料筛选标准（避免搜到营销文）

1. 优先官方文档和官方仓库示例
2. 社区文章优先看最近 12 个月内容
3. 必须有可运行代码或完整截图
4. 结论要能回到你的业务页面约束，不抄纯视觉稿
5. 任何“趋势建议”都要落到具体组件和交互状态

## 6.3 UI 搜索到落地的最短流程

1. 在 `Figma Dev Mode MCP` 明确页面目标、组件层级和状态
2. 用 `Context7` 校验对应框架官方写法
3. 用 `shadcn MCP` 产出基础组件结构
4. 用 `Chrome DevTools MCP` 做样式和交互验收
5. 用 `Playwright MCP` 固定关键 UI 回归流程

## 五、落地顺序建议（避免一开始装太多）

1. 第一步：先装 `Context7`，保证文档写法准确
2. 第二步：装 `Chrome DevTools MCP`，保证页面问题能定位
3. 第三步：装 `GitHub MCP`，保证能深入源码与变更
4. 第四步：装 `Playwright MCP`，保证修复可重复验证
5. 第五步：按团队需求补 `shadcn MCP` 或 `Figma Dev Mode MCP`

一句话收口：

**前端选 MCP，优先顺序不是“谁更火”，而是“谁能把你的交付闭环补完整”。**
